# B302 - Graph Cleanup: Relabel or Retire Wrong-Polarity Outcome Lessons

State: ready
Priority: P2

Plan: (inline — this card is self-contained and sized for a Sonnet-level implementer)

### Problem (flagged by B301, 2026-07-14)

B301 stopped the *creation* of wrong-polarity outcome Lessons (assistant self-summaries
minting "failure" Lessons out of passing test counts). It deliberately did no retroactive
cleanup. The damage is still in the graph:

- Two durable B290 Lessons read "Plan outcome (**failure**): ✅ B290 Continuous Work State —
  COMPLETE & CERTIFIED … 192 passed, daemon healthy…" at 0.85 confidence, valence −0.8.
- They surface in top `current_truth` results and feed `_plan_feedback_from_similarity`
  ("similar plans failed!") — wrong-signed history poisoning future plan feedback.
- B300's assumption that "decay will age them out" has not held: they were still
  top-ranked in a real review session a day after being flagged.

### What This Card Does

**Task 1 — audit sweep.** Find every Lesson whose `text_raw` starts with
`"Plan outcome ("` and does NOT contain `"[valence_trigger:"` (i.e. system-labeled
before B301's audit trail existed). For each, re-run the current (post-B301)
`infer_outcome_valence` on the outcome body (the text after the prefix line):

- New verdict agrees with stored polarity → leave untouched.
- New verdict is the opposite sign → rewrite the prefix (`failure` ↔ `success`), flip the
  Lesson's `valence` sign, and append `\n[valence_relabel: B302, was <old>]` to the text.
- New verdict is `None` (ambiguous under the margin rule) → set `archived = true` (do not
  delete; graph-native rule — the node stays queryable, it just stops surfacing).

**Task 2 — repair linked Plans.** For each relabeled/archived Lesson, follow its edge to
the Plan (if any). Where `Plan.valence_source == "system"` and the sign matches the old
wrong label, update `Plan.valence` to the corrected value (or NULL it when the Lesson was
archived as ambiguous). Explicit (`valence_source != "system"`) plan valences are never
touched.

**Task 3 — one-shot CLI entry point.** Expose as `campy graph repair-outcome-polarity`
(dry-run by default, `--apply` to write; print a table of lesson_id, old→new polarity,
action). This is a maintenance sweep, not a Loop step — no daemon involvement.

**Task 4 — tests.** Fake-db tests covering: agree → untouched; flip → prefix + valence +
`[valence_relabel:` marker; ambiguous → archived; linked system-valence Plan corrected;
explicit-valence Plan untouched; lessons WITH `[valence_trigger:` skipped entirely.
Fixture texts: use the two real B290 lesson bodies from B301's Problem section.

### What This Card Does NOT Do

- No changes to capture/inference logic (B301 owns that; this card only consumes it).
- No deletion of nodes — relabel or archive only.
- No LLM re-judgment — the post-B301 regex + margin verdict is the arbiter; anything it
  can't call confidently gets archived, not guessed.
