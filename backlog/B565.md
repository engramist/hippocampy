# B565: question words are stored as Concepts

**Status:** Open. Found 2026-11-13 by the plan lead during the step-2 probe. Not fixed.

**Principles:** P8 (subjects are the backbone: a Concept is an entity or a kind, never a function word), P6 (measure correctly before believing).

**What.** Four of the five principled per-conversation stores from step 0c hold a Concept whose label is "What"/"what" or "who"; conv-48's store holds none. Each is linked to one turn by `MENTIONS`.

**Why it matters.** Step Q's `query_hits.objects` resolves a question term to any Concept with an exact label. So "What ..." questions name the "What" Concept.
- Hits are not affected: no fact's object is that Concept.
- The miss classes are. Of the 404 questions that step 2 targets ("object is text" 291, "object not reached" 113), 237 name a wh-word Concept.
- For 106 of them (74 + 32) it is the only Concept named. Those 106 belong in "the question names no object Concept", not in step 2's classes.

**Fix (capture, not the query).** Entity admission must not admit a closed-class word (the interrogatives and other function words) as a Concept. A store-side cleanup archives the existing ones. Then re-run step Q's miss table on the same stores. The hit count should not move; the miss classes should.

**Not in scope.** Filtering wh-words inside `query_hits` would hide the capture defect (P8: fix capture first).
