# B95 - ARC Solve Engine: Goal-Directed Strategy from Game Archetype Classification

State: ready
Plan: backlog/plans/B-95-arc-solve-engine.md

### Problem

The ARC agent has a strong Explore phase (B88 Hypothesis Engine) that learns *what actions do*,
but it has no Solve phase. It has no concept of what winning looks like, no goal decomposition,
and no strategy that says "I think this is a Chase game, and I need to reach the exit before
energy runs out." The agent is a sophisticated observer with no victory condition.

The `_draft_plan_steps()` method still generates generic 3-step templates. The `plan()` step
calls `register_plan` but with no goal-specific content. The agent is exploring blindly.

### What This Card Builds

A `SolveEngine` (`agents/arc3/solver.py`) implementing the 5 cognitive steps humans use to
solve an unfamiliar game — grounded in SideQuests tools as the cognitive substrate:

**Step 1 — Visual Archetyping (`ArchetypeClassifier`)**
Classify the game into `RACE | SPACE | CHASE | DISPLACE | UNKNOWN` using algorithmic signals
from the hypothesis context (object counts, convergence vectors, reward patterns). Anchored
by `analogical_search` against past game observations — structurally similar past games vote
on archetype. Mirrors how SideQuests `GistClass` centroid matching works in Step 2 of the
Consolidation Loop: fast cosine comparison, sticky once confidence > 0.65.

**Step 2 — Object Role Assignment (`ObjectRoleMapper`)**
Assign semantic roles (`PLAYER | ENEMY | GOAL | WALL | COLLECTIBLE | EXIT | UNKNOWN`) to each
distinct color group in the grid. Uses `InvariantDetector` output (walls never change) and
`Transition.diff_summary` (player moves with actions). Cross-referenced with `current_truth`
queries for "similar object roles in prior games." Mirrors SideQuests schema.org type mapping:
classify the entity's shape before doing semantic work on it.

**Step 3 — Victory Condition Hypothesis (`VictoryHypothesizer`)**
Identify the win condition *before* planning actions (the Inverted Pyramid — solve backwards
from the goal). Uses `recall_plans(goal_query="<archetype> game win condition")` to surface
successful past plan goals as templates. Uses `recall_relevant_lessons(domain="arc_game")` for
explicit game lessons. One LLM call synthesizes the victory condition hypothesis from archetype
+ object roles + past plan goals + reward history. Called once when archetype confidence > 0.65,
then only when dissonance is detected.

Victory condition types: `REACH_GOAL | COLLECT_ALL | SURVIVE | SCORE_THRESHOLD | ELIMINATE`

**Step 4 — Cognitive Dissonance Detection (`DissonanceDetector`)**
Monitor plan progress against the victory condition prediction. When reality diverges (zero
progress for N steps while on-strategy), call `report_outcome(valence=-0.7)` on the active
plan chunk — encoding the dissonance as negative valence in the SideQuests graph. Negative
valence propagates via `OUTCOME_SIGNAL` edges to related Concept nodes, shaping future
`analogical_search` rankings. On dissonance: re-run `VictoryHypothesizer` with the contradiction
as evidence. Mirrors how SideQuests Step 6 (Constrained Contradiction Arbitration) handles
conflicting knowledge.

**Step 5 — Plan Chunking (`PlanChunker`)**
Decompose the goal into macro-action sequences. Key insight: use **BFS on the in-memory
`StateGraph`** to find the shortest action path between known states — this is a graph
algorithm, not an LLM problem. For unvisited goal states, generate directional chunks from
object role positions. Register each chunk via `register_plan` to get Amygdala Reflex warnings
from past failed similar chunks. Report chunk completion via `report_outcome(positive valence)`.
The `register_plan` / NEXT_STEP graph edges IS chunked memory — plan steps are macro-actions.

### SideQuests Tool Wiring (No Schema Changes)

| Cognitive Step | Tool | Purpose |
|---|---|---|
| Archetyping | `analogical_search` | Past games of similar structure vote on archetype |
| Archetyping | `recall_relevant_lessons(domain="arc_game_type")` | Explicit archetype lessons |
| Victory Hypothesis | `recall_plans` | Past successful plan goals as victory templates |
| Victory Hypothesis | `recall_relevant_lessons(domain="arc_game")` | Explicit game lessons |
| Chunking | `register_plan` | Register each chunk; get Amygdala Reflex warnings |
| Dissonance | `report_outcome` | Encode failed prediction as negative valence |
| Chunk completion | `report_outcome` | Encode success as positive valence |

### StateGraph Extension (hypothesis.py)

Add `find_path(from_hash, to_hash) -> List[Transition]` — BFS returning the ordered list of
transitions between two known states. Used by `PlanChunker` to extract exact action sequences
for navigating between visited states.

### Acceptance Criteria

1. `ArchetypeClassifier` returns a non-UNKNOWN archetype after ≥5 observations with
   consistent movement patterns
2. `analogical_search` is called during archetype classification; result influences confidence
3. `ObjectRoleMapper` correctly identifies PLAYER (moves with actions), WALL (invariant), and
   GOAL/COLLECTIBLE (disappears or produces reward on contact) from transition history
4. `VictoryHypothesizer.hypothesize()` calls `recall_plans` and `recall_relevant_lessons`
   before the LLM call; LLM prompt includes archetype + object roles + past plan goals
5. `VictoryHypothesizer` is NOT re-called when archetype confidence > 0.65 and no dissonance
6. `DissonanceDetector` fires after N consecutive zero-progress steps during on-strategy
   execution; calls `report_outcome(valence < 0)` on active plan chunk
7. `PlanChunker.find_path_chunk()` uses BFS on `StateGraph` (not LLM) when goal state is in
   the graph; returns ordered `List[Transition]`
8. `PlanChunker` calls `register_plan` for each new chunk; chunk plan_id is tracked
9. `build_action_prompt()` includes `=== SOLVE CONTEXT ===` section with archetype, object
   roles, victory condition, active chunk, and dissonance status
10. `_draft_plan_steps()` uses `SolveContext.active_chunk` and `VictoryCondition.description`
    instead of static template
11. `reset_for_retry()` clears active chunk and dissonance state but preserves archetype and
    victory condition (they are cross-attempt knowledge)
12. `StateGraph.find_path()` returns correct BFS path or empty list if no path exists
13. All 63 existing B88 tests continue to pass
14. ≥15 new tests in `tests/test_arc3_solver.py`
15. No new MCP tools introduced; no SideQuests schema changes

### Outcome

The ARC agent transitions from "sophisticated explorer" to "goal-directed solver." It classifies
the game type, assigns roles to objects, hypothesizes a win condition, decomposes it into
trackable chunks, and detects when its model is wrong — exactly as a human does when sitting
down to an unfamiliar game. Cross-game learning accumulates via the SideQuests Plan graph:
successful chunk sequences and victory conditions build up in memory, making each new game
easier than the last.
