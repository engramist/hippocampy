# B506: Observation extractor stringifies dict-shaped objects

**Status:** open · **Found:** 2026-10-21 (B499 follow-up, R72 store analysis)

## Problem

When the extraction model returns a claim's `object` as a JSON object rather than a
string (e.g. `{"attribute": "completed", "value": "20 videos"}`), `extract.py` keeps
it via `_clean(p.get("object"))`, which calls `str()` on it. The Observation's
`object_text` becomes a Python repr: `{'attribute': 'completed', 'value': '20 videos'}`.
In the 40 R72 LongMemEval knowledge-update stores, 3 of the 7 attribute pairs that
should have linked were this shape, and the old B499 key collapsed every such row to
the attribute `{'name'`, causing false supersessions.

## Fix

At parse time, when `object` is a mapping, render it structurally: `name: value`
from the known keys (`name`/`attribute`/`key` + `value`), or reject the claim when it
cannot be rendered. Add a test with each shape seen. Measure on the R72 store copies
(`~/campy-lead/stores/r72/`) how many rows change.

## Principle

6 (measure correctly), 2 (structure in the graph is only as good as what is written).
Target: LongMemEval knowledge-update via B499 supersession and attribute retrieval.
