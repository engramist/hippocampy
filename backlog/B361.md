# B361 - Flaky test_periodic_checkpoint_task_interval Under CI (Wall-Clock Timing Assertion)

State: ready
Priority: P3

Plan: none yet.

### Problem

`tests/test_manual_checkpoint.py::test_periodic_checkpoint_task_interval` failed in CI on a purely
docs-only PR (#115, `docs/ARCHITECTURE.md` only, 85 insertions/14 deletions — confirmed via `git diff
--stat`, nothing else touched):

```
FAILED tests/test_manual_checkpoint.py::test_periodic_checkpoint_task_interval - AssertionError: Spacing
0.1609825960000535 not near 0.1
```

The test (`tests/test_manual_checkpoint.py:104-129`) asserts that a periodic checkpoint task's real
`asyncio.get_event_loop().time()` timestamps land close to a 100ms interval, driven by a real
`asyncio.sleep(0.35)` over the test's own wall-clock duration — no mocked clock. On a shared/busy CI
runner, 60ms+ of scheduling drift on a 100ms target is unsurprising, not evidence of an actual regression
— this is the same *class* of flake as B360 (order-dependent/environment-sensitive, not a real bug), just
a different test and a different specific mechanism (wall-clock precision vs. state leakage).

Found while shipping a docs-only PR; investigated before merging (confirmed the diff couldn't plausibly
cause this) rather than assumed unrelated, then merged per this project's own "any other failure needs
confirmation" discipline — filed as its own card rather than silently noted, per standing practice.

### What it does (scope)

1. Reproduce with a repeated-run loop (matching this project's established standard from B351/B358) to
   confirm it's genuinely timing-sensitive and not a one-off CI blip.
2. Fix at the root: either mock the clock (`asyncio.get_event_loop().time()` / the sleep interval) so the
   assertion is deterministic regardless of real scheduling delay, or widen the tolerance to something
   realistic for a shared CI runner (e.g. a multiple of the interval, not a fixed absolute delta) — prefer
   the mocked-clock fix since it eliminates the flake class entirely rather than just making it less
   likely.
3. Check whether other tests in `tests/test_manual_checkpoint.py` (or elsewhere) use the same
   real-`asyncio.sleep`-plus-tight-tolerance pattern and would benefit from the same fix.

### Dependencies

None — independent of B360, found incidentally during an unrelated docs PR.
