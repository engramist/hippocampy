# B461 - Measure Save-Gate Changes on LoCoMo; Opt-In Jev Provider Trial (Conditional)

State: ready (blocked on B460)
Priority: P3

### Problem Statement

B458–B460 are judged on a small author-labeled set. That shows whether the
gate classifies statements correctly; it doesn't show whether better save
decisions improve recall at question time. LoCoMo is already wired in
`campy-benchmarks` (`check_locomo10.py`), and it's the benchmark the Jev-Mem
paper (arXiv 2609.23986) reports on (0.777 LLM-judge overall, 6.6× faster
memory construction than the fastest baseline), so it gives a like-for-like
comparison.

Jev itself (TypeSafe AI, launched 2026-09-15) returns typed answers with
calibrated probabilities, ~70–500 ms, $0.042 per million input tokens. It is
**hosted-only** (no weights, no on-prem, early-access waitlist). Campy is
local-first and the Loop sees every user and assistant turn, so a Jev
provider would send the full conversation to a third party. That is why it
is last, conditional, and opt-in.

### What It Does (Scope)

1. **LoCoMo before/after:** run `campy-benchmarks` LoCoMo against the
   pre-B458 baseline commit and after each of B459 and B460. Record overall
   and per-category scores, memory construction time, and nodes created
   (fewer, better-typed nodes is a result in itself).
2. **Decision gate for the Jev trial:** only proceed if B460's local
   calibrated gate misses its acceptance targets, or LoCoMo shows the save
   gate is still the bottleneck. Record the decision here either way.
3. **If proceeding:** add a `jev` decision provider behind the existing
   per-step LLM client selection (`create_llm_client_for_step`), off by
   default, requiring explicit config and an API key from env. Map Steps 2,
   3b, 4, 6 onto Jev typed questions using the B458 spec as the decision
   criteria. Document the data-egress implication in `campy.toml` comments
   and the README.
4. Compare local vs. Jev on the B458 set and LoCoMo: accuracy, calibration,
   latency, cost.

### Out of Scope

- Making any hosted model the default.

### Dependencies

- B460 (and B459 if landed). `engramist/campy-benchmarks` LoCoMo harness.

### Files to create/modify

- `campy-benchmarks`: results write-up for each run.
- If step 3 proceeds: `campy/brain/llm/provider.py`, `campy.toml`,
  `README.md`, tests with the provider mocked (no network in CI).

### Acceptance Criteria

- [ ] LoCoMo numbers recorded for baseline, post-B459, post-B460.
- [ ] Go/no-go decision on the Jev trial recorded with its reason.
- [ ] If built: provider is off by default, never called without explicit
      config, and CI never touches the network.

### Outcome

We know whether better save decisions improve recall, and whether a hosted
decision model adds anything a local calibrated gate doesn't.
