### Background & Problem

In B314, HippoCampy introduced `GraphGateway` (`campy/brain/hippocampus/graph/gateway.py`) and an automated CI ratchet (`scripts/check_cypher_ratchet.py`) to create an architectural chokepoint between application code and the database engine. B314 stated:
> *"A single card cannot safely migrate 500 query sites. This card builds the seam, proves it on one vertical slice, and installs a ratchet so the number can only go down. Bulk migration happens in follow-up cards, one module at a time."*

However, the follow-up bulk migration was never completed:
- **592 lines of raw inline Cypher** remain scattered across 48 application files outside `graph/queries/`.
- **43 files** import `KuzuClient` directly, bypassing the gateway entirely.
- Top offender modules include: `brainstem/sweep.py` (68 lines), `tools/arc_queries.py` (46 lines), `tools/quests.py` (42 lines), `web/server.py` (31 lines), `loop/step7_pathway.py` (27 lines), `tools/task_graph.py` (27 lines), `loop/orchestrator.py` (24 lines).

**Why This Is a P0 Blocker for B384:**
Oxigraph speaks **SPARQL**, not Cypher. If B384 attempts to swap `KuzuClient` for `OxigraphClient` without completing this chokepoint:
1. Removing `kuzu` from `pyproject.toml` immediately breaks 43 application files with import errors.
2. The storage cutover would require an unmanageable, simultaneous rewrite of ~1,100 query call sites across 38+ files at Gate 2.
3. B380's patent claim tests cannot be portable if the underlying loop steps still call `KuzuClient.execute_read()` directly.

### What It Does (Scope)

This card finishes the B314 migration, driving the Cypher ratchet count from **592 to 0**:

1. **Centralize All Application Queries into `graph/queries/`:**
   - Follow established conventions from existing migrated modules:
     - Existing: `arc.py` (134 lines), `lessons.py` (438 lines), `capability.py` (376 lines), `continuity.py` (157 lines), `backup.py` (47 lines).
     - Standard naming convention: `<domain>.<verb>_<subject>` (e.g. `sweep.find_stale_working_memory`, `arc.fetch_investigation_thread_state`).
   - Slices to create or modify:
     - Modify `queries/arc.py`: Centralize remaining ARC queries from `arc_queries.py`, `arc_artifacts.py`, `arc_mechanics.py`.
     - Create `queries/sweep.py`: Background decay, vacuum, and maintenance queries.
     - Create `queries/quests.py`: Quest creation, activation, and hierarchy queries.
     - Create `queries/pathways.py`: Step 7 pathway strengthening and co-occurrence queries.
     - Create `queries/orchestrator.py`: Loop step persistence and state transitions.
     - Create `queries/retrieval.py`: Candidate expansion, neighbor traversal, and working memory tracking queries.
     - Create `queries/task_graph.py`: ActionItem DAG and dependency queries.
     - Create `queries/web.py`: Web dashboard graph exploration and stats queries.

2. **Parallelizable Sub-Batch Decomposition (No 50k Monolith):**
   - The ~1,100 call sites across 48 files are partitioned into 5 disjoint groups:
     - **Group A (ARC):** `arc_queries.py` (46), `arc_artifacts.py` (27), `arc_mechanics.py` (27) = 100 lines.
     - **Group B (Brainstem + Core):** `sweep.py` (68), `quest.py` (27), `hippocampus.py` (19), `export.py` (13) = 127 lines.
     - **Group C (Loop + Retrieval):** `step7_pathway.py` (27), `orchestrator.py` (24), `retrieval.py` (16), `working_memory.py` (14), `capture.py` (14), `ingest.py` (11) = 106 lines.
     - **Group D (Tools + Web):** `quests.py` (42), `task_graph.py` (27), `web/server.py` (31), `procedure_synthesis.py` (11), `wiki_projection.py` (10) = 121 lines.
     - **Group E (Tail):** ~30 remaining files = ~138 lines.
   - Shared write surface is strictly append-only `queries/__init__.py` and `scripts/cypher_baseline.json` (orchestrator updates at merge).

3. **Multi-Engine Query Abstraction in `gateway.py`:**
   - Keep `NamedQuery` as the semantic contract (`name`, `params`, `mutating`, `description`).
   - Add provisional `sparql: str | None = None` for pure-graph traversal queries (~90% of queries).
   - **Explicit Handler Boundary:** Explicitly document and carve out that Vector ANN search (`QUERY_VECTOR_INDEX` -> `sqlite-vec` + SPARQL hydration in Python) and RDF-star edge reification (quoted triples with `:event_id` discriminators) are handler-dispatched in B384 Phase 2B, not 1:1 SPARQL string transliterations.

4. **Zero-Ratchet CI Enforcement:**
   - Drive `scripts/check_cypher_ratchet.py` count to **0**.
   - Update `scripts/cypher_baseline.json` to `{ "cypher_lines": 0, "execute_raw_calls": 0 }`.
