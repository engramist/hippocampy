## Problem Statement

`get_open_loops` surfaces confidence-low items, but the brain never reasons about what's *absent*. It can't say "I have lots of Lessons about spatial navigation but zero about elimination puzzles — that's a knowledge gap." There's no process that identifies "I should know X but I don't."

Karpathy's metacognition: the system should model its own knowledge state and identify areas of uncertainty or missing coverage.

## Root Causes

1. No coverage analysis — no mechanism to check "for each domain/archetype, how many Lessons exist?"
2. No `KnowledgeGap` node type to represent identified gaps
3. No sweep step that audits domain coverage
4. `get_open_loops` is reactive (surfaces existing low-confidence items), not proactive (identifies missing knowledge)

## What This Card Does

1. **New `KnowledgeGap` node type**: Represents an identified gap in the knowledge graph
2. **New sweep step**: `_detect_knowledge_gaps()` — counts Lessons/Plans/Decisions per domain and flags low-coverage domains
3. **Gap identification heuristics**:
   - Domain with < 2 Lessons but > 5 Messages mentioning it → gap
   - Archetype with solved_count > 0 but lesson_count == 0 → gap
   - Domain where all Lessons have confidence < 0.5 → low-quality gap
4. **New MCP tool**: `get_knowledge_gaps` — returns active gaps for proactive use by agents
5. **IDENTIFIED_GAP_IN edge**: Links KnowledgeGap → MainQuest or domain Concept

## Graph Design (Graph Expert Analysis)

**New node type:**
```
KnowledgeGap:
    gap_id           STRING,
    domain           STRING,
    gap_type         STRING,    -- "missing_lessons", "low_quality", "no_procedures"
    description      STRING,
    severity         DOUBLE,    -- 0.0 (minor) to 1.0 (critical)
    message_count    INT32,     -- how many messages reference this domain
    lesson_count     INT32,     -- how many lessons exist
    resolved         BOOLEAN,
    created_at       TIMESTAMP,
    resolved_at      TIMESTAMP,
    PRIMARY KEY (gap_id)
```

**New relationship:**
```
IDENTIFIED_GAP_IN (FROM KnowledgeGap TO MainQuest, FROM KnowledgeGap TO Concept)
```

**Access pattern for gap detection** (sweep):
```cypher
-- Count lessons per domain
MATCH (l:Lesson) WHERE l.archived = false
RETURN l.domain, count(l) AS lesson_count
```
```cypher
-- Count messages mentioning a domain concept
MATCH (m:Message)-[:ESTABLISHED]->(c:Concept)
WHERE c.gist_class = $domain
RETURN count(m) AS message_count
```

**Gap resolution**: When a new Lesson is created in a gap domain, check if the gap should be resolved:
```cypher
MATCH (g:KnowledgeGap {domain: $domain, resolved: false})
SET g.resolved = true, g.resolved_at = timestamp($now)
```
