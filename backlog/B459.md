# B459 - Evidence-Aware Save Gate: Retrieve Before Judging (Uncertain Band Only)

State: ready (blocked on B458 baseline)
Priority: P2

### Problem Statement

The save decision never looks at the graph. In `orchestrator.run_loop`,
`classify_artifact` (Step 4) runs on the message text alone, and Step 5
retrieval (`retrieve_candidates`) runs only afterwards, for entities that
already passed the gate.

So several "senses" documented in `docs/ARCHITECTURE.md` (Step 4 table)
cannot influence whether something clears the noise floor:

- **Entity sense:** the text names a known graph entity;
- **Contradiction sense:** it's 0.75–0.92 similar to an existing confirmed node;
- relation to a high-confidence `GlobalConstraint`.

A sentence about a core project entity gets exactly the same gate score as a
sentence about a random noun. Tony Seale's post on Jev makes the same point
in general form: "the message alone may not tell you… the graph supplies the
evidence."

### Provenance risk (must be handled in the same card)

Once graph evidence feeds the gate, poisoned or self-generated evidence
becomes a way to get content promoted. The concrete case here: ISSUE-024
caps assistant turns at `ASSISTANT_CAP = 0.85` and says assistant content
"must be corroborated by user input or graph evidence to be promoted"
(`step4_pattern.py`). If the "graph evidence" is itself assistant-derived,
the model can corroborate its own earlier claims. Not yet traced whether a
path like that exists today (`Concept.source` / `Concept.authority` exist;
whether they record turn role consistently is unverified).

### What It Does (Scope)

1. **Trace first:** document whether turn role (user/assistant/ingested doc)
   is recorded on Concepts and artifacts today, and whether any current
   promotion path (sweep re-scoring, Hebbian promotion, arbitration
   "additive") can promote assistant content using only assistant-derived
   neighbors. Write findings into this card.
2. **Uncertain band only:** for entities whose Step 4 result lands in a
   configurable band (default: `0.45 <= confidence < HARD_LOCK`), run
   retrieval before the final gate decision and pass the top-k neighbors as
   evidence. Clear noise and clear saves skip retrieval, so the per-message
   cost stays bounded.
3. **Evidence carries provenance:** each neighbor passed to the gate includes
   its source (user / assistant / document) and authority. The gate may only
   use evidence to raise an assistant-originated item if at least one
   supporting neighbor is user- or document-originated.
4. **Evidence features (no LLM):** known-entity match, similarity to a
   confirmed artifact of the same type, and contradiction-band hit. Feed them
   into the gate score in a clearly separated, logged adjustment so the
   effect is attributable.
5. Re-run the B458 harness (extended with a small fixture graph so evidence
   exists) and record before/after.

### Out of Scope

- Replacing the scoring model (B460).
- LLM calls in the gate.

### Dependencies

- B458 (spec, labeled set, harness, `gate_entity` helper).

### Files to create/modify

- Modify: `campy/brain/temporal_lobe/loop/orchestrator.py` (retrieve before gate in band)
- Modify: `campy/brain/temporal_lobe/loop/step4_pattern.py` (`gate_entity` accepts evidence)
- Modify: `campy/brain/temporal_lobe/loop/step5_retrieval.py` (return source/authority on candidates, if not already)
- Modify: `benchmarks/save_gate/run_baseline.py` (fixture graph mode)
- Create: `tests/test_gate_evidence.py`

Tool/adapter allow-lists: no tool changes. No shadow stores: evidence is read
from the graph per call, nothing cached as primary state.

### Acceptance Criteria

- [ ] Trace findings (step 1) recorded in this card.
- [ ] Entities outside the band do no extra retrieval (test counts calls).
- [ ] A test where an assistant claim is "supported" only by assistant-derived
      neighbors: it is **not** raised. Same claim with a user-derived neighbor:
      it is.
- [ ] B458 harness before/after numbers recorded; false-save rate does not
      increase.
- [ ] Loop timing logs show the added retrieval cost per message.

### Outcome

The save decision uses what the graph already knows, without letting the
model promote its own earlier output.
