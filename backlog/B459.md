# B459 - Evidence-Aware Save Gate: Retrieve Before Judging (Uncertain Band Only)

State: in-progress (Parts A and B done 2026-10-01; harness fixture-graph run and tuning pending the B462 full-mode baseline)
Priority: P2

### Problem Statement

The save decision never looks at the graph. In `orchestrator.run_loop`,
`classify_artifact` (Step 4) runs on the message text alone, and Step 5
retrieval (`retrieve_candidates`) runs only afterwards, for entities that
already passed the gate.

So several "senses" documented in `docs/ARCHITECTURE.md` (Step 4 table)
cannot influence whether something clears the noise floor:

- **Entity sense:** the text names a known graph entity;
- **Contradiction sense:** it's 0.75–0.92 similar to an existing confirmed node;
- relation to a high-confidence `GlobalConstraint`.

A sentence about a core project entity gets exactly the same gate score as a
sentence about a random noun. Tony Seale's post on Jev makes the same point
in general form: "the message alone may not tell you… the graph supplies the
evidence."

### Provenance risk (must be handled in the same card)

Once graph evidence feeds the gate, poisoned or self-generated evidence
becomes a way to get content promoted. The concrete case here: ISSUE-024
caps assistant turns at `ASSISTANT_CAP = 0.85` and says assistant content
"must be corroborated by user input or graph evidence to be promoted"
(`step4_pattern.py`). If the "graph evidence" is itself assistant-derived,
the model can corroborate its own earlier claims. Not yet traced whether a
path like that exists today (`Concept.source` / `Concept.authority` exist;
whether they record turn role consistently is unverified).

### What It Does (Scope)

1. **Trace first:** document whether turn role (user/assistant/ingested doc)
   is recorded on Concepts and artifacts today, and whether any current
   promotion path (sweep re-scoring, Hebbian promotion, arbitration
   "additive") can promote assistant content using only assistant-derived
   neighbors. Write findings into this card.
2. **Uncertain band only:** for entities whose Step 4 result lands in a
   configurable band (default: `0.45 <= confidence < HARD_LOCK`), run
   retrieval before the final gate decision and pass the top-k neighbors as
   evidence. Clear noise and clear saves skip retrieval, so the per-message
   cost stays bounded.
3. **Evidence carries provenance:** each neighbor passed to the gate includes
   its source (user / assistant / document) and authority. The gate may only
   use evidence to raise an assistant-originated item if at least one
   supporting neighbor is user- or document-originated.
4. **Evidence features (no LLM):** known-entity match, similarity to a
   confirmed artifact of the same type, and contradiction-band hit. Feed them
   into the gate score in a clearly separated, logged adjustment so the
   effect is attributable.
5. Re-run the B462 harness (extended with a small fixture graph so evidence
   exists) and record before/after.

### Outcome

model promote its own earlier output.

### Trace findings (2026-09-30)

**Turn role was not recorded on Concepts.** `_store_concept` wrote no
`source`, `authority` or role, and Concepts have no edge to the Message they
came from, so a Concept's origin could not be recovered. (Messages store
`role`; artifacts link back via `ESTABLISHED`, but artifacts only exist above
`HARD_LOCK`, which assistant turns can't reach.) `Concept.source` already
means the producing system under the B312 provenance contract, so reusing it
for speaker role would have mixed two meanings.

**Two automatic paths let assistant content confirm itself** (both reproduced
against a real Oxigraph store before the fix):

1. **Dedup.** `orchestrator.touch_dedup_concept` cleared `confidence_low` for
   any repeat mention at `>= 0.80`, below both `HARD_LOCK` (0.90) and
   `ASSISTANT_CAP` (0.85). An assistant sentence with one keyword hit (0.82),
   said twice, left a confirmed Concept at confidence 0.82.
2. **Event-driven re-scoring.** `rescore_nearby_low_confidence` raises a
   `confidence_low` neighbor by `0.05 × neighbor_count` (+0.10 if the average
   neighbor strength > 0.70), counting any neighbor at confidence ≥ 0.60.
   From the 0.85 cap, a single neighbor is enough. Two Concepts from one
   assistant turn are linked by `CO_OCCURS_WITH`, so the next pathway update
   on one promoted the other to 0.99, confirmed.

Neither path creates artifact nodes, but a promoted Concept drops out of the
soft-lock review list and is served as confident in recall. The background
sweep does not re-score `confidence_low` nodes (despite `ARCHITECTURE.md`
saying so), and the only other writers of `confidence_low = false` are
human-initiated (disambiguation) or ingestion paths.

### Part A: provenance + self-promotion fixes (done 2026-09-30)

- New column `Concept.origin_role` (`user` | `document` | `assistant`; NULL =
  pre-B459), migration in `SCHEMA_MIGRATIONS`, `ORIGIN_ROLES` in `schema.py`.
  Written by `create_concept` and by `create_minimal_concept` (relation
  endpoints), from the turn role.
- Dedup: promotes only when the new mention itself clears `HARD_LOCK`;
  stronger origin wins; an unknown origin is never relabelled `assistant`.
  **Behavior change for user turns too:** a repeat user mention at 0.80–0.89
  no longer confirms a node, matching the threshold for a first mention.
- Re-scoring: an assistant-originated candidate counts only user/document
  neighbors (`pathways.count_corroborating_neighbors`). Non-assistant and
  legacy nodes are unchanged.
- Tests: `tests/test_b459_origin_provenance.py` (9, all failing on the pre-fix
  code). Migration fixtures regenerated with
  `scripts/generate_migration_fixture.py` (the `all_110` variant also picks up
  a previously missing `Session.last_proactive_push_msg_count`).

Known gap: existing graphs have NULL `origin_role` everywhere, so
assistant content stored before this change is still unrestricted. A backfill
isn't possible from the graph alone (no Concept→Message link).

### Part B: evidence rescue in the gate (done 2026-10-01)

Implemented narrower than scope items 2 and 4, on purpose. Without the B462
full-mode baseline there is no data to choose weights for raising scores
within the band, so Part B adds no new thresholds:

- **Band:** only entities the gate would drop at `0.45 <= confidence <
  NOISE_FLOOR` (the existing salience-rescue band, `EVIDENCE_RESCUE_MIN`).
  Entities above the floor are unchanged, so nothing here can reify.
- **Retrieve before dropping:** for those entities only, Step 5 retrieval runs
  before the gate decision, and its candidates are reused by Step 5 (no
  double retrieval). Everything outside the band does no extra retrieval.
- **Evidence:** a candidate counts when it is at or above `MATCH_THRESHOLD`
  similarity, confirmed (`confidence_low = false`), and not
  `flagged_for_review`. For assistant turns it must also be `user`- or
  `document`-originated (Part A's `origin_role`); unknown origins don't count.
- **Effect:** a supported entity is kept as tentative at `NOISE_FLOOR + 0.02`
  (the salience rescue's landing point), never confirmed. Downstream, a
  strong match reinforces the existing node (additive); a gray-zone match goes
  to Step 6 arbitration, so a weakly worded contradiction of a confirmed node
  is no longer silently dropped.
- Step 5 candidates now carry `confidence_low`, `origin_role`,
  `flagged_for_review` (already returned by `vector_search`).
- `summary["evidence_rescues"]` counts rescues; each check logs
  `[Loop:Timing] step=step4_evidence` with elapsed time, candidate count and
  supporting node ids.

Tests: `tests/test_b459_evidence_gate.py` (9): the pure rescue rules, plus
end-to-end `run_loop` runs on a real Oxigraph store (precomputed entities,
stubbed embedder):
- a known confirmed entity is kept and reinforces the existing node;
- an unknown one is still dropped;
- a tentative neighbor is not evidence;
- an assistant turn ignores unknown-origin evidence;
- retrieval runs once in band and not at all outside it.

The same scenario on the pre-Part-B code: `noise_count = 1`; after:
`noise_count = 0`, `additive_updates = 1`.
