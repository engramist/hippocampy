# B434 - Gated Consolidation Loop Worker Crashes on Every Turn (Queue Tuple Arity Mismatch)

State: fixed — merged via PR #230 (2026-09-20)
Priority: P0
Branch: fix/b434-loop-worker-unpack-crash
PR Target: main

### Problem

`campy/brain_daemon.py::_loop_worker` unpacks a **4-element** tuple from
`self._loop_queue`:

```python
message_id, text, role, session_id = await self._loop_queue.get()
```

but `notify_turn` (`campy/brain/thalamus/tools/capture.py:362`) enqueues a
**5-element** tuple:

```python
await loop_queue.put((message_id, content, role, session_id, precomputed))
```

This is an unconditional `ValueError: too many values to unpack` on the
very first `.get()` — independent of what `precomputed` actually
contains (even `None` still makes it a 5-tuple). The unpack happens
*before* the surrounding `try/except`, so nothing catches it locally.

`brain_daemon.py`'s own `_restart_on_failure` callback does restart the
crashed `loop_worker` task, but the restarted worker immediately calls
`.get()` on the same queue and hits the exact same arity mismatch on the
next queued item — every deployment where turns are actively flowing
enters a permanent crash-restart loop, and **no turn is ever run through
`run_loop`**. This means Gated Consolidation (spaCy NER, schema
classification, LLM entity extraction — the entire mechanism that turns
conversation turns into graph facts) silently never executes.

`run_loop` (`campy/brain/temporal_lobe/loop/orchestrator.py:48-52`)
already declares `precomputed: dict | None = None` as a real parameter
— it is not dead code on that side, just never reached because the
worker crashes before ever calling it.

### How this was found

While auditing an orphaned, never-committed benchmark report
(`docs/benchmarks/kuzu-baseline-kpis.md`, see PR #229) that documented a
live external-harness run from 2026-09-04/06. Its root-cause section
("2. The GCL Loop Worker Unpack Bug in `d35b28b`") described this exact
bug against that commit. Re-verified against current `main`
(2026-09-19, well past the Kùzu → Oxigraph cutover) — **the bug is
still present, unfixed, in `brain_daemon.py`**. Git blame:
- The 5-tuple `.put()` (with `precomputed`) has existed since at least
  2026-07-13 (B292's `tools/__init__.py` split).
- The 4-var unpack in `_loop_worker` dates to 2026-05-16 (project
  rename commit) and has apparently never been updated since
  `precomputed` was added to the tuple.

### Fix

Unpack all 5 elements in `_loop_worker` and pass `precomputed` through
to `run_loop(..., precomputed=precomputed)`.
