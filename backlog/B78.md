### B78 · Monitor Retrospective Plan Dedup Threshold

**Problem:** B68 retrospective plan inference uses a 0.90 embedding similarity threshold for dedup. This may be too low, allowing near-duplicate plans from similar but distinct conversations through. The concern is false negatives (allowing duplicates) rather than false positives (blocking valid plans).

**What it does:** Adds observability to the plan dedup process and establishes a threshold review mechanism.

**Depends on:** B68

**Files to modify:**
- `mcp_engine/sweep.py` — add logging of plan dedup decisions (similarity scores, accept/reject)
- `mcp_engine/sweep.py` — make dedup threshold configurable via `sidequests.toml`

**Adapter allow-list propagation check:** No tool changes — N/A.

**Acceptance Criteria:**
- Plan dedup logs similarity score and decision for each candidate
- Dedup threshold is configurable in `sidequests.toml` (default: 0.90)
- `pytest tests/ -k sweep -q` passes
- Log output includes: `"Plan dedup: similarity={score:.3f}, threshold={thresh}, action={accept|reject}"`

**Outcome:** Plan dedup behavior is observable and tunable without code changes.
