### Problem

`memory_decision` currently recommends which single tool to call. With the bundle compiler (252), agents should know when to request a compiled bundle vs. individual tools. The agent-side skill and onboarding prompts need updating to reflect the new memory capabilities.

### What This Card Does

Upgrades `memory_decision` to be bundle-aware and updates the agent-facing skill documentation and onboarding prompts to teach agents how to use `compile_context` effectively.

- B253 complete (Agent Output Formatters)

### Audit Findings (2026-08-03 re-verification)

- `.venv/bin/python -m pytest -q tests/test_memory_decision.py` → 37 passed. This module (`campy/brain/thalamus/memory_decision.py`) is a pure rule-based function with no DB dependency, so its tests are genuinely trustworthy.
- **"memory_decision recommends compile_context for multi-entity queries" — met.** `_is_multi_entity()` (proper-noun / quoted-term heuristic) and an explicit `bundle_triggers` list (`"everything about"`, `"full context"`, `"brief me on"`, `"summary of"`, `"overview of"`, `"bundle"`, `"compile"`, etc.) both route to `compile_context` with `suggested_params` (token_budget, `include_tabular`, `output_format`). Verified by reading Rule 0, which is checked first.
- **"memory_decision recommends compile_context for 'tell me everything about X' patterns" — met** (`"everything about"` is literally in `bundle_triggers`).
- **"memory_decision still recommends individual tools for simple fact checks" — met** (e.g. "what did we decide" → `current_truth`, unaffected by the new Rule 0).
- **Gap — "Token budget guidance included in recommendations based on agent context window" is not implemented.** `decide_memory_action()` accepts a `client_name: Optional[str] = None` parameter (documented in the docstring as "Optional client identifier (e.g., 'codex', 'claude-desktop')"), but `client_name` is **never referenced anywhere in the function body** (`grep -n "client_name" campy/brain/thalamus/memory_decision.py` only matches the parameter declaration and its docstring line). The `compile_context` recommendation's `suggested_params.token_budget` is a hardcoded `32000` regardless of which agent/client is asking — there is no logic anywhere that varies the token budget by agent context window size. No test in `tests/test_memory_decision.py` passes or asserts on `client_name` either, so this gap is untested as well as unimplemented.
- **Gap — "Layer 2 onboarding prompt mentions bundle compilation" is not implemented.** The actual Layer 2 onboarding prompt is `LAYER_2_ONBOARDING` in `adapters/openclaw_gateway.py` (built by `build_openclaw_prompt()`, exposed via the `get_openclaw_prompt` MCP tool). Checked its full text — it lists `memory_recall`, `memory_search_analogies`, `register_plan`, `recall_plans`, `report_outcome`, `memory_store` — **`compile_context` (or any bundle-related tool) is not mentioned anywhere in it.** `grep -rln "compile_context" adapters/` only finds a reference in `adapters/hermes/README.md`, not in any `adapter.py`. The card's own file list says `adapters/*/adapter.py` should be modified for this; none of `adapters/{codex,claude_code,gemini_cli,hermes,chatgpt_desktop,claude_desktop}/adapter.py` reference `compile_context`, `memory_decision`, or "Layer 2" at all.
- **Met** — Skill documentation: both `skills/campy-memory/SKILL.md` and the packaged copy `campy/data/campy-memory/SKILL.md` (the card's listed path `sidequests/data/campy-memory/SKILL.md` is stale post-anatomy-refactor; this is its current location) cover `compile_context` in detail — when to use it vs. `current_truth`, token-budget behavior, a routing-priority table, and anti-bloat guidance for consuming bundles ("If the bundle includes tabular data, reference it by table name or row count—don't paste entire tables inline," "Respect the bundle's truncation flag"). Both files were checked directly and are consistent.
- Full suite: `.venv/bin/python -m pytest -q` → 1600 passed, 59 skipped, 2 xfailed (no regressions).

Two of eight acceptance criteria are unmet (agent-aware token budgeting, onboarding-prompt update). Not fixed inline: the onboarding-prompt gap in particular touches a shared prompt-construction module used across live sessions, and the "based on agent context window" criterion has no defined per-agent window table anywhere in the repo to wire up — both are real implementation work, not one-line fixes.

### Outcome

Agents know when and how to use the full Campy Memory OS capabilities. The system guides them to the right retrieval strategy without requiring manual tool selection.
