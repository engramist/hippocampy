# B299 - Surface the Plan Lane in ask / current_truth / compile_context

State: ready
Priority: P1

Plan: (inline — this card is self-contained)

### Problem (observed in a real cross-agent user test, 2026-07-13)

A GitHub Copilot agent implemented three backlog cards and documented its work in Campy
exactly as intended: `register_plan` with a goal per card, `report_outcome` per step with
valences. `recall_plans` retrieves all of it, correctly ranked.

But when a reviewing agent asked the obvious question — `ask("What work did the GitHub
Copilot agent do on B292, B293, and B298?")` — Campy answered **"my memory is empty
regarding this topic."** `current_truth` with the same query returned unrelated Lessons and
noise Concepts, zero plans. The work was documented, durable, and ranked — and invisible to
the two tools an agent reaches for first. This directly undermines the B290/B252 promise
(switch agents, ask what happened, continue), and it recreates the exact failure mode B298's
design review warned about: content that is "in the graph" but not reachable through the
primary retrieval surfaces.

### Root Cause

1. `campy/brain/hippocampus/table_registry.py` — the `"retrievable"` tag set does not
   include `Plan`, `PlanStep`, or `Procedure`. `current_truth` builds its vector sweep from
   `tables_with("retrievable")`, so the Plan lane is never searched even though
   `Plan.vector_index` exists (it is used by `recall_plans` and passive-plan dedup today).
2. `campy/brain/thalamus/bundle_compiler.py` — no Plan/Procedure lane at all (zero
   references), so `compile_context` and therefore `ask` never see plan-lane content
   regardless of tags.

This is a capture-side-fine, query-side-blind gap: consistent with the graph-native rule
(tag data by type, filter at query time), the fix is to make the query surfaces see the
lane — not to change how the lane is written.

### What This Card Does

1. Add `Plan` and `Procedure` to the `"retrievable"` tag in `table_registry.py`.
   `current_truth`'s result assembly then needs two mechanical accommodations in
   `campy/brain/thalamus/tools/retrieval.py`:
   - the `node_id` extraction chain must also try `plan_id` / `procedure_id`;
   - the `text_raw` field must fall back to `goal` (Plan) / `description` (Procedure),
     since those tables don't have a `text_raw` column. Include plan `status`/`valence` in
     the result dict when present — a plan whose steps all succeeded should say so.
2. Add a plans lane to `bundle_compiler.py`: for a bundle query, run the same
   similarity × |valence| × pathway ranking `recall_plans` uses (reuse its logic — do not
   duplicate it; extract a shared helper if needed) and include top plans with their step
   outcomes as a bundle section. `ask` inherits this for free via `compile_bundle`.
3. Decide (and document in code) whether `PlanStep` is separately retrievable or only ever
   surfaced through its parent Plan. Recommendation: parent-only — steps without their plan
   context are noise; the bundle/`current_truth` entry should carry its steps inline the way
   `recall_plans` already does.

### Files to Modify

- `campy/brain/hippocampus/table_registry.py` — tag additions
- `campy/brain/thalamus/tools/retrieval.py` — node_id/text fallbacks in `current_truth`
- `campy/brain/thalamus/bundle_compiler.py` — plans lane
- `campy/brain/thalamus/tools/quests.py` (or a shared module) — extract the recall_plans
  ranking helper for reuse rather than copy-paste
- Tests: extend `tests/test_recall_contract.py` (or a new file) — see acceptance criteria

### Acceptance Criteria

- [ ] Regression test reproducing the observed failure: `register_plan` a goal +
      `report_outcome` its steps against a fake/real db, then assert the plan surfaces in
      (a) `current_truth` results and (b) a `compile_context` bundle for a related query —
      not only in `recall_plans`
- [ ] `ask` over a graph containing only plan-lane documentation of some work answers with
      that work rather than "memory is empty" (can be asserted at the bundle layer:
      the compiled bundle passed to the LLM contains the plan's goal and step outcomes)
- [ ] Plan results in `current_truth` carry a non-empty text field (goal), a node_type of
      `Plan`, and valence/status when set — no empty-text ghost rows
- [ ] `recall_plans` behavior unchanged (shared helper refactor is invisible to it)
- [ ] Full suite: no regressions vs baseline

### Outcome

"What did agent X do?" works no matter which documentation lane the work landed in.
Plan-lane provenance — the lane agents are explicitly told to use for work documentation —
is first-class in every retrieval surface, not just its own dedicated tool.
