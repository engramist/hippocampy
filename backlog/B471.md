# B471 - Recall of What the Assistant Said: the Conversation Stage Drops Every Assistant Turn

State: complete, option (b) (decided and implemented 2026-10-06; benchmark confirmation pending)
Priority: P2

### Problem Statement

`GraphGateway._bundle_conversation` (B454) keeps only user-role turns. Its
rule is that assistant text is capped and untrusted (ISSUE-024), and questions
are not evidence. That rule is right for facts and decisions: an assistant's
paraphrase or hallucination must not become "what the user decided". It also
makes a whole class of questions unanswerable from memory: what did the
assistant say? "Which pasta shape did you suggest for pesto?", "What was the
name of the hotel you recommended?"

Measured with campy-benchmarks LongMemEval (oracle variant, 35 questions, 5 per
type), llama3.1:8b, gemma4:26b judge, hippocampy `13484ba`, local agent R10b on
engramist/hippocampy#278:
- single-session-assistant: **evidence recall 0.0**, accuracy 0.2. The other
  types: recall about 0.5, accuracy 0.2-0.6.
- The assistant turns are ingested (`notify_turn` with role `assistant`), so the
  Messages exist; the stage filters them out after ranking.

LongMemEval-S has 56 single-session-assistant questions of 500 (11%), so this
caps the published score.

### Options

**(a) Keep the rule; document the limit.** No behaviour change. The
benchmark category stays near zero by design.

**(b) Recommended: a separate, labelled "what the assistant said" section.**
- Assistant turns that rank on topic go into their own bundle section, marked
  as the assistant's words, e.g. `[assistant said, <date>] ...`, never mixed
  with the user assertions.
- Small limit (2-3), ranked after the user items.
- Included only when the question is about the assistant's own words. Cues:
  "you said / suggested / recommended / mentioned / told me", "your
  suggestion". The gate keeps them out of decision and fact questions, so
  ISSUE-024 still holds for everything it was written for.
- The B463 successor bridge and the B459 anchor rules are unchanged; they
  still consider user turns only.

**(c) Always include labelled assistant turns.** Simpler. It puts untrusted
text into every bundle, where the answering model may treat it as fact. That
is the risk ISSUE-024 exists to prevent.

### Decision and Implementation

Option (b), chosen by the user on 2026-10-06.
- `thalamus.bundle_assistant_words` (`GraphGateway._bundle_assistant_words`)
  ranks the same way as the conversation stage:
  - vector hits at >= 0.30, echoes dropped;
  - FTS through B470's `_lexical_query`;
  - reciprocal-rank fusion;
  - a lexical-only hit needs two content words.
  It keeps assistant turns only and returns the top `limit` (default 3),
  oldest first.
- `bundle_compiler._stage_assistant_words` runs after the conversation stage,
  only when `asks_about_assistant_words(query)` holds.
  - Triggers: "you said / suggested / recommended / mentioned / told...",
    "did you say / suggest...", "your suggestion / recommendation / advice /
    tips...".
  - Not triggered by a present-tense request ("can you tell me...", "could
    you suggest...").
  - Items are stamped `[assistant said, <date>]` in their own section,
    `assistant_said`.
  - `[retrieval] assistant_words_limit` sets the limit; 0 disables it.
- `ask` describes the section as the assistant's own past words, not facts
  the user stated.

### Acceptance Criteria (for option b)

- [x] A question with an assistant-words cue gets the on-topic assistant
      turns in their own labelled section; one without the cue gets none
      (both tested, `tests/test_b471_assistant_words.py`).
- [x] Decision and fact bundles are unchanged: the B454/B459/B463/B470 tests
      pass as they are. Full suite: the same 10 failures as main
      (pre-existing), plus 14 passing tests.
- [ ] campy-benchmarks LongMemEval single-session-assistant evidence recall
      above 0 on a real run, with no drop in the other categories beyond
      noise.
