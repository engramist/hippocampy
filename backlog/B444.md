# B444 - Definition-of-Done Tracking for Plans (generate_handoff v2)

State: ready
Priority: P2
Branch: feat/b444-plan-step-expected-outcome
PR Target: main

### Note on origin

Deferred out of B383 (Automated Model Handoff Generator, merged via
[PR #237](https://github.com/engramist/hippocampy/pull/237)). B383's
card wanted a "Definition of Done: Verification commands, test suites,
and expected exit criteria" section in the generated handoff.
Confirmed by direct grep at the time (not inferred) that no schema
field or mechanism tracked this — B383 shipped without it rather than
fabricate content from nothing.

### The actual finding (2026-09-22)

`PlanStep` (`campy/brain/hippocampus/schema.py`) already declares an
`expected_outcome STRING` column, paired with `actual_outcome
STRING` — but `expected_outcome` **is hardcoded to `NULL` at creation
time everywhere it's written** (`queries/lessons.py:94`,
`queries/sweep.py:117`) and never accepted as caller input anywhere.
`actual_outcome` is the live half of the pair: `report_outcome`
(`campy/brain/thalamus/tools/quests.py:232`) writes it via
`quests.set_plan_step_outcome`
(`campy/brain/hippocampus/graph/queries/quests.py:784`):

```cypher
SET ps.actual_outcome = $outcome, ps.valence = $valence,
    ps.status = $status, ps.completed_at = timestamp($now)
```

This is the same shape of gap this session found repeatedly in B382/
B383/B440: a real, declared column that's semantically almost exactly
what's needed, just never wired up to accept a value. This is **not**
a "definition of done" node type needing invention — it's a dead
column needing a writer.

### Recommendation

Wire `expected_outcome` up as the per-step "how we'll know this step
succeeded" field, and surface it in `generate_handoff`'s markdown as
the Definition of Done section, rather than inventing a new node type
or a plan-level (vs. step-level) field.

**Why step-level, not plan-level:** `PlanStep` already has
`step_number`, `description`, `status`, and now (via this card)
`expected_outcome` — a plan's real "definition of done" is naturally
the union of its steps' individual expected outcomes ("step 3:
`pytest tests/test_foo.py` passes", "step 5: manual smoke test of the
new endpoint confirms X"). A single plan-level free-text field would
either duplicate this per-step structure in prose or lose the
step-by-step granularity `report_outcome` already tracks against.

**Capture mechanism — explicit only, not inferred:** `register_plan`
(`campy/brain/thalamus/tools/quests.py:182`) should accept an optional
`expected_outcomes: list[str] | None` parameter, positionally paired
with `steps` (same length, or shorter with trailing steps left
`NULL`), threaded through `_create_plan_graph`
(`campy/brain/thalamus/tools/lessons.py:49`) into the step-creation
NamedQuery. **Do not** try to infer "this looks like a verification
step" from passive conversation text (e.g. via keyword matching on
"run tests"/"verify"/"acceptance criteria") as a first pass — that's
exactly the kind of heuristic that produces false positives/noise
without a caller's explicit intent behind it, unlike B382's Reflex-tier
keyword match (which only ever affects *routing*, a low-stakes,
easily-wrong-and-corrected decision) or B383's negative-control
extraction (explicitly labeled heuristic in the output, never asserted
as fact). A "definition of done" claim is higher-stakes — if wrong, it
could tell a handoff's recipient the wrong thing counts as success.
Passive inference could be a genuine v3 if explicit capture proves too
much friction in practice, but shouldn't be the v1 default.

**Consumer:** `generate_handoff`
(`campy/brain/thalamus/handoff.py`) already fetches the quest's active
Plan via `model_router.get_active_plans_for_quest`
(reused from B382) — add a query for that Plan's `PlanStep`s with a
non-null `expected_outcome` (a new NamedQuery, following B383's own
"new file, don't touch `thalamus.py`/`arc.py` while they're being
audited" convention — check whether that audit is still in flight
before deciding the query file location), render as a
"## Definition of Done" markdown section, one bullet per step.

**Bonus, not required for v1:** since `actual_outcome` already exists
and is written by `report_outcome`, a future card could have
`generate_handoff` cross-reference expected vs. actual per step and
flag mismatches — but that's real scope beyond "surface what's there,"
left for a follow-up once expected_outcome capture itself is proven
useful.

### Files to create/modify

- Modify: `campy/brain/thalamus/tools/quests.py` (`register_plan`:
  accept `expected_outcomes`)
- Modify: `campy/brain/thalamus/tools/lessons.py` (`_create_plan_graph`:
  thread the param through to step creation)
- Modify: `campy/brain/hippocampus/graph/queries/lessons.py`
  (`lessons.create_plan_step`-equivalent: accept and write
  `expected_outcome` instead of hardcoding `NULL`)
- Modify: `campy/brain/thalamus/tool_schemas.py` (`register_plan`'s
  schema: document the new param)
- Create: a new quest-scoped "PlanSteps with expected_outcome" query
  (file TBD per the note above)
- Modify: `campy/brain/thalamus/handoff.py` (`generate_handoff`: new
  section)
- Modify: `tests/test_handoff.py`, and whichever test file already
  covers `register_plan`/`report_outcome` (`tests/test_quest.py` or
  similar — check first)

### Acceptance Criteria

- [ ] `register_plan` accepts and persists `expected_outcomes` per step.
- [ ] `generate_handoff` renders a "Definition of Done" section from
      populated `expected_outcome` values, and omits the section
      entirely (not an empty header) when none are set — matching
      every other optional section's existing convention in
      `handoff.py`'s `_render_markdown`.
- [ ] A real regression test proves a plan registered with
      `expected_outcomes` produces the correct section content, and a
      plan registered without them produces no section (not an empty
      one).
- [ ] Work executed in branch `feat/b444-plan-step-expected-outcome`
      and PR created targeting `main`.

### Outcome

`generate_handoff` can finally show a real, user-authored Definition
of Done instead of omitting the section entirely — built on a column
that already existed and just needed a writer, not new schema.
