# B132: Fix LLM Initialization — openai Package Not Installed in .venv

**Status**: Ready  
**Assigned**: TBD  
**Depends on**: None  
**Complexity**: Small (< 1 hour)  
**Priority**: P0 (CRITICAL — LLM is None every run; all reasoning/sandbox functionality dead)  
**Plan**: backlog/plans/B-132-fix-llm-initialization.md

## Problem Statement

On every single run, `self.llm` inside the orchestrator is `None` because the `openai` package is missing from the project `.venv`. The failure cascade is severe:

1. `LLMProvider.__init__` logs: `[LLM] Could not initialize provider 'ollama': No module named 'openai'`
2. `self.llm` is never assigned → it remains `None`
3. Every call to `_mental_sandbox()` reaches `self.llm.chat(...)` → throws `AttributeError`
4. The sandbox catches the exception and emits `mental_sandbox_parse_error` + `mental_sandbox_fallback_query_llm`
5. `_query_llm()` also calls `self.llm` → also throws → returns hardcoded fallback every time
6. Every reasoning step is silent/dead; the agent runs 15 steps producing no real reasoning output

Evidence from `master_timeline.json`:
```
event: mental_sandbox_parse_error  (every step)
event: mental_sandbox_fallback_query_llm → "ACTION1" (every step, hardcoded)
log:   [LLM] Could not initialize provider 'ollama': No module named 'openai'
```

This is the root cause of B133 (guard cycling) — without real LLM output, the guard always sees the same fallback action.

## What This Card Builds

1. Installs `openai` (and any other missing LLM provider packages) into the project `.venv`.
2. Adds `openai` and `anthropic` (as optional extras) to `pyproject.toml`/`requirements.txt` so they survive reinstalls.
3. Adds a startup health-check in `LLMProvider.__init__` that surfaces a **clear, fatal-level log** when initialization fails, rather than silently setting `self.llm = None`.
4. Adds a guard in `_mental_sandbox()` that raises `RuntimeError` instead of silently catching and producing a hallucinated fallback when `self.llm is None`.
