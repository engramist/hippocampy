# B484 - Time Normalisation at Capture (M4.2)

State: implemented (flag-free; gate pending: LoCoMo temporal categories via replay with the backfill)
Priority: P2

Plan: `learnings/e2e-improvement-plan.md` M3/M4 and Part G; `backlog/plans/B-472-phase3-observations.md` section 5c; `backlog/B472.md`

### Problem Statement

The Observation worker stores `time_text` as the speaker wrote it ("yesterday",
"last Saturday", "two days ago") and leaves `time_start`/`time_end` NULL, so
an Observation line shows "(when: yesterday)" and the answering model has to
do date arithmetic from `[speaker, date]` itself. LoCoMo temporal questions
("When did X ...?") have dates as gold.

### Fix

- `campy/brain/temporal_lobe/observations/timeparse.py`: pure, stdlib-only
  `normalize_time(time_text, anchor) -> (start, end, precision) | None`. Rules
  and conventions (ISO weeks Mon..Sun; "last <weekday>" = most recent strictly
  before; year-less dates = nearest to the anchor; ambiguous numeric dates,
  vague amounts, seasons, ranges, bare weekdays -> None) are documented in the
  module docstring.
- The worker calls it with the evidence Message's `occurred_at` (else
  `created_at`) and fills `time_start`/`time_end`/`time_precision`; `time_text`
  is kept as written. New stats `time_resolved` / `time_unresolved`.
- The content hash includes the resolved start date when there is one, so
  "went there yesterday" said on two different days is two Observations, not
  one with merged evidence. (Rows without a resolved date hash as before.)
- Rendering: `render_observation` shows `(when: yesterday -> 2023-05-07)` /
  `(when: last week -> week of 2023-04-24)`. A row with NULL `time_start`
  (written before this card) is resolved on the fly from `time_text` and
  `observed_at`: a read-only fallback, so the read path needs no backfill.
- Backfill: `backfill_time(db)` (`observations/backfill.py`) fills
  `time_*` for live Observations with a `time_text` and NULL `time_start`.
  Idempotent; never changes text, embedding, hash or evidence. Two new
  NamedQueries: `observations.list_untimed`, `observations.set_time`.
  It writes, so run it as maintenance or on a store copy, never inside `ask`.

### Not done

- Seasons, holidays, "the next day" / "two days later" (need a referent), and
  "N Sundays before X".
- `text_raw` / the embedding do not include the resolved date (backfill must
  not re-embed); the date is added at render time.
