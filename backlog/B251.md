# B251 - Memory Router (Ingestion Classification)

State: needs work -- re-verified 2026-08-03: classify_input() and file-based routing are solid, but raw-content routing silently ignores the classifier's recommendation. See Audit Findings below.
Priority: P2

Plan: backlog/plans/B-251-memory-router-ingestion.md

### Problem

Currently `notify_turn` and `ingest_document` are separate ingestion paths with no shared classification logic. As Campy gains more storage types (tabular, future: audio, images), each new type would need its own entry point. A unified ingestion router prevents this fragmentation.

### What This Card Does

Builds an intelligent ingestion classifier that examines incoming data and routes it to the optimal storage strategy. Also adds a unified `ingest_data` MCP tool as a single entry point.

### Dependencies

- B249 complete (Dataset node + tabular store)
- B250 complete (tabular ingestion pipeline)

### Design Decisions

| Decision | Choice | Rationale |
|---|---|---|
| Classification approach | Rule-based (extension, MIME, structure) with LLM fallback | Fast for obvious cases, accurate for ambiguous ones |
| `notify_turn` unchanged | Conversational text always goes to graph | No need to route what's already well-handled |
| New tool name | `ingest_data` | Unified entry point; `ingest_document` remains for backwards compat |

### Audit Findings (2026-08-03 re-verification)

- `classify_input()` (`campy/brain/temporal_lobe/memory_router.py`) is a pure function with no DB dependency, so its own tests are genuinely trustworthy (not mock-masked). Ran `.venv/bin/python -m pytest -q tests/test_memory_router.py -v` → **43 passed**. Manually re-checked the extension/MIME/content-structure rules against the code; they correctly route `.csv`/`.xlsx` → tabular, `.md`/`.txt` → document, and JSON arrays / delimiter-consistent text → tabular (`graph+tabular`).
- File-based routing through `ingest_data` works correctly, but not for the reason the card claims. `ingest_data()` (`campy/brain/thalamus/tools/context_tools.py`) calls `classify_input()` only to populate the `route` field of its response — that value is **never used to pick a code path**. For any `file_path`, it always calls `ingest_document(...)`. The reason CSV/XLSX files still end up in the tabular store is that `ingest.py`'s own `ingest_document()` (the B250 code) independently re-checks the file extension against a **second, separately-defined** `TABULAR_EXTENSIONS` set and dispatches to `tabular_ingest.ingest_tabular()` before doing any document chunking. Both extension sets happen to match today, so the net behavior for files is correct, but the classification logic is effectively duplicated in two places and the router's decision is dead data for the file path.
- **Real, reproducible gap: raw-content routing ignores the classifier.** When `ingest_data` is called with `content` (no `file_path`) — e.g. a user pasting a CSV or a JSON array directly — `classify_input()` correctly returns `storage_type="graph+tabular"`, `suggested_tool="ingest_tabular"`, but the handler's `else` branch unconditionally calls `notify_turn(...)` (the conversational/graph path) regardless of what the classifier said. Reproduced directly:
  ```
  content = "name,age,dept\nAlice,30,Eng\nBob,25,Sales\nCharlie,35,Eng\n"
  classify_input(content=content)
    -> MemoryRoute(storage_type='graph+tabular', reason='Content has tabular structure',
                    confidence=0.75, suggested_tool='ingest_tabular')
  ingest_data({"content": content, "session_id": "s1"}, db=None, config={})
    -> notify_turn() called: True   # tabular content silently sent through the conversational path
  ```
  There is no code path anywhere that writes raw `content` to a temp file and hands it to `tabular_ingest.ingest_tabular()` (which only accepts a file path, not raw text). This means "ingest_data MCP tool accepts file path or raw content and routes internally" is false for the content-only case — tabular-shaped pasted content never reaches the tabular store.
- `ingest_document` unchanged / backwards compatible: confirmed, untouched signature and behavior.
- `notify_turn` unaffected: confirmed via full suite pass (no regressions).
- Classification confidence is logged for observability: `MemoryRoute.confidence` is returned in every `ingest_data` response's `route` field, so it is surfaced to callers, though not written to any structured log — a minor, non-blocking gap versus "logged."
- Full test suite: `.venv/bin/python -m pytest -q` → 1600 passed, 59 skipped, 2 xfailed (no regressions from this audit's B250 fix).

Not fixed here — routing raw tabular-shaped content into the tabular pipeline requires a real design decision (write to a temp file? extend `ingest_tabular` to accept in-memory content? how does the "graph+tabular" hybrid route dual-write?) rather than a one-line patch, so left as a documented gap per audit instructions.

### Outcome

Campy has a single intelligent ingestion entry point that routes data to the optimal storage strategy.
