### Problem

Currently `notify_turn` and `ingest_document` are separate ingestion paths with no shared classification logic. As Campy gains more storage types (tabular, future: audio, images), each new type would need its own entry point. A unified ingestion router prevents this fragmentation.

### What This Card Does

Builds an intelligent ingestion classifier that examines incoming data and routes it to the optimal storage strategy. Also adds a unified `ingest_data` MCP tool as a single entry point.

### Dependencies

- B249 complete (Dataset node + tabular store)
- B250 complete (tabular ingestion pipeline)

### Design Decisions

| Decision | Choice | Rationale |
|---|---|---|
| Classification approach | Rule-based (extension, MIME, structure) with LLM fallback | Fast for obvious cases, accurate for ambiguous ones |
| `notify_turn` unchanged | Conversational text always goes to graph | No need to route what's already well-handled |
| New tool name | `ingest_data` | Unified entry point; `ingest_document` remains for backwards compat |
