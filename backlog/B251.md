### Problem

Currently `notify_turn` and `ingest_document` are separate ingestion paths with no shared classification logic. As Campy gains more storage types (tabular, future: audio, images), each new type would need its own entry point. A unified ingestion router prevents this fragmentation.

### What This Card Does

Builds an intelligent ingestion classifier that examines incoming data and routes it to the optimal storage strategy. Also adds a unified `ingest_data` MCP tool as a single entry point.

### Dependencies

- B249 complete (Dataset node + tabular store)
- B250 complete (tabular ingestion pipeline)

### Design Decisions

| Decision | Choice | Rationale |
|---|---|---|
| Classification approach | Rule-based (extension, MIME, structure) with LLM fallback | Fast for obvious cases, accurate for ambiguous ones |
| `notify_turn` unchanged | Conversational text always goes to graph | No need to route what's already well-handled |
| New tool name | `ingest_data` | Unified entry point; `ingest_document` remains for backwards compat |

### Audit Findings (2026-08-03 re-verification, historical — issue is now fixed, see Implementation below)

- `classify_input()` (`campy/brain/temporal_lobe/memory_router.py`) is a pure function with no DB dependency, so its own tests are genuinely trustworthy (not mock-masked). Ran `.venv/bin/python -m pytest -q tests/test_memory_router.py -v` → **43 passed**. Manually re-checked the extension/MIME/content-structure rules against the code; they correctly route `.csv`/`.xlsx` → tabular, `.md`/`.txt` → document, and JSON arrays / delimiter-consistent text → tabular (`graph+tabular`).
- File-based routing through `ingest_data` works correctly, but not for the reason the card claims. `ingest_data()` (`campy/brain/thalamus/tools/context_tools.py`) calls `classify_input()` only to populate the `route` field of its response — that value is **never used to pick a code path**. For any `file_path`, it always calls `ingest_document(...)`. The reason CSV/XLSX files still end up in the tabular store is that `ingest.py`'s own `ingest_document()` (the B250 code) independently re-checks the file extension against a **second, separately-defined** `TABULAR_EXTENSIONS` set and dispatches to `tabular_ingest.ingest_tabular()` before doing any document chunking. Both extension sets happen to match today, so the net behavior for files is correct, but the classification logic is effectively duplicated in two places and the router's decision is dead data for the file path.
- **Real, reproducible gap: raw-content routing ignores the classifier.** When `ingest_data` is called with `content` (no `file_path`) — e.g. a user pasting a CSV or a JSON array directly — `classify_input()` correctly returns `storage_type="graph+tabular"`, `suggested_tool="ingest_tabular"`, but the handler's `else` branch unconditionally calls `notify_turn(...)` (the conversational/graph path) regardless of what the classifier said. Reproduced directly:
  ```
  content = "name,age,dept\nAlice,30,Eng\nBob,25,Sales\nCharlie,35,Eng\n"
  classify_input(content=content)
    -> MemoryRoute(storage_type='graph+tabular', reason='Content has tabular structure',
                    confidence=0.75, suggested_tool='ingest_tabular')
  ingest_data({"content": content, "session_id": "s1"}, db=None, config={})
    -> notify_turn() called: True   # tabular content silently sent through the conversational path
  ```
  There is no code path anywhere that writes raw `content` to a temp file and hands it to `tabular_ingest.ingest_tabular()` (which only accepts a file path, not raw text). This means "ingest_data MCP tool accepts file path or raw content and routes internally" is false for the content-only case — tabular-shaped pasted content never reaches the tabular store.
- `ingest_document` unchanged / backwards compatible: confirmed, untouched signature and behavior.
- `notify_turn` unaffected: confirmed via full suite pass (no regressions).
- Classification confidence is logged for observability: `MemoryRoute.confidence` is returned in every `ingest_data` response's `route` field, so it is surfaced to callers, though not written to any structured log — a minor, non-blocking gap versus "logged."
- Full test suite: `.venv/bin/python -m pytest -q` → 1600 passed, 59 skipped, 2 xfailed (no regressions from this audit's B250 fix).

Not fixed at the time of the audit — routing raw tabular-shaped content into the tabular pipeline required a real design decision (write to a temp file? extend `ingest_tabular` to accept in-memory content? how does the "graph+tabular" hybrid route dual-write?) rather than a one-line patch. See Implementation below for the decisions actually made.

### Implementation (2026-08-03)

**Design decisions for the three open questions the audit left unresolved:**

1. **In-memory content vs. temp file** — `ingest_tabular()` (and the pandas parsing underneath it) is entirely file-path-based, so extending it to accept in-memory content would have meant a parallel parsing path to keep in sync. Instead, added `ingest_tabular_from_content()` in `campy/brain/sensory_cortex/tabular_ingest.py`: writes content to a throwaway temp file with an extension inferred from its structure, delegates to the existing `ingest_tabular()`, and always deletes the temp file in a `finally` block (including on failure). This is safe because `Dataset.storage_uri` points at the independently-created SQLite table (`create_table_from_dataframe`), not the source file — nothing downstream depends on the temp file surviving past the call.
2. **Extension inference** — new `_infer_content_extension()` mirrors `memory_router._looks_tabular()`'s structural checks (JSON array via `json.loads`, then delimiter-count consistency) but returns a suffix (`.json` / `.tsv` / `.csv`) instead of a bool, since `ingest_tabular()` dispatches its parser purely off the file extension.
3. **`.json` was a real, separate gap**: `classify_input()` has promised "JSON arrays → tabular" since this card's first pass, but `ingest_tabular()` never had a `.json` branch at all — even a *correctly routed* JSON array would have hit `"Unsupported file extension: .json"`. Added `pd.read_json(...)` as a third parser branch alongside `.csv`/`.tsv`/`.xlsx`. (File-extension classification is untouched: a file literally named `foo.json` still routes to `ingest_document`, per `DOCUMENT_EXTENSIONS` — only content-structure detection of a raw pasted JSON array triggers the tabular path. That distinction was already correct and is preserved.)
4. **"graph+tabular" dual-write** — `ingest_data()` in `campy/brain/thalamus/tools/context_tools.py` now branches on `route.storage_type`: `"tabular"`/`"graph+tabular"` call `ingest_tabular_from_content()`; `"graph+tabular"` additionally calls `notify_turn()` (the conversational turn is still recorded, not dropped) and returns `{"tabular": ..., "graph": ...}`; `"graph"`/`"document"` fall through to the original unconditional `notify_turn()` call, unchanged. (Raw-content `"document"` classification still has nowhere else to go — there's no file-based document pipeline for content with no `file_path` — so it deliberately keeps falling back to `notify_turn`, same as before; only the tabular gap the audit flagged was in scope here.)

**Also fixed, low-risk:** `campy/brain/sensory_cortex/ingest.py` redefined its own local `TABULAR_EXTENSIONS = {".csv", ".xlsx", ".tsv", ".xls"}` for file-based dispatch — the exact duplication the audit flagged ("classification logic is effectively duplicated in two places"). Now imports `TABULAR_EXTENSIONS` from `memory_router.py` instead (same four extensions, verified identical before the swap) — one source of truth, as the card's own premise requires.

**Also fixed:** classification confidence is now genuinely logged — `_logger.info("ingest_data classified input as storage_type=%s confidence=%.2f suggested_tool=%s (%s)", ...)` in `context_tools.py`, closing the "surfaced in response but not logged" gap the audit called out as minor.

- `tests/test_ingest_data_routing.py` (new, 7 tests): the exact scenario the audit reproduced (paste a CSV, paste a JSON array) now lands in the tabular store — against a real Kuzu `Dataset` table and real tabular store, with `notify_turn`/`ingest_document` mocked since their own behavior is tested elsewhere and is orthogonal to the routing decision. Covers: tabular content reaches the tabular store, `"graph+tabular"` dual-writes to both, plain conversational text and long prose still route through `notify_turn` unchanged, file-path routing still calls `ingest_document` unchanged, and the new observability logging fires.
