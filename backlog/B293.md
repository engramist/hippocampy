# B293 - Single Source of Truth for the MCP Tool Surface

State: complete (2026-07-13) — implemented by GitHub Copilot (GPT-5.3-Codex), reviewed by Fable; additive generation strategy (existing 53 handwritten entries preserved); see PR from feat/b292-b293-b298-copilot-batch
Priority: P2

Plan: (inline — this card is self-contained)

### Problem

Adding one MCP tool currently requires editing FOUR hand-maintained declaration sites that must stay set-equal:

1. `TOOL_HANDLERS` in `campy/brain/thalamus/tools/__init__.py`
2. `TOOLS` in `campy/brain/thalamus/tool_schemas.py` (906 lines of hand-written schema dicts)
3. `extensions/hippocampy/src/index.ts` (~1,633 lines; TypeBox `Type.Object` params + a tool entry)
4. `EXPECTED_TOOLS` in `tests/test_adapters.py`

This has bitten twice: B288 (stale OpenClaw/Codex lists — 3 tests failing on main for weeks) and B290 (`register_artifact` added to TOOL_HANDLERS only — 4 invariant tests broke). The invariant tests catch drift but the tax is paid on every tool, and the failure mode is "all adapter tests red" which masks real regressions.

### What This Card Does

Make `tool_schemas.py` the single authored source and DERIVE the other three sites:

1. **`EXPECTED_TOOLS` derivation (trivial, do first):** in `tests/test_adapters.py`, replace the hardcoded `EXPECTED_TOOLS = {...}` set with `EXPECTED_TOOLS = {t["name"] for t in TOOLS}` imported from `tool_schemas`. The per-adapter test then verifies "adapter's live tools/list == schema names" which is the real invariant. Delete the hand-list. (`test_adapter_tool_names_match_handlers` already checks schemas == handlers, so transitivity holds.)
2. **`TOOL_HANDLERS` completeness guard:** keep `TOOL_HANDLERS` hand-written (handlers need explicit phase wrapping via `_with_phase`), but add a startup assertion in `tool_schemas.py` or a dedicated test that fails with a NAMED diff (`missing from schemas: {...} / missing from handlers: {...}`) instead of a bare set-inequality — improves the error message that confused B290's implementer.
3. **TypeScript generation:** write `scripts/generate_extension_tools.py` that reads `TOOLS` and emits `extensions/hippocampy/src/generated_tools.ts` containing, for each tool: `{ name, label, description, parameters }` where `parameters` is a TypeBox `Type.Object(...)` translated from the tool's JSON `inputSchema` (string → `Type.String({description})`, optional = not in `required` → `Type.Optional(...)`, enum → `Type.Union([Type.Literal(...)])`, integer/number → `Type.Number()`, boolean → `Type.Boolean()`, object/array passthrough → `Type.Object({}, {additionalProperties:true})` / `Type.Array(...)`). Preserve existing HAND-WRITTEN entries that have extras the schema can't express (`transformParams`, `callName` aliases): the generator must support a per-tool override map (`OVERRIDES: dict[str, str]` of raw TS snippets) OR generation can target only NEW tools going forward, with `index.ts` importing the generated list and concatenating it with the legacy hand-written array. **Read `index.ts` fully first and pick the least invasive of these two approaches; document the choice in the script header.**
4. **Regeneration check in CI:** add a step to `.github/workflows/security-gate.yml` (or a small separate workflow) that runs the generator and fails if `git diff --exit-code` shows drift — so a schema edit without regeneration can't merge.
5. Update `docs/tool-catalog.md` header and `.github/copilot-instructions.md` Rule 3 to describe the new flow ("add to tool_schemas.TOOLS + TOOL_HANDLERS, run `python scripts/generate_extension_tools.py`").
6. Update the memory-relevant AGENTS.md Rule 3 wording the same way.
