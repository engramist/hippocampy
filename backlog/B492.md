# B492: Model-derived memories enter as candidates, then get promoted

**Status:** open · **Found:** 2026-10-19 (e2e lead)

## Problem

Several write paths put LLM output straight into the store as durable memory:
auto-created Lessons/Procedures (Layer 3 anticipatory bindings), Observations
(B472, when enabled). Nothing checks a claim against an independent source
before it is recalled as fact. Known damage: two wrong-polarity B290 Lessons
still in the live graph.

Published memory-governance work points the same way: provenance at write
time, candidate first, promotion only on independent agreement (a quote that
matches the source turn, a rule, a second model family, or a person).
Repeated runs of one model count as one source.

## Fix (to be designed; graph-native: tag, don't filter at capture)

- Add a status to model-derived nodes: `candidate | promoted | rejected`,
  plus `derived_from` (source turn/message) and `asserted_by` (model, prompt
  version).
- Promotion rule per type, e.g. Observation: quoted words found verbatim in
  the source turn → promoted; Lesson: valence agrees with the recorded
  outcome → promoted; otherwise stays candidate.
- Readers default to promoted; candidates are queryable on request.
- A one-off sweep marks existing model-derived nodes candidate and re-runs
  promotion; the two B290 Lessons are the test case.

## Done when

No model-derived node is returned as fact unless it passed its promotion
rule, and the wrong-polarity B290 Lessons are no longer recalled as fact.
