# B195: Active Context Push — Proactive Lesson Injection

## Problem Statement

Retrieval is pull-only. The agent must call `current_truth` or `recall_relevant_lessons` to get context. The brain never proactively pushes relevant knowledge. When the agent is about to repeat a known mistake (e.g., using ACTION4 on a puzzle where ACTION4 was proven ineffective), the brain stays silent unless asked.

The warm frontier (B91) pre-activates nodes in working memory, but it's passive — it doesn't inject warnings or lessons into the agent's prompt.

## Root Causes

1. `notify_turn` processes incoming turns but doesn't return proactive context
2. Warm frontier activation sets scores but doesn't trigger injection
3. No mechanism for "if the agent mentions X, proactively surface Lesson about X"
4. No negative-valence lesson injection (warnings about things that failed)

## What This Card Does

1. **Extend `notify_turn` response**: Return a `proactive_context` field with relevant high-confidence Lessons
2. **Trigger conditions**: Surface a Lesson proactively when:
   - Agent's current action/topic has a high-confidence negative-valence Lesson (warning)
   - Agent's archetype has a Procedure (from B194) that hasn't been loaded yet
   - A KnowledgeGap (from B193) is relevant to the current context
3. **Matching logic**: Embed the incoming turn, compare against Lesson embeddings. Only push when similarity > 0.80 AND (|valence| > 0.7 OR pathway_strength > 0.8)
4. **Rate limiting**: Max 1 proactive push per 5 turns to avoid noise
5. **Trace logging**: Record proactive pushes as `PROACTIVE_PUSH` events for eval

## Graph Design (Graph Expert Analysis)

**No new node types needed.** This reads existing Lesson, Procedure, and KnowledgeGap nodes.

**Access pattern** (on each `notify_turn`):
```cypher
-- Find high-signal Lessons matching the current turn
CALL db.index.vector.queryNodes('lesson_emb_idx', $turn_embedding, 5)
YIELD node, score
WHERE score > 0.80 AND (abs(node.valence) > 0.7 OR node.pathway_strength > 0.8)
  AND node.archived = false
RETURN node, score
ORDER BY score DESC
LIMIT 2
```

**Performance**: Single HNSW lookup per turn — O(log n), ~1ms. Rate-limited to every 5 turns. Negligible overhead.

**Working memory integration**: Proactively pushed nodes get `LOADED` edges with `source = "proactive_push"` to prevent dedup demotion.
