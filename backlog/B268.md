# B268 - Upgrade Daemon to Streamable HTTP Transport

State: complete -- verified via git log 2026-08-02 (feat: implement B265-B276 215b588); card file was stale

Plan: backlog/plans/B-268-streamable-http-transport.md

### Problem

The brain daemon's MCP endpoint uses the deprecated SSE transport (MCP spec 2024-11-05): `GET /sse` opens an event stream, client gets a `connection_id`, then `POST /mcp?connection_id=X` for each request. This was deprecated in MCP spec 2025-03-26 in favor of Streamable HTTP — a single `POST /mcp` endpoint that returns JSON directly or opens an SSE stream per-request.

The daemon already partially supports Streamable HTTP (`POST /mcp` without `connection_id` works), but `GET /sse` is still the advertised primary endpoint.

### What This Card Does

1. Promotes `POST /mcp` as the primary MCP endpoint (Streamable HTTP transport).
2. Adds `GET /mcp` support for server-initiated streams (optional per spec, but good practice).
3. Archives `GET /sse` — keeps it working for backwards compat but marks it deprecated.
4. Updates all references from `/sse` to `/mcp`.

### Dependencies

- None (daemon change, independent of plugin restructure)

### Files to Modify

   **a) Add `GET /mcp` handler** (after the existing `POST /mcp` at line ~876):
   ```python
   @app.get("/mcp")
   async def mcp_get(request: Request):
       """Streamable HTTP GET — server-initiated stream (MCP 2025-03-26).
       
       Returns 405 if server has no pending messages for the client.
       In the future, this can be used for server-to-client notifications.
       """
       accept = request.headers.get("accept", "")
       if "text/event-stream" not in accept:
           return JSONResponse(
               {"error": "Accept header must include text/event-stream"},
               status_code=406,
           )
       # For now, return 405 — we don't have server-initiated messages yet
       return Response(status_code=405)
   ```
