### Why this card exists

The Oxigraph migration has been justified three different ways, and the first two did
not survive measurement:

1. ~~`<80 MB` featherweight daemon~~ — the target was import-time RSS. Clean-install
   warm is **595.3 MB**; Kùzu costs ~1 MB over fastembed. Dead.
2. ~~Memory/dependency weight from torch~~ — torch was never a declared dependency. Dead.
3. **RDF-native semantics**: standards-based ontology reuse (GIST, PROV-O, SKOS),
   declarative validation (SHACL), and inference (RDFS/OWL). **This is the surviving
   justification and the stated product motivation.**

**It has never been validated.** We are ~70% through translating 865 queries on the
strength of a thesis nobody has tested.

`anti-patterns.md` §10 is direct about this: *"Do not recommend a full replatform when
one bounded, query-driven pilot could prove value."* This card is that pilot.

### The problem the pilot must confront

Measured against `pyoxigraph 0.5.11`:

```
rdfs:subClassOf inference     -> EMPTY (no inference)
owl:TransitiveProperty        -> False (no inference)
SHACL support in pyoxigraph   -> NONE
reasoner / inference API      -> NONE
```

**Oxigraph is a triple store, not a reasoner.** It stores OWL axioms as inert triples.
The engine that best serves this goal per `engines-and-portability.md` is Stardog —
which is JVM/server and violates Campy's embedded, single-process, zero-egress
invariant (B377 reason #4, B385's Fargate target). That tension is the real
architectural decision and it has not been made deliberately.

One mitigation already works: SPARQL property paths. `campy:DEPRECATED_BY+` correctly
answered a transitive deprecation-chain query in testing — without any reasoner.

### Scope — a bounded pilot, not a system

Pick **two** real needs, not hypothetical ones:

1. **An inference need.** Suggested: the deprecation chain — *"Constraint A is
   deprecated by B, B by C. Is A still active?"* This is a real Campy question with a
   real current implementation to compare against.
2. **A validation need.** Suggested a SHACL shape such as *"a `Decision` must have at
   least one `prov:wasAttributedTo` and a valid timestamp."*

For each, implement and measure **all three** routes:

| Route | What to measure |
|---|---|
| SPARQL property paths / plain SPARQL | correctness, latency — the zero-dependency baseline |
| Oxigraph + `owlrl` / `pySHACL` materialization | correctness, added RSS, **and re-materialization cost per write** |
| Current Kùzu + Python implementation | correctness, latency — the incumbent |

### The measurement that decides it: write amplification

Campy ingests continuously via `notify_turn`. **Every write invalidates an OWL
closure.** Measure, against the real turn ingestion rate:

- time to re-materialize the closure after a single new turn
- how that scales at 10x and 100x current graph size
- whether stale inference between materializations is acceptable

If re-materialization exceeds the inter-turn interval, materialized OWL inference is
not viable in this architecture regardless of engine, and the thesis has to become
"property paths + SHACL-at-write" rather than "native reasoning".

### Intake to gather (never captured, and it changes the answer)

Per `graph-solutions` §1a — record these before concluding:

- top 3–5 real queries or user journeys that motivate inference
- current graph size and **turn ingestion rate** (writes/hour under normal use)
- latency expectation for an inference-dependent read
- which ontologies are actually wanted vs. aspirational (GIST? PROV-O? SKOS? all?)

### Decision rule — fixed in advance

- **Property paths sufficient** → proceed with B397. Justification is standards
  alignment + ontology interop, honestly stated, with no reasoner in the stack.
- **Materialization viable at the real write rate** → proceed with B397, and card the
  reasoner stack explicitly as part of the architecture rather than an afterthought.
- **Neither works** → **stop before B397.** The surviving justification has failed and
  the engine choice must be reopened, including whether the embedded invariant or the
  inference goal is the one that bends.

Record the outcome in `ARCHITECTURE.md`'s Open Research Questions section (B402).

### Outcome & Empirical Findings

**Decision Rule Mapping**: **Branch 1: Property paths sufficient.** Proceed with B397 (engine cutover). Justification is standards alignment + ontology interop, honestly stated, with **NO reasoner in the runtime stack**.

Empirical results (`benchmarks/results/b407_inference_pilot.json`):
1. **Need 1 (Transitive Deprecation Chain)**:
   - **SPARQL Property Paths (`campy:DEPRECATED_BY+`)**: 0.026 ms read latency (28x faster than Kùzu's 0.775 ms; 72x faster than OWL 2 RL's 1.920 ms), 100% correct, 0.000 ms write penalty, 0 external dependencies.
   - **OWL 2 RL Materialization (`owlrl`)**: 1.920 ms read latency, 100% correct, but prohibitive write amplification (499 ms re-materialize at 500 entities; 5.09s at 5,000 entities; >60s at 50,000 entities).
   - **Kùzu Incumbent**: 0.775 ms read latency (`-[:DEPRECATED_BY*1..10]->`).
2. **Need 2 (SHACL Shape Validation)**:
   - **Plain SPARQL `FILTER NOT EXISTS`**: 0.079 ms validation latency (42x faster than pySHACL's 3.194 ms; 2.3x faster than Kùzu's 0.179 ms), 100% precision/recall, 0 external dependencies.
   - **pySHACL**: 3.194 ms validation latency.
   - **Kùzu Incumbent**: 0.179 ms validation latency.
3. **Write Amplification & Scaling vs Real Ingestion Rate**:
   - Interactive turn rate is 1 turn every 10–30s.
   - `owlrl` full materialization takes 5.09s per write at 5,000 entities (breaching daemon's 500ms budget by 10x) and >60s at 50,000 entities (exceeding turn interval entirely). Full deductive closure is not viable in the daemon runtime.
   - SPARQL property paths require zero re-materialization, add zero ms to writes, and evaluate queries in <0.03 ms.
4. **§1a Intake**:
   - Motivating queries: transitive deprecation chains, PROV-O attribution/derivation chains, concept subsumption.
   - Ingestion rate: 100–300 writes/hour during active coding.
   - Latency target: <10 ms.
   - Ontologies: PROV-O (provenance), SKOS (lexical gazetteer), GIST (domain concepts).
