### Why

A swarm of build agents collides because the orchestrator assigns work that was always going
to overlap, then discovers the overlap at write time. A lock table cannot prevent this — it
only reports collisions already in progress. Overlap is predictable *before assignment* if
you know which files move together.

The obvious way to know that is a static import graph. **This card deliberately does not
build one.** Parsing TypeScript, JS, Python and whatever else an app builder generates —
with path aliases, monorepo workspaces, barrel files and dynamic imports — is a permanent
maintenance treadmill, and it is Layer-4 compute work that does not belong in a memory
service.

Instead, learn the coupling from what Campy already observes. If two files are repeatedly
touched in the same unit of work, they are coupled — regardless of whether an import
statement connects them. This **change-coupling** signal is often better than the import
graph for this purpose: it catches a config key and the code reading it, a schema and its
migration, a component and its test, none of which appear in an import graph. And it costs
no external dependency, no parser, and no per-language upkeep.

It also improves with use, which is the correct behavior for a memory system: weak with
little history, stronger over time.

### Scope Boundary vs B321

- **B321** surfaces *observed recent activity* to an **agent**, at recall time, as advisory
  bundle text. Exact-path and directory-prefix matching only.
- **B322** computes *learned coupling* and exposes a **forecast tool for the orchestrator**,
  at assignment time.

Different consumer, different timing, different query. Do not reimplement B321's matching
here — call it or share its helper.

**This card still adds no locking.** It returns a risk assessment; the orchestrator decides.
Per B318, an unavailable Campy means the orchestrator assigns naively — degraded, never
blocked.

### What This Card Does

**Task 1 — The `CO_CHANGES` relationship.**

Add a rel table (`campy/brain/hippocampus/schema.py`, `REL_TABLES` at line 842) between file
identities. `WorkArtifact` (PK `artifact_id`, carries `file_path`) is the existing node; decide
whether to couple `WorkArtifact -> WorkArtifact` or introduce a normalized `FilePath` node.

**Recommendation: introduce a `FilePath` node** keyed on the normalized path. `WorkArtifact`
rows are per-touch events, so coupling them directly produces edges between *occurrences*
rather than between *files*, and degree explodes. A `FilePath` node is the stable identity the
coupling is actually about. This is the skill's standard n-ary/event-modeling split: keep the
event (`WorkArtifact`) and add the entity (`FilePath`).

Edge properties on `CO_CHANGES`:

```
co_count      INT64    -- units of work touching both
support       INT64    -- units of work touching either
confidence    DOUBLE   -- co_count / support  (0.0 - 1.0)
last_seen_at  TIMESTAMP
source        STRING   -- "campy:cochange"
source_version STRING  -- algorithm version + data cutoff
authority     STRING   -- always "projected"
```

**Unit of work** = the `Session`. `WorkArtifact` already carries `session_id`, so this needs
no new capture. If `linked_card` is populated it is a better unit; prefer it when present and
fall back to session. State which you used in the PR.

`CO_CHANGES` is symmetric. Kùzu rel tables are directed — store one edge per unordered pair
with a canonical ordering (lexicographic on path) and query both directions, rather than
storing two edges. Halves the degree and removes an update-consistency hazard.

**Task 2 — Recompute, and why it is `projected`.**

This is derived data: fully rebuildable from `WorkArtifact` history. Per B313 that makes it
`authority='projected'` with `source='campy:cochange'` and `source_version` = algorithm
version plus data cutoff timestamp. That is not a technicality — it means B313's
`drop_projections(source='campy:cochange')` can wipe and rebuild the whole coupling layer
safely, which is exactly what you want when the algorithm changes.

Implement as a recompute function callable from the existing background sweep
(`campy/brain/brainstem/sweep.py`, invoked from `brain_daemon.py:_background_sweep` line 324).
Full recompute over a bounded window (default: last 90 days of `WorkArtifact`) is simpler and
safer than incremental maintenance; do that unless it proves too slow, and report timings on a
realistic row count in the PR.

**Task 3 — Supernode handling. This is the make-or-break detail.**

In an app builder, `package.json`, `tsconfig.json`, root `index.ts`, shared type and config
files are touched by nearly every unit of work. Naive coupling makes them couple to
everything, and the forecast then says **all tasks conflict** — which is worse than no signal,
because the orchestrator learns to ignore it.

Handle it as a first-class case, and note that the mitigation is itself a useful output:

- Compute per-`FilePath` touch frequency across the window.
- Files above a configurable percentile (default: touched in >25% of units of work) are marked
  `ambient=true` on the `FilePath` node.
- **Ambient files are excluded from pairwise coupling and from conflict forecasting entirely.**
- They are instead reported by a separate `contention_hotspots()` query as **serialize-only**:
  a file every task touches is not a conflict signal, it is a structural bottleneck the
  orchestrator should never parallelize.

Also floor the edges: drop pairs with `co_count < 3` or `confidence < 0.3`. Two files touched
together once is noise, and unfloored edges are what makes this degrade into a dense mess.

**Task 4 — The forecast query.**

```python
async def conflict_forecast(
    db, *, candidate_files: list[str],
    in_flight: list[dict],          # [{session_id, agent_source, files: [...]}]
    max_hops: int = 2,
) -> list[dict]:
    """Risk of assigning work touching `candidate_files` while `in_flight`
    work is active. Returns [{session_id, agent_source, risk, why,
    shared_files, coupled_files}] sorted by risk descending."""
```

Rules:

- **Bound the traversal.** `[:CO_CHANGES*..2]`, never unbounded. Default 2 hops; hard-cap at
  3 even if a caller asks for more.
- Risk tiers, not a false-precision float: `direct` (same file — highest), `coupled`
  (1 hop), `indirect` (2 hops). Include `why` as human-readable text so the orchestrator can
  log a reason a person can follow.
- Ambient files never contribute to risk.
- Filter early, expand late — restrict to in-flight sessions' file sets *before* expanding
  coupling edges, not after.
- Index the entry point: `FilePath.path` needs an index or the lookup is a scan.

**Task 5 — Expose to the orchestrator.**

Register `conflict_forecast` and `contention_hotspots` as MCP tools in `TOOL_HANDLERS`
(`campy/brain/thalamus/tools/__init__.py`), following the existing
`async def name(params, db, config)` convention and, if B315 has landed, accepting
`principal`.

The tool description must state plainly that this is **advisory risk assessment, not mutual
exclusion**, so a model reading the tool list cannot mistake it for a lock. Apply B321's
denylist discipline to the description text and the response strings.

### What This Card Does NOT Do

- Does not parse source code or build an import graph — see the top section. If static
  dependency edges are wanted later, they arrive as `projected` facts from the platform's
  own build tooling (esbuild `--metafile`, webpack stats, `tsc --listFiles`), never from a
  parser inside Campy.
- Does not lock, lease, claim, block, or gate anything
- Does not assign work — it answers a question the orchestrator asks before assigning
- Does not do incremental edge maintenance (bounded full recompute on the sweep cadence)
- Does not detect contradictory decisions between agents — separate card

### Outcome

The orchestrator can ask "is this a bad time to assign this work, and why" and get a bounded,
explainable answer built from what actually changes together — with no source parsing, no
external dependency, and no availability contract Campy cannot honor. Collisions become rarer;
the runtime's own worktree isolation stays the backstop for the ones that slip through.
