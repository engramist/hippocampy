# B367 - campy/brain_daemon.py Never Emits Activity-Log Events (Silent Since B365)

State: ready
Priority: P2

Plan: none yet.

### Problem

Found live 2026-08-26 while auditing B348 (local memory-pressure watchdog) against what's actually
implemented. The root-level `brain_daemon.py` (before B365 collapsed it into a re-export shim) had
`emit_activity()` calls at six points: `"daemon"`/`started` in `start()`, `"daemon"`/`stopped` in
`shutdown()`, `"tool"`/`ok` and `"tool"`/`error` around every dispatched call in `_dispatch()`, and
`"capture"`/`ok`/`error` in the passive-capture background loop. `campy/brain_daemon.py` — the module
that has been the sole live implementation since B365 — has **none of these**. Confirmed via
`grep -n "emit_activity" campy/brain_daemon.py`: zero hits.

Verified this isn't theoretical: restarted the live dev daemon (picking up B365's shim), made several
real tool calls (a `arc_update_goal_confidence` write, a SIGUSR1 snapshot trigger) against the new
process, then checked `~/.campy/activity.log` for anything logged after the old process's own
`"daemon"`/`stopped` entry (which came from the *old*, pre-shim in-memory code, not evidence the new
code emits anything) — zero `"daemon"` or `"tool"` events appear for the new process at all, despite
real activity happening.

This matters because `CLAUDE.md`'s own "Campy Activity Indicator" section establishes
`~/.campy/activity.log` (via `campy activity --follow`) as *the* recommended way to check daemon
status — "instead of the noisy daemon log" — and this has been silently non-functional for the
daemon-lifecycle and per-tool-call events specifically (the `"capture"` events from passive
session-journaling still work fine — those come from a different module,
`campy/brain/sensory_cortex/capture.py`, unaffected by this gap). This predates B365; B365 just made
it universal (previously only packaged/pip installs hit the affected module — anyone running from a
git checkout got root's working version until B365 unified everything onto the gapped one).

### What it does (scope)

1. Port the same six `emit_activity()` call sites from root's pre-shim history
   (`git show 27e765e:brain_daemon.py` for the exact reference) into `campy/brain_daemon.py`:
   `start()` (started), `shutdown()` (stopped), `_dispatch()`'s success and exception paths (tool
   ok/error, using `compact_details()`), and the background capture loop's success/error paths.
2. While in there, also add an activity event for the memory-safety background tasks B365 ported —
   root never had these either (they're newer than root's own emit_activity wiring), but this is a
   natural place to add them given B348's own ask: a checkpoint failure, a scheduled restart firing,
   and a footprint-watchdog breach/restart should all be visible via `campy activity --follow`, not
   just the noisy `daemon.log`.
3. Verify live: restart the daemon, make a few tool calls, trigger SIGUSR1 and a manual checkpoint,
   confirm all of it shows up in `~/.campy/activity.log`.

### Dependencies

None. Referenced from B348's audit (`backlog/B348.md`) as the reason that card isn't fully closeable
yet — its "log a clear, visible warning... per this project's existing activity-indicator
convention" acceptance criterion can't be satisfied while the daemon has no activity-indicator
wiring to hook into at all.

### Files to create/modify

- `campy/brain_daemon.py` — add the `emit_activity` import and the call sites above.
