# B281 - Kuzu Export/Restore and Engine Exit Strategy

### Problem

Campy is pinned to `kuzu==0.11.3` and the engine's upstream project was archived (per the comment in `kuzu_client.py`: "archived Oct 2025, pinned"). The facade pattern makes migration *possible* — only one file imports kuzu — but there is no export path, no restore path, and no way to validate a replacement engine against the facade's contract. The longer the graph grows, the more expensive this gets.

### What This Card Does

1. Adds `campy export-graph` CLI command: dumps all node tables and rel tables to a versioned, engine-neutral format (JSONL per table + manifest).
2. Adds `campy import-graph` CLI command: restores a dump into a fresh database via the facade.
3. Adds a facade conformance test suite that exercises every `KuzuClient` method against a temp database — the checklist any replacement engine adapter must pass.
4. Adds a round-trip test: seed fixture graph → export → import into fresh DB → assert graph equality.

### Acceptance Criteria

- [ ] `campy export-graph --out /tmp/dump` writes one `<Table>.jsonl` per node/rel table plus `manifest.json` (schema version, table list, row counts, embedding dim, export timestamp)
- [ ] `campy import-graph --in /tmp/dump --db /tmp/fresh` restores into an empty database
- [ ] Round-trip test passes: node counts, rel counts, and spot-checked properties (including FLOAT[384] embeddings and TIMESTAMP fields) survive export→import
- [ ] Conformance test exercises: `execute` (read+write), `execute_write` lock path, `execute_read` dict normalization, `create_vector_index`, `vector_search`, `close`
- [ ] Export handles the full live DB at `~/.campy/` without OOM (streams rows, doesn't materialize tables)
- [ ] Embeddings round-trip with float precision adequate for HNSW re-indexing (assert cosine of re-imported vs original ≥ 0.9999)

### Outcome

Engine risk is contained: a tested escape hatch exists while the graph is still small, and any future engine swap has a conformance suite to validate against.
