# B522: Observations record subject and object roles as typed edges

**Status:** Open — gate pending (R101 vs R100 on conv-42,conv-43,conv-47)

Lever 1a of the object-linking work. On a copy of a real benchmark store (844 Observations) 711 have
`subject_id` but only 68 (8%) have `object_id`, while 402 (48%) have an `OBSERVATION_ABOUT` Concept
that is not the subject. `write_entity` and `_link_concepts` link subject and object through the same
untyped `OBSERVATION_ABOUT`, so a query can ask what an Observation is about but not what a subject
owns, prefers or plans. Principle 8: if an answer needs an edge capture does not write, fix capture.

1. **Edges.** `HAS_SUBJECT` and `HAS_OBJECT`, Observation to Concept, property-free, each at most one
   (first written wins). Declared in `schema.py`, `oxigraph_client.EDGE_REIFICATION`, the SHACL shapes
   (`sh:maxCount 1`) and `campy_vocab.ttl` (functional object properties). `OBSERVATION_ABOUT` is
   unchanged; the retrieval walk still reads it.
2. **Writes** behind `[observations] object_roles` (env `CAMPY_OBSERVATIONS_OBJECT_ROLES`, default off):
   `record_observation` writes HAS_SUBJECT from `subject_id` and HAS_OBJECT from `object_id`; the
   extraction path also writes HAS_OBJECT for the entity `write_entity` resolved. An empty `object_id`
   is filled from the object edge. An object equal to the subject is not an object.
3. **Readers.** `observations.objects_of_subject` (subject id, optional predicate: object Concept,
   label, kinds via `INSTANCE_OF` then `BROADER*`, predicate, evidence message, date) and
   `observations.role_link_counts`; both used by `scripts/graph_structure_report.py` (`--subject`,
   the HAS_SUBJECT / HAS_OBJECT columns) and `scripts/drift_report.py`. Not wired into answering.
4. **Backfill.** `backfill_roles` (`scripts/backfill_observation_roles.py`): three set-based graph
   updates. HAS_SUBJECT from `subject_id`; HAS_OBJECT from `object_id`, else from the one non-subject,
   non-kind `OBSERVATION_ABOUT` Concept whose label (3+ characters) appears as whole words in
   `object_text`; several fitting Concepts are skipped and counted.

Measured on the store copy: object-linked share 8.1% -> 23.6%, subject-linked 0 -> 84.2%, 24
Observations skipped as ambiguous. The rule stays conservative on purpose, so it does not reach the
48% ceiling: the rest of the non-subject ABOUT links are kinds ("my dogs"), fragments, or words the
object text does not contain. The wrong-predicate problem (Toby appears under `plans`, `prefers` and
`relates_to`, none under `owns`) is Lever 1b.

Serves Principles 8 (typed relation to an object entity), 2 (the reader is a registered query) and 7
(flag, off by default). Gate pending; flipping the flag can only change scores through `object_id`
readers, listed in the PR.
