# B500: Upgrade pillow past the 12.3.0 CVEs (transitive via fastembed)

**Status:** complete (2026-10-24, resolved by B512) · **Investigated:** 2026-10-21 · **Found:** 2026-10-21 (security advisory comment on PR #341)

## Problem

The CI security advisory reports eight HIGH CVEs against `pillow==12.3.0`
(CVE-2026-112395, -112397, -112400, -112404, -112895, -112896, -112897, -112899);
the fix is `pillow>=13.0.0`. Pillow is not a direct dependency: `fastembed` pulls it in.

## Fix

Check whether the installed `fastembed` accepts pillow 13; if so, add a floor
(`pillow>=13.0.0`) to the dependency list and re-lock. If it does not, check for a
fastembed release that does, or record why the pin has to stay.

## Verify

`pip show pillow` in a fresh install shows >= 13.0.0; the embedding tests pass; the
advisory comment no longer lists pillow.

Not a benchmark lever (no score effect); found in passing.

## Finding (2026-10-21): blocked upstream, no change made

The project pins `fastembed==0.8.0` (pyproject.toml, requirements.txt). Its metadata
requires `pillow<13.0,>=10.3.0` on Python 3.10-3.12 (the project is `>=3.12,<3.13`).
The newest fastembed on PyPI (0.9.0, also 0.8.1) keeps the same `pillow<13.0` cap
(`<13.0,>=11.0.0` on 3.13, `<13.0,>=12.0.0` on 3.14+). No fastembed release accepts
pillow 13, so a `pillow>=13.0.0` floor would make the install unresolvable. A bump of
fastembed would not help, and would also break the B355 exact-pin parity rationale.

Exposure: fastembed's image-embedding models use pillow, and this project embeds
text only. Campy itself imports PIL in one place, `campy/cli/indicator.py`
(`_make_icon_image`), which draws a 22x22 coloured circle in memory and never
opens or decodes an external image file. So the CVEs' attack surface, parsing
untrusted image files, is not reached by current code (checked 2026-10-21). Options when picking this up again: (a) wait for a fastembed
release that lifts the cap, then add the floor; (b) ask upstream (qdrant/fastembed)
to relax the cap; (c) install with `--no-deps` overrides, which is not recommended.
Re-check fastembed's `requires_dist` before acting. Dependency files untouched.

## Tracked in the security gate (2026-10-23)

All 37 pillow 12.3.0 advisories (pip-audit, 2026-10-23; the first count of 8 came from a truncated comment) are listed by id in `.github/security-tracked.json`, so the PR
security comment shows one "known and tracked" line for them instead of eight rows.
Matching is by exact CVE id and package: a new pillow CVE is still listed. The entry
expires on its `review_by` date (2027-01-31); after that the CVEs are listed again
until someone re-checks fastembed and renews or removes the entry. An upstream request
to raise the cap already exists upstream: qdrant/fastembed#829 (issue) and #830 (PR raising the cap to `<14.0`, awaiting review since 2026-10-19). When a fastembed release with #830 ships: bump the pin, re-check search parity (B355), and remove the tracked entry.

### Reachability check (2026-10-23)

All 37 are fixed in pillow 13.0.0. Each needs one of: opening/decoding/saving an image
file (TIFF, GIF, PDF, EPS, BMP, PNG/EXIF, JPEG, MSP, XBM, SPIDER, MIC, FPX, WMF), or
`Image.transform` / `Image.merge` / `ImageMorph`, text drawn with a stroke width, or
`PILLOW_ALIGNMENT` > 1. Campy calls none of these: fastembed is used for text
embeddings only, and `campy/cli/indicator.py` only does `Image.new` + `ImageDraw.ellipse`
in memory. Re-check if any feature starts handling images.

## Resolution (2026-10-24, B512)

Resolved by removing fastembed rather than waiting for qdrant/fastembed#830. B512 runs
`qdrant/all-MiniLM-L6-v2-onnx` directly with ONNX Runtime and `tokenizers`
(`campy/brain/hippocampus/graph/onnx_embedder.py`); the vectors are bit-identical to fastembed
0.8.0 (2,259 texts, max absolute difference 0.0), so no re-embedding and no search-parity risk.
`pillow` is no longer in the base install: a fresh venv installs neither fastembed nor pillow.
The `pillow` entry is removed from `.github/security-tracked.json` (the file now has an empty
`tracked` list; the mechanism stays for future use). `campy/cli/indicator.py` still imports PIL
for the in-memory status icon, so the `indicator` extra is now pillow's only source and is
floored at `Pillow>=13.0.0` (resolves to 13.0.0, which fixes all 37 advisories). Anyone who
installs `campy[indicator]` gets the fixed pillow; everyone else gets no pillow at all.
