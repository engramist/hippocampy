# B357 - Backlog Tracker Ignores Each Card's Own Priority Line (Shows P99 for Most Recent Cards)

State: done — fixed in `scripts/rebuild_backlog_tracker.sh` (2026-08-22). Priority now read directly
from each card's own `Priority: P<N>` line (grepped across the whole file, since its line position
varies — B357 itself has it on line 4, B342 on line 26), falling back to the legacy archive lookup only
when a card has no `Priority:` line of its own. P99 rows dropped from 175 to 39 (spot-checked B342=P1,
B356=P4, B351=P3, B357=P4 — all correct); the remaining 39 genuinely have no `Priority:` line in their
own file, verified programmatically (zero mismatches).
Priority: P4

Plan: none yet.

### Problem

`scripts/rebuild_backlog_tracker.sh` extracts each card's priority **only from a static legacy file**
(`Backlog_Archive032726.md`, matched via `## P<N>` headers followed by `### B<N>` references), never from
the card's own `Priority:` line in its actual markdown file. Any card created or referenced after that
archive was last relevant to a given card number falls back to the hardcoded default, `P99`.

Found while rebuilding the tracker for B353-B356 (this session, 2026-08-22) and noticing all four showed
`P99` in `masterBacklogTracker.md` despite having explicit `Priority: P1`/`P2`/`P4` lines in their own
files. Confirmed pre-existing and widespread, not something specific to those four cards:
`backlog/B342.md` has `Priority: P1` in the file itself but also shows `P99` in the tracker. A quick count
across the current tracker: **175 rows show P99** out of 65 `B*` cards alone (plus however many `A*`
cards) — this is not a handful of edge cases, it's most of the recently-created backlog.

### What it does (scope)

1. Change the priority-extraction logic in `scripts/rebuild_backlog_tracker.sh` to read each card's own
   `Priority: P<N>` line directly from its markdown file (the same file the script already opens to read
   `title` from line 1 and `state` from line 3 — `pri` should be extracted the same way, by grepping the
   card's own file for a line matching `^Priority: P[0-9]+`, not by cross-referencing the legacy archive).
2. Decide what the legacy-archive lookup should still be used for, if anything (e.g., as a fallback only
   for cards that genuinely have no `Priority:` line of their own — check whether any current cards are
   missing one before assuming this fallback path is still needed at all).
3. Re-run the rebuild after the fix and spot-check that previously-P99 cards now show their real priority
   (e.g. B342 should show P1, not P99).
