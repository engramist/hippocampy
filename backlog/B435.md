# B435 - bundle_compiler.py Semantic Stages Have No Lexical Fallback (Paraphrased Queries Fall Below the 0.30 Distance Floor)

State: ready
Priority: P1
Branch: fix/b435-bundle-compiler-lexical-fallback
PR Target: main

### Problem

`_stage_semantic_context` and its sibling stages in
`campy/brain/thalamus/bundle_compiler.py` enforce a hardcoded `0.30`
cosine-distance floor (documented at several points in that file,
e.g. line 411's "B305: distance floor tightened from 0.40 to 0.30") with
**no lexical fallback** for queries that fall below it. The only
exemption is B303's narrow `\bB\d+\b` backlog-identifier bypass — a
plain paraphrase gets no rescue at all.

`current_truth()` (`campy/brain/thalamus/tools/retrieval.py`) already
has this exact problem solved for its own Message-node lexical path via
B284: an FTS (`message_fts_idx`) fallback with a recency window, used
when cosine similarity alone misses a real match. `bundle_compiler.py`'s
semantic stages (which back `ask()` / `compile_context()`, not
`current_truth()`) never got the equivalent treatment.

### Evidence

The orphaned pre-cutover benchmark report
(`docs/benchmarks/kuzu-baseline-kpis.md`, committed via PR #229)
documented this directly: natural-language probe questions (e.g. *"What
is Alex's current diet? Are they vegan or pescatarian?"*) against short
concept nodes measured `~0.50` embedding distance — above the `0.30`
floor — and were silently dropped, producing an empty context bundle.
This is the likely cause of that report's **Paraphrase Accuracy: 0.25**
score (target `>= 0.80`) in the Tier 3 Ask-Eval matrix.

Not yet re-verified against current `main` with a fresh benchmark run —
this card is filed from re-reading the report's root-cause section, not
from re-running the harness. **Verifying against a live re-run should be
step 1 of this card**, since B375 (warm-frontier boost) and other work
merged since the baseline was recorded could plausibly move this number
even without a fix.

### Scope

1. Re-run (or write a targeted regression test reproducing) the
   paraphrase-miss scenario against current `main` to confirm this is
   still live before designing a fix.
2. If confirmed, add a lexical fallback to `bundle_compiler.py`'s
   semantic stage(s) analogous to B284's pattern in `retrieval.py` —
   exact mechanism (FTS index per node table vs. a shared approach) is
   an open design question, not prescribed here.
3. Re-run the ask-eval harness (`benchmarks/ask_eval/`) and confirm the
   Paraphrase Accuracy metric improves without regressing Identifier
   Accuracy or Negative Control Compliance (both currently 1.00).

### Acceptance Criteria

- [ ] Confirmed (or refuted) against current `main` whether the
      paraphrase-miss gap still reproduces.
- [ ] If confirmed: `bundle_compiler.py`'s semantic stage(s) gain a
      lexical fallback path, with a real regression test proving a
      previously-below-floor paraphrase now surfaces content.
- [ ] `benchmarks/ask_eval/` re-run shows Paraphrase Accuracy improved,
      with no regression to other Tier 3 metrics.
- [ ] Work executed in branch `fix/b435-bundle-compiler-lexical-fallback`, PR to `main`.

### Outcome

Paraphrased natural-language queries against `ask()`/`compile_context()`
stop silently returning empty bundles when a real match exists just
outside the cosine-distance floor.
