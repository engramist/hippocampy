# B336 - Hermes Adapter Calls REST Routes That Don't Exist on the Server (404s Live, CI Can't Catch It)

State: complete — merged via PR #58 (2026-08-20)
Priority: P1

Plan: none yet.

### Problem

`adapters/hermes/adapter.py` calls four REST endpoints against the brain daemon:

- `GET  {memory_url}/api/v1/recall` — `adapters/hermes/adapter.py:58`
- `POST {memory_url}/api/v1/decide` — `:85`
- `POST {memory_url}/api/v1/notify` — `:113`
- `POST {memory_url}/api/v1/bundle` — `:145`

None of these routes exist on `web/server.py`. Confirmed for this card by listing every route the
FastAPI app actually registers: `/health`, `/`, `/memory/node/{node_id}`, `/api/node/{node_id}`,
`/api/stats`, `/api/graph`, `/api/open-loops`, `/api/confirm/{node_id}`, `/api/reject/{node_id}`,
`/api/merge-events`, `/api/merge-events/{merge_event_id}`, `/api/export/constraint-ledger`,
`/api/export/constraint-ledger.json`, `/api/quests`, `/api/thinking`, `/sse`, `/mcp`. There is no
`/api/v1/*` namespace at all. Every call the Hermes adapter makes would 404 against the real server.

This is invisible to CI because `tests/adapters/test_hermes_adapter.py` mocks `httpx.AsyncClient`
entirely (`patch("httpx.AsyncClient", return_value=fake_client)`) — the tests verify the adapter
constructs the right request shape against a fake transport, but never verify that shape against a real
or realistic server, so the mismatch between adapter and server was never caught. Per the project's own
adapter conventions (see `docs/tool-catalog.md` and the "Adding MCP tool surfaces" pattern used
elsewhere in this repo), the correct integration point for a harness adapter like Hermes is almost
certainly the `/mcp` JSON-RPC surface (the same one every other adapter and the SigV4-authenticated path
use) — calling tool names like `recall`, `ask`/`decide`-equivalent, `notify_turn`, and
`compile_context`/`bundle`-equivalent — not a bespoke `/api/v1/*` REST namespace that was apparently
planned but never built server-side.

### What it does (scope)

1. Confirm the correct integration surface: read `web/server.py:907-969` (the `/mcp` and `/sse`
   handlers) and `campy/brain/mcp_engine/tool_schemas.py` (or wherever `TOOL_HANDLERS` is defined — grep
   `rg -n "TOOL_HANDLERS"`) to see the actual available tool names and how another already-working
   adapter (e.g. whichever adapter in `adapters/` is confirmed working — check
   `tests/test_adapters.py`'s `EXPECTED_TOOLS` list per this project's own "Adding MCP tool surfaces"
   convention) talks to the daemon.
2. Rewrite `adapters/hermes/adapter.py`'s four methods (`recall`, `decide`, `notify`, `bundle` — exact
   method names per the current file) to call the real `/mcp` JSON-RPC surface with the correct tool
   names (`recall`/`current_truth`, `ask`, `notify_turn`, `compile_context` — map Hermes's four
   conceptual operations to whichever real tool names are the closest fit; if a genuine gap exists
   where no real tool matches a Hermes operation, document that explicitly in the card outcome rather
   than inventing a fake mapping).
3. Add at least one integration-style test that exercises the adapter against the real
   `create_app(...)`-built FastAPI app (via `httpx.AsyncClient` with an ASGI transport pointed at the
   real app, or `fastapi.testclient.TestClient`) instead of a fully mocked transport — so a future
   drift between adapter and server routes is caught by CI. Keep the existing mocked-transport tests if
   they're still useful for fast unit-level checks, but add the real-route test as the regression
   guard this bug proves was missing.
4. Update `adapters/hermes/README.md` if it documents the old (wrong) endpoint paths.
