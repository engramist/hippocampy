### B71 · Centralize Adapter Tool Routing from tool_schemas.TOOLS

**Problem:** Each of the 5 adapters has its own hardcoded tuple of tool names. There's no shared constant or auto-discovery from `tool_schemas.TOOLS`. Every new tool requires manually updating 5 files — this drift has already caused R2-A1 (4 tools missing from all adapters).

**What it does:** Replaces hardcoded tool-name tuples with a single import-derived set, ensuring new tools are automatically routable without per-adapter edits.

**Depends on:** B70 (so the 4 missing tools are present when we centralize)

**Files to modify:**
- `adapters/claude_code/adapter.py`
- `adapters/claude_desktop/adapter.py`
- `adapters/codex/adapter.py`
- `adapters/chatgpt_desktop/adapter.py`
- `adapters/gemini_cli/adapter.py`

**Adapter allow-list propagation check:** This card eliminates the need for per-adapter propagation entirely.

**Acceptance Criteria:**
- All 5 adapters import tool names from `mcp_engine.tool_schemas.TOOLS` (or a shared constant derived from it)
- No adapter contains a hardcoded tool-name tuple longer than 3 items
- Adding a new tool to `tool_schemas.TOOLS` automatically makes it routable through all adapters without editing adapter files
- `pytest tests/test_adapters.py -q` passes
- `rg "TOOL_HANDLERS|TOOLS" mcp_engine/tool_schemas.py mcp_engine/tools/__init__.py adapters/` shows adapters reference the shared source

**Outcome:** New tools are automatically available in all adapters. Adapter allow-list drift is structurally impossible.
