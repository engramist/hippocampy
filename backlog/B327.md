# B327 - hippocampy 0.1.0 Published to PyPI

State: complete
Priority: P0

### Problem

`hippocampy` (and its predecessor, `sidequests-brain`) had never actually
been uploaded to PyPI, despite B4 being marked `complete` and B236 doing
all the packaging/audit/validation work short of the real upload. B236
closed with two acceptance criteria genuinely unmet: no TestPyPI dry-run
record, and README not labeling the install command's publish status. This
card is the record of the actual, first-ever publish event that closes
both gaps.

### What Happened

- **Published:** `hippocampy` 0.1.0 to real PyPI on 2026-08-18.
  https://pypi.org/project/hippocampy/0.1.0/
- **Pre-flight:** `pytest tests/ -q` run in a corrected local venv (Python
  3.12.13; the pre-existing `.venv` was stale and missing `boto3`,
  reinstalled via `pip install -e ".[dev]"`) — 2087 passed, 31 skipped, 2
  xfailed, 11 failed. All 11 failures individually triaged and confirmed
  local-environment artifacts, not regressions:
  - 7× `tests/test_fail_open.py` — macOS's default `TMPDIR` produces Unix
    socket paths that exceed macOS's 104-byte `AF_UNIX` limit; all 29
    tests in the file pass with `TMPDIR=/tmp`. Linux CI runners don't hit
    this.
  - 1× `tests/test_mcp_tool_surface.py::test_sse_exposes_all_tool_handlers`
    — passes 3/3 standalone; only fails after 2000+ preceding tests in the
    full suite (state pollution, not this test's own logic).
  - 2–3× `tests/test_capability_queries.py` (non-deterministic across
    reruns) — real KuzuDB + real Ollama embeddings + HNSW index
    construction per test; timing race in the fixture, not query-logic
    breakage.
  - `bash scripts/audit_public_release.sh --release` — passed cleanly.
- **TestPyPI dry run:** explicitly skipped (Option B in the runbook this
  card closes out). No separate test.pypi.org account/token was available;
  build, `twine check`, audit, and packaging tests had already passed
  repeatedly against the real artifacts, and Step 4 below covers the
  residual "does it actually install" risk instead.
- **Bug found and fixed:** `scripts/release_build.sh` ran the
  `--release`-mode audit (which requires `dist/` to already exist) before
  the build step that creates `dist/` — `--release` mode could never pass
  from a clean checkout. Reordered: clean → build → `twine check` → audit
  → packaging tests → upload.
- **`.env` bug found and fixed:** `TWINE_PASSWORD` referenced an undefined
  `$PYPI_TOKEN` variable (the real variable was named `TOKEN`), so
  `TWINE_PASSWORD` silently resolved empty. Fixed the reference; unrelated
  to the package itself.
- **Real publish:** `bash scripts/release_build.sh --publish`, confirmed
  with the typed `publish` prompt. Build, `twine check`, audit, and
  packaging tests all passed again immediately before upload.
- **Post-publish verification (Step 4):** clean venv,
  `pip install hippocampy` (succeeded on the first attempt, no index
  propagation delay), `campy --help` and `campy doctor --help` both exited
  cleanly with full usage text.
- **Docs flipped:** `README.md` (removed both "not yet on PyPI" callouts,
  promoted `pipx install hippocampy` to the single recommended path),
  `docs/one-click-install-release-gate.md` (verdict NO-GO → GO, Known
  Limitations bullet removed, publish date recorded), `backlog/B236.md`
  (both unmet ACs closed), `backlog/B4.md` (historical record corrected —
  the old card's "complete" status never included an actual upload).

### Acceptance Criteria

- [x] `hippocampy` installable via `pip install hippocampy` / `pipx install
      hippocampy` from real PyPI, verified in a clean venv.
- [x] `campy --help` and `campy doctor --help` both run cleanly from the
      installed package.
- [x] README no longer claims the package is unpublished.
- [x] `docs/one-click-install-release-gate.md` verdict reflects reality.
- [x] B236's two previously-unmet acceptance criteria closed with dated,
      reasoned notes (not silently checked off).
- [x] B4's stale "complete" record corrected to point at the real event.

### Outcome

`hippocampy` is live on PyPI for the first time under any name. The
one-click install story (`pipx install hippocampy`) is now genuinely
canonical, not aspirational.
