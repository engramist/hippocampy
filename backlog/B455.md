# B455 - Running the Test Suite Kills the Developer's Live Daemon

State: fixed (2026-09-24)
Priority: P2

Observed 2026-09-24: a full `pytest tests` run while the daemon was up gracefully
stopped it mid-benchmark (activity.log `stopped` -> launchd KeepAlive restart ~8 s
later; the strict benchmark harness correctly marked the in-flight suites invalid).
Earlier unexplained `stopped` events on 2026-09-23 line up with test runs too.
`tests/test_bringup_priorities.py` even documents the hazard ("FakeDaemonSetup's
pkill kills a live campy daemon") and adds a `subprocess.run` guard, but something
still reaches the real daemon. Find the caller (a tripwire run with stub
`pkill`/`launchctl`/`killall` on PATH is described in the investigation notes in
B454's session) and add a suite-wide autouse guard in `tests/conftest.py` that
refuses `pkill`/`killall`/`launchctl bootout|unload|kickstart` against
`ai.hippocampy.brain` / `brain_daemon.py` unless a test explicitly re-patches it.
CI is unaffected (no daemon there); this only bites local development.

## Completion notes (2026-09-24)

Found with a tripwire run (stub `pkill`/`killall`/`launchctl` on PATH logging every
caller): the suite issued `launchctl unload` + `launchctl load` on the REAL
`~/Library/LaunchAgents/ai.hippocampy.brain.plist` (plus `launchctl remove` of the
legacy `ai.sidequests.brain`/`ai.campy.brain` labels), bouncing the live daemon.
Fix: an autouse fixture in `tests/conftest.py` makes `subprocess.run` a no-op
(returncode 0) for `pkill`/`killall` and mutating `launchctl` verbs; tests that
need to observe those calls re-patch `subprocess.run` themselves, which overrides
it. Re-ran the tripwire: only read-only `launchctl list` reaches the system, the
daemon stayed up, and the suite is unchanged (2885 passed).
