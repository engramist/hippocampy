# B328 - CRITICAL: Enforce Auth on All HTTP Routes, Not Just /mcp (16 of 18 Routes Unauthenticated)

State: complete — merged via PR #55 (2026-08-20)
Priority: P0

Plan: none yet — write one before implementing if the scope below turns out to need more than a
straight middleware/dependency addition.

### Problem

An external security audit of this repo (read-only, against public HEAD `b96e05e`) found that
`web/server.py`'s FastAPI app mounts 18 routes, but the SigV4/IAM auth check
(`_principal_resolver.resolve(...)`) is called in exactly **one** place — `web/server.py:938`, inside
the `POST /mcp` handler. Verified again against current HEAD: still true, same line.

The other 16 routes have **no authentication of any kind**, including three destructive writes:

- `POST /api/confirm/{node_id}` — `web/server.py:409`
- `POST /api/reject/{node_id}` — `web/server.py:436`
- `DELETE /api/merge-events/{merge_event_id}` — `web/server.py:494`

Plus full read access to: `GET /` (`:116`), `GET /memory/node/{node_id}` (`:125`),
`GET /api/node/{node_id}` (`:139`), `GET /api/stats` (`:206`), `GET /api/graph` (`:235`),
`GET /api/open-loops` (`:378`), `GET /api/merge-events` (`:464`),
`GET /api/export/constraint-ledger` (`:613`), `GET /api/export/constraint-ledger.json` (`:643`),
`GET /api/quests` (`:663`), `GET /api/thinking` (`:722`), `GET /sse` (`:842`), `GET /mcp` (`:969`).
(`GET /health` at `:111` is fine to leave open — it's a liveness probe with no data.)

The bind guard (`_enforce_bind_guard`, `campy/brain_daemon.py:170-185`) only gates **process startup**
— it refuses to start only when `bind_host` is non-loopback AND `auth == "none"`. With
`auth == "iam"` it binds `0.0.0.0` happily, and all 16 unauthenticated routes come along for the ride.
There is no config flag to disable the dashboard/REST surface — `create_app()` is called
unconditionally at `campy/brain_daemon.py:595`.

`docs/deployment-agentcore.md:135-137` currently instructs operators to configure exactly the
vulnerable combination:

```toml
[server]
bind_host = "0.0.0.0"
auth      = "iam"
```

So the documented deployment path stands up an unauthenticated, write-capable memory store on the
network. This is the single highest-priority finding from the audit.

Also stale and misleading: `web/server.py:4-5`'s module docstring still says *"bound strictly to
127.0.0.1 — never 0.0.0.0. No authentication needed (local-only access by design)"* — this predates
B325 (which added remote MCP + IAM auth) and is exactly the comment that would falsely reassure a
reviewer who doesn't read 900 lines further down to find `_enforce_bind_guard`.

Neither `tests/test_bind_guard.py` nor `tests/test_remote_mcp.py` exercises any route except `/mcp`,
so no existing test would catch a regression here.

### What it does (scope)

1. Add a global auth dependency (FastAPI `Depends(...)` applied app-wide, or ASGI middleware) that
   calls the same `_principal_resolver.resolve(...)` check the `/mcp` handler already uses, applied to
   every route **except** `GET /health`. When `auth == "none"` (loopback-only mode, already guarded by
   `_enforce_bind_guard`), the dependency should be a no-op passthrough — this card is about closing
   the gap when `auth != "none"`, not about requiring auth in trusted local-only mode.
2. Update the stale module docstring at `web/server.py:4-5` to describe the real, current
   loopback-vs-remote-auth model (reference `_enforce_bind_guard` and the new global dependency by
   name) instead of the flatly false "no authentication needed" claim.
3. Add a config flag (e.g. `[server] dashboard_enabled` or `mcp_only`, default `true`/`false` matching
   current behavior for backward compatibility in loopback mode) that, when set, mounts only `/health`
   and `/mcp`/`/sse` and skips registering the dashboard/REST routers entirely — belt-and-braces on top
   of item 1, per the audit's suggested fix.
4. Add regression tests in `tests/test_bind_guard.py` (or a new `tests/test_route_auth.py`) that
   iterate every route the app registers (introspect `app.routes`, not a hand-maintained list — so a
   future new route can't silently reintroduce this gap) and assert each non-`/health` route rejects an
   unauthenticated request when `auth != "none"`.
5. Update `docs/deployment-agentcore.md:135-137`'s example config if the new dashboard-disable flag
   changes the recommended production posture, and add a short note there that the `bind_host =
   "0.0.0.0"` / `auth = "iam"` combination is now safe by default because every route (not just `/mcp`)
   is authenticated.
