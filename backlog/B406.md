# B406 - Schema Conformance Guard: Fail on Queries Referencing Non-Existent Properties

State: ready
Priority: P0
Branch: feat/b406-schema-conformance-guard

### Problem

Three independent SPARQL-translation agents (B392, B393, B394) each surfaced the same
bug class without looking for it: **named queries referencing node or relationship
properties that do not exist in the schema.**

Kùzu's behaviour differs by case, and both are bad:

- **Reads** return `NULL` silently. `RETURN m.content` on `Message` (whose column is
  `text_raw`) yields NULL for every row, forever, with no error.
- **Writes** raise. Verified against `kuzu==0.11.3`:
  `CREATE (c)-[:HAS_ALT_LABEL {created_at: ...}]->(l)` →
  `Binder exception: Cannot find property created_at`.

Confirmed instances so far:

| Module | Reference | Actual | Effect |
|---|---|---|---|
| `sweep.py` | `GlobalConstraint.constraint_id` | `global_constraint_id` | decay/archive never runs (B404) |
| `sweep.py` | `GlobalPreference.pref_id` | `global_preference_id` | same (B404) |
| `sweep.py` | `Requirement.req_id` | `requirement_id` | same (B404) |
| `quests.py` | `HAS_ALT_LABEL.created_at` | edge has no properties | dedup aborts mid-merge (B405) |
| `retrieval.py` | `Message.content` | `text_raw` | message text always NULL |
| `thalamus.py` | `Concept.prefLabel` / `.altLabel` | separate `Label` nodes | concept names always NULL |

### Why a guard, not a cleanup

Attempts to size this by inspection produced **false positives twice**. `schema.py`
builds its true property set from three sources:

1. `NODE_TABLES` / `REL_TABLES` base DDL
2. `_MIGRATIONS` — ~100 literal `(table, column, type)` tuples
3. **Comprehension-generated migrations** over `PROVENANCE_TABLES` and
   `CONTENT_HASH_TABLES` (`schema.py` ~1854, ~1886, ~1903)

Any check that misses source 3 flags ~34 valid `last_accessed_at`/`content_hash`
references as bugs. Any check that misses source 2 flags ~30 more. **This is not
reviewable by eye — it needs to be computed from the same source of truth the schema
itself uses.**

### Scope

1. Build `scripts/check_schema_conformance.py`:
   - Derive the authoritative property set **by importing `schema.py`**, not by
     re-parsing it — including migration-generated columns. If the derivation cannot
     see comprehension-generated migrations, refactor `schema.py` to expose the
     resolved set as a module-level structure rather than approximating it.
   - Parse every `NamedQuery.cypher` in `graph/queries/`, scope variable→table
     bindings **within each query** (file-wide scoping cross-contaminates reused
     variable names like `n`/`c`/`a`), and flag property references not in the set.
   - Cover **relationship** properties too, not just node properties — B405 was an
     edge-property bug.
2. Report the true violation list. **Do not fix them in this card** beyond those
   already carded (B404, B405) — file the rest with evidence per case.
3. Wire into CI alongside `check_cypher_ratchet.py`.
4. Establish a baseline like the Cypher ratchet does, so the count can only go down.

### Acceptance Criteria

- [ ] Guard derives properties from `schema.py` including all three migration sources.
- [ ] Zero false positives on the six confirmed cases' *valid* neighbours — verified by
      confirming `last_accessed_at` and `content_hash` on provenance tables pass.
- [ ] Catches all six confirmed cases above — demonstrated by running against current
      `main` before any fix lands.
- [ ] Covers rel-table properties (B405's class), not just node properties.
- [ ] Wired into CI with a ratchet-style baseline.
- [ ] Remaining violations filed individually with evidence, not fixed en masse.

### Outcome

A whole class of silent-NULL and runtime-raise bugs becomes impossible to merge, and
the true extent of the existing damage is measured rather than guessed.
