# B419 - B412 Regression Guard Recursively Scans `.claude/worktrees/`, Failing on Sibling Agents' Checkouts

State: fixed (this PR)
Priority: P2
Branch: docs/b419-b412-guard-scans-worktrees

### Problem

`tests/test_b412_read_path_fixes.py::test_action_fact_detail_has_no_callers_anywhere_in_repo`
walks `REPO_ROOT` recursively looking for references to the deleted
`arc.get_action_fact_detail` query, allow-listing only a few historical files. But
`REPO_ROOT` includes `.claude/worktrees/`, where other Claude sessions keep live git
worktrees (stale checkouts that still contain the old `arc.py` / `B412.md` /
`test_b412_read_path_fixes.py`). When any such worktree exists on disk, the guard fails:

```
AssertionError: arc.get_action_fact_detail is referenced outside the expected historical
record: ['.claude/worktrees/agent-a3ac3281f95e9a7fb/campy/.../arc.py',
'.claude/worktrees/sharp-newton-15d7ad/backlog/B412.md', ...] — it may have grown a real
caller since B412 deleted it
```

These are false positives — the references live in unrelated worktree checkouts, not the
repo tree under test. The guard is environment-dependent: it passes on a clean clone and
fails on any machine currently running sibling worktree sessions (which is the norm here).

### Fix

Exclude non-source directories from the walk — at minimum `.claude/`, plus `.git/`,
`.venv/`, and any nested `worktrees/`. Prefer scoping the scan to tracked files via
`git ls-files` (which already ignores worktrees and untracked scratch), or prune the
directory walk. Keep the allow-list for the genuine historical references.

Found 2026-09-09 while running the suite for B418 — the only failure in an otherwise green
related-suite run (366 passed), and unrelated to the change under test. Relates to B412
(the guard's origin) and the general worktree-heavy multi-agent setup.
