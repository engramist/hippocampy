### Problem

SideQuests memory retrieval (`current_truth`, `explore_graph`) returns isolated nodes — an action
ID, a fact, a decision. But the surrounding context (the 2-3 rationale lines before and after that
decision in the original conversation) is lost. When the ARC agent recalls a past puzzle memory,
it sees "ACTION3 → strong_progress" but not *why* that action worked or what the agent was thinking
at the time.

This is the graph equivalent of `grep` without `-A`/`-B` context lines.

### What This Card Builds

Context-windowed recall for SideQuests memory retrieval:

1. `explore_graph` gets an optional `context_window: int` parameter (default 0, max 3).
   When > 0, each returned node also includes up to N neighbor nodes connected by temporal
   or causal edges (NEXT_MESSAGE, CAUSED_BY, ESTABLISHED_IN) — the "surrounding lines."
2. `current_truth` gets an optional `include_rationale: bool` parameter. When true, each
   retrieved fact includes the originating Message content (1-hop ESTABLISHED_IN traversal).
3. Results are formatted as `[context_before] → [target_node] → [context_after]` in the
   returned payload.
4. Context is capped to avoid blowing up token budget — max 200 chars per context neighbor.

## Acceptance Criteria

1. `explore_graph(context_window=2)` returns temporal neighbors around each visited node.
2. `current_truth(include_rationale=true)` includes originating message content per fact.
3. Context text is truncated to 200 chars per neighbor.
4. Default behavior (context_window=0, include_rationale=false) is unchanged.
5. All existing tests pass unchanged.
6. New tests cover context retrieval and truncation.

## Outcome

Memory recall includes the reasoning context around facts, enabling the agent to understand
*why* a past action worked, not just *that* it worked.
