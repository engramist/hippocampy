# B325 - Reconcile SUPERSEDES into DEPRECATED_BY

State: todo
Priority: P2

Depends on: **B312** (provenance + `SUPERSEDES`), **B323** (task dependency graph, agent
provenance, card/branch context bundle — this card is B323's Task 4 follow-up, filed rather
than done silently because B312 had already landed when B323's audit ran).

### Why

Two rel tables currently express the same idea — "this node was replaced by that node" —
with opposite arrow conventions:

- `DEPRECATED_BY` (pre-existing, covers `Concept`/`Decision`/`Constraint`/`Lesson`
  self-pairs): `(older)-[:DEPRECATED_BY]->(newer)`, i.e. "A is deprecated by B".
- `SUPERSEDES` (added by B312, covers all of `PROVENANCE_TABLES` as same-type pairs):
  `(newer)-[:SUPERSEDES]->(older)`, i.e. "A supersedes B".

B323 audited this drift (its Task 4) and judged the *preferred* fix to be: extend
`DEPRECATED_BY` with the missing pairs and edge properties, and stop writing `SUPERSEDES` —
rather than maintaining two rel tables that mean the same thing with mirrored arrows and no
shared write path. It did not do this in place because B312 (and its `mark_superseded()` /
`tests/test_provenance.py`) had already landed with `SUPERSEDES` live by the time the audit
ran, and merging two live rel tables is a schema-safety decision this card should make
deliberately, not as a drive-by inside B323.

### What This Card Does

1. Extend `DEPRECATED_BY`'s `FROM ... TO ...` pairs to cover every table in
   `PROVENANCE_TABLES` (matching `SUPERSEDES`'s current coverage), and add `SUPERSEDES`'s
   edge properties (if any were added beyond bare FROM/TO — check `schema.py`'s current
   `SUPERSEDES` DDL) to `DEPRECATED_BY`.
2. Decide and document the arrow direction `DEPRECATED_BY` keeps. Changing an existing,
   already-relied-upon table's semantic direction is itself a breaking change for any code
   written against the old `(older)-[:DEPRECATED_BY]->(newer)` reading — audit
   `campy/brain/hippocampus/hippocampus.py` and any other reader before deciding whether to
   flip it to match `SUPERSEDES`'s `(newer)->(older)` convention or keep the original and
   flip `mark_superseded()`'s edge direction instead.
3. Repoint `mark_superseded()` (`campy/brain/hippocampus/provenance.py`) to write
   `DEPRECATED_BY` instead of `SUPERSEDES`, in whichever direction Task 2 above settles on.
4. Migrate or drop the `SUPERSEDES` rel table. Check for existing `SUPERSEDES` edges first
   (same safety pattern as every other rel-table change in this codebase — see
   `schema.py`'s `_REL_MIGRATIONS`); if any exist, migrate them to `DEPRECATED_BY` edges
   before dropping `SUPERSEDES`, don't just orphan them.
5. Update `tests/test_provenance.py`'s `SUPERSEDES`-specific assertions to match.
6. Update `docs/ARCHITECTURE.md`'s B312 section (the "Explicit supersession" subsection)
   and this reconciliation note in `backlog/B312.md` to reflect the merged state.

### What This Card Does NOT Do

- Does not change the `superseded_by`/`superseded_at`/`supersession_reason` node columns —
  those stay as the fast filter regardless of which rel table backs the traversable edge.
- Does not add cross-type supersession/deprecation edges (same scope boundary B312 and
  B323 both drew).

### Acceptance Criteria

- [ ] `DEPRECATED_BY` covers every `PROVENANCE_TABLES` same-type pair
- [ ] `mark_superseded()` writes `DEPRECATED_BY`, not `SUPERSEDES`
- [ ] Pre-existing `SUPERSEDES` edges (if any exist on a real DB) are migrated, not dropped
      silently
- [ ] Only one rel table expresses "replaced by" after this card lands
- [ ] `pytest tests/ -q` failure set identical to pre-change baseline

### Outcome

One mechanism for "this fact was replaced", not two with opposite arrows and no shared write
path — closing the drift B312 introduced and B323 caught rather than compounded.
