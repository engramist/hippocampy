### Problem

Claude Code has hooks (B259), but the other 3 active agents — Codex, Gemini CLI, and VS Code (Copilot) — each have different configuration mechanisms for injecting recall behavior. Currently these agents have MCP server registration but no recall-triggering configuration.

### What This Card Does

Configures recall behavior for each non-Claude-Code agent using their native mechanisms:
1. **Codex**: Memory skill at `~/.codex/skills/campy-memory/SKILL.md` + AGENTS.md instruction
2. **Gemini CLI**: `GEMINI.md` instruction file + MCP tool instructions
3. **VS Code (Copilot)**: `.github/copilot-instructions.md` + MCP server config

### Dependencies

- B258 complete (assertive skill content to reference)
- B255 complete (plugin must be installable)

### Design Decisions

| Decision | Choice | Rationale |
|---|---|---|
| Codex approach | Skill file + AGENTS.md section | Codex reads `~/.codex/skills/` and project AGENTS.md |
| Gemini approach | GEMINI.md + tool description hints | Gemini CLI reads GEMINI.md for project instructions |
| VS Code approach | copilot-instructions.md + MCP config | Copilot reads `.github/copilot-instructions.md` |
| Content source | All derive from the same session-start protocol | One protocol, three delivery shapes |

### Verification Findings (2026-08-03)

- Located all 3 functions in `campy/cli/register.py`: `register_codex()` (line 288), `register_vscode()` (line 317), `register_gemini_cli()` (line 510). Read each in full.
- **`register_gemini_cli()` is definitively not a no-op.** It attempts `gemini extensions link <plugin_dir>` natively first, and on failure/absence falls back to `_register_gemini_cli_legacy()`, which writes a marker-delimited Campy section into `GEMINI.md`, sourced from `campy/data/campy-memory/SKILL.md`. This directly answers the card's own stated premise (AC2 explicitly flags the prior no-op).
- **`register_codex()`** tries native `codex plugin install <plugin_dir>`, falls back to `_register_codex_legacy()` which edits `~/.codex/config.toml` and calls `install_codex_memory_skill()` (line 102) to write `~/.codex/skills/campy-memory/SKILL.md`.
- **`register_vscode()`** writes VS Code's global `mcp.json` (stdio server entry) and, if `.github/` exists in the target repo, calls `_add_copilot_recall_instructions()`. **Live-tested this function for real** against a scratch copy of a `.github/copilot-instructions.md` (not the tracked repo file): confirmed it correctly inserts a `<!-- CAMPY-MEMORY-START -->...<!-- CAMPY-MEMORY-END -->` block containing the skill catalog and campy-memory content.
- **Caveat:** this hippocampy repo's own `.github/copilot-instructions.md` (42 lines, PR-review ecosystem-rules checklist) does NOT currently contain a Campy memory block — `register_vscode()` was apparently never actually run against this repo's own file (likely because VS Code/Copilot isn't the detected local client, or this repo intentionally keeps its own copilot-instructions.md focused on the PR-review checklist). The mechanism is proven to work via the live scratch test above; its absence here is not evidence of a bug.
- **AC1 "assertive" language caveat — real, but intentional, later design reversal:** `campy/data/campy-memory/SKILL.md` uses lowercase "must"/soft "Always On" framing and a "Core Rule" section, NOT the B258-style "MUST"/"ALWAYS" mandatory phrasing. `tests/cli/test_recall_config.py:15-19` has an explicit comment explaining why: *""MUST"-worded mandatory framing predates the canonical policy's shift to softer, permission-based language ... Do not recall on every turn... Recall only when a decision needs memory."* This matches this repo's own current `CLAUDE.md` Campy Memory Usage Policy verbatim ("Do not recall on every turn. Use recall only when the answer or plan depends on durable prior decisions..."). So the assertive-language requirement was deliberately superseded by a later, documented product decision — not a defect.
- `campy/data/recall-instructions.md` (mentioned in the plan as a separate template file) does not exist — the actual design consolidated everything into `campy/data/campy-memory/SKILL.md` directly rather than a separate parameterized template. No functional gap; the plan's exact file layout wasn't followed but the requirement (recall instructions reach all 3 agents) is met.
