# B509: OWL attribute properties — functional properties drive supersession (flag, default off)

**Status:** open (PR pending gate) · **Step 3 of 3** in the graph-structure plan (1 SHACL, 2 SKOS vocabulary, 3 OWL typed properties). Stacked on B508; merges B506 (object render) and the B499 supersession writer.

## Problem

B499 superseded `has_attribute` Observations by matching free strings (the text before the first colon,
token sets). Measured, it rarely fires (attribute names are free strings, often JSON reprs), and when it
does it is wrong for multi-valued attributes: "hobby: tennis" then "hobby: chess" are both true, yet the
string rule replaced one with the other. Whether a newer value replaces an older one is a property of
the *attribute* (your age has one current value, your hobbies do not), not of the strings.

## Change (flag `[observations] owl_properties` / `CAMPY_OWL_PROPERTIES=1`, default off)

**Model.** An attribute name is an `AttributeProperty` node (new node table): an `owl:DatatypeProperty`
(literal value) or `owl:ObjectProperty` (Concept value), and a `skos:Concept` in `campy:PropertyScheme`
with `text_raw` as prefLabel and altLabels as Label nodes (`HAS_ALT_LABEL`). It is a separate table, not
a Concept, so attribute names never enter the Concept linker or Concept retrieval. Edges: `HAS_PROPERTY`
(Observation to property, at most one: `owl:FunctionalProperty`), and the existing `BROADER` /
`CLOSE_MATCH` now also join two properties. The Observation keeps its value apart from the name:
`attr_value` (text as written), `attr_value_kind` (number / duration / money / date / clock / text) and
the parsed typed literal (`attr_value_num` + `attr_value_unit` for number, money and duration in seconds;
`attr_value_time` for a date; `attr_value_ref` for an object-valued attribute). A two-part clock such as
"25:50" is kept as text: minutes:seconds or hours:minutes cannot be told apart without guessing. Datatype
and object properties are disjoint in OWL, so a property's type is fixed by its first value; a later
conflicting value stays text and is not forced.

**Consolidation (rules, no model; `hippocampus/attribute_properties.py`).** A name's key is its set of
stemmed content tokens, order and filler words (time, total, count, articles, current) ignored.
- (a) same token set as an existing property's prefLabel/altLabel or a seed property: the SAME property;
  other wordings become altLabels. "personal best 5K" and "5K personal best time" are one property.
- (b) an existing property's tokens are a proper subset of the new name's ("5K personal best" over
  "personal best"): NOT merged (the unqualified one is not interchangeable) but recorded as `BROADER`.
  Order independent. Chosen over merging because a merge would let a marathon time supersede a 5K time.
- (c) optional embedding similarity above `skos_closematch_threshold`: `CLOSE_MATCH` only.

**Which properties are functional (rules decide, `campy_vocab.ttl` holds the data).**
1. Seed properties declared `owl:FunctionalProperty` in the vocab file (age, birthday, occupation, employer,
   residence, relationship status, follower count, weight, height, salary), matched by label. Functional by
   IRI identity: nothing is copied onto the node.
2. A name containing a `campy:SingleValuedModifier` ("favorite", "personal best", "birth"): such a name picks
   out one thing. Stored as `functional_basis = 'modifier'`.
3. Rule-confirmed (`functional_basis = 'confirmed'`): the extractor advised `cardinality: "one"` more often
   than `"many"` AND a newer value arrives for the same subject, different from the older, AND that turn uses
   replacement language ("now", "moved", "no longer", "switched" ...). All three. Advice alone never decides
   (it is stored as `advised_one` / `advised_many` counts, a candidate), and replacement language alone never
   decides ("I switched to chess" is about chess). It confirms only when the incoming value is the newer.
   One confirmed replacement is enough: waiting for two would leave the commonest case (a single update)
   unfixed, and a wrong confirmation costs one superseded row that is kept, marked and rendered.

**Supersession.** For a functional property, the newer value (by `observed_at`, ties `created_at`) for the
same subject (B499's `same_subject`) supersedes the older: `superseded_by` / `superseded_at`, a
`DEPRECATED_BY` edge, rendered `(superseded <date>)`. Out-of-order arrival marks the incoming row. Same
value restated (equal typed literal, else equal text) never supersedes. A non-functional property never
supersedes. With the flag on, B499's string rule does not run and the bundle keeps superseded rows (marked).

**Checks.** `campy_shapes.ttl`: `FunctionalSlotShape` (`sh:maxCount 1`) over the live projection that
`validator.owl_project` builds: one `FunctionalSlot` per (subject, functional property) holding the values of
live, non-superseded, asserted Observations; an `AttributePropertyShape`; `HAS_PROPERTY` max one;
`skos:broader` may not cross schemes. `validator.reasoning_report` (report only, nothing is edited):
`broader_cycles` (strongly connected groups of any length, Tarjan), `redundant_broader` (transitive
reduction), and an `owlrl` pass over a reasoning view that flags a pair both `INSTANCE_OF` and `BROADER`
(`owl:propertyDisjointWith`, declared in B508's vocab).

**Structure report.** `scripts/graph_structure_report.py` adds: attribute properties, functional share,
share of `has_attribute` Observations linked to a property, share with a typed value, supersessions,
functional violations, broader cycles / redundant edges / owlrl inconsistencies.

## Out of scope / known limits
- Seed list is small and English; extend it in `campy_vocab.ttl`, not in Python.
- The subject of a slot is keyed by resolved id else text; an id-resolved and a text-only row for one real
  subject land in different slots (the writer matches them, the projection does not).
- No backfill is wired to a command; `attribute_properties.backfill` exists and is tested.
