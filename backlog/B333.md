# B333 - AMA-Bench / MemoryArena: Synthetic Toy Generators Are Cited as Real Published Datasets

State: complete — merged via PR #57 (2026-08-20)
Priority: P1

Plan: none yet.

### Problem

`benchmarks/benchmark_sources.md` describes "AMA-Bench" and "MemoryArena" as real external benchmarks:
AMA-Bench as "2,496 expert-curated QA pairs (Real-world subset)" from `arxiv:2602.22769`
(`github.com/AMA-Bench/AMA-Bench`), MemoryArena as "4 Domains (Bundled Shopping, Travel Planning, Info
Search, Formal Reasoning)" from `arxiv:2602.16313` (`github.com/MemoryArena/MemoryArena`).

But the actual implementation, `benchmarks/causal/__init__.py:74-99` (`generate_ama_bench_tasks`) and
the neighboring `MemoryArenaTask` generator (`:148-173`), generates **seeded-random synthetic tasks** —
simple arithmetic-with-constraints puzzles (e.g. "If X + Y = 20 and X > Y, find X when Y = 7") for
AMA-Bench, and box-capacity-style puzzles for MemoryArena — with a default `num_tasks: 10`, not the
2,496 real curated pairs the sources doc describes. Confirmed again for this card: `random.seed(seed)`
at `benchmarks/causal/__init__.py` line ~85, no data loading from an external dataset file anywhere in
that module.

So any benchmark report citing "AMA-Bench" or "MemoryArena" results is, today, reporting performance on
a small in-house toy generator while wearing the name (and implied credibility/scale) of a real
published academic benchmark. This is a data-integrity problem independent of whether our system
actually performs well — the label is what's wrong.

### What it does (scope)

Two parts, both required:

1. **Rename to stop borrowing external credibility.** Rename the benchmark identifiers used in code,
   result files, and reports from "AMA-Bench"/"MemoryArena" to something that honestly describes what
   they are — e.g. `synthetic-causal-arithmetic` and `synthetic-capacity-constraints` (pick names that
   fit this project's existing naming conventions; check `benchmarks/runner.py`'s
   `register_benchmark` call sites for the identifier format used elsewhere). Update
   `benchmarks/benchmark_sources.md` to either remove the AMA-Bench/MemoryArena entries entirely (if
   there's no intent to ever run the real datasets) or clearly split it into two sections: "Datasets we
   cite as inspiration" (the real arXiv papers, kept as design references) vs. "Our synthetic proxies"
   (the actual generators, clearly labeled as such, with no claimed task count or "expert-curated"
   language).
2. **Decide and document whether real-dataset support is planned.** If there's appetite to eventually
   run the real AMA-Bench/MemoryArena datasets, add a tracking note (in `benchmarks/benchmark_sources.md`
   or a new backlog card) that the current generators are explicitly a placeholder/proxy pending real
   dataset integration — do not silently drop the real-dataset ambition, just stop presenting the proxy
   as if it already were the real thing. If there's no such appetite, say so plainly instead of
   implying future real-dataset support.

Do NOT attempt to download and wire up the actual AMA-Bench/MemoryArena datasets as part of this card
unless doing so is trivial (e.g. they turn out to already be pip-installable or a small static
download) — that's a larger, separate effort. This card's job is to stop the mislabeling, not to
build real dataset integration.

### Dependencies

None. Independent of B332/B334/B335 — separate files, can run in parallel.

### Files to create/modify

- `benchmarks/causal/__init__.py` (rename identifiers/class names if they reference "AMA-Bench" or
  "MemoryArena" directly, e.g. `AmaBenchTask`/`MemoryArenaTask` class names — check whether renaming
  breaks any existing result-file schema expectations before renaming wholesale; a `benchmark_name`
  field rename is the minimum required, class renames are optional cleanup).
- `benchmarks/benchmark_sources.md` (restructure per item 1).
- Any result files or report docs under `benchmarks/results/` or wherever aggregate reports live that
  cite "AMA-Bench"/"MemoryArena" by name — grep `rg -rln "AMA-Bench|MemoryArena" -i` to find all hits.
- `benchmarks/runner.py` call sites registering these benchmarks, if the registered name changes.

### Acceptance Criteria

- [ ] No document in the repo describes the current synthetic generator output as "2,496

      references, if desired) from the in-house synthetic proxies actually being run.
- [ ] The renamed benchmark identifiers are consistent across code, config, and any result/report files
      that reference them (no half-renamed state where docs say one name and code emits another).
- [ ] Existing tests for this benchmark module (`rg -l "causal" tests/` to find them) still pass after
      any renaming.
