# B414 - Silent-Duplicate Guard + Mechanical Card-Number Allocation

State: proposed
Priority: P0

### Problem

Two independent agents shipped the same fix as separate cards/PRs on the
same three days, each one branch-cutting from a `main` that already had
the fix merged:

| Duplicate PR | Duplicate of | Gap between them |
|---|---|---|
| #191 ("B403" sweep PK fix, closed) | #178 (B404) | 2 days |
| (agent-collision on B409 and one spec §, handled manually today) | — | same day |

Neither triggered [B408](B408.md)'s stale-base guard. B408 fires on
`merge-base(pr, main) != HEAD(main)`, so a branch cut from **current**
main passes the guard even when the work it proposes is redundant.
Staleness and "already fixed" are orthogonal:

|                                            | branch base fresh | branch base stale |
|---                                          |---                 |---                |
| PR diff adds real changes                    | normal            | B408 blocks if it silently reverts merged work |
| PR diff re-applies changes already on main   | **B414 blocks (new)** | **B414 blocks (new)** |

Also observed: the B403 collision was pure card-number allocation —
`ls backlog/B403.md` was all the check needed, but the number was picked
by memory from an older tree.

### Why this rather than more agent instruction

Telling agents to "remember to rebase" failed six times before B408 was
built (see B408 §"Why this keeps happening"). Telling agents to "grep
`main` for the same fix before starting" is the same shape of ask and
will fail the same way. The judgment-heavy part ("is this the same fix
as one that already landed?") *does* belong in agent memory
([[feedback_check-base-fresh-before-fix]] captures the personal side).
The two mechanical parts do not need judgment and belong in scripts.

### Scope

1. **`scripts/check_pr_effective_noop.py`** — new CI check.

   For a PR head against `origin/main`, compute a 3-way merge tree
   (`git merge-tree $(git merge-base origin/main HEAD) origin/main HEAD`)
   and compare it to `origin/main`'s tree. If identical, the PR
   contributes nothing — fail with a message naming the merged commit(s)
   whose diff already covers this work. Detection heuristic that works
   here: `git cherry origin/main <pr-head>` — lists PR commits with **no
   equivalent** already on main; if it prints nothing, every commit is
   already represented and the PR is a no-op.

   Wire it into `.github/workflows/tests.yml` next to
   `check_branch_current.py` (line 67) — same job, same failure story.

   Edge cases to handle in the design: whitespace-only diffs count as
   no-op; a PR that intentionally reverts a merged commit is NOT a no-op
   (its diff subtracts, does not duplicate); base branch other than
   `main` skips the check.

2. **`scripts/next_card_number.py`** — mechanical card-number allocator.

   Scans `backlog/B*.md`, returns the smallest unused positive integer
   above the highest existing one, or `--gap` returns the smallest unused
   *interior* gap for filling holes. Prints just the number, so it composes:

   ```bash
   N=$(python scripts/next_card_number.py) && $EDITOR "backlog/B${N}.md"
   ```

   Not a CI check — a one-line safety net for anyone (agent or human)
   about to file a card. Also update `docs/backlog/` conventions doc (if
   one exists) to point to it as the canonical way to pick a number.
