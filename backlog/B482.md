# B482 - Conversation Stage Token-Budget Mode

State: implemented (2026-10-12; off by default, gate pending)
Priority: P2

Plan: (inline -- this card is self-contained; context in `learnings/e2e-improvement-plan.md` Part D/G)

### Problem Statement

The conversation stage always returns a fixed `[retrieval] conversation_limit`
(6) turns, however small the store. On 200 DMR dev questions (R44a) Campy
scores 0.535 while the full-history baseline scores 0.825 with only ~3,450
prompt tokens on average, and naive RAG (top-5) scores 0.62. A DMR store
holds ~50 turns: the whole user side of it is under 1,100 tokens. On
LoCoMo-10 (conv-26: 419 turns, ~15.8k tokens of eligible user turns) full
history is far larger, and earlier tests showed that raising the fixed limit
to 12/20 raised recall but not accuracy and doubled latency. So the rule has
to be general: fill a token budget, not a turn count.

### Proposed Fix

`[retrieval] conversation_token_budget = 0` (env
`CAMPY_RETRIEVAL_CONVERSATION_TOKEN_BUDGET`; 0 = off = today's fixed-limit
path, byte-identical). When > 0, `_stage_conversation` calls the new
`thalamus.bundle_conversation_budget` (a new NamedQuery: params of the
existing one are untouched, G.2):

1. If every eligible user turn (user role, not archived, not a question, not
   an echo of the query, de-duplicated on (speaker, text)) fits the budget,
   return all of them oldest first -- full history. Only enumerated when the
   lexical index holds <= `token_budget` documents.
2. Otherwise rank as today (RRF of vector + FTS, B459 gate, B463 bridge) over
   a candidate pool sized to the budget (`budget // 12` instead of
   `conversation_limit`), take turns in rank order until the budget is full
   (a turn that would overflow is skipped), present in `conversation_order`.

Token cost per turn = `len(stamp + text) // 4`, the estimate the section's
`token_estimate` already uses (`gateway.conversation_turn_tokens`).

Compression (`ask.py`): the compression router has no route for the
"conversation" section type (NoOp), so it is never truncated. It does count
toward the pressure-relief threshold (`[compression] budget_tokens`, 4000 in
`campy.toml`); in budget mode it is exempted from that count so a full
history does not push the semantic/graph sections into lossy compression.
`compile_bundle`'s own 90% gates are on the 32000 bundle budget and are
unaffected for budgets of a few thousand tokens.

### Measure

Offline (no LLM): turns / tokens returned for budgets 2000, 3500, 6000 on
golden-store copies (see PR). Behaviour: T0 replay on DMR dev (R44a split)
and LoCoMo-10 with budget 3500 vs 0, same pins; watch avg latency (prompt
size) and LoCoMo-10 adversarial abstention.
