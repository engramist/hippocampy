# B220 - Post ARC-AGI Extraction Repo Cleanup Audit

State: complete
Priority: P1

Plan: backlog/plans/B-220-post-arc-extraction-cleanup.md

### Problem

SideQuests Brain still contains historical ARC-specific files, backlog cards, generated outputs, ignore rules, docs, and diagrams from before ARC-AGI was split into its own repository. This makes ownership blurry: contributors cannot easily tell which files are still part of SideQuests core and which are migrated ARC artifacts.

The risk is not just aesthetics. Stale ARC references can hide dead imports, stale test assumptions, misleading architecture diagrams, and duplicated implementation work between this repo and the sibling ARC_AGI repo.

### What it does

Audits the repository after the ARC extraction and classifies every ARC-related artifact as one of:

- `keep`: SideQuests-owned integration contract, memory API, task graph, or documentation
- `move`: belongs in the sibling ARC_AGI repo
- `archive`: historical result or migration record worth keeping but not active
- `delete`: generated/debug artifact that should not live in source control
- `document`: retained artifact needs a note explaining ownership

This card should not perform a large deletion sweep blindly. It produces a reviewable cleanup manifest first, then applies only low-risk changes that are clearly SideQuests-owned.

- [x] `docs/arc-extraction-cleanup-audit.md` lists all ARC-related files/directories found by `rg -n "ARC|arc|ARC_AGI|arc-agi"`.
- [x] Each listed artifact has an ownership classification: `keep`, `move`, `archive`, `delete`, or `document`.
- [x] SideQuests-owned ARC integration boundaries are explicitly documented: adapters, MCP tools, task graph, memory retrieval, and external client expectations.

- [x] Any deletion or relocation is small, reviewable, and listed in the audit manifest.
