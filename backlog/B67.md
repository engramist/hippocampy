### B67 · Active Agent Tools (register_plan, report_outcome, recall_plans)

**Problem:** The Brain's tool surface is entirely passive — agents can ingest observations (`notify_turn`) and query memory (`current_truth`), but cannot declare intent, report outcomes, or learn from past strategies. This means agents re-discover approaches from scratch every session instead of building on what worked before.

**What it does:** Adds three new MCP tools that give agents an active learning loop: Perceive → Model → Plan → Act → Evaluate. Depends on B66 (Plan/PlanStep schema).

**Depends on:** B66

**New Tools:**

### `register_plan`
Agent declares a multi-step strategy. The Brain creates Plan + PlanStep nodes, chains them via `[NEXT_STEP]`, and runs an internal similarity check against past plans before returning.

```json
{
  "name": "register_plan",
  "inputSchema": {
    "properties": {
      "goal":       { "type": "string", "description": "What this plan aims to achieve" },
      "steps":      { "type": "array", "items": { "type": "string" }, "description": "Ordered list of steps" },
      "session_id": { "type": "string" }
    },
    "required": ["goal", "steps", "session_id"]
  }
}
```

Response: `{ plan_id, step_ids[], quest_id, warnings[], suggestions[] }`

**Amygdala Reflex (IP Claim):** At registration time (before the first step executes), the Brain vector-searches for similar past Plans. If a high positive-valence match exists → surface as `suggestions` ("Golden Path: this strategy worked before"). If a high negative-valence match exists → surface as `warnings` ("Pain Path: a similar approach failed — here's what went wrong"). This is the preemptive reflex — cheap because it runs once at plan creation, not on every action.

### `report_outcome`
Agent reports step-level or plan-level results. Triggers valence propagation and optional Lesson extraction.

```json
{
  "name": "report_outcome",
  "inputSchema": {
    "properties": {
      "plan_id":     { "type": "string" },
      "step_number": { "type": "integer", "description": "Omit for plan-level outcome" },
      "outcome":     { "type": "string", "description": "What actually happened" },
      "valence":     { "type": "number", "minimum": -1, "maximum": 1 },
      "session_id":  { "type": "string" }
    },
    "required": ["plan_id", "outcome", "valence", "session_id"]
  }
}
```

Response: `{ updated, plan_status, lesson_id? }`

When step_number is provided: updates PlanStep.actual_outcome, PlanStep.valence, PlanStep.status.
When omitted: updates Plan.valence, Plan.status → "completed".

**Auto-Lesson extraction:** When a plan completes with |valence| > 0.7, auto-trigger Step 7.5 (lesson extraction) to create a Lesson node linked via `[PRODUCED_LESSON]`. High-pain plans produce "what to avoid" lessons; high-reward plans produce "what works" lessons.

**Valence propagation:** PlanSteps with negative valence propagate to their `[ACTS_ON]` Concept nodes — those concepts get flagged so future `current_truth` retrievals can warn about them.

### `recall_plans`
Agent asks "what strategies worked (or failed) for a similar goal?"

```json
{
  "name": "recall_plans",
  "inputSchema": {
    "properties": {
      "goal_query":  { "type": "string", "description": "What you're trying to accomplish" },
      "session_id":  { "type": "string" },
      "min_valence": { "type": "number", "default": 0.0, "description": "Set negative to include failed plans" },
      "limit":       { "type": "integer", "default": 5 }
    },
    "required": ["goal_query", "session_id"]
  }
}
```

Response: `{ plans[{ plan_id, goal, valence, steps[{ description, valence, status }], similarity }] }`

Retrieval ranked by `similarity × |valence| × pathway_strength`. Returns full PlanStep chains so the agent can replicate or adapt.

**Adapter Instruction Updates:**
Add to Layer 2 onboarding skill:
```
- register_plan: call when you formulate a multi-step approach.
  The Brain tracks your strategy and warns if a similar plan failed before.
- report_outcome: call after key steps or when your plan completes.
  Valence: -1.0 (total failure) to +1.0 (perfect success).
- recall_plans: call before planning to learn from past strategies.
  Set min_valence negative to also see what failed.
```
