# B136: Trigger Re-Planning When Solve Engine Detects Dissonance

**Status**: Ready  
**Assigned**: TBD  
**Depends on**: None  
**Complexity**: Small-Medium (1–2 hours)  
**Priority**: P1 (HIGH — agent detects it's lost for 5 consecutive steps and does nothing; plan phase fires once at startup, never again)  
**Plan**: backlog/plans/B-136-dissonance-replan.md

## Problem Statement

The solve engine correctly detects when the agent's current plan is misaligned with reality — it sets `dissonance=True` in `_solve_context`. However, the runner loop **never checks this flag** and never re-triggers the plan phase. The agent silently continues executing a stale, invalid plan.

Evidence from `master_timeline.json`:
```
step 10: solve phase_end  dissonance=True
step 11: solve phase_end  dissonance=True
step 12: solve phase_end  dissonance=True
step 13: solve phase_end  dissonance=True
step 14: solve phase_end  dissonance=True

plan phase_start: fires exactly ONCE (at startup, step 0)
plan phase_start: NEVER fires again, even after 5 consecutive dissonance flags
```

The agent knows it's lost. It has working plan/hypothesis infrastructure. But runner.py calls `orchestrator.plan(...)` only once and then never again.

## What This Card Builds

1. After each solve step, the runner checks `orchestrator._solve_context.get("dissonance")`.
2. If `dissonance=True`, the runner calls `await orchestrator.plan(observation, memory_context)` to re-generate a plan before the next act step.
3. A `replan_triggered` trace event is emitted with the triggering step and dissonance reason.
4. A `replan_backoff` is applied — re-planning does not fire more than once per 3 steps (prevent plan-thrashing).

- [ ] `replan_triggered` event appears in `master_timeline.json` with step number and reason
- [ ] Re-planning does not fire more than once per 3 steps (backoff)

## Outcome Statement

After this card, the agent responds to genuine confusion by updating its plan. The plan phase becomes a live adaptive mechanism rather than a one-time startup procedure. Combined with B132 (live LLM), re-planning produces real updated goals and action sequences.
