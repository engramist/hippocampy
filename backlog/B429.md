# B429 - Unify Instance-URI Base (`/data/` -> `/id/`) — Fixes a Live Phantom-Edge Bug in 4+ Gateway Handlers (B418b)

State: fixed (this PR)
Priority: P1
Branch: fix/b418b-unify-instance-uri-base

### Background

B418 documented two coexisting instance-URI bases: `mint_uri()` / `CID_BASE` /
`vector_search()` use the canonical `https://campy.dev/id/`, but 26 `sparql=` create
templates across 7 query modules (`basal_ganglia.py`, `ingest.py`, `lessons.py`,
`orchestrator.py`, `pathways.py`, `task_graph.py`, `temporal_lobe.py`) minted new nodes at
`https://campy.dev/data/` instead. B418 filed unifying them as "B418b" — framed as
hygiene, since B418a's base-agnostic `vector_search`/`fts_search` made recall work either
way.

### What scoping the "hygiene" fix actually found: a live bug

Six node tables — **Concept, Dataset, Label, Lesson, Plan, Procedure** — are *only ever
created* via the drifted `/data/`-minting templates. `OxigraphClient.write_node()` (the
only thing that mints a fresh node at `/id/`) is **never called** for any of them anywhere
in `campy/`.

But several `gateway.py` `_handle_oxigraph_handler` branches construct **edge endpoints**
for these exact tables via `mint_uri("Concept", …)`, `mint_uri("Plan", …)`, etc. — which
always assumes `/id/`. So the edge is written to a URI **no real node occupies** — the
node lives at `/data/{Table}/{pk}`, the edge attaches to `/id/{Table}/{pk}`, a phantom
subject typed nothing. The edge is present in the store but permanently unreachable from
the real node it was meant to connect to.

Confirmed reachable in production (not latent, unlike B422): `quests.link_distinct_from`
is called from `campy/brain/thalamus/tools/quests.py:901`. Every `DISTINCT_FROM` edge ever
written between two Concepts landed on phantom URIs — `retrieval.get_distinct_pairs`
(the only read of it) would always return empty for a real Concept, silently. Same pattern
implicated for:

- `sweep.link_generalizes_lesson` (`GENERALIZES_LESSON`, Lesson→Lesson)
- `ingest.link_concept_dataset` (`DESCRIBED_BY_DATASET`, Concept→Dataset)
- `quests.link_plan_applied_procedure` (`APPLIED_PROCEDURE`, Plan→Procedure)
- `gateway.py:601`'s `upsert_vector(mint_uri("Label", …), …)` — a Label's embedding
  indexed at a URI with no matching node, so `vector_search("Label", …)` would fail to
  hydrate (or hydrate nothing) even though the vector itself was found.

This is the same handler-writes-to-a-URI/table-the-node-doesn't-live-at class as B420/B421
(and the guard class B422 shipped) — except triggered by base mismatch rather than a wrong
edge/table name, so B422's guard (which checks table *existence* and edge *classification*,
not which of two valid bases a table happens to live at) did not catch it.

### Fix

`mint_uri()`'s `/id/` is the documented canonical base
(`docs/rdf-schema-mapping.md` §2) and is what every edge-writing handler already assumes.
All 26 `https://campy.dev/data/` literals in the 7 query modules' `sparql=` templates are
changed to `https://campy.dev/id/` — a targeted, verified-safe substitution:

- Every occurrence is a `BIND(IRI(CONCAT("https://campy.dev/data/{Table}/", …)))` inside a
  node-creation `WHERE` clause (including the two `COALESCE(...)` find-or-create variants
  and the `orchestrator.py` f-string generator covering 4 artifact-type queries) — never a
  property-based lookup of an *existing* node (those match by `?n a campy:Table ;
  campy:pk ?id`, which is base-agnostic and needed no change).
- No table had conflicting literal `/id/{Table}/` references elsewhere that this could
  collide with (checked per table before editing).
- `DATA_BASE`/`CID_BASE` dual-base matching in `vector_search`/`fts_search`
  (`oxigraph_client.py`) is left in place as harmless defense-in-depth, not removed.

### Proof

`tests/test_b418b_uri_base_unification.py`:
- a Concept create now mints at `/id/`;
- **regression proof for the phantom-edge bug**: `quests.link_distinct_from` written
  between two really-created Concepts is now readable via `retrieval.get_distinct_pairs`
  (previously would have silently returned nothing);
- same proof for `sweep.link_generalizes_lesson` reaching the real Lesson node;
- a registry-wide guard asserting no `sparql=` template mints at `/data/` any more.

`tests/test_b418_vector_index_roundtrip.py` updated (its
`test_created_lesson_hydrates_despite_data_uri_base` assertion of the OLD `/data/` mint
behavior is now obsolete by design — renamed and updated to assert `/id/`).

Regression: 727 passed across the full domain-test sweep (all 7 touched query modules +
gateway/oxigraph/vector/arc/quests/sweep/capability, including Kùzu-backed tests
unaffected since they run the `.cypher`/Kùzu path); focused suite (oxigraph/gateway/
b418/b420/b421/b422/vector/rdf-mapping) 116 passed; schema-conformance ratchet unchanged
(32).
