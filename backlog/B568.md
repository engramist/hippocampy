# B568: a reply cut at the output token limit keeps its complete facts

**Status:** Fixed 2026-11-13 (`observations/extract.py: salvage_cut_reply`; counts `cut_replies`, `salvaged_items`;
the log line `[Observations] msg=... reply cut; salvaged_items=N`). Found by the capture-recall diagnosis.

**Principles:** P3 (every kept fact goes through the same rules), P6.

**What.** On a re-run over 57 substantive gold turns with no fact, 7 replies were malformed (2 of 60 control turns).
- 8 of all 9 were cut off at the output token limit, each after 7-8 complete facts.
- 1 had a stray quote mark inside a quote.

`parse_observations` rejected each whole reply, so the turn kept nothing.

**Rule.**
- When the reply does not parse, and it is a JSON array that was never closed, the complete top-level objects before
  the cut are kept, decoded one by one. The partial last object is dropped.
- Each kept object is a proposal like any other: the same predicate, quote, subject and SHACL rules apply.
- A closed array that is broken inside (the stray-quote shape) stays malformed, as does a cut array with no complete
  object.
- The token limit is not changed. No flag: a parse fix at the write (review session ruling).

**Measure.** Re-run the extractor on the same 57 gold and 60 control turns, then run step Q on the copies.
Prediction: query hits +0 to +3; "no fact on a gold turn" from 76 to 70-74; control turns gaining facts: 2.
