# B219 - Fix `register_task_graph` Kuzu Parser Failure on `TaskNode` Creation

State: complete
Priority: P0

Plan: backlog/plans/B-219-fix-register-task-graph-kuzu-parser-failure.md

### Problem

`register_task_graph` is currently failing during real ARC smoke runs when SideQuests tries to create `TaskNode` rows for a new batch DAG. The MCP call reaches the correct tool, but the backend write fails with a Kuzu parser exception while executing the `CREATE (t:TaskNode { ... })` statement in `mcp_engine/tools/task_graph.py`.

This breaks the intended B128 contract in real usage: ARC can call the MCP endpoint, but it cannot persist the task graph it needs for batch coordination. As a result, the orchestration path falls back to degraded behavior and we lose one of the main benefits of the shared-memory/task-graph design.

### What it does

Diagnoses and fixes the Kuzu write/query shape used by `register_task_graph` so real callers can create a `TaskGraph`, create all `TaskNode` rows, attach them with `TASK_OF`, and then add `DEPENDS_ON` edges without parser failure.

### Real Failure Observed

From the ARC MCP smoke path:

- caller: sibling `ARC_AGI` repo via `sidequest_mcp_client`
- tool: `register_task_graph`
- backend: `mcp_engine/tools/task_graph.py`
- failure: Kuzu parser exception on `TaskNode` creation query

Observed query shape:

```cypher
CREATE (t:TaskNode {
    task_id: $tid,
    graph_id: $gid,
    name: $label,
    label: $label,
    description: $desc,
    status: 'pending',
    owner: $owner,
    created_at: timestamp($now)
})
WITH t
MATCH (g:TaskGraph {graph_id: $gid})
CREATE (t)-[:TASK_OF]->(g)
```

### Acceptance Criteria

- `register_task_graph` succeeds in a real MCP-backed call path for a minimal graph with one task.
- `register_task_graph` succeeds for a multi-node graph with at least one dependency edge.
- The fix preserves the B128 response contract:
  - `graph_id`
  - `task_ids`
  - `ready_tasks`
  - `cycle_errors`
- `get_ready_tasks` still returns the correct frontier after the fix.
- A focused regression test covers the previously failing write path.
- The fix does not require ARC to work around the problem client-side.

### Notes

- This is a SideQuests-owned bug, not an ARC bug. ARC is already using the published MCP contract.
- Preserve the architecture rule: the fix belongs here in SideQuests, not as an in-process bypass in the consumer repo.
- Investigate whether the parser failure is caused by the combined `CREATE ... WITH ... MATCH ... CREATE` statement shape, a property expression such as `timestamp($now)`, or another Kuzu Cypher limitation in the current runtime.
