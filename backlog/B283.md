### Problem

Three hub-formation risks have no monitoring or pruning:

1. **Session edges grow unboundedly**: every recall injects `LOADED` edges and every message updates `WARM_NODE` edges (`Session → artifact` rel tables). Long-running sessions accumulate hundreds of edges that are never pruned, and dead sessions keep theirs forever.
2. **CO_OCCURS_WITH is quadratic**: Step 7 writes co-occurrence edges between all concept pairs in a message — a message with 15 extracted concepts writes 105 edges.
3. **MainQuest is a natural hub**: everything links to it via `ESTABLISHED_IN`, `BELONGS_TO`, `WORKING_ON`, `TARGETS`. Unavoidable by design, but currently invisible — nobody knows when a quest node's degree makes traversals slow.

The graph-engineering rule is "treat dense nodes as a first-class risk." Campy currently has zero degree visibility.

### What This Card Does

1. Adds a `_report_degree_hotspots()` step to the background sweep: finds the top-K highest-degree nodes per major rel table and writes the report to sweep stats + activity log.
2. Adds `WARM_NODE` pruning: keeps only the most recent `MAX_WARM_NODES` (20) per session — currently bounding happens at write time per update but stale sessions keep edges forever; prune edges for sessions inactive > N days.
3. Adds `LOADED` edge TTL pruning: removes LOADED edges for sessions inactive > 30 days (configurable).
4. Caps CO_OCCURS_WITH pair writes per message at a configurable max (default 45 pairs ≈ 10 concepts), selecting highest-confidence pairs first.
