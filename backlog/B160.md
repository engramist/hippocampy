## Problem Statement

SideQuests builds its knowledge graph dynamically from scratch. The first N conversations suffer from cold-start problems:
- Entity resolution has no prior knowledge — common abbreviations ("k8s" = "Kubernetes", "PG" = "PostgreSQL") aren't recognized until the user says both forms
- The Gist classifier has general centroids but no domain-specific vocabulary
- The system must re-learn terminology that domain experts already know

For power users (developers, researchers, domain experts), this cold start is unnecessary friction. They already know their domain's canonical terms, abbreviations, and synonyms. A simple file dropped into the workspace should pre-seed the graph with this knowledge.

## What This Card Builds

1. **`domain_dictionary.yaml` format** — a simple file users can create:
   ```yaml
   # .sidequests/domain_dictionary.yaml
   version: 1
   entities:
     - term: "PostgreSQL"
       alt_labels: ["Postgres", "PG", "pg"]
       gist_class: "PhysicalThing"        # optional
       schema_org_type: "schema:Product"   # optional

     - term: "Kubernetes"
       alt_labels: ["k8s", "K8s", "kube"]

     - term: "Internal Family Systems"
       alt_labels: ["IFS", "parts work"]
       gist_class: "Category"
   ```

2. **Dictionary ingestion on Brain Daemon startup**:
   - Check for `.sidequests/domain_dictionary.yaml` (or `domain_dictionary.yaml` in workspace root)
   - For each entity: create a Concept node with high confidence (0.95), `confidence_low=false`, `source: "domain_dictionary"`
   - Create Label nodes: prefLabel for the canonical term, altLabel for each synonym
   - Embed all labels (prefLabel + altLabels) so they're searchable from turn 1
   - Skip entities that already exist (exact-match dedup on text_raw, case-insensitive)
   - Idempotent: re-running with the same dictionary doesn't create duplicates

3. **Dictionary reload via MCP tool** — `reload_domain_dictionary`:
   - Allows refreshing the dictionary without restarting the daemon
   - Adds new entities, adds new altLabels to existing entities
   - Does NOT delete entities removed from the dictionary (graph is additive)

4. **Validation**: On load, validate YAML structure and warn about:
   - Duplicate terms across entries
   - Unknown gist_class values (not in the 7 Gist classes)
   - Empty alt_labels lists (valid but useless)

## Outcome Statement

After this card, power users can drop a domain dictionary into their workspace and get instant entity resolution accuracy from turn 1. Common abbreviations, acronyms, and domain synonyms are pre-loaded. The agent recognizes "k8s" as "Kubernetes" on the very first mention, without needing to discover the synonym through conversation. Zero cold-start friction for users who know their domain.
