# B318 - Fail-Open: A Campy Outage Must Degrade Agents, Never Block Them

State: todo
Priority: P0

Plan: (inline — self-contained, sized for a Sonnet-level implementer)

Depends on: nothing. Can land immediately, in parallel with anything in B312–B317.

### Why

Campy is being positioned as a Layer-5 data product inside an external platform whose
architecture is explicitly designed so no single component is unrecoverable. The moment
Campy sits on a build path, one question decides whether it is adoptable:

> **If Campy is down, do the customer's agents keep working?**

The answer must be yes, always. An agent that cannot recall memory should proceed without
it — degraded, slower, dumber, but running. An agent that *fails* because a memory service
is unreachable makes Campy a new outage source for someone else's product, which is
disqualifying regardless of how good the memory is.

This is not currently guaranteed. It may be true in places by accident. Nobody has
verified it, and nothing tests it.

### Current State (verified in code)

`campy/brain_transport.py:call_brain()` (line 143) **raises** on failure:

- `RuntimeError("DAEMON_HTTP_ERROR: ...")` when an explicit HTTP endpoint is unreachable
- `RuntimeError("DAEMON_OFFLINE: socket transports failed (...); HTTP fallback failed ...")`
  when no socket candidate connects

Raising at the transport layer is correct — the transport should not silently invent an
answer. **The contract that is missing is at the callers.** Every one of these calls
`call_brain` and must be audited:

```
campy/cli/notify_turn_cmd.py
campy/brain/thalamus/ask.py
campy/adapters/mcp_server.py
campy/adapters/claude_desktop/adapter.py
adapters/claude_code/adapter.py
adapters/claude_code/hook_user_turn.py
adapters/claude_code/hooks/post_tool_use.sh
adapters/gemini_cli/adapter.py
adapters/codex/adapter.py
adapters/claude_desktop/adapter.py
adapters/chatgpt_desktop/adapter.py
```

plus the plugin hook surface: `plugin/hooks/session_start.sh`, `pre_tool_use.sh`,
`post_tool_use.sh`, `pre_tool_use_wrapper.py`, `post_tool_use_wrapper.py`.

**Second finding — latency, not just availability.** `call_brain`'s default is
`timeout: float = 10.0`. The Layer-2 hooks (`pre_tool_use.sh` / `post_tool_use.sh`) fire on
*every tool call* an agent makes. A hung or slow daemon therefore adds up to 10 seconds per
tool call before anything fails. A blocked agent and a 10-second-per-call agent are the same
outage from the customer's side. Availability failure is the loud case; latency failure is
the one that quietly ruins a product.

### What This Card Does

**Task 1 — Write the degradation contract down first.**

Add a section to `docs/ecosystem-rules.md`. This is a non-negotiable, in the same class as
"no shadow stores":

> **Fail-open.** No Campy call may block, fail, or error an agent's own work when the
> daemon is unavailable, slow, or returns an error. Read paths (recall, context injection,
> hooks) degrade to empty and let the caller proceed. Write paths (capture) drop the write
> and log — memory loss is acceptable, blocking the agent is not. The only surfaces allowed
> to hard-fail are explicit user-invoked CLI commands, where the user asked Campy a direct
> question and deserves a real error.

That last exemption matters — `campy ask` should say "daemon offline," not silently return
nothing. Degrading is for *implicit* calls the agent didn't ask for; explicit ones report
honestly.

**Task 2 — One helper, applied everywhere.**

Add to `campy/brain_transport.py`:

```python
async def call_brain_soft(
    method: str, params: dict, *, timeout: float, default: Any = None,
) -> Any:
    """Fail-open wrapper. Returns `default` on ANY failure — unreachable
    daemon, timeout, HTTP error, malformed response. Logs at DEBUG (not
    WARNING: an offline daemon is a normal state for a local install, and
    warn-level noise on every tool call trains users to ignore logs).
    Never raises."""
```

`timeout` is keyword-only and **required** — no default. Forcing each call site to state
its own budget is the point; a shared default is how the 10-second hook path happened.

Then convert every implicit-path caller in the audit list to `call_brain_soft`. Leave
explicit CLI commands (`campy ask`, `campy recall`, `campy doctor`) on `call_brain`.

**Task 3 — Timeout budgets by surface.**

Define as named constants in `campy/brain_transport.py` so they are reviewable in one place:

| Surface | Budget | Reasoning |
|---|---|---|
| `pre_tool_use` / `post_tool_use` hooks | **1.0s** | fires per tool call; anything more is a tax on every agent action |
| session start / context injection | 3.0s | once per session, some latency tolerable |
| capture / write paths | 2.0s | fire-and-forget; the agent is not waiting on the result |
| explicit CLI (`ask`, `recall`) | 30.0s | user asked, user waits, synthesis is slow |

Pick the shell-side equivalent for the `.sh` hooks — they cannot import Python constants,
so use `timeout 1` (coreutils) or the adapter's own flag, and add a comment pointing back to
this table so the two do not drift.

**Task 4 — Test it by actually taking the daemon away.**

The tests are the deliverable here. A fail-open claim nobody exercises is not a guarantee.
For each surface, simulate daemon-unavailable and assert the caller proceeds:

- no socket, no HTTP endpoint (the `DAEMON_OFFLINE` path)
- socket exists but connection refused
- daemon accepts the connection and never responds (the timeout path — the one most likely
  to be handled wrong, since it is the only case where the caller waits)
- daemon returns a JSON-RPC error object
- daemon returns malformed/truncated JSON

The hang case needs a stub server that accepts and stalls; do not fake it by patching the
client, because patching proves the mock returns a default, not that the timeout fires.

**Task 5 — Make the degraded state visible.**

Degrading silently forever is its own failure — a user whose memory has been offline for a
week should be able to find out. Record consecutive soft failures and surface them in
`campy doctor` and the activity feed (`~/.campy/activity.log`, see `campy/cli/indicator.py`).
Do not surface it in the agent's context — that would put an infrastructure complaint in
front of an end user who cannot act on it.

### Acceptance Criteria

- [ ] `call_brain_soft()` returns the default for every failure mode in Task 4 and never
      raises — one test per mode, including the stall/timeout case against a real stub
      server that accepts and does not respond
- [ ] `timeout` is keyword-only and required — omitting it is a `TypeError`
- [ ] Every implicit-path caller in the audit list uses `call_brain_soft`; assert by
      grepping for `call_brain(` in those files in a test, so it cannot regress
- [ ] Explicit CLI paths still raise a clear daemon-offline error (`campy ask` with no
      daemon reports the failure rather than printing an empty answer)
- [ ] Hook scripts exit 0 with the daemon down — run them in a test with no daemon and
      assert exit status and empty-but-valid output
- [ ] The per-tool-call hook path completes in under 1.5s wall-clock against a stalled
      daemon (budget 1.0s + overhead), measured, not assumed
- [ ] `campy doctor` reports consecutive soft-failure count
- [ ] `pytest tests/ -q` failure set identical to pre-change baseline

### What This Card Does NOT Do

- Does not add retry/backoff — a retry on the per-tool-call path multiplies the latency
  problem. Fire once, degrade, move on.
- Does not add a local write buffer to replay dropped captures later. That is a real
  follow-up (and interacts with B320's idempotency), but this card's contract is "dropping
  the write is acceptable," and adding a buffer without idempotent writes creates duplicates.
- Does not change the daemon's own availability, restart, or supervision behavior
- Does not surface degradation into agent context

### Outcome

A Campy outage becomes an agent that is temporarily dumber instead of an agent that is
broken, and the per-tool-call path stops being able to hold an agent for ten seconds. Both
are prerequisites for anyone putting Campy on a build path they are accountable for.
