# B403 - RDF-star Annotation Delete Cascade

State: complete
Priority: P0
Branch: claude/nostalgic-blackburn-6486c9

### Problem

B391 translated `provenance.py`'s 198 queries to SPARQL, including 29
`drop_projected_*` queries whose Cypher is `DETACH DELETE n`. The translation
removes the node's property triples and its plain incoming/outgoing edge
triples:

```sparql
DELETE { ?n ?p ?o . ?s ?p2 ?n . }
WHERE  { ?n a campy:Concept ; ... { ?n ?p ?o } UNION { ?s ?p2 ?n } }
```

That is not equivalent to `DETACH DELETE` for a `star` or `occurrence` edge. An
RDF-star annotation is a statement about a *reifier*, not about the node, so no
pattern over `?n` reaches it. B391 deferred this rather than forcing it.

Effect: orphaned annotation triples — and, for `occurrence` edges, one orphaned
occurrence node per edge write — accumulate silently. Not a wrong-answer risk
(reads anchor on the plain triple, which is gone) but an unbounded storage leak
once B397 cuts the engine over to Oxigraph.

### Cascade semantics (now normative — spec §4.2e)

| class | what a node delete must additionally remove |
|---|---|
| `plain` | nothing — the edge is one triple, already covered |
| `star` | the reifier's `rdf:reifies` quad and every annotation property on it |
| `occurrence` | the same per reifier, **plus each occurrence node's property triples** |

`occurrence` is the case that is easy to get half-right: the occurrence node is a
real URI hanging off the quoted triple, minted fresh per write and referenced only
from its one reifier. Deleting the reifier alone leaves it as unreachable garbage,
and an occurrence edge mints one per write — the larger half of the leak.

No class was ambiguous enough to escalate. `write_edge()`'s call sites settle all
three: `plain` rejects properties outright, `star` enforces one reifier per
(s,p,o) via `_remove_existing_reifiers()`, and `occurrence` mints a fresh
never-reused ULID per write, so no occurrence node is ever shared.

### Design: orphan sweep, not a per-query targeted delete

The sweep rests on the invariant spec §4.2a already states and `write_edge()`
enforces — *always assert the plain triple as well as the quoted annotation* —
which makes "the reified triple is not asserted" a sound and complete test for
orphanhood. One static statement is therefore correct for all 29 queries, with no
per-query node selector to duplicate or drift, and it also collects annotations
orphaned by delete paths the other translation batches have not reached yet.

Ordering is load-bearing: the cascade is appended, never prepended — "orphaned"
is only true once the node delete has run.

Measured on real `pyoxigraph 0.5.11`: ~22 ms over 20 000 annotations / 120 000
quads, flat whether it finds 0 orphans or 100.

### Known follow-ups (not this card)

- `OxigraphClient.execute()` rejects params on Update text, so
  `drop_projected_*`'s `$source` cannot be bound yet. Pre-existing; B397's
  executor owns it. The cascade statement itself takes no params.
- The 198 provenance SPARQL strings carry no `PREFIX` prologue; B397's executor
  must supply one. `ANNOTATION_CASCADE_SPARQL` uses absolute IRIs specifically so
  it does not depend on that.
- Importing `oxigraph_client` from `queries/provenance.py` adds ~36 ms
  (pyoxigraph's own import) to query-registry import. B397 puts it on the main
  path regardless.
