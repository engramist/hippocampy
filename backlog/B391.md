### Normative rules

`docs/rdf-schema-mapping.md` is the specification. Read §3, §4, and §7 before
starting. It is not advisory — a mapping invented here will corrupt data or silently
return wrong results.

The five rules that break queries most often:

1. **NULL vs absent (§3.4).** RDF has no NULL. `WHERE n.archived = false` becomes
   `OPTIONAL { ?n campy:archived ?archived } FILTER(!BOUND(?archived) || ?archived = false)`.
   A bare equality filter on a nullable column is a **defect**, not a style choice.
2. **Explicit datatypes (§3.2).** Bare Turtle `0.8` is `xsd:decimal`, not
   `xsd:double`. Every numeric literal and comparison carries an explicit tag.
3. **Edge class matters (§4.2).** Check `EDGE_REIFICATION` in `oxigraph_client.py`
   before writing any edge-property query. `star` edges annotate the quoted triple;
   `occurrence` edges hang occurrence nodes off it. Querying an `occurrence` edge as
   if it were `star` returns empty, not an error.
4. **Never interpolate parameters (§7.2).** `$param` binds via `VALUES`/`BIND`.
5. **Result shape is the contract (§7.6).** Same column names, same types as the
   Cypher original returned. `name`, `params`, and `mutating` do not change, and
   **no call site changes.** If you feel you need to edit a caller, stop and report —
   that means the translation is wrong.

### Vector and FTS queries

Any query in your batch using `QUERY_VECTOR_INDEX` or `QUERY_FTS_INDEX` gets **no
`sparql=` field** (spec §5). Mark it as a Python handler and list it in your report.
Do not invent a SPARQL form for ANN or full-text search — there isn't one.

### Batch-specific note

The largest single module. Provenance queries carry the `authority`/`source_version`/`superseded_by` fields, so spec §3.4 (NULL vs absent) applies to nearly every filter here — this batch is the highest-risk for the bare-equality defect.
