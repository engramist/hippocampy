# B495: Principles and drift controls for coding agents

**Status:** complete (2026-10-20)· **Found:** 2026-10-20

Lessons from a related knowledge-graph project: agents drift from a stated goal toward their own defaults (paperwork, rule-tweaking, prompt rewording) unless three things hold. Short principles sit in the one rules file every agent reads, every PR names its principle, lever, target and score effect, and tooling enforces it. None of the rules files said what the work is for, and the PR template never asked about score effect. The current goal is the benchmark score (LoCoMo-10 categories 1-4, LongMemEval overall, DMR accuracy); see `learnings/e2e-improvement-plan.md` (C.5 and Part F) and `learnings/2026-10-metric-switch.md`.

## Fix
- `AGENTS.md`: new `## Principles` section (seven principles) and `### Signs of drift`. `CLAUDE.md`, `GEMINI.md` and `.github/copilot-instructions.md` each carry one line pointing to it as binding.
- PR template: now the single canonical `.github/pull_request_template.md` (the tracked upper-case variant was renamed, not duplicated). New required sections Principle, Lever and target, Score effect; the checklist no longer names KuzuDB.
- CI: `.github/scripts/check_pr_score_effect.py` plus `.github/workflows/pr-score-effect.yml` fail a PR that touches retrieval, answering or config paths without a filled `## Score effect` section (`None — <reason>` is accepted).
- `scripts/drift_report.py`: local Markdown report of commit kinds, retrieval-path commits, recent gate mentions and open PRs lacking a score effect, with a one-line verdict.

## Done when
`tests/test_check_pr_score_effect.py` and `tests/test_drift_report.py` pass; the new check runs on its own PR.
