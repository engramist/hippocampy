## Problem Statement

Messages have timestamps and `SENT_IN` edges to Sessions, but there's no `FOLLOWED_BY` relationship between Messages. The brain can answer "what do I know about X?" but not "what was the sequence of decisions that led to Y?" or "show me the trajectory of archetype guesses for this puzzle."

Karpathy emphasizes temporal reasoning over experiences — understanding *when* things happened relative to each other, not just *what* happened.

## Root Causes

1. No `FOLLOWED_BY` edge between Messages within a session
2. No `DECISION_CHAIN` relationship between sequential Decisions
3. No `reconstruct_timeline` tool to walk temporal chains
4. `current_truth` retrieval is similarity-based, not time-ordered

## What This Card Does

1. **Add `FOLLOWED_BY` edge**: Between consecutive Messages within the same Session (written in `notify_turn`)
2. **Add `DECISION_CHAIN` edge**: Between Decisions established in consecutive Messages (written in Step 7 of consolidation loop)
3. **New `reconstruct_timeline` MCP tool**: Given a topic/entity, walks temporal chains to reconstruct "what happened in order"
4. **Expose in `current_truth`**: Add `temporal_mode` parameter that returns time-ordered results instead of similarity-ranked

## Graph Design (Graph Expert Analysis)

**New relationship types:**
```
FOLLOWED_BY (FROM Message TO Message, gap_seconds DOUBLE)
DECISION_CHAIN (FROM Decision TO Decision, session_id STRING, step_number INT32)
```

**Access pattern for `reconstruct_timeline`**:
```cypher
MATCH (start:Message)-[:ESTABLISHED]->(d:Decision)
WHERE d.text_raw CONTAINS $topic
WITH start
MATCH path = (start)-[:FOLLOWED_BY*1..20]->(subsequent:Message)
RETURN nodes(path) ORDER BY length(path)
```

**Bounded path**: Always bound `FOLLOWED_BY*1..N` — per graph expert rule #2. Default N=20 (covers a typical session).

**Supernode risk**: None. Each Message has exactly 1 FOLLOWED_BY successor and 1 predecessor within a session. Degree = 2 max.

**Write cost**: One additional edge per `notify_turn` call — negligible.
