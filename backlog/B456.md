# B456 - CAMPY_HOME: Fully Isolated Runtime Dir (Benchmarks Must Not Use the Personal Store)

State: fixed (2026-09-28)
Priority: P1

Every external benchmark run (B446 v1-v5) read and wrote the developer's
personal `~/.campy` store: benchmark turns landed in personal memory, earlier
runs' identical turns (fixed session ids and seeds) contaminated later runs
(B454 found "dozens of `ask` echoes" filling the window), and scores depended
on whatever else was in the store. B454's retrieval changes were tuned against
the same fixtures on that same store.

There was no way to point a daemon elsewhere: `campy/paths.py` only knew
`~/.campy` / `~/.sidequests`. (B385's acceptance criteria mark "`paths.py`
honors `CAMPY_HOME`" as done, but it was never in the code -- see the note
added to B385.)

## Change

`CAMPY_HOME`, when set, is the runtime dir, used as-is with no legacy
fallback:

- `campy/paths.py`: `home_override()`; `runtime_dir()` / `primary_runtime_dir()`
  honor it, so socket, `brain.db`, workspace shards, logs, offline queue,
  trigger manifest and backups follow.
- Three sites that bypassed `paths.py` now honor it too:
  `vector_store._default_db_path()` (without this an isolated daemon would
  share the personal vector/FTS index), the `activity_log` fallback, and
  `brain_daemon`'s `memory_debug.log`.
- `load_config()`: under `CAMPY_HOME` searches cwd, then only
  `$CAMPY_HOME/config.toml` -- never the personal config.

Default behaviour (no `CAMPY_HOME`) is unchanged.

## Transport caveat (not changed here)

`brain_transport.call_brain` falls back to HTTP after the socket fails, and
the default URL is the personal daemon on `127.0.0.1:7799`. A client of an
isolated daemon must pin `CAMPY_BRAIN_URL` as well as `CAMPY_SOCKET_PATH`, and
unset `BRAIN_URL` / `SIDEQUESTS_*` / `CAMPY_BRAIN_SOCKET`, which outrank them.
campy-benchmarks' `--isolated` mode does all of this.

(Also noticed: the explicit-HTTP-first branch checks `SIDEQUESTS_BRAIN_URL` /
`BRAIN_URL` but not `CAMPY_BRAIN_URL`, which `brain_url()` does read -- an
inconsistency, left as is.)

## Verification

- `tests/test_campy_home_isolation.py`: every runtime path follows
  `CAMPY_HOME`; the legacy fallback is skipped; config never falls back to
  the personal one; default behaviour unchanged. 5 of its 6 tests fail
  without the change.
- The real daemon started with `CAMPY_HOME` and a fake `HOME` created
  `brain.db`, `vectors.db` and `daemon.log` under `CAMPY_HOME` and nothing
  under `HOME/.campy` (it then stopped at the embedding-model download, which
  the sandbox's network blocked).
- campy-benchmarks `run_all.py --isolated` end to end against a stub
  daemon/adapter: outranking env stripped, calls reached only the isolated
  store, temp dir removed after the run and after a startup crash.
