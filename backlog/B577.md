# B577 - current_truth soft-fails with "Invalid control character" JSON errors

State: open
Priority: P2
Found: 2026-11-18, in passing (review session), while checking the personal daemon after the B575 restart.

## What

`~/.campy/activity.log` holds 169 `soft_failure` events for `current_truth` with the same error:

```
JSONDecodeError: Invalid control character at: line 1 column 37 (char 36)
```

Each event reports 5 consecutive failures, and the lane is marked `degraded`. The first one is dated 2026-09-15 and the latest 2026-11-18, so this predates B575 and is unrelated to the flag flip. Column 37 is the same every time, which points to one fixed-position field in one producer's output, such as a raw newline or tab in a string that is parsed with `json.loads` at its default `strict=True`.

## Why it matters

`current_truth` is the recall tool for raw facts. A degraded lane means agents silently get no recall. That may be why the 2026-11-16 personal-store recall check returned unrelated older messages.

## To do

1. Find the producer: log the raw payload at the decode site in the `current_truth` path (MCP adapter, then daemon handler) for the next failure. Redact the payload, and keep the char offsets only.
2. Fix it at the source (escape on write) rather than with `strict=False` at the reader, unless the payload is third-party text.
3. Add a test with a control character in a stored value that `current_truth` returns.

## Done when

No new `current_truth` soft failure for this error over a day of normal use, and the test passes.

## Note (2026-11-20, B580)

B580 shares only the adapter path with this card: before B580 every soft failure, a daemon-replied error included,
was reported to MCP clients as `DAEMON_OFFLINE`. After B580 a daemon-replied error is reported as an error and is
never queued offline, and a poisoned offline-queue entry is dropped after one daemon-replied error. The personal store
had no offline queue file, so this card's repeating "5 consecutive failures" do not come from queue replays; the
JSON-decode cause stays open here.
