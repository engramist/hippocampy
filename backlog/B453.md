# B453 - Daemon Cold Start Takes 4-7 Minutes (Store Open + Gist-Centroid Recompute Every Start)

State: fixed (2026-09-27 — resolved as a side effect of B451, see completion notes)
Priority: P2

Observed 2026-09-23: opening the 7.7 GB RocksDB store took ~150s; and every
start logs "Bootstrapping gist class centroids from seed examples" and
recomputes 7 classes x ~45 seed embeddings (~35 s/class, ~3 min total) even
though the seeds do not change. During any restart the MCP adapter answers
"offline" — which, before B450, silently corrupted benchmark runs. Suggested:
persist/cache centroids keyed by (seed-set hash, embedding model) and only
recompute on change; investigate store-open time after B451's cleanup and
compaction shrinks the store (much of the 7.7 GB is orphan reifier garbage).


## Completion notes (2026-09-27)

Measured directly before writing any code: two clean restarts of the live
daemon (store now 341 MB, down from the 7.7 GB this card was filed against)
took **5.5s and ~3.8s** start-to-idle, log-timestamped store-open + centroid
bootstrap included. The original 4-7 minute observation was a symptom of
[B451](B451.md)'s reifier explosion, not an independent problem: with 26.9M
quads (13M of them duplicate reifiers) the RocksDB WAL replay dominated
startup, and the same CPU/IO contention plausibly explains why gist-centroid
bootstrap (a fixed, tiny ~320-example embedding job) was measured at
~35s/class back then vs. the **~0.3-0.4s/class** measured now -- both numbers
moved together, pointing at one shared cause rather than two separate slow
paths.

No code change: caching/persisting the gist centroids (this card's original
suggestion) isn't worth the complexity for a ~3s cost that already exists
only once per restart. Re-open if cold start regresses again as the store
grows with real use -- but re-measure first rather than assuming it's this
same bug, since B451's fix (routing star-edge writes through `write_edge`
instead of a runaway SPARQL upsert) already prevents the specific mechanism
that caused the store to reach 7.7 GB in the first place.
