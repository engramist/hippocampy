### Problem (observed 2026-07-13, real graph)

`current_truth` results and `quest_context` for the main hippocampy quest contained:

- a **Constraint** node whose entire text is `"four"` — confidence 0.92, confidence_low=false
- a Concept `"four"` at 0.92, Concepts `"windows"` and `"maoc"` at 0.60 (sitting in
  `open_loops`), Concept `"Task 2"` at 0.72

These crowd out real results in the flagship recall tool and make `quest_context` (which
every `current_truth` call returns) look broken. Fragments this small carry no meaning on
their own — "four" WHAT? — so they fail the architecture's own bar: the Step 4 confidence
gate "IS the selective attention filter" (`docs/ARCHITECTURE.md`, Step 4). The filter has
holes; this card closes the specific observed ones.

**Scope guard:** this is NOT a data-exclusion card. The graph-native rule (tag and filter
at query time, don't drop at capture) applies to *meaningful* data. Terminal fragments and
bare number-words are noise the selective-attention gate was always designed to suppress —
the fix is tightening existing designed gates, not adding a new exclusion layer. When in
doubt, prefer capping `confidence` / setting `confidence_low=True` (node still exists,
decays fast, filterable) over hard rejection.

### Root Causes (verified in code)

1. `campy/brain/temporal_lobe/loop/step1_ner.py` `_is_junk_entity()` rejects numeric
   strings via `float(stripped)` (so `"0.92"` dies) — but **cardinal number words pass**:
   `"four"`, `"three"`, `"twenty"` are alphabetic. `_ORDINAL_RE` only catches ordinals
   ("first", "2nd").
2. Single-token entities can reach Step 4 and **reify at full confidence**:
   `campy/brain/temporal_lobe/loop/step4_pattern.py` `classify_artifact()` — one keyword
   hit ≈ 0.82, `+0.10` gist-agreement boost → 0.92 ≥ `HARD_LOCK` (0.90) → a REIFIED
   artifact (the `"four"` Constraint). A single token can never justify a confirmed
   Decision/Constraint/Requirement — there is no actionable content in one word.
3. Generic single common words (`"windows"`, `"maoc"`-style fragments) become
   confidence_low Concepts that then linger in `open_loops`. They're allowed to exist —
   but nothing prevents them surfacing prominently.

### What This Card Does

**Task 1 — number words are junk (step1).**
In `_is_junk_entity()`, alongside the existing `float()` check, reject bare cardinal
number words and simple compounds. Implementation: a small set is enough — units
(`one`…`nine`), teens (`ten`…`nineteen`), tens (`twenty`…`ninety`), `hundred`,
`thousand`, `million`, `billion` — plus hyphenated/spaced combinations of those tokens
only (e.g. `twenty-four`, `two hundred`). Mirror the placement and comment style of the
existing ordinal check. Do NOT reject numbers embedded in larger phrases ("four retries
max" must survive as an entity if NER yields it).

**Task 2 — single tokens never reify (step4).**
In `classify_artifact()`: if the candidate text is a single token (no whitespace after
`.strip()`), cap `confidence` at `0.60` and force `confidence_low=True` **before** the
HARD_LOCK comparison, regardless of keyword/gist boosts. Add a short comment naming the
invariant: *single-token entities may exist as tentative Concepts but can never become
confirmed artifacts.* Follow the existing ISSUE-024 `ASSISTANT_CAP` pattern in the same
function — this is the same kind of cap, placed the same way.

**Task 3 — quest_context stops surfacing sub-signal fragments.**
`get_quest_context()` (in `campy/brain/hippocampus/quest.py`) feeds
`recent_constraints` and `open_loops` in every `current_truth` response. Add a minimal
signal floor to its queries/post-filter: exclude nodes whose `text_raw`, after strip, is
a single token shorter than 6 characters. (Query-time filtering — the nodes stay in the
graph; this is presentation hygiene, consistent with the scope guard above.)

**Task 4 — regression tests from the real observed junk.**
New test file `tests/test_junk_concept_gate.py`:
- `_is_junk_entity("four")` / `("twenty-four")` / `("Twenty")` → True;
  `_is_junk_entity("four retries max")` → False
- `classify_artifact("four", gist_class="Restriction", ...)` (mirror an existing
  classify test's calling convention from `tests/test_loop.py`) → `confidence <= 0.60`
  and `confidence_low is True`, even when keyword/gist boosts would otherwise fire
- `classify_artifact` on a real multi-word constraint sentence still reaches ≥ 0.90
  (no regression on legitimate reification — copy an existing passing case)
- `get_quest_context` fake-db test: a Constraint row `"four"` and one
  `"Use Apache-2.0 for all new files"` → only the latter appears

### What This Card Does NOT Do

- No changes to `NOISE_FLOOR`, embeddings, or the gist classifier.
- No new config options.
