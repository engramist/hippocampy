# B440 - SessionEnd Hook Automation for generate_handoff (B383 v2)

State: ready
Priority: P2
Branch: feat/b440-sessionend-hook-handoff
PR Target: main

### Note on origin

Deferred out of B383 (Automated Model Handoff Generator, merged via
[PR #237](https://github.com/engramist/hippocampy/pull/237)). B383's
own card described "Automated Hook Handoff: Claude Code / Codex
session-end and session-start hooks automatically sync the handoff
bundle through Unix domain socket IPC" as scope item 3. B383 shipped
v1 (the `generate_handoff` MCP tool + `campy handoff` CLI) and
deliberately deferred this item — see `backlog/B383.md`'s completion
notes for the full reasoning.

### Problem

Right now, getting a handoff artifact requires the developer to
remember to run `campy handoff` (or call `generate_handoff`) themselves
before switching models. The B383 card's original vision was for this
to happen automatically at session end, with zero manual action
required — matching the "zero-amnesia" framing of the parent feature.

### What's actually there today (verified 2026-09-21)

- `plugin/hooks/hooks.json` registers exactly three hook events:
  `SessionStart`, `PreToolUse`, `PostToolUse`. **No `SessionEnd` entry
  exists.**
- None of the three existing hook wrappers
  (`session_start_wrapper.py`, `pre_tool_use_wrapper.py`,
  `post_tool_use_wrapper.py`) touch `WorkSummary`/handoff data, or call
  the Unix socket transport (`campy/brain_transport.py`). They use a
  `campy` CLI subprocess (`session_start_wrapper.py`) or local file +
  regex matching against `~/.campy/triggers/manifest.json` (the two
  tool-use wrappers) — no daemon graph query at all in the latter two.
- **Open question, not yet resolved:** whether the Claude Code plugin
  host framework actually supports a `SessionEnd` hook event at all.
  A repo-wide grep found no reference to `SessionEnd` anywhere outside
  this card's own notes — meaning this hasn't been confirmed against
  the actual host framework's supported event list. This needs to be
  checked (Claude Code plugin/hook documentation, or empirically by
  registering a `SessionEnd` entry in a test plugin and observing
  whether it fires) before designing the rest of this card in detail.

### Scope

1. Confirm `SessionEnd` (or whatever the actual supported event name
   is — may differ from `SessionStart`'s naming convention) is a real,
   supported hook event in the Claude Code plugin framework.
2. If supported: add a `session_end_wrapper.py` (mirroring
   `session_start_wrapper.py`'s structure) that calls `campy handoff`
   (or `generate_handoff` directly over the Unix socket transport,
   consistent with how the daemon is otherwise reached) and writes the
   result somewhere durable — needs a design decision: a file next to
   `CONTEXT.md` (matching B290's `## Current Work` convention), a
   dedicated `HANDOFF.md`, or delivered via the socket to a waiting
   client. Not prescribed here.
3. Register the new event in `plugin/hooks/hooks.json` and (per the
   existing convention) the Gemini-equivalent `plugin/hooks/gemini-hooks.json`
   if that file also needs a matching entry.
4. Decide graceful degradation: what happens if the daemon isn't
   running, or the session has no active quest — must not block or
   error out the actual session-end/exit flow (matching every existing
   hook wrapper's fail-open convention).

### Acceptance Criteria

- [ ] Confirmed whether `SessionEnd` (or equivalent) is genuinely
      supported by the host hook framework, documented either way.
- [ ] If supported: a session ending automatically produces an
      up-to-date handoff artifact without any manual `campy handoff`
      call, verified end-to-end against a real Claude Code session.
- [ ] Fails open — a daemon-down or cold-start session must not block
      or error the actual session exit.
- [ ] Work executed in branch `feat/b440-sessionend-hook-handoff` and
      PR created targeting `main`.

### Outcome

Zero-amnesia handoff genuinely requires zero manual action, matching
B383's original framing, once (and only if) the underlying hook
framework supports it.
