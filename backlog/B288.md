### Problem

Three tool-surface tests fail on a clean `main` (verified — they fail identically with no uncommitted changes). They are pre-existing debt from B250 (`ingest_data`) and B252 (`compile_context`) landing in the canonical tool registry without propagating to every adapter surface, compounded by B278 adding 15 ARC tools to a test with a hardcoded expectation.

Per `backlog/BacklogRules.md`, every card that adds/changes a tool must propagate it to adapter allow-lists and `docs/tool-catalog.md`. That step was missed for `ingest_data` and `compile_context`.

The three failures:

1. **`tests/test_openclaw_tool_surfacing.py::test_openclaw_extension_registers_all_tools`**
   `canonical_names - registered == {"compile_context", "ingest_data"}` — those two canonical tools have no definition in `extensions/hippocampy/src/index.ts`.

2. **`tests/test_openclaw_tool_aliases.py::test_all_mcp_tools_registered`**
   `set(TOOL_HANDLERS) - call_map == {"compile_context", "ingest_data"}` — same root cause (the OpenClaw `toolDefinitions` array is missing both).

3. **`tests/test_analogical.py::test_codex_adapter_has_all_tools`**
   The Codex adapter's `TOOLS` is **dynamically** sourced from `campy.brain.thalamus.tool_schemas.TOOLS` (so it already has all 51 tools). The failure is the test's **hardcoded `expected` set** (34 names) being stale — it lacks the 15 ARC tools, `compile_context`, and `ingest_data`. The adapter is correct; the test is wrong.

### What This Card Does

1. Adds `compile_context` and `ingest_data` tool definitions to the OpenClaw extension (`extensions/hippocampy/src/index.ts`) so all 51 canonical tools surface there.
2. Replaces the brittle hardcoded `expected` set in `test_codex_adapter_has_all_tools` with a registry-derived assertion, so it can never go stale again when a tool is added.
3. Updates `docs/tool-catalog.md` to include all currently-canonical tools (verify `compile_context`, `ingest_data`, and the 15 ARC tools are listed).
