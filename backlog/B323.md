### Origin, and a warning about the source prompt

This card is the salvageable core of an externally-drafted "Star Map" spec. **That draft was
audited against the tree and most of it was wrong.** The mistakes are recorded here because
anyone re-reading the original will otherwise repeat them:

- It referenced `mcp_engine/graph/` and `mcp_engine/tools/`. **No such directory exists** —
  that name survives only in stale module docstrings. Real paths are
  `campy/brain/hippocampus/graph/` and `campy/brain/thalamus/tools/`.
- It asked to `CREATE` eight tables. **Six already exist**: `Workspace`, `ANCHORED_TO`,
  `BLOCKS`, `ENABLES`, `DEPRECATED_BY`, `LOADED`.
- **`BLOCKS` and `ENABLES` exist for entirely different domains.** `BLOCKS` is
  `FROM GridEntity TO GridEntity (action_id STRING, step INT32)` — ARC puzzle-grid mechanics.
  `ENABLES` is `FROM Concept TO Concept (confidence DOUBLE, inferred_by STRING,
  inferred_at TIMESTAMP)` — concept inference.

That last point is a **data-loss hazard**, not a naming annoyance. Kùzu 0.11.3 has no
`ALTER REL TABLE`; adding FROM/TO pairs requires drop-and-recreate, and `schema.py`'s own
`_REL_MIGRATIONS` comment states that is only safe when no existing edges use the old types.
ARC runs have `BLOCKS` edges. Following the original spec destroys them.

**Therefore: new names, `TASK_BLOCKS` and `TASK_ENABLES`.** Never touch the existing two.

### Why the remaining core is worth building

Three things survive the audit and are genuinely valuable:

1. **Declared task dependency** — which work blocks or enables which other work.
2. **Agent-as-node provenance** — traversing *from* an agent to everything it did.
3. **A context bundle keyed on a card or branch** rather than on a free-text query.

(1) pairs with B322. B322 *learns* coupling from observed co-change; this *declares* it.
Learned is automatic but noisy; declared is precise but needs someone to state it. Both feed
`conflict_forecast`, and together they are materially better than either alone.

### What This Card Does

**Task 0 — Audit before writing any DDL.**

Read `NODE_TABLES` and `REL_TABLES` (`campy/brain/hippocampus/schema.py`, `REL_TABLES` begins
line 842) and confirm current definitions for `Workspace`, `ANCHORED_TO`, `DEPRECATED_BY`,
`LOADED`, `PRODUCED_LESSON`. **Do not issue `CREATE` for anything that exists.** State in the

**Task 1 — `TASK_BLOCKS` / `TASK_ENABLES`.**

New rel tables, multi-pair (Kùzu supports several `FROM ... TO ...` in one table; the existing
`DEPRECATED_BY` does exactly this):

```
TASK_BLOCKS:  FROM MainQuest TO MainQuest, FROM SideQuest TO SideQuest,
              FROM ActionItem TO ActionItem
TASK_ENABLES: same pairs
```

Edge properties, matching codebase conventions — note the original spec got both types wrong
(`INT64` for a timestamp, `FLOAT` for a confidence):

```
declared_by   STRING       -- principal or agent that asserted the dependency
confidence    DOUBLE       -- NOT FLOAT; the codebase uses DOUBLE throughout
observed_at   TIMESTAMP    -- NOT INT64 unix; the codebase uses TIMESTAMP throughout
source        STRING       -- B312 provenance
source_version STRING
authority     STRING       -- "earned" when an agent declares it (B313)
```

**Cycle safety.** `TASK_BLOCKS` must be acyclic to be meaningful — A blocks B blocks A is
unsatisfiable. Reject an edge that would close a cycle, checked with a bounded traversal
(`*..10`) from the target back to the source before insert. Raise a clear error naming the
cycle path. Do not attempt full transitive-closure maintenance.

**Task 2 — Extend, do not recreate.**

- `Workspace` currently has `(workspace_id, path, os, hostname)`. The draft wanted
  `branch_name` and `active`. Add both via `_MIGRATIONS` (`schema.py:1116`) — **never** by
  redefining the table.
- `ANCHORED_TO` is currently `FROM MainQuest TO Workspace`. Adding `ActionItem -> Workspace`
  needs the `_REL_MIGRATIONS` drop+recreate path. **Check for existing edges first**; if any
  exist, either preserve them across the recreate or defer this and say so in the PR.
- `LOADED` already covers more `Session -> *` pairs than the draft asked for. Leave it alone.

**Task 3 — Agent provenance: reconcile, do not duplicate.**

There are already two ways to record which agent did something: B312's `source`
(`"agent:claude-code"` form) and the existing `agent_source` column on `WorkArtifact` and
`WorkSummary`. The draft proposed a third (`AgentWorker` node + `SOLVED_BY` edge).

**Three mechanisms is worse than one.** Add the node type only for what a string column
cannot do — traversing *from* an agent ("what else did this worker touch, and what came of
it?"). So:

- `AgentWorker (worker_id STRING PRIMARY KEY, model_name STRING, provider STRING,
  first_seen_at TIMESTAMP, last_seen_at TIMESTAMP)`
- `SOLVED_BY: FROM Decision TO AgentWorker, FROM ActionItem TO AgentWorker,
  FROM Lesson TO AgentWorker` with `confidence DOUBLE, observed_at TIMESTAMP`
- **`worker_id` must be the same string B312 writes into `source`.** One identity, two
  access paths — the column for filtering, the node for traversal. Assert this in a test.
- Do not populate `SOLVED_BY` from a separate capture path; derive it in the same write that
  sets B312 provenance.

**Task 4 — `DEPRECATED_BY` is a correction to B312.**

`DEPRECATED_BY` **already exists** (`Concept`, `Decision`, `Constraint`, `Lesson` self-pairs).
B312 as written introduces a parallel `SUPERSEDES` table plus `superseded_by` columns.

**That is drift, and this card is where it gets caught.** Pick one before implementing either:

- *Preferred:* B312 **extends `DEPRECATED_BY`** (add the missing pairs, add its edge
  properties) instead of creating `SUPERSEDES`. B312's node columns
  (`superseded_by`/`superseded_at`/`supersession_reason`) still make sense as the fast filter.
- *Alternative:* keep both only if they mean genuinely different things, and document the
  distinction where both are defined.

Whichever you choose, **update B312's card text in the same PR** so the two cards do not
disagree on disk. If B312 has already landed, file the reconciliation as a follow-up and say
so — do not silently add a third mechanism.

**Task 5 — Card/branch context bundle.**

New tool: `compile_card_context(params, db, config)` in `campy/brain/thalamus/tools/`, and
registered in `TOOL_HANDLERS` (`campy/brain/thalamus/tools/__init__.py`).

```python
# params: {"target_id": "B317" | "feature/foo", "max_hops": 3}
```

Behavior:

- Resolve `target_id` against a card identifier (`MainQuest`/`SideQuest`/`ActionItem`) **or** a
  `Workspace.branch_name`. Ambiguity resolves to the card; report which interpretation was used
  in the output so a caller is never guessing.
- Traverse `ANCHORED_TO`, `TASK_BLOCKS`, `TASK_ENABLES` — **bounded**, default 3 hops, hard cap
  5. No unbounded `*`.
- Pull `PRODUCED_LESSON` and `DEPRECATED_BY` edges on everything reached, so the caller sees
  prior failures and superseded decisions rather than repeating them.
- Include `SOLVED_BY` attribution on each item.
- Return **structured data plus** a rendered Markdown string. The draft asked only for Markdown;
  a string-only tool cannot be tested on anything but substring presence and cannot be consumed
  programmatically. Render from the structure, and test the structure.
- Fail-open per B318: a traversal failure returns the target's own context with the dependency
  sections omitted, never an error.

Reuse `bundle_compiler.py` conventions rather than inventing a second formatter.

### What This Card Does NOT Do

- Does not modify or extend the existing `BLOCKS` / `ENABLES` tables
- Does not add external issue-tracker sync (Jira/Linear). The draft's framing implied it;
  that is a harvester producing `projected` facts (B313) and belongs in its own card.
- Does not infer dependencies automatically — declared only. Learned coupling is B322.
- Does not implement transitive-closure materialization
- Does not add a third agent-identity mechanism — see Task 3

### Outcome

Declared task dependencies become queryable and cycle-safe, agent attribution gains a
traversable node without becoming a third competing identity scheme, and an agent picking up a
card or branch can pull one bounded bundle containing its blockers, enablers, prior lessons and
superseded decisions.
