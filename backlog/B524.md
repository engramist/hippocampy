# B524: Count and list questions answered by a subject-anchored graph query

**Status:** Open — gate pending (R102 vs R100 on conv-42,conv-43,conv-47)

Lever 2 of the object-linking work, on top of B522 (HAS_SUBJECT / HAS_OBJECT) and B523 (rule-written `owns`
Observations). The earlier attempt (B505, closed) picked a kind from the question and counted every
`INSTANCE_OF` member in Python, with no subject and no relation: "How many pets will Andrew have?" got 11.
The edges the answer needs now exist, so it is a query.

1. **Queries** (`graph/queries/observations.py`): `observations.count_objects_of_subject` returns
   `COUNT(DISTINCT ?x)`; `observations.objects_of_subject_kind` returns the same objects, one row each, with
   the earliest live evidence (observation id, quote, message id, date). Both share one SPARQL pattern:
   `?o HAS_SUBJECT ?s ; predicate ?p ; HAS_OBJECT ?x ; EVIDENCED_BY ?m`, `?x (INSTANCE_OF|IS_A)/BROADER* ?kind`,
   live = not archived and not `DEPRECATED_BY`, optional exclusive upper bound on the evidence message's
   `occurred_at`. Two named queries, not one: the parameter binder injects its `VALUES` at the outermost
   `WHERE`, so a count sub-select cannot see `sid`/`kind_id`/`before`.
2. **Routing** (`campy/brain/thalamus/graph_count.py`): wording only routes. A documented set of count/list
   forms; the subject is the one non-kind Concept the question names (the closed-set lookup the bundle
   compiler uses; zero or several decline); the kind is the one kind Concept whose label or altLabel the
   question names (plural folded by `norm_key`); the relation is a verb mapped to the closed predicate set
   (have/own/adopt/get/keep -> `owns`, anything else unmapped). An "as of <date>" / "by <date>" is parsed by
   `timeparse.normalize_time` (a phrase that does not parse declines). Missing anything: no section.
3. **Section** (`bundle_compiler`, after exact facts): `graph_count`, behind `[retrieval] graph_count` (env
   `CAMPY_GRAPH_COUNT`, default off): "[graph count] Andrew owns 2 of kind pet (...): Toby (date, message id,
   quote), ...". Python formats rows; it never counts, dedupes or filters.

Measured on a copy of the B523 backfilled store (conv-30 + conv-44), nothing tuned: see the PR. Two capture
gaps found, left for their own cards: a possessed proper noun with no head noun in its sentence ("lucky to
have Scout") gets no kind, and the store has no `dog` kind (only `my dogs`, `puppies`).

Serves Principles 2 (answered by a query anchored on the subject), 8 (subject -> relation -> object), 3 (every
item cites its turn) and 7 (flag, off by default). Gate pending.
