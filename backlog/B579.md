# B579 - The personal daemon ignores ~/.campy/config.toml (the repo's campy.toml wins)

State: open
Priority: P2
Found: 2026-11-19, in passing (review session), while turning on the B578 turn reranker for the personal daemon.

## What

The launchd agent `ai.hippocampy.brain` runs `brain_daemon.py` with `WorkingDirectory` set to the repo. `load_config()` searches `./campy.toml` before `~/.campy/config.toml`, so the daemon reads the repo's tracked `campy.toml` and never sees the user's own config. Its `EnvironmentVariables` holds only `PATH`, so an env override given to `campy start` (for example `CAMPY_TURN_RERANK_PATH`) doesn't reach the daemon either.

Seen: with `[retrieval] turn_rerank_path` set in `~/.campy/config.toml` and the daemon restarted, every bundle still logs "turn_rerank is on but [retrieval] turn_rerank_path is not set". The same happens with the env var passed to `campy start`. The config change was reverted from its backup.

## Why it matters

- No user setting in `~/.campy/config.toml` takes effect on the personal daemon. That includes the model path that B578's default (`turn_rerank = true`, window mode) needs, so the shipped reranker is inert on the personal daemon.
- Machine-specific values can only be set by editing a tracked repo file, which is the wrong place for them.

## To do

1. Decide the precedence. Suggested: `~/.campy/config.toml` (or `$CAMPY_HOME/config.toml`) is the user's file; a cwd `campy.toml` applies only when it is explicitly requested, or is merged under the user's file.
2. Let the launchd plist carry `CAMPY_*` overrides, or have the daemon read the user's file whatever its working directory is.
3. Make `campy status` show the config path in use.
4. Test: with a cwd `campy.toml` and a user file both present, the daemon's effective `retrieval.turn_rerank_path` comes from the user file.

## Done when

The personal daemon picks up `[retrieval] turn_rerank_path` from `~/.campy/config.toml` after a restart, with no "path is not set" warning, and the test passes.
