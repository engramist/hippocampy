# B467 - Benchmark Data Leaked Into the Personal Store

State: fixed in the sandbox (2026-10-05); personal-store run pending (the user's decision)
Priority: P2

### Problem Statement

The user's personal store (`~/.campy`) holds campy-benchmarks fixture
conversations as if they were real project memory. Found while running B465's
dry run on a copy of it (2026-10-05): all 50 inverted CHOSEN_OVER edges the
repair would flip ("Zipkin CHOSEN_OVER OpenTelemetry OTel", "HS256
CHOSEN_OVER RS256", "PostgreSQL 14 CHOSEN_OVER PostgreSQL 16", ...) come from
LoCoMo messages, and most of the 133 unverifiable ones are LoCoMo noise too
("Updated storage_tier CHOSEN_OVER S3 Glacier", "Vim CHOSEN_OVER Jordan").
`ask`, `current_truth` and the bundle stages read these as the user's own
decisions: a question about the user's real tracing or auth setup can be
answered from a fixture.

Counted on a copy (Messages by `SENT_IN` session name):

| session prefix | sessions | messages | source |
|---|---|---|---|
| `locomo_*` | 99 | 1,344 | LoCoMo fixture |
| `msc_*` | 26 | 276 | MemBench (MSC) fixture -- verify |
| `memgym_*` | 21 | 273 | MemoryGym fixture |
| `arc_*` | 13 | 334 | **ambiguous**: ARC suite or the user's real ARC_AGI work |

Messages are repeated per run (the same LoCoMo statement appears 3+ times
with different `created_at`: 2026-09-22, -24, ...).

### Root cause

`run_all.py` (campy-benchmarks) without `--isolated` talks to the live daemon
on `~/.campy`. It prints a warning ("[!] Not isolated: this run reads and
writes the personal ~/.campy store") but runs anyway. Earlier runs used that
mode. Consolidation then derived Concepts and CHOSEN_OVER edges from the
fixture messages, so the leak is not just Messages: Concepts, edges, Lessons
and vectors (`vectors.db`) carry it too.

Two more findings while building it (2026-10-05):

- **Concepts have no provenance.** A Concept's only non-literal links are to
  other Concepts, to Decisions (REIFIED_AS) and from Sessions (WARM_NODE:
  recent activation, not origin) -- in a sandbox LoCoMo store and in the
  user's store alike. "Derived only from benchmark Messages" cannot be read
  off the graph for Concepts; it can for Messages (`SENT_IN`), what they
  ESTABLISHED (Decisions, Constraints) and Lessons (`CONTAINS_LESSON`).
- **Archived Concepts still reached bundles through graph traversal.** The
  bundle's 1- and 2-hop expansion (`thalamus.bundle_graph_one_hop` /
  `two_hop`, both variants) filtered flagged neighbours but not archived
  ones, so archiving "PostgreSQL 16" would still show "Kuzu REQUIRES
  PostgreSQL 16" in any bundle anchored on Kuzu. That was true of everything
  the sweep archives, not only this card's.

The user chose (2026-10-05) to archive, with whole-word mention standing in
for the missing Concept provenance (option "a"). The local agent measured it
on a copy of `~/.campy`: 262 of 405 Concepts named only by benchmark messages,
none of a 20-name sample a false positive; 49 of B465's 50 inverted edges
lose an endpoint.

### What It Does (Scope) -- as built

`campy graph purge-sessions --prefix P [--prefix P ...] [--db-path] [--apply] [--sample N]`
(`campy/cli/graph_repair.py`, named queries `cli.purge_*`):

1. Sessions whose `session_id` starts with a given prefix (no default; an
   empty prefix is refused). The user's store: `locomo_`, `msc_`, `memgym_`,
   `arc_game_`, `arc_occlusion_test` -- never a bare `arc` (`arc-arc_eval_*`
   is a retired real ARC agent's telemetry, `arc_agi` real notes).
2. Their Messages, plus session-less Messages that repeat one of them word
   for word (case and spacing aside): the user's store has 11 leaked
   Messages with no `SENT_IN`.
3. Decisions / Constraints (ESTABLISHED) and Lessons (CONTAINS_LESSON) whose
   every producing Message is purged; one also produced by a real Message
   stays.
4. Concepts a purged Message names (whole words, case-insensitive) and no
   remaining Message names. Concepts no Message names at all (documents,
   ingest) are not touched.
5. Everything is **archived**, not deleted: retrieval already skips archived
   Messages, Concepts, Decisions and Lessons, their `vectors.db` rows stay
   consistent with the graph (the bundle stages drop vector hits on
   archived nodes when they hydrate them), and an archive is reversible. Edges stay; the report counts
   Concept-Concept edges with both / one end archived.
6. Graph traversal (all four bundle traversal queries) now skips archived
   Concepts, in their SPARQL (`FILTER NOT EXISTS { ?b campy:archived true }`,
   safe when the property is absent). Their legacy Kuzu Cypher is
   unchanged: Kuzu test schemas have no `archived` column on Concept and the
   bundle compiler does not select variants for it.

Dry run by default; `--apply` needs the daemon stopped (same lock rule as
B465). A second run finds nothing.

Not changed:

- Sessions themselves and the MainQuests benchmark sessions were routed to
  are not archived.
- Edges between two kept Concepts that were only ever derived from benchmark
  text stay (the local agent counted 15 such CHOSEN_OVER edges in the user's
  store, mostly nonsense like "What -> monitoring"). Removing them needs
  Concept/edge -> Message provenance: follow-up card.
- Concepts are still matched by name: a fixture term the user's real
  sessions also discuss (e.g. "MysteryPath navigation sequence", mentioned in
  real sessions about MemoryGym) is kept.

### What It Does (Scope) -- as filed


1. **Stop new leaks** (campy-benchmarks): a non-isolated run against a real
   daemon must be an explicit opt-in (`--shared-store` or similar), not a
   warning. Decide whether a non-isolated mode is needed at all.
2. **Find what leaked** (hippocampy): a dry-run report of everything that
   originates only from benchmark sessions -- Messages `SENT_IN` the
   benchmark sessions, and derived nodes/edges whose only provenance is
   those Messages (a Concept also mentioned in a real session stays). Use the
   graph's own provenance (`SENT_IN`, `DERIVED_FROM`/mention edges); do not
   match on text.
3. **Remove or archive it** behind `--apply`, after a backup, with the
   daemon stopped (same lock rule as B465). Archive vs hard-delete is a
   decision for this card (archive is reversible; hard-delete also clears
   `vectors.db` rows). The vector store must stay in sync with the graph.
4. **Session prefixes are not proof.** `arc_*` may be the user's real
   ARC_AGI agent work; the user decides per prefix. The command takes an
   explicit prefix list, no default.

### Not changed

- B465's repair is not run on the personal store: its 50 inverted edges are
  all fixture data and go away with this card.
- Per-workspace stores (B316) are separate runs.
