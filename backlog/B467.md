# B467 - Benchmark Data Leaked Into the Personal Store

State: ready (filed 2026-10-05)
Priority: P2

### Problem Statement

The user's personal store (`~/.campy`) holds campy-benchmarks fixture
conversations as if they were real project memory. Found while running B465's
dry run on a copy of it (2026-10-05): all 50 inverted CHOSEN_OVER edges the
repair would flip ("Zipkin CHOSEN_OVER OpenTelemetry OTel", "HS256
CHOSEN_OVER RS256", "PostgreSQL 14 CHOSEN_OVER PostgreSQL 16", ...) come from
LoCoMo messages, and most of the 133 unverifiable ones are LoCoMo noise too
("Updated storage_tier CHOSEN_OVER S3 Glacier", "Vim CHOSEN_OVER Jordan").
`ask`, `current_truth` and the bundle stages read these as the user's own
decisions: a question about the user's real tracing or auth setup can be
answered from a fixture.

Counted on a copy (Messages by `SENT_IN` session name):

| session prefix | sessions | messages | source |
|---|---|---|---|
| `locomo_*` | 99 | 1,344 | LoCoMo fixture |
| `msc_*` | 26 | 276 | MemBench (MSC) fixture -- verify |
| `memgym_*` | 21 | 273 | MemoryGym fixture |
| `arc_*` | 13 | 334 | **ambiguous**: ARC suite or the user's real ARC_AGI work |

Messages are repeated per run (the same LoCoMo statement appears 3+ times
with different `created_at`: 2026-09-22, -24, ...).

### Root cause

`run_all.py` (campy-benchmarks) without `--isolated` talks to the live daemon
on `~/.campy`. It prints a warning ("[!] Not isolated: this run reads and
writes the personal ~/.campy store") but runs anyway. Earlier runs used that
mode. Consolidation then derived Concepts and CHOSEN_OVER edges from the
fixture messages, so the leak is not just Messages: Concepts, edges, Lessons
and vectors (`vectors.db`) carry it too.

### What It Does (Scope)

1. **Stop new leaks** (campy-benchmarks): a non-isolated run against a real
   daemon must be an explicit opt-in (`--shared-store` or similar), not a
   warning. Decide whether a non-isolated mode is needed at all.
2. **Find what leaked** (hippocampy): a dry-run report of everything that
   originates only from benchmark sessions -- Messages `SENT_IN` the
   benchmark sessions, and derived nodes/edges whose only provenance is
   those Messages (a Concept also mentioned in a real session stays). Use the
   graph's own provenance (`SENT_IN`, `DERIVED_FROM`/mention edges); do not
   match on text.
3. **Remove or archive it** behind `--apply`, after a backup, with the
   daemon stopped (same lock rule as B465). Archive vs hard-delete is a
   decision for this card (archive is reversible; hard-delete also clears
   `vectors.db` rows). The vector store must stay in sync with the graph.
4. **Session prefixes are not proof.** `arc_*` may be the user's real
   ARC_AGI agent work; the user decides per prefix. The command takes an
   explicit prefix list, no default.

### Not changed

- B465's repair is not run on the personal store: its 50 inverted edges are
  all fixture data and go away with this card.
- Per-workspace stores (B316) are separate runs.

### Files

- campy-benchmarks: `run_all.py` (opt-in for non-isolated runs)
- hippocampy: new `campy graph purge-sessions` (or similar) in
  `campy/cli/graph_repair.py`, named queries, tests

### Acceptance Criteria

- [ ] `run_all.py` with `CAMPY_MCP_CMD` and no `--isolated` refuses unless
      explicitly opted in.
- [ ] On a real Oxigraph store holding a benchmark session, a real session,
      and a Concept mentioned by both, the dry run lists the benchmark-only
      Messages/Concepts/edges, `--apply` removes them (graph and vectors),
      the shared Concept and the real session stay, and a second run is a
      no-op (tests fail on main: the command does not exist).
- [ ] No other test changes result (full suite, same failure set as main).
- [ ] On a COPY of `~/.campy`: report counts per prefix; after `--apply`,
      B465's dry run reports 0 inverted edges from fixture messages.
- [ ] The user decides which prefixes to purge from the real `~/.campy`
      (dry run on a copy first; backup before apply).
