# B490: Agent rules files still name KuzuDB as the store

**Status:** complete (2026-10-19) · **Found:** 2026-10-19, in passing (e2e lead)

## Problem

The live store is Oxigraph (SPARQL) with vectors in SQLite; Kùzu is used only by the
legacy migrator and backups. The files every coding agent loads still say otherwise:

| File | Kùzu mentions |
|---|---|
| `CLAUDE.md` ("No Shadow Stores": "KuzuDB is the single source of truth") | 1 |
| `AGENTS.md` (Codex) | 4 |
| `GEMINI.md` | 4 |
| `.github/copilot-instructions.md` | 3 |
| `docs/ecosystem-rules.md` | 10 |

A rule that names the wrong store tells an agent to write to, query or reason about a
store that is not the source of truth. The intent of the rule (one persistent store, no
shadow stores) is still right; only the name is stale.

## Fix

- State the rule by role, not product: "the graph store (Oxigraph today) is the single
  source of truth; vectors live in `vectors.db` and are an index, not a store."
- Update all five files the same way, keeping each one short.
- Leave Kùzu mentions that are about the legacy migrator or backups.

## Done when

`grep -il kuzu CLAUDE.md AGENTS.md GEMINI.md .github/copilot-instructions.md` finds only
migrator/backup context, and `docs/ecosystem-rules.md` describes the current store.
