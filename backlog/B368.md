# B368 - tests/test_remote_mcp.py Writes Real tools/call Activity Events into ~/.campy/activity.log

State: ready
Priority: P3

Plan: none yet.

### Problem

Found live 2026-08-28 while verifying B367's isolation fix didn't miss a code path. B367 added
`emit_activity()` calls to `campy/brain_daemon.py`'s `_dispatch` (the Unix-socket transport) and
updated every test that constructs a `BrainDaemon` directly to point `config.activity.log_path` at
an isolated temp file, specifically so test runs stop polluting the developer's real
`~/.campy/activity.log`.

Running the full pre-existing test suite immediately after that fix confirmed it worked for the
socket-transport tests, but `~/.campy/activity.log` still grew by 10 lines (36434 -> 36444) during
the same run. The new lines are all `tools/call` events for made-up test tool names
(`remote_mcp_test_tool_a/b/c`, `router_spy_http_method`) with real current timestamps — these come
from `web/server.py`'s own `emit_activity()` call in its `tools/call` HTTP/MCP dispatch path (B325),
which has existed since before B367 and is unrelated to it. `tests/test_remote_mcp.py`'s
`_make_client()` helper calls `create_app(db, principal_resolver=...)` with no `config` argument at
all, so `web/server.py`'s internal `_cfg` defaults to `{}` — `activity_log_path({})` falls back to
the real `~/.campy/activity.log` on this machine, not a temp file. `tests/test_workspace_router.py`
has a second `create_app(...)`-based HTTP test with the same gap.

This is a pre-existing test-hygiene bug, not a B367 regression — `web/server.py`'s HTTP path has
always behaved this way since B325 shipped `emit_activity()` there. It just wasn't yet possible to
notice by an "activity.log line count changed after running tests" check, since B367 is what made
that check meaningful for the socket-transport side. Left out of B367's own PR deliberately, to keep
that PR scoped to the one real gap it exists to close (campy/brain_daemon.py never emitting anything
at all) rather than also touching an unrelated pre-existing test-isolation gap in a different
transport's tests.

### What it does (scope)

1. Give `web/server.py`'s `create_app()` a way to accept a `config` with an isolated
   `activity.log_path` from tests, if it doesn't already (check the function signature first).
2. Update `tests/test_remote_mcp.py`'s `_make_client()` (6 call sites) and
   `tests/test_workspace_router.py`'s HTTP-path test to pass a `tmp_path`-based activity log config,
   matching the pattern `tests/test_auth_context.py`'s `_daemon_with_activity_log()` helper (added in
   B367) already uses for the socket-transport tests.
3. Verify: run the full suite, confirm `~/.campy/activity.log`'s line count and mtime are unchanged
   before/after (`wc -l` before, run tests, `wc -l` after — the exact check that surfaced this).
4. Grep for any other `create_app(` call site across `tests/` that might have the same gap — don't
   assume only these two files are affected.
