### Consolidation Context

This card consolidates **B376** (Eliminate spaCy/PyTorch Baseline Memory Floor) and **B377** (Kùzu to Oxigraph + sqlite-vec Migration) into a single, cohesive architectural initiative. 

**Why Consolidated:** Step 1/1b (the ingestion front-end) directly feeds the graph schema (the storage back-end). Implementing them separately forces throwaway intermediate code (adapting a new NER pipeline to the legacy Kùzu schema, only to immediately rewrite it for Oxigraph). Furthermore, `brain_daemon.py` suffers from two coupled memory monsters:
1. `spacy`/`thinc` importing `torch` for Step 1/1b NER, pinning an idle startup floor of **~1.2 GB** (even though B355 already moved vector embeddings to fastembed/ONNX).
2. `kuzu` causing **1.1 GB transient spikes** during commit checkpoints (B311) and lacking in-place index updates (B285), while being permanently archived/EOL since October 2025.

Solving both together transitions Campy to a unified, featherweight, 100% Apache-2.0 / MIT native stack running in **<80 MB total idle RAM**.

#### Phase 2A: Ingestion Front-End (Pure ONNX + Rule Parser, Drop PyTorch)
- Replace `spacy` and `thinc` in `step1_zoning.py` with an ONNX-native token classification model (reusing `fastembed`'s existing ONNX Runtime execution provider).
- Refactor `step1b_fast_relations.py` with a lightweight, non-torch dependency/verb pattern parser extracting universal lemmas (*require, enable, replace, contradict, part_of*).
- Remove `torch`, `torchvision`, `thinc`, and `spacy` from `pyproject.toml` and `requirements.txt`.
- **Milestone Verification:** `tests/test_torch_free_import.py` confirms zero instances of `torch` in `sys.modules`, independently dropping physical daemon RSS from **~1.2 GB down to ~245 MB**.

#### Phase 2B: Storage Back-End (`pyoxigraph` + `sqlite-vec` on Torch-Free Base)
- Build `campy/brain/hippocampus/graph/oxigraph_client.py` replacing `kuzu_client.py`.
- Native RDF-star (`<< :s :p :o >>`) modeling for all Campy edge metadata:
  - `<< :Session_s1 :LOADED :Decision_d1 >> :injected_at ... ; :token_estimate ...`
  - `<< :Concept_c1 :CO_OCCURS_WITH :Concept_c2 >> :count ... ; :strength ...`
  - `<< :Plan_p1 :ENABLES :ActionItem_a1 >> :confidence ... ; :inferred_by ...`
  - `<< :Constraint_c1 :DEPRECATED_BY :Constraint_c2 >> :superseded_at ...`
- **Graph Guardrail (`model-selection.md`):** Disambiguate RDF set semantics vs LPG multi-edges. For discrete repeated events (such as repeated `LOADED` interactions across session sub-turns), attach an event occurrence discriminator (`:event_id` or timestamp term) so that subsequent loads don't overwrite edge properties on the unique `<< :s :p :o >>` statement term.
- Build `campy/brain/hippocampus/graph/vector_store.py` using `sqlite-vec` over `~/.campy/vectors.db`.
  - Indexes `FLOAT[384]` embeddings produced by `fastembed`.
  - Replaces Kùzu's `QUERY_VECTOR_INDEX` with sub-millisecond SQLite cosine distance queries.
- Remove `kuzu` from `pyproject.toml` and `requirements.txt`.
- **Milestone Verification:** Drops idle physical footprint from **~245 MB down to <80 MB RAM**.

#### Phase 2C: Cutover, Data Migration & Patent Re-Certification
- Update `gateway.py` to route all graph queries to `oxigraph_client.py` and vectors to `vector_store.py`.
- Update `scripts/check_cypher_ratchet.py`: Update `ALLOWLIST_FILES` to replace `kuzu_client.py` with `oxigraph_client.py`, and adjust scanning regex to avoid false-positive Cypher alerts on SPARQL 1.1 `CREATE GRAPH` statements.
- Update `campy export-graph` and `campy import-graph` (B281) to migrate legacy Kùzu JSONL dumps into the Oxigraph + sqlite-vec store.
- Re-run the full Gated Consolidation Loop test suite (`tests/test_loop.py`, `tests/test_retrieval.py`).
- **Dual-Engine Patent Re-Certification:** Re-run the entire B380 patent claim suite against `gateway.py` backed by Oxigraph, confirming 100% claim conformance on the new engine.
- Certify that the entire live daemon process idles at **<80 MB physical footprint** on macOS (`vmmap -summary`) and Linux (`/proc/[pid]/status`).
