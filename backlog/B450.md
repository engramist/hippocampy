# B450 - Benchmark Harness Could Silently Turn a Dead/Offline Daemon Into Fake Scores

State: fixed (2026-09-23, in the sibling `campy-benchmarks` repo)
Priority: P0
Branch: n/a (campy-benchmarks local `master`)

B446's v3 run ended with instant, all-zero results because the daemon had been
killed mid-run (B451); the adapter answered "offline"/`queued_offline` in ~1 ms
and the harness scored that as real. Fixes in `campy-benchmarks`:

- `CampyMCPClient` real mode (a `CAMPY_MCP_CMD` is set) is strict: no silent
  mock fallback (a failed start, dead process, EOF, timeout, JSON-RPC error, or
  an adapter-reported `Brain: OFFLINE` / `queued_offline` now raises
  `CampyClientError`/`DaemonOfflineError`).
- Real 240s response timeout via a stdout reader thread (the old `timeout`
  argument was never enforced; `readline()` blocked forever), and stderr goes
  to a file instead of an undrained PIPE (a full 64 KB pipe blocks the child).
- `run_all.py` records a suite that lost the daemon as `valid: false` with the
  reason, per-suite `client_calls`/`client_failures`, and a top-level
  `all_suites_valid`.
- B448: `run_sweep()` is now a real settle (polls `context_status.consolidation_pending`
  to 0); `memory_gym` now settles before probing (it had no synchronization).
