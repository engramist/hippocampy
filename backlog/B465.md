# B465 - Repair Supersession Edges Written Backwards Before B460

State: fixed; real-store confirmation done on a copy of `/tmp/diag-store`
(2026-10-04: 8 INVERTED -> 0, with B466 merged in). Reaches the inverted
edges Step 1b's grammar can verify, not all of them -- see "Why not every
inverted edge is reachable". Personal-store decision pending.
Priority: P1

### Problem Statement

B460 fixed relation extraction going forward. Before it, consolidation's
Step 3b LLM wrote "A CHOSEN_OVER B" edges with the RETIRED value as A: in the
kept pre-B460 real-model LoCoMo store (`/tmp/diag-store`)
`diag_supersession_edges.py` found 8 of 11 such edges inverted ("PostgreSQL
14 CHOSEN_OVER PostgreSQL 16" from "We have completely migrated from
PostgreSQL 14 to PostgreSQL 16", "Zipkin CHOSEN_OVER OpenTelemetry OTel",
"ActiveMQ CHOSEN_OVER Apache Kafka", "TLS 1.2 CHOSEN_OVER Strict TLS 1.3",
...), next to nonsense ones ("PostgreSQL CHOSEN_OVER Primary database").
Every store written before B460 -- the user's personal `~/.campy` store
included -- still holds these, and whatever reads them (bundle graph
structure, traversal) learns that the old value won. B460 does not touch
existing data.

### Root cause

The edges were written by pre-B460 extraction (see B460's root cause); the
data was never revisited. Nothing records where an edge came from: the edge
annotations are only `confidence`, `inferred_by` ('LLM' for both the loop's
Step 3b and the sweep's Hebbian promotion) and `inferred_at`, and there is
no edge -> Message link. So an inverted edge cannot be found from the edge
alone -- it has to be checked against what the user said.

### What It Does (Scope)

`campy graph repair-supersession-edges [--db-path PATH] [--apply] [--all]`,
next to B302/B303's `repair-outcome-polarity` / `repair-plan-valence` and
built the same way (dry run by default, `--apply` writes, opens the store
directly, refuses with "stop the daemon first" when the daemon holds the
lock):

1. Lists every Concept -> Concept CHOSEN_OVER / REPLACES edge.
2. Re-reads the stored **user** Messages with B460's Step 1b (spaCy
   grammar, no LLM: passive, "from X to Y", active) and keeps its REPLACES
   statements ("new REPLACES old"). Only messages that share a word with
   both ends of some edge are parsed.
3. Classifies each edge against those statements. A Concept "names" a side
   when, case-insensitively, the texts are equal or one contains the other
   as whole words (B460's `_names_entity` rule, both ways: Step 1b keeps
   versions NER drops, NER keeps words Step 1b's span stops at --
   "OpenTelemetry OTel" vs "OpenTelemetry" from "OpenTelemetry (OTel)"). A
   Concept naming both sides ("PostgreSQL" for "PostgreSQL 16 REPLACES
   PostgreSQL 14") proves nothing.
   - `inverted`: a user message says the edge's tail replaced its head;
   - `right`: a user message says the head replaced the tail;
   - `conflicting`: user messages say both (e.g. a later rollback);
   - `unverifiable`: no user message states a supersession of the pair
     (the nonsense edges, pairs only an assistant turn spoke of).
4. Prints one row per edge (inverted and conflicting by default, every edge
   with `--all`): the edge, its verdict, the action, and the user
   message(s) that justify it.
5. `--apply` repairs only `inverted` edges: removes the edge (its plain
   triple and every RDF-star reifier, `OxigraphClient.remove_star_edge`) and
   MERGEs "tail REPLACES head" between the same two Concepts
   (`orchestrator.merge_semantic_rel_replaces`, `inferred_by =
   'system:b465-repair'`, confidence 0.85 as Step 1b). When that edge
   already exists (the reverse-pair case: "TLS 1.3 REPLACES TLS 1.2" beside
   "TLS 1.2 CHOSEN_OVER TLS 1.3") it is kept as it was. No Concept is
   created; nothing is written for `right`, `conflicting` or `unverifiable`
   edges.

Idempotent: after `--apply` every repaired pair reads `right`, so a second
run writes nothing.

Not changed:

- **Unverifiable edges stay.** The nonsense ones ("PostgreSQL CHOSEN_OVER
  Primary database") are wrong in a different way (no supersession at all);
  deleting edges no user message speaks to would be guessing. They are
  reported (`--all`).
- **Assistant messages are not evidence.** Only the user's own statements
  decide an edge's direction.
- **Step 1b's coverage is the limit.** A supersession Step 1b cannot parse
  ("ActiveMQ is deprecated and has been replaced by Apache Kafka": the
  coordinated passive yields nothing) leaves its edge unverifiable.
- **Workspaces.** The command repairs one store (`--db-path`, default the
  local `brain.db`); per-workspace stores (B316) are separate runs.
- No daemon coordination beyond refusing on the store lock: like B302/B303
  it is an offline maintenance command. Stop the daemon, or run on a copy.

### Why not every inverted edge is reachable

The repair can only be as sure as Step 1b's grammar. The 2 sandbox edges it
leaves are stated only as:

- "HS256 is deprecated ... We must migrate to RS256 asymmetric keys." --
  a "to" with no "from"; B460 deliberately reads no supersession from that
  (the link between the deprecated value and the migration target is
  discourse, not grammar).
- "Architecture change: Replace Memcached with Redis cluster ..." -- the
  imperative "replace X with Y" has no subject, and Step 1b's active pattern
  needs one. (The same verb with a subject, "We replaced Memcached with
  Redis", yields "We REPLACES Memcached" today -- a live Step 1b gap,
  separate card.)

On the LoCoMo fixture's user messages, Step 1b reads 6 of the real store's
8 inverted pairs (PostgreSQL 14/16, Zipkin/OpenTelemetry, ActiveMQ/Kafka,
TLS 1.2/1.3, Bazel/Hatch, JSON REST/GraphQL); both HS256 -> RS256 edges are
stated only as "deprecated ... migrate to RS256". So on `/tmp/diag-store`
the expected result was **8 INVERTED -> 2** when this card was written.
B466 then widened Step 1b to read "replace X with Y" and "X is deprecated
... migrate to Y"; with it merged into this branch, both HS256 -> RS256
edges are verifiable too and the measured result is **8 -> 0** (see the
criteria). Any further Step 1b improvement widens this repair with no
change here; edges no user message states in Step 1b's grammar are still
left alone.
