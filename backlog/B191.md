# B191: Offline Consolidation / "Dreaming" — Synthesize Lesson Clusters into Meta-Lessons

**Status**: complete (2026-04-09)
**Assigned**: TBD
**Depends on**: None
**Complexity**: Large (4-6 hours)
**Priority**: P1 (compounds knowledge over time; directly enables cross-puzzle learning)
**Plan**: backlog/plans/B-191-dreaming-consolidation.md

## Problem Statement

SideQuests archives low-strength nodes via Ebbinghaus decay (sweep.py) but never *synthesizes* clusters of related knowledge into higher-level abstractions. After 100 ARC puzzle runs, there are 100 individual Lesson nodes about strategies, but no meta-lesson that says "exploration-first strategies outperform goal-seeking 2:1 for spatial navigation puzzles."

Karpathy's "dreaming" concept: offline consolidation that creates compressed summaries from raw experience. The brain sleeps on what it learned and wakes up with structured understanding.

## Root Causes

1. `run_sweep()` only decays/archives/resurrects — no synthesis step
2. No mechanism to cluster related Lesson nodes by domain + similarity
3. `GENERALIZES` edge exists in schema (Hypothesis→Hypothesis) but no equivalent for Lesson→Lesson synthesis
4. No `MetaLesson` or summary node type

## What This Card Does

1. **New sweep step**: `step_dream_consolidation` in `mcp_engine/sweep.py` — runs after decay, before centroid recomputation
2. **Cluster related Lessons**: Group Lessons by domain + embedding similarity (cosine > 0.75) using KuzuDB vector search
3. **LLM synthesis**: For clusters of 3+ Lessons, call LLM to produce a synthesized meta-lesson
4. **Store as new Lesson node**: With `lesson_type = "synthesis"`, higher `pathway_strength` than constituents
5. **GENERALIZES edges**: Link meta-lesson → constituent lessons via `GENERALIZES_LESSON` edge
6. **Constituent decay acceleration**: Boost decay rate for synthesized lessons so they naturally fade while the meta-lesson persists
7. **Configurable**: `[sweep.dreaming]` section in `sidequests.toml` with `min_cluster_size`, `similarity_threshold`, `max_syntheses_per_sweep`

## Graph Design (Graph Expert Analysis)

**New relationship type:**
```
GENERALIZES_LESSON (FROM Lesson TO Lesson, synthesized_at TIMESTAMP, cluster_size INT32)
```

**Why a new edge type instead of reusing GENERALIZES**: `GENERALIZES` is `FROM Hypothesis TO Hypothesis` — different source/target node types. KuzuDB requires explicit FROM/TO type declarations per relationship table. Lesson→Lesson needs its own.

**Access pattern**: The dreaming step needs:
1. `MATCH (l:Lesson) WHERE l.domain = $domain AND l.archived = false AND l.lesson_type != 'synthesis'` — filter candidates
2. Vector similarity within domain cluster — use HNSW index on Lesson embeddings
3. Check no existing synthesis: `WHERE NOT EXISTS { MATCH (l)<-[:GENERALIZES_LESSON]-(m:Lesson) }`
4. After synthesis: `CREATE (m)-[:GENERALIZES_LESSON]->(l)` for each constituent

**Supernode risk**: Low. Each meta-lesson links to 3-10 constituents. No fan-out concern.

**Index**: Lesson already has HNSW embedding index. Domain filtering is a property filter on the scan — acceptable for sweep (offline, not latency-sensitive).
