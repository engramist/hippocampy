# B488 - An Archived Message Can Keep a Stale `archived=false`

State: complete (2026-10-19; found while building B487)
Priority: P2

Plan: (inline — this card is self-contained)

### Problem Statement

`capture.archive_earlier_message_version` can leave a Message with two
`archived` values in the Oxigraph store: the new `true` and a stale `false`
(reproduced in a test store while building B487 neighbour expansion). Readers
that look at one row at a time — `GraphGateway._bundle_conversation_impl` and
`_hydrate_messages` — may then treat an archived (superseded) turn as live and
put it into the conversation section, where it competes with the turn that
replaced it.

### Proposed Fix

1. Make the archive write replace the property (delete the old `archived`
   triple before inserting the new one), the way other single-valued
   properties are written.
2. A one-off repair in `campy doctor` / migration: for Messages with both
   values, keep `true`.
3. Readers: treat a Message as archived if any `archived` value is true.

### Test

A store where a Message is archived after capture has exactly one `archived`
value; the conversation stage never returns it; the repair fixes an existing
double-valued Message.

### Resolution (2026-10-19)

Root cause: the SPARQL of `capture.archive_earlier_message_version` had
`DELETE { ?m campy:archived ?old_archived }` but `?old_archived` was never
bound in the WHERE clause, so the DELETE matched nothing and the stale `false`
stayed beside the new `true`. The query now binds it, so the property is
replaced.

- Readers: `GraphGateway._hydrate_messages` and the conversation enumeration
  collapse rows per subject (`_collapse_archived`, archived if any value is
  true); `retrieval` text search and `working_memory` message count add
  `FILTER NOT EXISTS { ?m campy:archived true }`; `observations.get_message`
  orders `DESC(?archived)` before `LIMIT 1`; the session-purge planner treats a
  Message with any archived-true row as archived.
- Repair: `campy graph repair-message-archived [--apply]` (dry run by default;
  idempotent; prints the count). It lives with the other graph repairs rather
  than in `campy doctor`, because doctor never opens the store (the daemon
  holds its lock).
- Tests: `tests/test_b488_archived_single_valued.py`.
- Scope: only `source_memory_key` captures (the B298 auto-memory piggyback)
  call the archive query; benchmark ingestion does not.
