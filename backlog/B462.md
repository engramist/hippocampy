# B462 - Save-Gate Category Spec, Labeled Set, and Baseline Measurement

State: in-progress (2026-09-30)
Priority: P2

### Problem Statement

Step 4 (`campy/brain/temporal_lobe/loop/step4_pattern.py`) decides what gets
saved to the graph and as what: `decision`, `constraint`, `requirement`,
`action_item`, or noise. Those categories have no written definitions. They
exist only as regex lists (`_DECISION_SIGNALS`, `_CONSTRAINT_SIGNALS`, ...)
and a hand-set gist prior table (`_GIST_ARTIFACT_PRIOR`).

Two consequences:

1. **Nobody can say what a correct answer is.** "We should probably look at
   caching" matches `\bshould\b` and scores as a `requirement`. Is that
   right? There is no definition to check it against. Overlaps (a decision
   that establishes a rule; a requirement vs. a standing constraint) have no
   stated tie-break.
2. **The confidence numbers aren't probabilities, but the gates treat them as
   if they were.** One regex hit gives `0.67 + 0.15 = 0.82`; a gist prior
   gives a fixed `0.80`. `NOISE_FLOOR = 0.60` and `HARD_LOCK = 0.90` then act
   on those numbers as if 0.90 meant "right 9 times in 10". Nobody has
   measured whether it does.

Motivation: Tony Seale's post on Jev (TypeSafe's calibrated "System One"
decision model) argues that cheap calibrated decisions are only as good as
the category definitions behind them ("a model cannot apply your business
definitions if you have never made them explicit"). Whatever classifier we
use later (B460), the definitions and a labeled set have to come first.

### What It Does (Scope)

1. **Category spec as versioned data:** `campy/data/artifact_categories.yaml`.
   For each of `decision`, `constraint`, `requirement`, `action_item`, plus
   `none`: a definition, include/exclude criteria, and near-miss examples
   with the reason they are excluded. A `precedence` list says which label
   wins when a statement fits more than one category (single-label
   classification).
2. **Loader:** `campy/brain/temporal_lobe/category_spec.py`, which parses and
   validates the spec (every category present, precedence covers every
   category, every near-miss label is a known category). No pipeline code
   reads it yet. B460 is the first consumer.
3. **Labeled set:** `benchmarks/save_gate/gold.yaml`, ~150 statements, each
   labeled with one category per the spec, and tagged with the failure mode
   it probes (hedged "should", casual "always", past-tense status, questions,
   ...).
4. **Baseline harness:** `benchmarks/save_gate/run_baseline.py` runs the real
   Steps 1, 2, 3, and 4 (plus the amygdala salience rescue) over the gold set,
   exactly as `run_loop` does, with no LLM (System 2 degraded, as on a machine
   without Ollama). It reports:
   - reified-type accuracy and per-category precision/recall (what `HARD_LOCK`
     turns into a Decision/Constraint/... node);
   - false-save rate (gold `none` → reified artifact);
   - missed-save rate (gold category → nothing stored);
   - a reliability table: Step 4 confidence bins vs. fraction correct.
5. **Shared helpers extracted (behavior-preserving):** the amygdala
   salience-rescue block in `orchestrator.run_loop` moves to
   `step4_pattern.apply_salience_rescue()`, and keyword scoring to
   `step4_pattern.signal_scores()`, so the harness and the Loop run the same
   code. `run_loop` still calls `classify_artifact` directly (a B108 test
   patches it there, and the patent evidence map cites it).
6. Record the baseline numbers in this card.

### Out of Scope

- Seeding the spec into the graph. The graph write belongs with the first
  code that reads the definitions at runtime (B460), which follows the
  `ROUTING_TABLE` pattern (Python/data constant seeded at `init_schema`).
  Seeding it now would add a node type that nothing reads.
- Gist class definitions (Step 2). `GIST_DESCRIPTIONS` stays as is until B460.
- Any change to thresholds or scoring. This card only measures.

### Known Limits

- The labeled set is **author-written and author-labeled**, not drawn from
  real sessions. It is a starting point to be reviewed and extended by the
  project owner, and ideally supplemented with real (redacted) turns. ~150
  items gives wide error bars: treat differences under ~10 points as noise.
- The categories have no slot for plain facts/observations ("the API returns
  404 for missing users") or preferences ("I prefer tabs"). Under this spec
  those are `none` for artifact typing, though the Loop may still store them
  as tentative Concepts. Whether they deserve their own category is an open
  question recorded in the spec.
- Reified artifacts store `entity["text"]` (the entity span, e.g.
  "PostgreSQL"), not the statement (`orchestrator._reify_concept`). That
  limits how useful even a correctly typed artifact is. Noted for B460.

### Progress notes (2026-09-30)

Spec, loader, labeled set (152 items: 28 per artifact category, 40 `none`),
harness and tests are in. **Full mode has not been run yet:** the session
that built this ran in a sandbox that blocks Hugging Face, so the embedding
model (all-MiniLM-L6-v2) could not be downloaded. Run it on a machine with the
models:

```bash
.venv/bin/python -m benchmarks.save_gate.run_baseline --mode full --json save_gate_full.json
```

**Signals-mode baseline** (Step 4 keyword layer; exact whenever a keyword
fires, since the gist class then only changes confidence by +0.10):

| Gold label | n | keywords fire | type correct |
|---|---|---|---|
| decision | 28 | 11 | 9 |
| constraint | 28 | 15 | 13 |
| requirement | 28 | 19 | 12 |
| action_item | 28 | 13 | 12 |
| none | 40 | 19 | – |

- Keywords fire on 50.7% of statements; when they fire, the type is right
  59.7% of the time.
- **19 of 40 `none` statements fire a keyword**, which always clears
  `NOISE_FLOOR` (one hit = 0.82), and reaches `HARD_LOCK` (0.92) whenever the
  gist prior agrees. By probe: hedged 6/8, casual rule words 5/5,
  descriptive decision words 4/5, questions 4/6.
- Only 2 of 49 `no_keyword` positives fire a keyword.
- Overlap items (statements fitting two categories): 1 of 4 typed right.

**What the code implies for keyword-less statements** (read from
`_GIST_ARTIFACT_PRIOR`, not measured): with no keyword hit, confidence is the
gist prior, at most 0.80, so such a statement can never be reified. Only gist
`Restriction` (constraint, 0.80) and `PlannedEvent` (action_item, 0.72) clear
the noise floor. `PhysicalThing`, `Category` (0.55), `Event`, `Magnitude`
(0.50) and `Agent` fall below it and are dropped unless the salience rescue
applies. So "OK, Postgres it is." or "We're dropping the SSE transport" can
never become a Decision. Full mode will show how often that bites.

Caveat: the `clear` probe items were written with the usual trigger words, so
their 45/55 keyword accuracy is flattering by construction. The informative
numbers are the `none`, `no_keyword` and `overlap` rows.
