# B366 - Flaky test_research_sim_detects_memory_benefit (Narrow-Margin Statistical Assertion)

State: ready
Priority: P3

Plan: none yet.

### Problem

`tests/test_research_sim.py::test_research_sim_detects_memory_benefit` failed in CI on PR #130 (a
docs-unrelated daemon change — `campy/brain_daemon.py`/`tests/test_auth_context.py` only, no
relation to `benchmarks/research_sim/` whatsoever):

```
assert baseline["regression_rate"] > sidequests["regression_rate"]
E   assert 0.6363636363636364 > 0.65
```

The test uses a fixed seed (`{"seed": 98765}`) and asserts `baseline["regression_rate"] >= 0.1` and
`baseline["regression_rate"] > sidequests["regression_rate"]` — a narrow-margin comparison (the
observed failure was off by only ~0.014) that depends on `ResearchSimHarness`'s internal
random-number draws. If the harness reseeds Python's *global* `random` module rather than using an
isolated `random.Random(seed)` instance, then whatever else runs earlier in the same pytest process
(and consumes global `random` state before this test's `setup()`/`run()`) could shift this test's
actual draws despite the "fixed" seed — consistent with this being a collection-order-sensitive
flake, the same general class as B360/B361, not a real regression. A full local suite run
immediately prior to this failure (after merging PR #125) came back completely clean (2180 passed,
0 failures), and PR #130's diff has no plausible connection to this test's subsystem.

### What was NOT established

- Whether the harness actually reseeds global `random` vs. using an isolated instance — not yet
  read. This is the first thing to check; if confirmed, it's the direct root cause and the fix is
  mechanical (use `random.Random(seed)` internally instead of `random.seed(seed)`).
- Whether this is genuinely order-dependent (reproduces when run after specific other tests) or a
  one-off CI environment quirk — not reproduced locally yet.

### What it does (scope)

1. Reproduce with a repeated-run loop, and specifically with `test_research_sim.py` run after
   `tests/test_auth_context.py`/`tests/test_daemon.py` (the two files most likely to consume
   `random` this session, given `_periodic_restart`'s `random.uniform()` jitter — B342/B365) to
   check for the exact cross-test interaction pattern.
2. Read `benchmarks/research_sim/`'s harness to confirm whether it reseeds the global `random`
   module or uses its own isolated `Random` instance.
3. Fix at the root: isolate the harness's RNG (a local `random.Random(seed)` instance, not global
   `random.seed()`) so this test's outcome is deterministic regardless of what ran before it in the
   same process — preferred over widening the assertion's margin, matching this project's existing
   preference (see B361) for eliminating the flake class over tolerating it.

### Dependencies

None.

- `benchmarks/research_sim/` (harness) — likely the actual fix, if global-`random` reseeding is
  confirmed.
