### Problem

Archived nodes stay in the HNSW vector indexes forever. Vector search post-filters `archived=true` rows in Python and compensates with a `+20` fetch headroom (`_FETCH_HEADROOM` in `step5_retrieval.py`, acknowledged in-code as "L10 / future M5 upgrade"). The Ebbinghaus decay sweep guarantees the archived fraction grows monotonically — over time an increasing share of every top-K result set is dead rows, silently degrading recall quality until real matches get crowded out entirely.

### What This Card Does

1. Adds an archived-ratio metric per vector-indexed table to the sweep stats (`archived_count / total_count`).
2. Adds a sweep-triggered HNSW index rebuild when a table's archived ratio crosses a threshold (default 0.5): drop index → (optionally compact) → recreate. On Kuzu 0.11.3, rebuild requires verifying `DROP_VECTOR_INDEX` (or equivalent) exists; if rebuild-in-place is impossible, the fallback is moving archived rows to parallel `<Table>Archive` tables that have no vector index.
3. Makes the fetch headroom adaptive: `headroom = ceil(limit × archived_ratio × 2)` clamped to [5, 50], instead of the fixed +20.
4. Documents the chosen approach and its trigger conditions in `docs/ARCHITECTURE.md`.
