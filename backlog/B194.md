## Problem Statement

Lessons capture *what* was learned ("exploration-first works for spatial navigation"). Plans capture *what was tried* (historical record). But there's no reusable *procedure* — "here's a proven recipe for solving spatial navigation puzzles: step 1, explore all actions; step 2, identify player; step 3, navigate to intermediates; step 4, reach goal."

Every new puzzle reinvents the strategy from scratch. `recall_plans` retrieves similar historical Plans, but they're records of what happened — not executable templates with parameterized steps.

## Root Causes

1. No `Procedure` node type — only `Plan` (historical) and `Lesson` (declarative)
2. `recall_plans` returns past Plans but the agent must re-derive the strategy each time
3. No mechanism to distill common successful patterns into templates
4. Karpathy's distinction: declarative (what) vs procedural (how) memory

## What This Card Does

1. **New `Procedure` node type**: A reusable, parameterized strategy template
2. **Automatic procedure creation**: When 3+ Plans in the same archetype/domain succeed with similar strategies, synthesize a Procedure via LLM
3. **`recall_procedures` MCP tool**: Retrieve applicable procedures for a given archetype/situation
4. **`DISTILLED_FROM` edge**: Procedure → Plan (provenance to source plans)
5. **`APPLIES_TO_ARCHETYPE` edge**: Procedure → Concept (archetype binding)
6. **Procedure structure**: Parameterized steps with preconditions, expected outcomes, and decision points

## Graph Design (Graph Expert Analysis)

**New node type:**
```
Procedure:
    procedure_id       STRING,
    name               STRING,
    domain             STRING,
    archetype          STRING,
    description        STRING,
    steps_json         STRING,     -- JSON array of {step, precondition, action, expected_outcome}
    embedding          FLOAT[384],
    embedding_model    STRING,
    embedding_dim      INT64,
    success_count      INT32,      -- how many plans this was distilled from
    application_count  INT32,      -- how many times applied by agents
    success_rate       DOUBLE,     -- of applications that succeeded
    confidence         DOUBLE,
    pathway_strength   DOUBLE,
    archived           BOOLEAN,
    created_at         TIMESTAMP,
    last_applied_at    TIMESTAMP,
    PRIMARY KEY (procedure_id)
```

**New relationships:**
```
DISTILLED_FROM (FROM Procedure TO Plan, synthesized_at TIMESTAMP)
APPLIES_TO_ARCHETYPE (FROM Procedure TO Concept)
APPLIED_PROCEDURE (FROM Plan TO Procedure, success BOOLEAN, applied_at TIMESTAMP)
```

**Access pattern for `recall_procedures`**:
```cypher
MATCH (p:Procedure)
WHERE p.archived = false AND p.archetype = $archetype
RETURN p
ORDER BY p.success_rate DESC, p.success_count DESC
LIMIT 3
```

Also vector search on Procedure embedding for situation-specific matching.

**Procedure creation** (sweep or dedicated consolidation step):
```cypher
-- Find successful plans in the same archetype
MATCH (p:Plan)
WHERE p.valence > 0.5 AND p.status = 'completed'
WITH p.strategy AS strategy, collect(p) AS plans
WHERE size(plans) >= 3
RETURN strategy, plans
```

Then LLM synthesizes the common pattern into a Procedure.

**Feedback loop**: After applying a procedure, `report_outcome` creates `APPLIED_PROCEDURE` edge with success flag. `success_rate` and `application_count` update. Poor procedures decay via pathway_strength.
