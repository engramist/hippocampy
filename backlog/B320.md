# B320 - Idempotent Writes: Content-Addressed Deduplication for Retried Captures

State: todo
Priority: P1

Plan: (inline — self-contained, sized for a Sonnet-level implementer)

Depends on: **B312** (uses `source` + `observed_at`; the hash must be stable across retries,
so provenance must exist first). Composes with B315/B316 but does not require them.

### Why

Agents retry. An LLM agent that gets a timeout, a dropped socket, or an ambiguous error will
re-issue the same capture — that is correct client behavior and Campy cannot stop it. Under
a fail-open transport (B318) retries get *more* likely, not less, because soft failures are
invisible to the caller.

Campy currently mints a fresh identifier on every write. `campy/brain/thalamus/tools/capture.py:108`
is `message_id = str(uuid.uuid4())`, and `uuid4` appears across the write paths
(`brainstem/sweep.py` 6 sites, `thalamus/tools/lessons.py` 5, `temporal_lobe/loop/orchestrator.py`
5, `temporal_lobe/dictionary.py` 3, and others). **The same fact captured twice becomes two
nodes**, with different IDs and no relationship between them.

Consequences compound rather than staying cosmetic. Duplicate facts inflate recall bundles and
crowd out genuinely distinct content under a fixed token budget. They corrupt any
frequency-derived signal — `pathway_strength`, valence aggregation, consolidation clustering
all treat "said twice" as evidence, so a network blip reads as reinforcement. And B317's
`ingest_facts` idempotency requirement cannot be met on top of a non-idempotent write layer.

### The Constraint That Shapes This Card

**Do not change primary keys.** Kùzu 0.11.3 cannot alter a primary key in place; changing the
PK of a node table means dropping and recreating it, which destroys every existing edge into
that table. Every user with an existing graph would lose their memory.

So: keep `uuid4` primary keys exactly as they are, add a **`content_hash` column**, and
deduplicate on that at write time. Additive, migration-safe via the existing `_MIGRATIONS`
mechanism (`schema.py:1116`), and reversible.

### What This Card Does

**Task 1 — `content_hash` column.**

Add via DDL + `_MIGRATIONS` to B312's Tier 1 fact-bearing tables:

| Column | Type | Meaning |
|---|---|---|
| `content_hash` | `STRING` | sha256 over the canonical identity of the fact. NULL on pre-B320 rows. |

**Task 2 — Define the hash, carefully.**

New function in `campy/brain/hippocampus/provenance.py` (created by B312):

```python
def content_hash(
    *, table: str, text: str, source: str,
    workspace_id: str = "local", extra: dict | None = None,
) -> str:
    """Stable identity hash for a fact. Same inputs -> same hash, forever."""
```

Canonicalization rules — these decide what "the same fact" means, so get them explicit:

- **Include**: table name, normalized text, `source`, `workspace_id`, and any caller-supplied
  `extra` discriminators (sorted keys, JSON with `sort_keys=True`, `separators=(',',':')`).
- **Normalize text** by stripping leading/trailing whitespace, collapsing internal runs of
  whitespace, and applying Unicode NFC. Do **not** lowercase — case can be semantically
  load-bearing in code and identifiers, and folding it merges facts that differ.
- **Exclude** anything that varies between a call and its retry: `observed_at`, `created_at`,
  `session_id`, `message_id`, embeddings, confidence, and every uuid. Including any of these
  makes the hash useless, because a retry would produce a different one — which is the entire
  bug this card fixes.

`workspace_id` is in the hash so the same fact learned in two workspaces stays two distinct
facts. That is correct: they have different owners and different lifecycles, and B316 keeps
them in different databases anyway.

Document the rules in the docstring. Changing them later silently re-partitions every future
dedup decision, so treat the function as a contract with a version constant
(`CONTENT_HASH_VERSION = 1`) included in the hashed input.

**Task 3 — Dedupe on write.**

In the write helper, before inserting a fact-bearing node:

1. compute `content_hash`
2. look for an existing non-superseded row in that table with the same hash
3. if found: **do not insert.** Update the existing row's `last_accessed_at` (where the table
   has it — `Concept` does; check per table), optionally bump `pathway_strength` if that is
   the existing reinforcement convention, and return the existing node's id
4. if not found: insert with the hash set

The return value must be indistinguishable between the two branches, so a retrying caller
gets the same node id it would have gotten the first time and any follow-up edge attaches to
the right node.

Step 3's reinforcement question needs a judgement call: a genuine re-observation arguably
*is* reinforcement, while a retry is not, and Campy cannot tell them apart from content alone.
**Default to not reinforcing on a dedup hit** — under-counting reinforcement is recoverable,
while inflating it from network retries poisons ranking in a way nothing later can undo. Note
the decision in the code comment.

**Task 4 — Explicit idempotency keys for callers that know better.**

Add an optional `idempotency_key` parameter to the capture write path. When supplied, it
replaces the content hash as the dedup key. This lets a well-behaved client (the external
platform's agent runtime, for instance) guarantee exact-once semantics for a specific logical
write even when the text differs slightly between attempts — which content hashing alone
cannot catch.

Keep it optional. Content hashing is the floor for clients that do nothing.

**Task 5 — Scope, deliberately narrow.**

Apply to `campy/brain/thalamus/tools/capture.py` and `lessons.py` (`upsert_lesson`) only —
the same two paths B312 and B315 converted. Do **not** touch `sweep.py`,
`temporal_lobe/loop/*`, or `dictionary.py` in this card: those are internal consolidation
paths where the daemon controls the call and retries are not the failure mode. They can be
converted later against the ratchet pattern if they prove to need it.

**Do not backfill `content_hash` on existing rows.** A backfill would surface pre-existing
duplicates and tempt an automated merge, which is a destructive operation against real user
memory and belongs in its own card with its own dry-run. NULL means "written before B320" and
must be treated as never matching.

### Acceptance Criteria

- [ ] Capturing identical content twice produces **one** node, and both calls return the
      same node id
- [ ] The second call does not raise, does not warn, and is indistinguishable from the first
      in its return shape — a retrying agent cannot tell it was deduped
- [ ] Text differing only by leading/trailing whitespace, internal whitespace runs, or
      Unicode normalization form deduplicates
- [ ] Text differing by **case** does **not** deduplicate
- [ ] Same text from a different `source` does not deduplicate
- [ ] Same text in a different `workspace_id` does not deduplicate
- [ ] `content_hash()` is stable across process restarts and across calls separated in time —
      assert by hardcoding an expected digest for a fixed input in the test, so an accidental
      change to canonicalization fails loudly
- [ ] A row with NULL `content_hash` (pre-B320) never matches anything and is never updated
- [ ] `idempotency_key` deduplicates two calls whose text differs
- [ ] A dedup hit does **not** increase `pathway_strength`
- [ ] Superseded rows (B312) do not block a re-capture — capturing content identical to a
      superseded fact creates a new live node
- [ ] `pytest tests/ -q` failure set identical to pre-change baseline

### What This Card Does NOT Do

- Does not change any primary key (see the constraint above — this is the load-bearing
  decision of the card)
- Does not backfill `content_hash` onto existing rows
- Does not merge or clean up duplicates that already exist in a user's graph — separate card,
  needs a dry-run and a human in the loop
- Does not convert `sweep.py`, `temporal_lobe/loop/*`, or `dictionary.py`
- Does not do semantic/near-duplicate detection — this is exact-content dedup only.
  Embedding-similarity merging already exists elsewhere in Campy (`MergeEvent`,
  `DisambiguationEvent`) and is a different mechanism with different risks.

### Outcome

A retried capture stops silently forking memory in two. Frequency-derived signals start
reflecting what actually happened rather than counting network conditions, B317's ingest
idempotency becomes implementable, and B318's fail-open posture stops being a duplicate
generator when a write buffer is eventually added.
