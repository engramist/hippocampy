# B454 - Retrieval/Consolidation Quality: Benchmark Facts Are Stored But Not Retrievable via ask/compile_context

State: ready
Priority: P1

First valid benchmark run (B446 v4) shows LoCoMo F1 0.011 / deprecation 0.074,
MemoryGym 0%, MemBench 0.0 (with an empty-bundle "100% token savings"
artifact). Direct probes (2026-09-23) show why, in order of leverage:

1. **Consolidation drops these statements as noise.** `Constraint for
   storage_tier: we use S3 Standard.` / `Update: S3 Standard is deprecated;
   migrate ...` log `entities=1-2 concepts=0 noise=1-2` — no Concept/Constraint/
   Decision is created, so `compile_context` has nothing to surface. Check
   Step 4 (`classify_artifact` signals + NOISE_FLOOR gating) against short
   declarative "Constraint ... / Decision ..." turns; B283/ask-eval fixtures
   pass because they seed structured nodes via tool handlers, not via
   `notify_turn` prose.
2. **`ask`/`compile_context` return empty bundles** (`sections: []`,
   "No relevant context was found in memory") even though the raw turns exist
   as `Message` nodes (confidence 0.0, `confidence_low: true`) that
   `current_truth` finds lexically. Decide whether low-confidence Messages
   should ever back an answer, and whether the bundle compiler's relevance
   floor (B305-B307) is too strict for this input.
3. **`system`-role messages are never returned** by `current_truth`
   (user-role ones are) — MemoryGym's observations were written as `system`
   and were unrecallable by construction (harness now writes `user`).
4. **Id-token / multi-word queries miss a just-written, settled Message**
   (`current_truth("memgym_mysterypath_dbg1")` -> 0 results while a single
   alnum token like `quixnar9` hits): underscore/punctuation tokenization in
   the lexical branch is worth checking.
5. MemBench `token_savings_pct` reads 100% because bundles are empty (0
   tokens) — meaningless until bundles have content; consider reporting N/A
   when `bundle_tokens_avg == 0`.
