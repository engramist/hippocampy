# B223 - Persona-Isolated Wiki Projections

State: complete
Priority: P1

Plan: backlog/plans/B-223-persona-isolated-wiki-projections.md

### Problem

A single generated wiki view will either be too broad or too generic. Engineers, researchers, product thinkers, and personal planning personas need different browsing surfaces over the same graph.

Without explicit persona isolation, a wiki projection can recreate the same context-bloat problem it is meant to solve.

### What This Card Does

Extends the wiki projection system so each persona gets an isolated read-only Markdown tree with its own filters, page templates, ranking, and budget.

Personas are projection views only. They do not create separate source-of-truth memory stores.

Each persona must be easy to browse in Obsidian: it gets its own `Home.md`, index pages, and bounded local link graph inside the shared vault.

### Acceptance Criteria

- [x] Multiple personas can be configured with distinct output directories.
- [x] Each persona has independent include/exclude filters.
- [x] Each persona has independent page and character budgets.
- [x] Each persona gets `Home.md`, `Index.md`, `Topics.md`, and `Sources.md` pages.
- [x] `sidequests wiki open --persona <name>` opens or points to that persona's home page when supported.
- [x] Persona pages use relative Obsidian links that stay inside the persona tree unless a cross-persona link is explicitly marked as shared.
- [x] Generated front matter includes the persona name.
- [x] No generated page in one persona links to private filesystem paths in another persona tree.
- [x] Default persona still works when no personas are configured.
- [x] Persona projection does not duplicate or fork graph nodes.
- [x] Persona filters are applied before relationship expansion to reduce fan-out and token bloat.

### Outcome

The wiki becomes browsable in the way humans actually think: same graph, different lenses, no duplicated truth.
