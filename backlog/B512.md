# B512: run all-MiniLM-L6-v2 with ONNX Runtime directly, drop fastembed (and pillow's 37 CVEs)

**Status:** complete (2026-10-24) · **Principle:** 6 (measure correctly before believing) · **Resolves:** B500

## Why

`fastembed==0.8.0` caps `pillow<13` in every release, which pinned Campy to pillow 12.3.0 and its
37 advisories (B500, `.github/security-tracked.json`). Campy uses fastembed for text embeddings
only, one model: `sentence-transformers/all-MiniLM-L6-v2` via `qdrant/all-MiniLM-L6-v2-onnx`.
`onnxruntime` and `tokenizers` were already installed as fastembed's dependencies.

## What fastembed 0.8.0 did for this model (read from the installed source)

- Files: HF repo `qdrant/all-MiniLM-L6-v2-onnx`, `snapshot_download` with patterns `model.onnx`,
  `config.json`, `tokenizer.json`, `tokenizer_config.json`, `special_tokens_map.json`
  (`preprocessor_config.json` is requested but unused for text).
- Cache: `$FASTEMBED_CACHE_PATH`, else `<tempdir>/fastembed_cache` (NOT the shared HF cache,
  contrary to the old comment in `embeddings.py`). Local cache is tried first; `HF_HUB_OFFLINE` in
  {1,true,yes,on} or `local_files_only=True` forbids the network.
- Tokenizer: `Tokenizer.from_file`, truncation at `model_max_length` = 256, right-padding to the
  longest in the batch with `pad_token_id` 0.
- ONNX inputs: `input_ids`, `attention_mask`, `token_type_ids` (zeros), int64. CPU provider,
  `ORT_ENABLE_ALL`, default ONNX Runtime threads (fastembed pins `threads=1` only in its
  parallel worker processes, which Campy never used).
- Output: first output (last hidden state, float32), attention-masked mean pooling in float64
  (float32 x int64 promotes), L2 normalisation (eps 1e-12). Result float64, shape (n, 384).
- Batching: 256 texts per ONNX call.

## What changed

- New `campy/brain/hippocampus/graph/onnx_embedder.py` (`OnnxTextEmbedder`) reproduces the above.
  Cache lookup order: `FASTEMBED_CACHE_PATH` (kept for the Dockerfile), else an existing
  `<tempdir>/fastembed_cache` left by an earlier install (so no re-download), else the standard
  huggingface_hub cache. Only `all-MiniLM-L6-v2` is supported (fastembed supported others, but the
  schema is `FLOAT[384]` and no config used another); anything else raises a clear `ValueError`.
- `embeddings.py` and `cli/install.py` switched over; public signatures unchanged
  (private `_fe_model`/`_get_fe_model` renamed `_onnx_model`/`_get_onnx_model`).
- `pyproject.toml` / `requirements.txt`: `fastembed==0.8.0` replaced by `onnxruntime==1.29.0`,
  `tokenizers==0.23.2` (exact pins, same rationale as fastembed's: vectors are schema-load-bearing),
  `huggingface_hub>=0.24`, `numpy>=1.26`.
- `deploy/Dockerfile` bakes the model through the new module (not built in this change; no Docker
  here). `FASTEMBED_CACHE_PATH` keeps its name.
- Pillow: see the decision below.

## Parity (measured, old fastembed 0.8.0 vs new module, same machine and model files)

2,259 texts: 113 sentences from `campy/data/GistSeedExamples.md` (the B353 source), 2,121 real
texts from a copy of a benchmark store's `vectors.db` (`~/campy-lead/stores/r88`, copied first,
opened read-only), and 25 edge cases (empty, whitespace, code, non-English, emoji, literal special
tokens, 250 to 300 tokens around the 256 limit, 5,000-character strings).

| | result |
|---|---|
| cosine min / mean / max | 1.0 / 1.0 / 1.0000000000000002 |
| max absolute difference | 0.0 |
| bit-identical vectors | 2,259 of 2,259 |
| vector norm difference | none (max 0.0; all norms within 2e-16 of 1) |
| single-text call path (first 300) | max abs diff 0.0 |
| dtype / shape | float64 / (n, 384), both |

Required cosine >= 0.9999; achieved exact equality. `tests/test_onnx_embedder.py` keeps a golden
file produced by fastembed (`tests/fixtures/onnx_embedder_golden.json`) and, wherever fastembed is
still installed, a live bit-for-bit comparison.

## Offline and cache checks (no network)

- Pre-populated HF cache, `HF_HUB_OFFLINE=1`, bogus `HTTPS_PROXY`, no legacy tmp cache: loads, norm 1.
- Same with `FASTEMBED_CACHE_PATH` pointing at the cache: loads.
- Offline with an empty cache: `FileNotFoundError`, surfaced by `embeddings.py` as the existing
  "Embedding model not found in local cache" message.
- Online first run into an empty `HF_HOME`: downloads 5 files (87 MB), then loads offline from it.

## Memory (macOS `vmmap` physical footprint, fresh process, 3 runs each, MB)

Process imports `embeddings`, pre-warms, embeds 1,000 real texts in one `embed_batch`:

| stage | old (fastembed) | new (direct) |
|---|---|---|
| after prewarm, no spaCy | 222.5 - 223.4 | 211.1 - 211.7 |
| after prewarm, spaCy loaded first | 247.9 - 248.8 | 242.7 - 246.9 |

Net: about 10 MB less at rest, nothing changes under load. The 1.2 GB after one 1,000-text batch
is pre-existing and identical in both (ONNX Runtime's arena growing with 256-wide padded batches);
filed as B513.

## Pillow decision

`campy/cli/indicator.py` imports PIL (to draw a 22x22 status-icon circle in memory). Pillow was
already declared directly, in the `indicator` extra (`pystray`, `Pillow>=10.0`), and the import is
inside `_make_icon_image`, behind that extra; the base install never needed it except as
fastembed's transitive dependency. Decision: keep the extra, raise its floor to `Pillow>=13.0.0`
(fixes the tracked advisories; `pip install --dry-run '.[indicator]'` resolves pillow 13.0.0).
Base install now has no pillow and no indicator crash path that did not already exist. The
`pillow` entry is removed from `.github/security-tracked.json`.
