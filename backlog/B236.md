State: complete -- both previously-unmet acceptance criteria closed 2026-08-18: `hippocampy` 0.1.0 published to real PyPI, README relabeled, TestPyPI dry run explicitly skipped with a recorded reason -- see "Publish Closure (2026-08-18)" below; tracked by B327

### Problem

Campy now builds clean wheel/sdist artifacts, but the project does not yet have a confirmed public package install path. A true one-click installer should not require cloning the repository; it should be able to install Campy from a published package using `pipx`, `uv tool`, or plain `pip` in a managed virtual environment.

### What This Card Does

Prepares and validates the canonical package distribution path for Campy: package metadata, package data, release audit, TestPyPI dry run, PyPI publish checklist, and installed-mode smoke tests.

This card does not force public publication if release ownership is not ready. It creates the exact publish workflow and validates it against TestPyPI or a local package index first.

### Re-verification Notes (2026-08-03)

Re-ran every acceptance criterion against real commands/tools rather than trusting the commit history. Used a real Python 3.12 venv (`/opt/homebrew/bin/python3.12`) since the ambient system Python is 3.14, which `pyproject.toml` deliberately excludes.

**What actually passed (real command output, not mocked):**
- `python -m build --wheel --sdist` — succeeded, produced `hippocampy-0.1.0-py3-none-any.whl` and matching sdist.
- `python -m twine check dist/*` — `PASSED` for both wheel and sdist.
- `bash scripts/audit_public_release.sh --release` — `AUDIT PASSED: No high-risk patterns detected`; wheel/sdist content scan clean (194 files in wheel, 0 suspicious entries — no `brain.db`, `.sock`, `.log`, `submission_results`, `agent_execution_trace`).
- Fresh venv install of the wheel: `campy --help`, `campy doctor --help`, `campy install --help`, `campy activity --help` all exited 0 with usage text.
- `pipx install dist/hippocampy-0.1.0-py3-none-any.whl` (isolated `PIPX_HOME`/`PIPX_BIN_DIR`) — installed cleanly, `campy --help` worked, `pipx uninstall hippocampy` cleaned up without error.
- `uv tool install dist/hippocampy-0.1.0-py3-none-any.whl` (isolated `UV_TOOL_DIR`/`UV_TOOL_BIN_DIR`) — installed cleanly, `campy --help` worked, `uv tool uninstall hippocampy` cleaned up without error.
- `pytest -q tests/test_public_release_manifest.py tests/test_packaging_installed_mode.py tests/test_release_build.py` — **32 passed**, real (non-mocked) subprocess-based tests that actually build wheels and pip-install them into throwaway venvs.

**Two real, unresolved gaps (not fixed — require an owner decision, not a mechanical edit):**

1. **README does not label install-command publish status, and is misleading as written.** `README.md`'s Quickstart says `pipx install hippocampy` with no caveat. But `docs/homebrew-install.md` (line 3) states explicitly: *"Campy is not yet published to PyPI and the `engramist/hippocampy` repository is not yet public."* Confirmed independently: `pip index versions hippocampy` → `ERROR: No matching distribution found for hippocampy`. So the literal top-of-README command does not work today, and nothing in the README says so. This is a real failure of the specific AC "README ... clearly labels it as public, private, or pending" — not a typo-level fix, since the right wording/placement is a product-messaging call for the repo owner, not something safe to guess at silently.
2. **TestPyPI dry-run has no completion or skip record.** `docs/release-publish-checklist.md` documents *how* to do a TestPyPI dry run but nothing records that one was ever run, or a reasoned decision to skip it (e.g. "skipped — release ownership not ready per problem statement"). The AC requires one or the other explicitly.

Given B236's own problem statement ("This card does not force public publication if release ownership is not ready"), gap 1 most likely should be resolved by adding an honest "not yet published — install from source or via `campy install` script" note, and gap 2 by writing down that TestPyPI was intentionally deferred. Both are copy/documentation decisions for whoever owns the actual release, so left as documented gaps rather than being fixed inline here.

### Publish Closure (2026-08-18)

`hippocampy` 0.1.0 published to real PyPI: https://pypi.org/project/hippocampy/0.1.0/
(tracked by [B327](B327.md)). Closes both gaps recorded above:

- **TestPyPI dry run:** explicitly skipped rather than executed. No separate
  test.pypi.org account/token was available, and build, `twine check`, the
  release audit, and packaging tests had already passed repeatedly against
  the real wheel/sdist — the residual risk a dry run would have caught
  (does the package actually install and run) is exactly what Step 4's
  post-publish verification checked instead (clean venv install, `campy
  --help`, `campy doctor --help`, all exit 0).
- **README publish-status labeling:** no longer needed — the Quickstart and
  Install sections now name `pipx install hippocampy` as the single
  recommended path without a status caveat, since it is genuinely true.

Also found and fixed in the course of this closure: `scripts/release_build.sh`
ran the `--release`-mode audit (which requires `dist/` to already contain
built artifacts) *before* the build step that creates `dist/`, so
`--release` mode could never pass from a clean checkout. Reordered to
build → `twine check` → audit → packaging tests → upload.
