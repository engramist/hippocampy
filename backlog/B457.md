# B457 - Cloud Deployment: Finish What B385 Claimed (REST Workspace Isolation, 12-Factor Env Config, Container Assets)

State: ready
Priority: P0
Depends on: B385 (parent, reopened), B316, B325, B328, B456

## Why

B385 was marked `complete` with every box ticked, but it reached `main` as a
restored backlog card (d3ef540) with no implementing PR. The 2026-09-29 audit
(see "Re-verification Audit" in [B385](B385.md)) found that only work from other
cards is on `main`: the bind guard (B325), `/mcp` workspace routing and
directory sharding (B316), and `CAMPY_HOME` (B456). All of B385's own
deliverables are missing. One gap is a correctness/security problem, not a
missing nicety:

- **REST is not workspace-isolated.** `campy/brain/brainstem/rest_api.py::create_router`
  runs every `/api/v1/*` tool against the one `db` passed at mount time and
  ignores `request.state.principal`. With the dashboard on and `auth = "iam"`,
  every authenticated tenant reads and writes the same database over REST,
  while `/mcp` correctly routes per workspace.
- **Minimal cloud mode removes REST entirely.** With `dashboard_enabled = false`,
  `web/server.py` keeps only `/health`, `/mcp` and `/sse`. The "dual ingress"
  B385 promised is therefore either unavailable or unisolated.

## Scope

Fix the REST items first. Leaving REST unisolated is a cross-tenant leak, so
item 2 must land before, or together with, item 1.

1. **REST in minimal mode.** Keep `/api/v1/*` when `dashboard_enabled = false`
   (`web/server.py` `allowed_paths`). UI, static and admin routes must still 404.
2. **REST workspace routing.** Pass `router` into `rest_api.create_router` and
   resolve each request's db from `request.state.principal.workspace_id`, in the
   same way `_dispatch_mcp` does, including `router.release()` on every exit path.
   Thread the principal into tool calls the way `route_tool_call` does so that
   B315's forbidden-key guard also applies to REST.
3. **12-factor env overrides** in `campy/brain/brainstem/config.py`:
   `CAMPY_SERVER_AUTH`, `CAMPY_SERVER_BIND_HOST`, `CAMPY_SERVER_DASHBOARD_ENABLED`,
   `CAMPY_IAM_WORKSPACE_MAP_JSON`, `CAMPY_IAM_TENANT_MAP_JSON`. Env wins over
   `campy.toml`. Malformed JSON fails startup loudly and never falls back to an
   empty map. The bind guard must see the overridden values.
4. **`CAMPY_DATA_DIR`.** Decide whether it is still needed now that `CAMPY_HOME`
   exists (B456). If it is, define precisely what it splits off from
   `CAMPY_HOME`. Otherwise drop it from the spec and record why.
5. **Enriched `GET /health`.** Return RSS, version and storage health. It must
   stay unauthenticated and cheap enough for ALB probes, and must not leak
   workspace ids.
6. **Container assets** under `deploy/`: a multi-stage `Dockerfile`
   (`python:3.12-slim`, non-root UID 1000, embedding model pre-baked,
   `HF_HUB_OFFLINE=1`), `docker-compose.yml` for local parity, and
   `ecs-task-definition.json` with an EFS mount.
7. **Multi-task writer safety.** `WorkspaceRouter`'s lock is an in-process
   `asyncio.Lock`, so two Fargate tasks on one EFS mount can open the same
   workspace. Either enforce one task (document `desiredCount: 1` and add a
   cross-process lock on the workspace dir), or prove the store tolerates it.
   Do not claim "single-writer" until one of these is in place.
8. **Integration doc.** Write a vendor-neutral `docs/cloud-deployment.md`, or
   extend `docs/deployment-agentcore.md`. It must name no customer (this is a
   public repo, see engramist/hippocampy#209 and B426).
9. **Tests.** Add `tests/test_cloud_deployment_readiness.py`, covering:
   - REST in minimal mode;
   - REST per-workspace isolation: two principals must never see each other's writes;
   - env overrides and the malformed-JSON failure;
   - the bind guard under env overrides;
   - the `/health` shape.

## Acceptance Criteria

- [ ] With `dashboard_enabled = false`, `/health`, `/mcp`, `/sse` and `/api/v1/*` are routable, and `/`, `/static/*` and `/api/node/*` return 404.
- [ ] A REST write by a principal in workspace A is not visible to a REST read by a principal in workspace B (test against real stores, not mocks).
- [ ] Each listed `CAMPY_*` env var overrides `campy.toml`. Malformed JSON aborts startup.
- [ ] `CAMPY_SERVER_BIND_HOST=0.0.0.0` with no auth set still trips the bind guard.
- [ ] `docker build -f deploy/Dockerfile .` succeeds. The container runs as UID 1000, starts with networking disabled, and serves `/health`.
- [ ] The writer-safety decision (item 7) is implemented and documented.
- [ ] `tests/test_cloud_deployment_readiness.py` passes.
- [ ] B385's "Re-verification Audit" is updated to point at the merged PR(s), and B385 is closed.
