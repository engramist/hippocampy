### Problem

`current_truth` returns a flat ranked list of results. But agents solving real tasks need assembled context: exact constraints alongside semantic context alongside relational structure alongside tabular data alongside synthesized summaries. Today, agents must make multiple tool calls and assemble context themselves — burning tokens on plumbing instead of reasoning.

This is the "rediscovery tax" problem: agents spend up to 85% of their token budget re-learning what the system already knows, because the system delivers raw ingredients instead of a prepared meal.

### What This Card Does

Builds the retrieval intelligence layer that assembles heterogeneous context from all memory types into a shaped `ContextBundle`, compressed to fit the requesting agent's token budget.

### Dependencies

- B249 recommended but not required (tabular queries enrich bundles, but the compiler works without them)

### Design Decisions

| Decision | Choice | Rationale |
|---|---|---|
| New tool vs. upgrade | New `compile_context` tool + keep `current_truth` unchanged | Backwards compatible; agents opt in to bundles |
| Token budget tiers | Small (4K-8K), Medium (32K-128K), Large (200K+) | Matches real agent context windows |
| Assembly strategy | Pipeline: semantic → exact → graph → tabular → summaries | Most important first; truncate from the tail |
| Provenance | Every bundle section includes source node IDs | Auditable; agents can cite sources |

### Audit Findings (2026-08-03 re-verification)

`tests/test_bundle_compiler.py` is **100% mock-based** — every `TestCompileBundle` test uses `mock_db = mocker.MagicMock()` with `mock_db.execute = mocker.MagicMock(return_value=[])`. `.venv/bin/python -m pytest -q tests/test_bundle_compiler.py` → 25 passed, but reading `campy/brain/thalamus/bundle_compiler.py` (not just the tests) shows why that passes trivially:

- **`_stage_graph_structure()` is a literal placeholder.** Its entire body is:
  ```python
  # For now, return minimal structure
  # In production, would traverse 1-2 hops from semantic result nodes
  return BundleSection(section_type="graph", content=[], token_estimate=0, source_node_ids=[])
  ```
  It never queries the graph. **Acceptance criterion "Graph structure (1-2 hop traversals) is included for entity relationships" is not met — no traversal code exists at all.**
- **`_stage_tabular_data()` is a literal placeholder.** Its entire body is:
  ```python
  # Check if any semantic results have DESCRIBED_BY_DATASET edges
  # If so, call tabular_store.get_table_summary() and include
  return BundleSection(section_type="tabular", content=[], token_estimate=0, source_node_ids=[])
  ```
  It never checks for `DESCRIBED_BY_DATASET` edges or calls `get_table_summary()`. **Acceptance criterion "Tabular data from Dataset nodes is included when linked to query results" is not met** — this is doubly confirmed by B250's audit finding that nothing ever creates a `DESCRIBED_BY_DATASET` edge in the first place, so even a correct implementation here would currently have nothing to find.
- **`_stage_summaries()` is a literal placeholder.** Same pattern — comments describing intended behavior, body returns `content=[]` unconditionally. **Acceptance criterion "Wiki summaries are included when available for relevant topics" is not met.**
- Because every test mocks `db.execute` to return `[]`, and stages 4-6 return `content=[]` unconditionally regardless of what the DB would return, none of the existing tests could ever have caught this — the mock and the stub produce identical (empty) output whether or not the DB has real linked data.
- **What is genuinely implemented and works:** Stage 1 (exact facts: `GlobalConstraint`/`GlobalPreference` via real cosine-similarity Cypher), Stage 2 (plan lane via `recall_plans_for_query`), and Stage 3 (semantic context: `Concept`/`Decision`/`Constraint`/`Requirement` via real cosine-similarity Cypher) all issue real, non-trivial Cypher and are structurally sound. Budget-tier logic (`small`/`medium`/`large`), truncation-on-budget-overrun, and source deduplication are also real and correctly implemented — verified by reading the full `compile_bundle()` pipeline logic, not just the tests.
- `current_truth` continues to work unchanged: confirmed, untouched code path, full suite green.
- `compile_context` MCP tool works end-to-end for the *implemented* stages: wired correctly in `campy/brain/thalamus/tools/context_tools.py::compile_context`, calls `compile_bundle()` then `format_bundle()`. Not separately smoke-tested against a live DB in this pass beyond what's already covered by the B249/B250 smoke tests, since the gap is unambiguous from source inspection (explicit "Placeholder" comments, not a subtle bug).
- Provenance trail: present for the three real stages (`source_node_ids` populated); moot for the three stub stages since they never produce content.
- Full suite: `.venv/bin/python -m pytest -q` → 1600 passed, 59 skipped, 2 xfailed (no regressions).

Half of this card's flagship pipeline is unbuilt. Not attempted as a trivial fix — implementing real 1-2 hop graph traversal, tabular-summary inclusion, and wiki-summary lookup are each non-trivial features in their own right, consistent with the audit brief's instruction to document rather than attempt a full fix for a real gap.

### Implementation (2026-08-03)

All three stubs flagged above are now implemented, TDD-first against a real Kuzu DB (`tests/test_bundle_compiler_stages.py`), following the same pattern already used for `_stage_exact_facts`/`_stage_semantic_context`/`_stage_graph_structure`: one Cypher `MATCH` per label (never `UNION`, per B280's binder rejection of cross-table `UNION ALL`), 0.30 cosine-distance threshold, real fixture data, no `db.execute` mocking.

- **`_stage_tabular_data`**: `MATCH (n:Concept)-[:DESCRIBED_BY_DATASET]->(d:Dataset) WHERE ... AND d.archived = false`, then `tabular_store.get_table_summary(dataset_id, sample_rows=...)` per matched Dataset (SQLite file read, not graph data). Tier-gated: `include_raw_tabular=False` (small tier) omits `sample_rows` entirely; `True` includes up to `max_tabular_rows`. Respects `remaining_budget` by stopping once the next entry's estimated tokens would exceed it. 7 real-Kuzu tests cover: no edge → `None`, anchor doesn't match query → `None`, zero budget → `None`, archived dataset excluded, matching case returns dataset metadata + schema + row count, and both tiers' `sample_rows` behavior. As predicted by the B250 audit, this stage returns `None` against real production data today because nothing yet creates a `DESCRIBED_BY_DATASET` edge — that's a B250 gap, not a B252 one; the mechanism itself is real and tested.
- **`_stage_summaries`**: live embedding-similarity queries over `Lesson` (`lesson_type = 'synthesis'`, `archived = false`) and `Procedure` (`archived = false`) nodes — the same node types `wiki_projection.py` renders into persona wiki pages. Queries the graph directly rather than reading exported `.md` files from the wiki vault, since `wiki_projection` is disabled by default (`config["wiki_projection"]["enabled"]`) and exporting is a batch sweep operation, not something that runs per-query. 5 real-Kuzu tests cover: no match → `None`, zero budget → `None`, matching Lesson + Procedure both included, archived Lesson excluded, non-synthesis Lesson excluded.
- Deliberately not implemented: an LLM-generated-summary fallback (mentioned in the original plan as a secondary path). That's a separate, non-trivial feature (LLM call + cost/latency tradeoffs) and the Lesson/Procedure path already satisfies the acceptance criterion for real, tested data.
- Full suite: `.venv/bin/python -m pytest -q` → 1649 passed, 31 skipped, 2 xfailed (no regressions).

### Outcome

Agents can request a complete, shaped context bundle with one tool call instead of assembling context from multiple raw queries. This is the flagship feature of the Campy Memory OS upgrade.
