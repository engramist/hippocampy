# B544: entity admission: every named entity of a user turn becomes a Concept (flag, default off)

**Status:** Implemented behind `[loop] entity_admission` (env `CAMPY_ENTITY_ADMISSION`, default off). Offline replay done (below). Pending GPU gate R105 vs R104 (unseen LoCoMo conv-26/41/48/49/50) before the default flips.

**Principles:** P8 (a fact hangs off an object entity, so the entity has to exist as a node first), P3 (spaCy marks, one declared rule writes; nothing a model says decides), P7 (one lever, behind a flag, current path untouched when off).

**Lever and target.** One lever: step 1's named entities are stored whatever Loop steps 2 and 4 decide. Target metric: LoCoMo categories 1-4 accuracy, through the list and set questions ("What books has Tim read?") whose object entities were never in the graph. The B542 prototype measured the rule half offline: named entities stored 81/248 -> 248/248 (design conversations) and 65/174 -> 174/174 (held-out). This card ships that rule. It does not by itself change a prompt (see Measured); the readers that use the entities are later levers.

**Why.** spaCy labels "The Name of the Wind" `WORK_OF_ART`; step 2 (whole-message embedding against seven software gist centroids, noise floor 0.18) and step 4 (decision / constraint / requirement / action-item gate, floor 0.60) then drop it. Both were built for an early developer-decision tracker (B543 deprecates them as the gate).

## What it does

In `run_loop`, right after step 1 (spaCy) and surface normalisation, for a **user** turn with the flag on:

1. Each entity whose label is in the closed set `PERSON, WORK_OF_ART, GPE, ORG, PRODUCT, LOC, FAC, EVENT, NORP` is resolved to a Concept by the existing lookups (`orchestrator.find_concept_by_exact_text`, then `orchestrator.find_concept_by_label_text`, the pair `_store_concept` uses); if neither finds one, a Concept is created with the existing `temporal_lobe.dict_create_concept`.
2. `Concept.ner_label` is set (first label wins; never overwritten).
3. `Message -MENTIONS-> Concept` is written (`concept_links.link_message_concept`).

Not done on purpose: no `INSTANCE_OF` / kind from the NER label (B540 audit: NER-label kinds 37% wrong); no quoted-title span rule (not added; would be its own lever); assistant turns admit nothing (assistant text is not evidence; ISSUE-024); `DATE/TIME/CARDINAL/ORDINAL/QUANTITY/MONEY/PERCENT/LANGUAGE/LAW` are not admitted. Steps 2-7 run as before (B543 is separate): `_store_concept` dedups on exact text, so it finds the admitted Concept and creates no second one.

## Guard (independent of the flag)

`entity_admission.can_be_kind` is false for a Concept with `ner_label` set or `schema_org_type = Person`. `kinds.mark_kind` now checks it and returns False (writes nothing); `entities.resolve_kind` drops the kind proposal when it is refused; the `is_a` path in `concept_links.link_observation_concepts` writes no edge on such a parent. Found in the prototype: a kind label equal to a person's name reused the person's Concept and marked it a kind. With the flag off this only differs for a Concept the Loop already typed `Person`.

## Graph design

| Written | Where |
|---|---|
| `Concept.ner_label` (string, new column, one property) | `entity_admission.set_ner_label`; schema.py Concept DDL + migration list |
| `Message -MENTIONS-> Concept` (existing plain edge) | `concept_links.link_message_concept` |
| `Concept` (existing node, `gist_class` Entity, `schema_org_type` Thing) | `temporal_lobe.dict_create_concept` |

Read by (so no write-only term): `entity_admission.concept_status` (the kind guard) and `entity_admission.named_entities`:

```sparql
SELECT ?ner_label ?concept_id ?text_raw (COUNT(DISTINCT ?m) AS ?turns) WHERE {
  ?m campy:MENTIONS ?c .
  ?c a campy:Concept ; campy:concept_id ?concept_id ; campy:text_raw ?text_raw ;
     campy:ner_label ?ner_label ; campy:archived false .
} GROUP BY ?ner_label ?concept_id ?text_raw
```

No Python store: the graph is the only state; every write is a named query through the gateway.

## Tests

`tests/test_b544_entity_admission.py` (15): flag default/key-less/env/packaged toml; flag off stores nothing for the D6:8 text and adds no summary key; flag on admits "The Name of the Wind" (WORK_OF_ART), "Nike" (ORG), "Barcelona" (GPE) with MENTIONS when step 2 is forced to drop them; no duplicate Concepts across repeated turns; existing Concept reused and labelled; DATE/CARDINAL admit nothing; assistant turn admits nothing; no kind or INSTANCE_OF written; guard tests (named entity, Person-typed, plain concept still a kind, `resolve_kind` refuses a person's name); the read query.

## Measured (offline, no GPU)

Fresh copy of the R104 store (5 unseen LoCoMo conversations, 2,840 user turns, 614 Concepts), `CAMPY_HOME` on the copy. Replay = step 1 (+ normalisation) on every user turn, then `admit_entities` (the exact function the flagged `run_loop` calls); the full Loop was not re-run (it needs the LLM). Unique entities by `norm_key`, found / already stored / stored after:

| label | found | before | after |
|---|---|---|---|
| PERSON | 73 | 33 | 73 |
| GPE | 33 | 8 | 33 |
| ORG | 28 | 7 | 27 |
| WORK_OF_ART | 11 | 7 | 11 |
| LOC | 8 | 2 | 8 |
| NORP | 5 | 2 | 5 |
| FAC | 3 | 1 | 3 |
| PRODUCT | 3 | 1 | 3 |
| all | 154 | 52 | 153 |

Concepts 614 -> 717; 1,430 turns got a MENTIONS from admission. Keys with more than one live Concept: 12 before, 14 after (new: "Frank Ocean" vs span "the Frank Ocean" typed LOC by spaCy, and "Rio de Janeiro" vs span "Rio de Janeiro-"; the lookups are exact-text, so span noise from step 1 is not merged). The one miss is "Pride month" (ORG), not matched by key after (not investigated). Precision is spaCy's: "Love" and "nature" are WORK_OF_ART spans, "Summer Sounds"- The playing an" a span error.

Rendered prompt (`compile_bundle` + `ask._bundle_to_prompt`) for "What books has Melanie read?" on the store before and after: byte-identical (7,469 characters). Admission adds nodes and MENTIONS, but with `graph_linking_limit = 0` and no reader of `ner_label`, the bundle does not use them yet. So this lever alone is expected to move the score by little; it is the precondition for the kind and walk levers (B542 item 2).
