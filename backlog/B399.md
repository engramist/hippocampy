# B399 - Restore Green CI on main: Failing Test + Hang Since B386

State: ready
Priority: P0
Branch: feat/b399-restore-green-ci
PR Target: main

### Problem

CI has been red on `main` since commit `d35b28b` (the B386 GraphGateway merge). The
break bisects cleanly — every run before it passes, every run from it onward fails:

```
success  5f7a52d   B380 merge
──────────────────────────────────── breaks here
failure  d35b28b   B386 merge (GraphGateway chokepoint, 592 Cypher lines migrated)
failure  ae75710 / 3407340 / e1db5c4 / 8a48aa9 / 88315dc / 5f16238
```

B386 was merged with `gh pr merge --admin` on local verification while CI was
stalled, so the regression was never caught at the gate. Every merge since has
inherited a red baseline, which is why "CI is flaky" became the working assumption.

There are **two independent problems**:

1. **A genuine test failure** — an `F` appears at ~18% of the run.
2. **A hang** at ~21% that never returns. The job is cancelled at ~5m23s.

### Contributing factor: nothing fails fast

- `.github/workflows/tests.yml:50` runs `pytest tests/ -q` with **no `--timeout`**,
  even though `pytest-timeout` is installed and available.
- The `pytest` job has **no `timeout-minutes`**.
- `pytest.ini` sets no global timeout.

So a hung test consumes the runner until an outer cancellation kills it, and the
log shows no indication of *which* test hung. A local run with
`--timeout=60 --timeout-method=thread` reproduces and names it.

### Scope

1. Identify and fix the failing test (`F` at ~18%).
2. Identify and fix the hang (~21%). Both regressions date to B386's query
   migration, so start by diffing what B386 changed in the relevant module.
   **If a test is wrong rather than the code, say so explicitly with evidence** —
   do not delete or `xfail` a test to get green. A silently disabled test here is
   worse than a red build, because the red build is at least honest.
3. Add `--timeout=60 --timeout-method=thread` to the CI pytest invocation (or
   `timeout` in `pytest.ini`) so a future hang fails fast and names itself.
4. Add `timeout-minutes` to the `pytest` job as a backstop.
5. Consider a `concurrency` group on the workflow so superseded pushes cancel
   cleanly and don't read as failures.

### Acceptance Criteria

- [ ] Root cause of the failing test identified and stated in the PR.
- [ ] Root cause of the hang identified and stated in the PR.
- [ ] Full `pytest tests/` passes locally and in CI, with no test deleted, skipped,
      or `xfail`ed to achieve it. Any test legitimately needing an `xfail` carries a
      written justification.
- [ ] CI fails fast and names the test on a future hang.
- [ ] `main` is green.

### Outcome

`main` returns to a trustworthy green baseline, so the "wait for green CI before
merging code" policy is actually enforceable rather than permanently blocked.
