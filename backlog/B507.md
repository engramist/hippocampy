# B507: SHACL shapes for Observation/Concept, a rule gate on extracted claims, a graph structure report

**Status:** open (PR pending gate) · **Step 1 of 3** in the graph-structure plan (1 SHACL, 2 SKOS vocabulary, 3 OWL typed properties)

## Problem

Campy validates model-extracted Observations in scattered Python (`_validate_shape` in
`hippocampus/observations.py`, the parsing in `temporal_lobe/observations/extract.py`). There is no
declarative statement of what a valid Observation or Concept is, no way to run that statement over a
whole store, and no structure measure to track next to the benchmark score. Stores built by real runs
show the cost: 3-7% of Observations (15-26% of `has_attribute` rows) carry a stringified dict/list as their object (B506), Concept
labels include stopword-only fragments, only ~1.5% of Observations in LongMemEval stores link to a
Concept, and 1-8% of `has_attribute` objects have the `name: value` form the extractor is asked for.

## Change

1. `campy/brain/hippocampus/shapes/campy_shapes.ttl`: SHACL shapes for Observation, Message, Concept
   and their plain edges (EVIDENCED_BY, OBSERVATION_ABOUT, MENTIONS, SENT_IN, FOLLOWED_BY,
   CO_OCCURS_WITH, HAS_*_LABEL). Observation: evidence Message (a live user turn), subject text or id,
   predicate / polarity / time precision / method from the allowed sets, `observed_at` xsd:dateTime,
   object required and not blank / stopword-only / a stringified dict or list, confidence in
   [0.60, 1], quote is the exact span of the evidence message. `has_attribute` object not of the form
   `name: value` is a sh:Warning only. Concept: preferred label present, not empty, not stopword-only.
2. `shapes/validator.py`: one candidate Observation plus its evidence Message becomes a tiny RDF graph
   and is validated (shapes graph parsed once and cached, ~35 ms per call, pyshacl/rdflib imported
   lazily). `pyshacl` and `rdflib` added to `pyproject.toml` / `requirements.txt`.
3. Gate: `[observations] shacl_gate` / `CAMPY_SHACL_GATE=1`, **default off**. On, `record_observation`
   (new optional `config=` argument, passed by the extraction worker) validates the draft as it would
   be written and rejects a non-conforming one as `shacl_violation`: nothing is written, the rejection
   is counted in `WriteStats.rejected["shacl_violation"]`, failed shapes in `WriteStats.shacl_shapes`
   (merged into the worker stats), and logged without content. Off: the writer is unchanged.
4. `scripts/graph_structure_report.py <store_dir>...`: read-only. SHACL conformance per node type with
   top failing shapes; % Observations linked to a Concept; % user Messages that MENTION a Concept (0
   until B503); Concept count, fragment share, redundant-duplicate rate; % `has_attribute` objects of
   the form `name: value`.

## Not in this card

SKOS prefLabel/altLabel (step 2: re-point the Concept label shape from `text_raw` to `skos:prefLabel`)
and OWL functional properties (step 3). The gate does not replace the Python checks; it runs after
them and adds the structural ones (observed_at present, object not blank/stopword/dict-shaped).

## Gate to flip the default

Fresh-ingest LoCoMo conv-30 + conv-44, main vs branch with `CAMPY_SHACL_GATE=1`; report cat1-4 and
the structure report for both. Flip only on a pooled net gain.

## Principle

2 (graph first: the shapes live next to the graph and validate it), 3 (the model advises; rules
decide), 6 (the structure report is a measure; doubt the writer before the pipeline).
