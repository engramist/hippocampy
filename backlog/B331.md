# B331 - Refresh Stale "Planned, Not Shipped" Disclosures + Close Cypher Ratchet Blind Spot in web/server.py

State: complete — merged via PR #57 (2026-08-20)
Priority: P1

Plan: none yet.

### Problem

An external audit comparing our public disclosures against actual HEAD source found the disclosure
list we'd been giving prospective integrators describes an **older state than HEAD** — several things
described as "planned, not shipped" are already built, substantial code:

| Described as "planned" | Actual state at HEAD (verified again for this card) |
|---|---|
| Multi-tenant workspace isolation | **BUILT** — `hippocampus/graph/router.py` (or wherever the workspace router lives — confirm current path), physical DB-per-workspace |
| Principal derivation from transport | **BUILT** — `campy/brain/auth.py` |
| AWS Bedrock provider | **BUILT** — `campy/brain/llm/bedrock.py` (confirm current path), wired as a provider |
| Backup / restore | **BUILT** — `cli/backup.py` (confirm current path), with checksum verify and schema-version refusal |
| Provenance fields + supersession | **BUILT** — `hippocampus/provenance.py` (confirm current path), `superseded_by`/`evidence_ref` on the majority of node tables |

This under-selling is harmless to correctness but costs credibility with anyone evaluating the project
against a stale description, and means we're not getting credit for work that's already done.

Separately, two smaller documentation-accuracy issues in the same family:

1. **Stale file count**: `docs/ARCHITECTURE.md:1831` says "~500+ lines across 33 files at the time
   this card was written." The actual current count, per the project's own CI-enforced ratchet
   (`scripts/check_cypher_ratchet.py`, baseline at `scripts/cypher_baseline.json`), is 554 lines —
   which matches the "~500" figure fine — but across **46** files, not 33. Confirm the current true
   file count (`grep -rl "execute_raw\|execute_write\|execute_read" campy/ scripts/` or whatever the
   ratchet script itself uses to enumerate) and correct the "33 files" figure wherever it's cited
   (`docs/ARCHITECTURE.md:1831`, and grep for "33 files" elsewhere in the repo — e.g.
   `backlog/B314.md` may reference the same stale number).

2. **Cypher ratchet blind spot**: `scripts/check_cypher_ratchet.py:56` defines
   `SCANNED_PREFIXES = ("campy/", "scripts/")`. `web/server.py` contains raw Cypher (roughly 32 lines,
   per the audit) but lives outside both scanned prefixes, so that file's Cypher coupling is invisible
   to the ratchet that's supposed to track this project's total raw-Cypher debt (the same debt B314
   built the `GraphGateway`/`NamedQuery` abstraction to reduce). This means the "554 lines / 46 files"
   baseline is itself an undercount of true raw-Cypher surface area.

### What it does (scope)

1. Update the public-facing disclosure document(s) — find the actual disclosure list (likely
   referenced from `README.md`, `docs/ARCHITECTURE.md`, or a dedicated
   `docs/`/`.github/` disclosure file; grep for language like "planned" or "not yet shipped" near
   mentions of "workspace isolation," "Bedrock," "backup," "provenance," or "principal derivation" to
   locate it) and move the five items above from "planned" to "shipped," citing the actual file paths.
2. Fix the "33 files" figure at `docs/ARCHITECTURE.md:1831` (and any other citations found via grep)
   to reflect the current true count.
3. Widen `scripts/check_cypher_ratchet.py`'s `SCANNED_PREFIXES` to include `web/` (i.e.
   `("campy/", "scripts/", "web/")`), re-run the ratchet to get the new true baseline line/file count
   including `web/server.py`'s raw Cypher, and update `scripts/cypher_baseline.json` to the new
   numbers. Confirm the ratchet script's CI check (if any — grep for where `check_cypher_ratchet.py` is
   invoked, e.g. in a GitHub Actions workflow or pre-commit hook) still passes against the new baseline.
