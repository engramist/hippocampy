# B483 - Conversation Budget "sessions" Mode and a Separate Large-History Budget (M2.2)

State: implemented (opt-in; default stays "fit_all"; gate pending)
Priority: P2

Plan: `learnings/e2e-improvement-plan.md` M2.2 (session prefilter for long histories), Part D/G

### Problem Statement

B482 shows the whole user history when it fits `conversation_token_budget`
(3500), else the fixed 6-turn path. LoCoMo-10 (~300-700 turns) and
LongMemEval s (~500 turns) never fit, so they get 6 turns, and full history
beats Campy there. Turn-level "more turns" did not raise accuracy, so M2.2
proposes whole sessions: coherent dialogue instead of scattered lines.

### Fix

`[retrieval] conversation_budget_mode = "sessions"` (env
`CAMPY_RETRIEVAL_CONVERSATION_BUDGET_MODE`), used only when the history does
not fit the budget:

1. Rank candidate turns as "fill" does (RRF of vector + FTS, B459 gate, B463
   bridge, pool = budget // 12).
2. Score each session (Message -[SENT_IN]-> Session) by its best candidate
   turn: the max fused RRF score of any candidate in it (the `sessK` rule of
   campy-benchmarks `diag_lme_fusion.py`). Ties: the session whose best turn
   ranked first. A candidate with no session link is a one-turn session.
3. Always keep the top-`conversation_limit` candidates (as far as they fit).
   Then take sessions best first, ALL their eligible user turns (not
   archived, not a question, not an echo of the query, de-duplicated on
   (speaker, text)), while they fit the remaining budget; a session that does
   not fit is skipped (a smaller, lower-ranked one may). If the best session
   alone does not fit, take its turns nearest the best-matching turn (a window,
   earlier turn first on a tie) up to the budget.
4. Present chronologically (time, stored time, uri); `conversation_order` is
   ignored in this mode. Stamps unchanged.

`[retrieval] conversation_budget_large` (env
`CAMPY_RETRIEVAL_CONVERSATION_BUDGET_LARGE`, int >= 0, 0/absent = same as
`conversation_token_budget`): the budget "fill" and "sessions" fill when the
history does not fit. `conversation_token_budget` stays the fit-all threshold.

Query: B482's `thalamus.bundle_conversation_budget` is untouched (G.2); a new
`thalamus.bundle_conversation_large` adds `large_budget`. The stage uses it for
"fill"/"sessions"; "fit_all" still calls the B482 query, so defaults are
byte-identical.

### Measure (offline, no LLM)

Evidence-turn recall, LoCoMo conv-42 + conv-43 golden-store copies, 255
questions (cat 1-4 with evidence mapped to stored turns), bundle conversation
stage only (limit 6, fit threshold 3500):

| variant | macro | micro | questions with >=1 | avg tokens | avg turns |
|---|---|---|---|---|---|
| default (fit_all, 6 turns) | 0.444 | 0.385 | 123/255 | 256 | 6.0 |
| fill@3500 | 0.731 | 0.703 | 197/255 | 3185 | 79.6 |
| sessions@3500 | 0.643 | 0.598 | 176/255 | 3372 | 81.6 |
| sessions@6000 | 0.691 | 0.638 | 189/255 | 5873 | 140.8 |
| fill@6000 | 0.770 | 0.755 | 207/255 | 4643 | 116.4 |

At equal budget sessions recalls less evidence than fill (it spends tokens on
non-matching neighbours), but it presents coherent dialogue. Whether coherence
wins on accuracy is the gate question (LoCoMo-10 dev replay, judge x3,
McNemar), not answered here. Default is unchanged.
