# B423 - Unbounded Campy Logs: Rotate `activity.log` (done) and Cap the launchd-Redirected `daemon.log` (deferred)

State: activity.log fixed (#202); daemon.log fixed (this PR)
Priority: P2
Branch: fix/b423-log-rotation

### Problem

`~/.campy/*.log` grow without bound. Found 2026-09-11 while investigating a
memory-leak report (the leak itself was not confirmed — see notes): `daemon.log`
was 69 MB and `activity.log` 26 MB. The B371 comment in `brain_daemon.py` already
flagged the risk ("this log's entire multi-month, never-rotated history").

### activity.log — FIXED here

`campy/brain/brainstem/activity_log.py` appended JSONL with no rotation. It is the
redacted operator feed (`campy activity --follow`), so it is worth keeping small and
Python-controlled. `emit_activity` now calls `_rotate_if_needed(path, max_bytes)`
before each append: at/over `max_bytes` it rolls the file to `<path>.1` (replacing any
prior backup) and starts fresh, so total stays ~2×cap. Default 10 MB, override via
`config["activity"]["max_bytes"]` (0 disables). Best-effort — any OSError is swallowed,
never breaking a memory op. Proven by `tests/test_b423_activity_log_rotation.py`
(rotates at cap, keeps newest record; disabled at 0).

### daemon.log — FIXED (this PR, option 1)

Implemented the preferred option: the daemon now owns `daemon.log` via an in-process
`logging.handlers.RotatingFileHandler` (default 10 MB × 5 backups ≈ 60 MB ceiling,
overridable via `config["logging"]["daemon_max_bytes"]`/`daemon_backup_count`), and launchd
no longer writes it.

- `brain_daemon.py`: `_build_daemon_log_handler()` (pure, unit-tested) + `_setup_daemon_logging(config)`,
  called at the top of `main()` (replacing `basicConfig`). A `_StreamToLogger` routes
  `sys.stdout`/`sys.stderr` — the daemon's 18 `print()` banners and any residual output,
  including unhandled-exception tracebacks — through the same rotating log, so operational
  output stays captured and bounded (and now carries timestamps, closing the B371 gap).
  Best-effort: any setup failure falls back to the prior stderr `basicConfig`.
- `campy/cli/launchd.py` `generate_plist()`: `StandardOutPath`/`StandardErrorPath` now point
  at a tiny `daemon.boot.log` (new `paths.get_daemon_boot_log_path()`) — a safety net for
  pre-init/crash output only. This is deliberate: pointing launchd at `daemon.log` would
  fight the handler's rotation (launchd's fd keeps writing to the rotated-away inode after a
  rename). Requires a plist regenerate + `launchctl` reload (done via `setup_daemon()`).

Verified live: after reload, daemon comes up clean (`campy smoke` all-pass), `daemon.boot.log`
is 0 KB, and `daemon.log` is freshly written by the handler with timestamps (print lines now
appear as `campy.stdout: …`). Proven by `tests/test_b423b_daemon_log_rotation.py` (handler
rotates by size + respects backupCount; `_StreamToLogger` forwards lines; plist redirects to
the boot log, not `daemon.log`).

Note: the pre-existing 69 MB `daemon.log` was set aside as `daemon.log.pre-b423b` during
verification — safe to delete.

### Provenance

Found by hippocampy-75 during a memory-leak investigation prompted via the ARC_AGI peer
session (arc-agi-5d), 2026-09-11. The memory leak was not substantiated (daemon physical
footprint 439 MB vs 503 MB startup baseline — flat/declining within its lifetime); the
unbounded logs are the concrete disk-hygiene issue that surfaced alongside it.
