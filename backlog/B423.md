# B423 - Unbounded Campy Logs: Rotate `activity.log` (done) and Cap the launchd-Redirected `daemon.log` (deferred)

State: activity.log fixed (this PR); daemon.log deferred (needs plist/newsyslog change)
Priority: P2
Branch: fix/b423-log-rotation

### Problem

`~/.campy/*.log` grow without bound. Found 2026-09-11 while investigating a
memory-leak report (the leak itself was not confirmed — see notes): `daemon.log`
was 69 MB and `activity.log` 26 MB. The B371 comment in `brain_daemon.py` already
flagged the risk ("this log's entire multi-month, never-rotated history").

### activity.log — FIXED here

`campy/brain/brainstem/activity_log.py` appended JSONL with no rotation. It is the
redacted operator feed (`campy activity --follow`), so it is worth keeping small and
Python-controlled. `emit_activity` now calls `_rotate_if_needed(path, max_bytes)`
before each append: at/over `max_bytes` it rolls the file to `<path>.1` (replacing any
prior backup) and starts fresh, so total stays ~2×cap. Default 10 MB, override via
`config["activity"]["max_bytes"]` (0 disables). Best-effort — any OSError is swallowed,
never breaking a memory op. Proven by `tests/test_b423_activity_log_rotation.py`
(rotates at cap, keeps newest record; disabled at 0).

### daemon.log — DEFERRED (documented)

`daemon.log` is **not** written by Python logging — `brain_daemon.py`'s `basicConfig`
uses the default stderr handler, and the file is **launchd redirecting the daemon's
stdout/stderr** (`StandardOutPath`/`StandardErrorPath` in `ai.hippocampy.brain.plist`,
`campy/cli/launchd.py`). So a `RotatingFileHandler` in Python would not touch it, and any
in-process truncation races launchd's concurrent `O_APPEND` writes. Capping it cleanly
needs one of:

1. **plist redirect (preferred):** point `StandardOutPath`/`StandardErrorPath` at a
   throwaway/`/dev/null` and have the daemon write its own log via a
   `logging.handlers.RotatingFileHandler` (maxBytes + backupCount) to `daemon.log`. Adds a
   real handler in `main()`'s `basicConfig(handlers=[…])` and updates the plist +
   reinstall.
2. **macOS `newsyslog.d` entry** installed alongside the plist to rotate `daemon.log` by
   size — no code change, but adds an install artifact.
3. **in-daemon periodic tail-truncate** from a maintenance task — simplest, but racy
   against launchd appends (acceptable only for a debug log; loses interleaved lines).

Deferred because it touches the install/plist (a standing-config change that should be an
explicit, user-approved step) and daemon.log is debug stderr, lower value than the
operator feed. Recommend option 1 when picked up.

### Provenance

Found by hippocampy-75 during a memory-leak investigation prompted via the ARC_AGI peer
session (arc-agi-5d), 2026-09-11. The memory leak was not substantiated (daemon physical
footprint 439 MB vs 503 MB startup baseline — flat/declining within its lifetime); the
unbounded logs are the concrete disk-hygiene issue that surfaced alongside it.
