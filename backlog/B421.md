# B421 - `arc.link_entity_moved_by` Handler Writes Undeclared Columns (`dr`/`dc`) From a Non-Existent Node Table (`Entity`) — MOVED_BY Never Written, `arc_perceive_state` Degrades

State: ready
Priority: P1
Branch: fix/b421-moved-by-link-handler

### Problem

The Python handler for `arc.link_entity_moved_by` (`campy/brain/hippocampus/graph/gateway.py:519`)
writes a `MOVED_BY` edge with the wrong property names from a non-existent source node
table, so the write **raises** and no `MOVED_BY` edge is ever created. Found live on
2026-09-10 during an ARC_AGI smoke test (task `sb26-7fbdac44`): `arc_perceive_state`
degraded repeatedly. Same family as B420 (a handler contradicting the query's own cypher).

```python
if name == "arc.link_entity_moved_by":
    self._client.write_edge("MOVED_BY",
        mint_uri("Entity", params["eid"]),
        mint_uri("ActionEffect", params["aeid"]),
        {"dr": params.get("dr"), "dc": params.get("dc")})
    return []
```

Two defects:

1. **Undeclared property names.** Passes `{dr, dc}`, but `MOVED_BY`'s declared columns are
   `delta_row` / `delta_col` (`schema.py:1465`:
   `CREATE REL TABLE ... MOVED_BY (FROM GridEntity TO ActionEffect, delta_row DOUBLE, delta_col DOUBLE)`).
   The query's own cypher is `SET m.delta_row = $dr, m.delta_col = $dc` — the *params* are
   `dr`/`dc`, the *columns* are `delta_row`/`delta_col`. The handler used the param names as
   edge property keys. `MOVED_BY` is a `"star"` edge (`oxigraph_client.py:393`), so
   `write_edge` validates against `REL_COLUMNS` and raises:
   `RuntimeError: MOVED_BY.dr is not a declared column in schema.REL_TABLES['MOVED_BY']`.
2. **Non-existent source node table.** Mints `mint_uri("Entity", eid)`, but there is no
   `Entity` node table (`"Entity" in NODE_PRIMARY_KEYS` is `False`). The schema and cypher
   use **`GridEntity`**. So even with correct columns the edge would originate from a
   bogus `/id/Entity/…` URI.

### Impact

- `arc_perceive_state` degrades every time an entity moves (208 `MOVED_BY.dr` errors in the
  activity log, earliest `2026-09-09T13:52:46Z` — broken since the B386/B397 gateway
  cutover, not new to this run).
- `MOVED_BY` edges are never written, so `arc_get_entity_movement`
  (`queries/arc.py:639`, `RETURN m.delta_row, m.delta_col`) returns nothing.
- Goal-evidence queries that traverse `<-[:MOVED_BY]-(ge:GridEntity)` for VictoryCondition
  evidence (`queries/arc.py:513`, `:538`) lose the movement signal → weaker goal evidence.

### Fix

One-line correction to the handler, matching the cypher/schema:

```python
if name == "arc.link_entity_moved_by":
    self._client.write_edge("MOVED_BY",
        mint_uri("GridEntity", params["eid"]),
        mint_uri("ActionEffect", params["aeid"]),
        {"delta_row": params.get("dr"), "delta_col": params.get("dc")})
    return []
```

Prove with a round-trip test (same shape as B420): link a move, then
`arc_get_entity_movement` returns the `delta_row`/`delta_col`. This is the same class as
B413/B420 — a `sparql=`/handler write that doesn't match the edge's declared
schema/type. The guard proposed in B420 (reject a handler `write_edge` whose props or
node table don't match the declared schema, at test time) would have caught all three.
