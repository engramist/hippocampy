### B91 · Passive Graph Pre-Activation for Likely-Needed Retrieval

**Problem:** Retrieval is currently reactive. The agent asks for context after it already needs it. That misses the biomimetic opportunity: passive SideQuests processes should be pattern-matching on incoming entities, neighborhoods, and paths so the most likely memory can be delivered with near-zero friction when the active agent asks. We also need the first input packet to carry a little more structure so the retriever has better features to score against.

**What this card builds:** A first graph-native pre-activation prototype. The passive system computes a small "warm frontier" of likely-needed nodes and paths based on recent sensory input and graph structure. The prototype should use a richer initial observation packet and action-effect deltas as activation signals so retrieval can pre-warm likely relevant neighborhoods before the agent asks.

**Design direction:**
- treat passive ingestion like sensory activation
- score likely-needed entities and neighborhoods ahead of demand
- keep the warm set small and queryable
- prefer graph-local activation over bulk preloading
- seed activation from a more detailed first input summary so entity/path matching has enough signal to work with
- bias toward observed effects, recent deltas, and stable ids rather than generic narrative text

**Graph fit:** This is graph-native work, not a relational join problem. The workload is relationship-heavy, traversal-centric, and centered on nearest relevant neighborhoods, recent paths, and reified artifact links. A labeled property graph is the right operational model for this first prototype.

**Depends on:** B90 (uncertainty-gated retrieval), B17 (Hippocampus ✅), B18 (Working Memory ✅)

## Acceptance Criteria

1. The system computes a bounded pre-activated set of likely-needed nodes or paths from recent session activity
2. Retrieval can preferentially serve this warm frontier before broader search
3. The warm frontier remains bounded and explainable
4. The warm-frontier scoring can consume a richer first-input packet and observed-effect deltas
5. Tests cover:
   - activation scoring
   - bounded warm-set size
   - retrieval preference for pre-activated items
   - fallback to normal retrieval when the warm frontier is empty or low confidence
6. Docs describe this as pre-activation, not prompt stuffing

## Outcome

SideQuests starts behaving more like a brain with passive pre-activation: likely-needed memories are already warm before the explicit request arrives, enabling faster, smaller, more targeted active prompts.
