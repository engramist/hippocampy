# B410 - Explicit Status Writes: Guaranteed-Written Status and the Cheap Filter Form

State: ready
Priority: P1
Branch: feat/b410-explicit-status-writes

Design: docs/rdf-schema-mapping.md §3.4a, §4.2f

### Problem

Two issues share one fix.

**1. The `OPTIONAL + !BOUND` filter costs ~2x, and the spec mandated it everywhere.**

Measured against `pyoxigraph 0.5.11` on a 148k-triple store:

| Query | Rows | Time |
|---|---|---|
| no status filter | 39,999 | 36.9 ms |
| `?n campy:archived false` (plain BGP) | 20,000 | **36.9 ms** |
| `OPTIONAL {…} FILTER(!BOUND(…) ‖ …=false)` | 32,000 | **52.7 ms** |

Consistent ~2x across 1–3 hops. At 3 hops the plain filter (61.4 ms) beats *no filter*
(69.3 ms) — filtering shrinks the intermediate set and pays for itself. Constraining a
hop is free-to-negative; the cost is entirely in the OPTIONAL wrapper.

`performance-and-debugging.md` flags "wide OPTIONAL sections" as a SPARQL red flag.
The spec's earlier unconditional rule wrote one into ~600 translated queries.

**2. Superseded-belief history has standalone value** — provenance, debugging *"why
did the agent believe X?"*, and the patent record.

The OPTIONAL form buys exactly one thing: matching "false **or unset**". If status is
always explicitly written, "unset" cannot occur, and both issues resolve.

### Not an OWL argument

B407 measured OWL 2 RL at 10,589x–86,576x write amplification and **permanently
rejected a runtime reasoner**; SPARQL property paths answer the same questions at
0.026 ms with zero write penalty. This card does **not** reopen that. Its value is the
faster filter and the audit trail — both independent of inference.

### Scope

1. **Backfill explicit status on all existing nodes** — `archived` and the supersession
   fields written explicitly wherever they can currently be absent. **Must land and be
   verified before any query converts.**
2. **Make writers always set status.** No conditional status writes; absence stops
   being representable.
3. **Convert queries to the plain BGP form** where the property is now guaranteed
   written. Mechanical across the ~600 translated queries, the same shape B391–B396
   handled well.
4. **Adopt the §4.2f timeless/status split** — class membership never encodes mutable
   state; supersession expressed with PROV-O (`prov:wasRevisionOf`,
   `prov:invalidatedAtTime`, `prov:wasAttributedTo`).

### The hazard — ordering is not negotiable

Converting a query to the plain form **before** the backfill **silently drops every
row where the property was never written.** No error, no failing test, just missing
results. That is B404's failure mode, which silently disabled decay for three node
types for an unknown period.

**Backfill → verify → convert.** A test must prove row-count parity between the two
filter forms on real data *before* any conversion lands.

### Acceptance Criteria

- [ ] Backfill complete; zero nodes with absent status where a filter depends on it.
- [ ] Row-count parity proven between `OPTIONAL` and plain forms on real data, per
      query family, **before** conversion.
- [ ] Writers guarantee explicit status; a test proves absence is unrepresentable.
- [ ] Converted queries measured — expect ≈2x improvement on filtered traversals.
- [ ] `OPTIONAL` retained only where absence is genuinely possible, per §3.4a.
- [ ] Supersession expressed in PROV-O terms per §4.2f.
- [ ] No mutable class membership asserted (`:x a :ActiveConstraint` and similar).
- [ ] Schema conformance guard (B406) and Cypher ratchet still pass.

### Related

- **B406** — schema conformance guard. Omitting a status filter still returns
  superseded facts; the correctness dependence survives even though the cost concern
  did not.
- **B404** — precedent for how silently a missing or mismatched filter fails.
- **B407** — settled the inference question; this card does not revisit it.

### Outcome

One discipline — always write status explicitly — buys a ~2x cheaper filter form and a
standards-based audit trail of superseded beliefs.
