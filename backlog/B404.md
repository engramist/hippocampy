# B404 - Decay/Archive Sweep Silently No-Ops for Three Node Types (Wrong PK Column)

State: ready
Priority: P0
Branch: feat/b404-sweep-pk-column-fix

### Problem

`campy/brain/hippocampus/graph/queries/sweep.py` references primary-key columns
that **do not exist** on three node tables:

| Node table | sweep.py uses | actual column (`schema.py`) |
|---|---|---|
| `GlobalConstraint` | `n.constraint_id` | `global_constraint_id` |
| `GlobalPreference` | `n.pref_id` | `global_preference_id` |
| `Requirement` | `n.req_id` | `requirement_id` |

Verified: none of `constraint_id`, `pref_id`, `req_id` exist on their respective
tables.

Kùzu returns NULL for a missing property rather than raising, so the sweep's
two-stage pattern fails silently:

```cypher
RETURN n.constraint_id, n.pathway_strength          -- returns NULL for every row
MATCH (n:GlobalConstraint) WHERE n.constraint_id = nid   -- NULL = nid is never true
```

The second stage matches nothing. **Ebbinghaus decay, archival, and resurrection
have therefore never run for `GlobalConstraint`, `GlobalPreference`, or
`Requirement` nodes.** They accumulate indefinitely, never decay, never archive,
and can never be resurrected.

Found incidentally during B392's SPARQL translation, which reproduced the same
property names for bug-for-bug parity (correctly — the translation rule is "same
columns as the Cypher original", so the fix belongs here, not there).

### Scope

1. Correct the three column names in `sweep.py`'s Cypher **and** in B392's
   corresponding `sparql=` strings, so both engines stay in parity.
2. **Assess the accumulated damage.** These nodes have never decayed. Determine
   whether a one-off backfill is needed to bring existing rows to the
   `pathway_strength` they would have had, or whether letting decay resume from
   current values is acceptable. **Report the finding and recommendation — do not
   run a destructive backfill without sign-off.**
3. Add a guard that fails when a query references a property absent from its
   node table's schema. `NODE_TABLES` is introspectable, and the same
   `NamedQuery` registry that made this findable makes this checkable. This bug
   class is what the B314/B386 chokepoint was built to enable catching.

### Acceptance Criteria

- [ ] All three PK references corrected in both `cypher` and `sparql` forms.
- [ ] A test proves decay/archive/resurrect now actually affects these three
      node types (assert state changes, not just that the query runs).
- [ ] Schema-property guard added and wired into CI alongside the Cypher ratchet.
- [ ] Guard demonstrated to catch this exact bug — verified by reintroducing it
      temporarily, as B400 did for its torch tripwire.
- [ ] Accumulated-damage assessment reported; no backfill run without sign-off.
- [ ] Cypher ratchet still 0.

### Outcome

Three node types rejoin the memory lifecycle they were silently excluded from,
and a whole class of silent property-name bugs becomes impossible to merge.
