# B518: CI requires a Graph design section and rejects new write-only graph terms

**Status:** Done

The graph-design rules (B516, B517) held only by prose. Two checks make them hold by tooling.

1. `.github/scripts/check_pr_score_effect.py`: a PR touching retrieval, answering, capture or config
   paths needs a `## Graph design` section naming the edge(s) read or written and the query that
   reads them (a SPARQL form or a NamedQuery name), or `None — <reason>`. Capture paths
   (`campy/brain/temporal_lobe/`, all of `campy/brain/hippocampus/`) were added to the shared path
   list, so they also need a `## Score effect` statement; capture changes move what can be
   answered. `scripts/drift_report.py` kept in sync. PR template restructured to Principle / Lever
   and target / Graph design / Score effect / What.
2. `.github/scripts/check_write_only_terms.py` (step in `tests.yml`): every edge and property declared
   in `schema.py` must be read by some SPARQL read site, else it is in the committed baseline
   `.github/scripts/write_only_terms_baseline.txt`. CI fails on a new write-only term, or when a
   baselined term becomes read. The baseline is the list of terms nothing reads.

Serves Principle 2 (graph first) and Principle 8 (subjects as backbone); enforcement, not a
retrieval lever.
