# B413 - Re-triage the Write-Path Schema Violations: "Guarded" Was a Kùzu Premise — but Unguarded ≠ Broken (0 broken / 3 inert / 27 unreachable)

State: ready
Priority: P1
Branch: docs/b413-write-path-retriage

### Problem

B406's schema conformance guard ratchets a baseline of violations — `NamedQuery`
entries referencing properties not declared in `schema.py`. B406, then B412, split the
baseline by the `mutating` flag and justified **ignoring the write-path** as "guarded":

> **B412's Problem table:** WRITE — **Guarded.** `OxigraphClient.write_node()` validates against `schema.NODE_TABLES` and raises `ValueError`. Verified directly.

Two things are wrong with that, and they cut in opposite directions:

1. **The "guarded" mechanism claim is false on Oxigraph.** It was inherited from
   Kùzu 0.11.3 (B406: *"Writes raise. Verified against `kuzu==0.11.3`"*). These queries
   are **not** runtime-guarded on the current backend (verified below).
2. **But unguarded ≠ broken.** An undeclared triple that nothing ever reads back is
   *inert* — it costs storage and nothing else. It is only a bug if the write is
   reachable **and** something reads the property back and gets wrong/empty results.

Re-triaging under the correct premise, and checking **reachability and readback
separately for each query**, the write-path is far less alarming than "unguarded"
suggests: **0 broken, 3 inert, 27 unreachable.** No emergency fixes; a cleanup that
drops the ratchet, not a bug hunt.

### The "guarded" mechanism is false (verified)

All flagged write queries carry a literal `sparql=` DELETE/INSERT template. On Oxigraph:

- `GraphGateway._dispatch_oxigraph` / `_dispatch_oxigraph_sync`
  (`graph/gateway.py:381`, `:390`) route any `NamedQuery` with `sparql is not None`
  **straight to** `OxigraphClient.execute_write(query.sparql, params)` / `execute(...)`.
- `OxigraphClient.execute()` (`graph/oxigraph_client.py:968`) calls
  `self.store.update(bound_sparql)` for update text — **no property validation**.
- The `ValueError(f"{table}.{key} is not a declared column…")` guard
  (`oxigraph_client.py:735`) is only reached from `write_node()` (`:842`) /
  `write_edge()` (`:874`), on the `sparql=None` handler path **none of these queries
  use**. B412's "Verified directly" tested that path — the wrong one.

Live reproduction (confirmed 2026-09-08):

```python
import tempfile, asyncio
from campy.brain.hippocampus.graph.oxigraph_client import OxigraphClient
from campy.brain.hippocampus.graph.gateway import GraphGateway
from campy.brain.hippocampus.graph.queries import REGISTRY
client = OxigraphClient(tempfile.mkdtemp())
client.write_node('ActionFact', {'fact_id':'f1','task_id':'t1','action_id':'a1'})
gw = GraphGateway(client, REGISTRY)
asyncio.run(gw.run('provenance.touch_last_accessed_actionfact', id='f1', now='2026-01-01T00:00:00Z'))
# Returns None, no exception. A follow-up SELECT shows campy:last_accessed_at now on the
# ActionFact node — a property ActionFact does not declare.
```

The mechanism is genuinely unguarded. The independent agent working this codebase
reproduced the same result (`write_node()` → `ValueError`; `execute_write(raw sparql)`
→ persisted). So the premise is corrected. The remaining question is what it *costs* —
answered per-query below.

### Method: reachability × readback, per query

For each violation, two independent checks (grep is not sufficient for reachability —
`provenance.py:543` dispatches via an f-string, so callers of the *dispatcher* and the
flag that gates it must be traced):

- **Reachable?** Any production caller — static or dynamic dispatch.
- **Read back?** Does any production query read the written property?

**Broken** = reachable AND read-back. **Inert** = reachable, written, but never read.
**Unreachable** = no live path writes it at all.

### Result (against the live checker, 32 baseline violations / 31 write-path)

**UNREACHABLE — 27 queries: `provenance.touch_last_accessed_*`**

The only production dispatch is `find_live_by_dedupe_key(..., touch_last_accessed=True)`
(`hippocampus/provenance.py:543`, dynamic `f"provenance.touch_last_accessed_{t_lower}"`).
`touch_last_accessed` is **keyword-only, default `False`**. All three callers of
`find_live_by_dedupe_key` live in `thalamus/tools/lessons.py` (`:106`, `:383`, `:655`),
pass only tables `Plan`/`Lesson`, and **none passes `touch_last_accessed`**. The gate
`if touch_last_accessed and existing_id:` (`:543`) is never true → **the dispatch never
fires for any table.** Dead code, exactly like the `find_live_arc*` cluster PR #189
deleted. (Confirming schema alignment: the two tables that *do* declare
`last_accessed_at` — `Concept`, `Dataset` — are correctly absent from the baseline; the
27 are precisely the undeclared tables.)

**INERT — 3 queries / 4 violations: written (or dropped), never read**

**BROKEN — 0.** No reachable write query persists a property that a reachable read query
then consumes.

**Already resolved (stale baseline artifact):** `capture.set_last_proactive_push_count`
was flagged in the pre-#190 baseline but is **no longer a violation** —
`Session.last_proactive_push_msg_count` is declared (`schema.py:1741`,

### Scope

No bug fixes are urgent (0 broken). This is a ratchet-lowering cleanup:

1. **27 unreachable `touch_last_accessed_*`:** delete them (as #189 did for
   `find_live_arc*`), *or* — if access-time reinforcement is genuinely wanted — guard the
   `provenance.py:543` dispatch to fire only for tables that declare `last_accessed_at`
   (Concept, Dataset) and delete the rest. Deletion is the default; re-confirm zero
   callers (static + the f-string dispatch) immediately before removing.
2. **`sweep.touch_subsumed_lesson`:** drop the two undeclared **node** writes
   (`synthesized_at`, `synthesis_cluster_size`) from the `.sparql`; the declared
   `GENERALIZES_LESSON` edge already carries this data and is what gets read. (If a
   node-level field is ever wanted, declare it — but nothing reads it today.)
3. **`dict_link_alt_label` / `dict_link_pref_label`:** remove the cosmetic
   `{created_at: $now}` from the `.cypher` so it matches the `.sparql` (which already
   drops it) and the "plain" edge mapping. Single-source the intent; no behavior change.
4. **Update `scripts/schema_conformance_baseline.json`** as each lands — the ratchet
   should fall from 32 toward ~1 (only `quests.get_session_onboarding_status`, the read
   B412 left, would remain), not merely shuffle.
5. **Measurement-gap note (optional / possible follow-on):** the guard scans `.cypher`
   while Oxigraph executes `.sparql`. The `dict_link_*` and `touch_subsumed` cases are
   exactly where the two diverge, which is why "unguarded" and "inert" coexist. If cheap,
   have the guard validate the `.sparql` templates (or fail when `.cypher` and `.sparql`
   reference different property sets). Otherwise file separately.
