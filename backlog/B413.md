# B413 - Re-triage the 31 Write-Path Schema Violations: "Guarded" Was a Kùzu Premise, Oxigraph Doesn't Hold It

State: ready
Priority: P0
Branch: TBD

### Problem

B406's schema conformance guard ratchets a baseline of write-path violations —
`NamedQuery` entries whose flagged property is not declared in `schema.py`. B406 (and
then B412) split the baseline into two risk classes and justified **ignoring the writes**:

> **B412's Problem table:**
> | Path | Count | Exposure |
> |---|---|---|
> | **WRITE** | 32 | **Guarded.** `OxigraphClient.write_node()` validates against `schema.NODE_TABLES` and raises `ValueError`. Verified directly. |

**This premise is false on the current Oxigraph backend.** The "Verified directly" claim
tested the wrong code path.

Root cause of the mis-framing: B406's Problem section grounds the entire read/write split
in **Kùzu 0.11.3** runtime behavior —

> *"Writes raise. Verified against `kuzu==0.11.3`: `CREATE (c)-[:HAS_ALT_LABEL {created_at: ...}]->(l)` → Binder exception: Cannot find property created_at."*

That was true under Kùzu. The backend is now Oxigraph, which has **no runtime property
validation** on the update path these writes actually use. The premise was inherited
across B406 → B412 without re-verifying it against the backend that now runs.

### Why the writes are not guarded (verified)

All 31 flagged write queries carry a literal `sparql=` field (a hand-written
`DELETE/INSERT ... WHERE` template). On Oxigraph:

- `GraphGateway._dispatch_oxigraph` / `_dispatch_oxigraph_sync`
  (`graph/gateway.py:381`, `:390`) route any `NamedQuery` with `sparql is not None`
  **straight to** `OxigraphClient.execute_write(query.sparql, params)` /
  `execute(...)`, bypassing `_handle_oxigraph_handler`.
- `OxigraphClient.execute()` (`graph/oxigraph_client.py:968`) calls
  `self.store.update(bound_sparql)` for update text. **No property-name validation.**
- The validation B412 cited — `_node_property_lines()` raising
  `ValueError(f"{table}.{key} is not a declared column…")` (`oxigraph_client.py:735`) —
  is only called from `write_node()` (`:842`) and `write_edge()` (`:874`). Those serve
  the **Python-handler** dispatch path (`sparql=None`). **None of the 31 flagged write
  queries use that path** — they all supply `sparql=`.

**Live reproduction** (any venv with pyoxigraph):

```python
import tempfile, asyncio
from campy.brain.hippocampus.graph.oxigraph_client import OxigraphClient
from campy.brain.hippocampus.graph.gateway import GraphGateway
from campy.brain.hippocampus.graph.queries import REGISTRY

client = OxigraphClient(tempfile.mkdtemp())
client.write_node('ActionFact', {'fact_id': 'f1', 'task_id': 't1', 'action_id': 'a1'})
gw = GraphGateway(client, REGISTRY)
asyncio.run(gw.run('provenance.touch_last_accessed_actionfact', id='f1', now='2026-01-01T00:00:00Z'))
# Returns None, no exception. A follow-up SELECT shows campy:last_accessed_at now on the
# ActionFact node — a property ActionFact does not declare in schema.py.
```

Confirmed 2026-09-08: the triple was written silently. Same class as the read-path
violations B412 addresses (silent, no error, no failing test) — not "guarded".

Also confirmed: the guard scans the `.cypher` field, but **`.sparql` is what actually
runs on Oxigraph**. For some queries the two diverge, which changes the runtime story
per-query (see Bucket B). The guard is currently measuring the wrong artifact for the
live backend — a measurement gap this card should note even if it doesn't fix the guard.

### The 31 write queries, triaged

Split by reachability and by what the `.sparql` (not `.cypher`) actually does at runtime.

**Bucket A — reachable, live caller, SPARQL silently writes the undeclared property (real bugs, same class as B404/B405):**

| Query | Undeclared write | Live caller | Likely fix |
|---|---|---|---|
| `capture.set_last_proactive_push_count` | `Session.last_proactive_push_msg_count` | `thalamus/tools/capture.py:585` | intended field — **add column to `schema.py`** |
| `sweep.touch_subsumed_lesson` | `Lesson.synthesized_at`, `Lesson.synthesis_cluster_size` | `brainstem/sweep.py:1242` | intended fields — **add columns to `schema.py`** |

These write meaningful, intended data under undeclared names. The fix is almost
certainly to make the schema match intent (add the columns), not to delete the query.

**Bucket B — reachable, live caller, but SPARQL diverges from Cypher and does NOT write the flagged property (checker false-positive on Oxigraph, but a real Cypher/SPARQL drift → silent data loss):**

| Query | Cypher writes | SPARQL actually writes | Live caller |
|---|---|---|---|
| `temporal_lobe.dict_link_alt_label` | `HAS_ALT_LABEL {created_at}` | edge only, **`created_at` dropped** | `temporal_lobe/dictionary.py:175` |
| `temporal_lobe.dict_link_pref_label` | `HAS_PREF_LABEL {created_at}` | edge only, **`created_at` dropped** | `temporal_lobe/dictionary.py:147` |

Note: this is B406's own canonical example. At runtime on Oxigraph it does **not** raise
and does **not** write an undeclared property — it silently omits `created_at`. Decide:
persist `created_at` (add it to the SPARQL and declare the edge property) or drop it from
the Cypher so intent is single-sourced.

**Bucket C — latent: `provenance.touch_last_accessed_*` (27 queries, one per table that lacks `last_accessed_at`):**

Reachable only through `find_live_by_dedupe_key(..., touch_last_accessed=True)`
(`hippocampus/provenance.py:533`, dynamic `f"provenance.touch_last_accessed_{t_lower}"`
dispatch). **No caller currently passes `touch_last_accessed=True`** — so these are
dead-in-practice today, like the `find_live_arc*` cluster PR #189 deleted, but *latent*:
the moment any caller opts in for one of these 27 tables it will silently write an
undeclared `last_accessed_at` (verified above for `ActionFact`). Only `Concept` and
`Dataset` declare the column (and are correctly absent from the baseline).

Decide one of:
- **Guard the dispatch** so `touch_last_accessed_*` only fires for tables that declare
  `last_accessed_at` (Concept, Dataset), and delete the 27 undeclared-table variants; or
- **Delete all 27** now (nothing opts in) and regenerate only on demand; or
- **Add `last_accessed_at`** to whichever tables genuinely want access-time reinforcement.

(The provenance.py docstring at `:519` still says a bad table "would raise from Kùzu" —
false on Oxigraph. The B412 branch corrects that specific docstring; this card fixes the
queries the docstring describes.)
