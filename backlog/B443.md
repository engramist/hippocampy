# B443 - Codex SessionEnd Hook Support for generate_handoff (B383/B440 v3)

State: ready
Priority: P2
Branch: feat/b443-codex-sessionend-handoff
PR Target: main

### Note on origin

Found while implementing B440 (Claude Code `SessionEnd` handoff
automation). B383's original card explicitly named both "Claude Code /
Codex session-end and session-start hooks" as scope — B440 only
implemented the Claude Code side. This card covers the Codex half.

### Problem / constraint

Confirmed via OpenAI's official Codex hooks documentation
(developers.openai.com/codex/hooks, verified 2026-09-22): Codex CLI
does have a `SessionEnd` hook event (added as a feature request,
openai/codex#20374/#33895), matching the same event name Claude Code
uses. But it has real constraints B440's `session_end_wrapper.py`
wasn't built for:

- **Runs synchronously**, with a timeout capped at **up to 3 seconds**
  (default 1s) — far tighter than Claude Code's `SessionEnd` (this
  repo's `hooks.json` gives it 15s) or B440's own internal
  `_HANDOFF_TIMEOUT = 10.0` subprocess bound.
- **Does not support MCP tool hooks** at all for this event.

`campy_hook.py::check_daemon_health()` alone has a 2-second internal
timeout — on a slow-to-respond daemon, that could consume most or all
of Codex's 3-second budget before `campy handoff` even starts,
meaning a naive reuse of B440's wrapper would likely time out and
silently no-op (fail-open, so not *broken*, just probably
unreliable/rarely-successful on Codex specifically) most of the time.

### Scope

1. Register `SessionEnd` in `campy/cli/plugin_installer.py`'s
   `_write_codex_hook_config()` (mechanical — the `campy_hooks` dict
   pattern already there makes this a small, well-understood addition;
   see how `SessionStart`/`PreToolUse`/`PostToolUse` are already done
   there for Codex).
2. Design a Codex-appropriate timeout budget for the whole chain
   (daemon health check + `campy handoff` subprocess) that reliably
   fits inside Codex's ~3s ceiling — likely needs a leaner health
   check (skip the 2s HTTP round trip, or shorten it substantially)
   and a tighter `campy handoff` invocation, not simply reusing
   `session_end_wrapper.py`'s Claude-Code-tuned budget as-is.
3. Verify end-to-end against a real Codex session (not just a
   simulated stdin payload) that the hook actually fires and reliably
   produces `HANDOFF.md` within the real timeout window.

### Acceptance Criteria

- [ ] Codex `SessionEnd` hook registered via `campy setup`/
      `install_codex_plugin`, verified via a test analogous to
      `test_install_codex_plugin_uses_shared_hooks` in
      `tests/cli/test_plugin_installer.py`.
- [ ] The full daemon-health-check + handoff-generation chain reliably
      completes within Codex's real SessionEnd timeout budget,
      measured, not assumed.
- [ ] Work executed in branch `feat/b443-codex-sessionend-handoff` and
      PR created targeting `main`.

### Outcome

Codex users get the same zero-manual-action handoff generation Claude
Code users get from B440, reliably within Codex's tighter
synchronous-hook timeout constraint.
