# B128 - Task Graph MCP Tools (register_task_graph, get_ready_tasks, advance_task, fail_task, get_task_graph)

State: complete ✅ DONE (2026-04-01)
Priority: P1

Plan: backlog/plans/B-128-dag-task-graph-tools.md

### Problem

The DAG schema (B127) exists in Kùzu but agents cannot interact with it. `ARCOrchestrator` needs a stable, contract-bound way to register its execution plan, query what's runnable right now, and report task outcomes — all through `BrainClientProtocol`. Without these tools, the Task Board from the Task-Graph Orchestration pattern is write-only infrastructure that no coordinator agent can use.

### What it does

Adds 5 MCP tools backed by the B127 schema, wires them into `BrainClientProtocol`, and implements them in `LocalBrainClient`, `NoOpBrainClient`, and `LedgerBrainClient`.

### New MCP Tools

#### 1. `register_task_graph`
Coordinator saves the full DAG (nodes + dependency edges) in one atomic call.

```json
{
  "name": "register_task_graph",
  "inputSchema": {
    "properties": {
      "label":      { "type": "string" },
      "session_id": { "type": "string" },
      "owner":      { "type": "string" },
      "tasks": {
        "type": "array",
        "items": {
          "type": "object",
          "properties": {
            "task_id":     { "type": "string" },
            "label":       { "type": "string" },
            "description": { "type": "string" },
            "depends_on":  { "type": "array", "items": { "type": "string" } }
          },
          "required": ["task_id", "label"]
        }
      }
    },
    "required": ["label", "session_id", "owner", "tasks"]
  }
}
```

Response: `{ graph_id, task_ids[], ready_tasks[], cycle_errors[] }`

Cycle detection runs before committing. If any edge would form a cycle, that edge is rejected, included in `cycle_errors`, and the rest of the graph is committed.

#### 2. `get_ready_tasks`
Returns the topological frontier: all pending tasks whose upstream dependencies are all complete/skipped.

```json
{
  "name": "get_ready_tasks",
  "inputSchema": {
    "properties": {
      "graph_id": { "type": "string" }
    },
    "required": ["graph_id"]
  }
}
```

Response: `{ graph_id, ready: [{ task_id, label, description, owner }] }`

#### 3. `advance_task`
Transitions a task to `active` or `complete`. On `complete`, automatically re-evaluates the frontier and returns newly unblocked tasks.

```json
{
  "name": "advance_task",
  "inputSchema": {
    "properties": {
      "graph_id":  { "type": "string" },
      "task_id":   { "type": "string" },
      "status":    { "type": "string", "enum": ["active", "complete", "skipped"] },
      "result":    { "type": "string", "description": "Optional outcome summary" }
    },
    "required": ["graph_id", "task_id", "status"]
  }
}
```

Response: `{ task_id, new_status, newly_unblocked: [task_id] }`

#### 4. `fail_task`
Marks a task as `failed`. Does not cascade-fail dependents by default (agent decides whether to replan or skip).

```json
{
  "name": "fail_task",
  "inputSchema": {
    "properties": {
      "graph_id": { "type": "string" },
      "task_id":  { "type": "string" },
      "reason":   { "type": "string" }
    },
    "required": ["graph_id", "task_id", "reason"]
  }
}
```

Response: `{ task_id, status: "failed", blocked_dependents: [task_id] }`

`blocked_dependents` lists downstream tasks that can no longer become ready (their deps include a failed node). The agent can choose to `skip` them or replan.

#### 5. `get_task_graph`
Returns full graph state for audit and replay. Returns the DAG as nodes + edges with current status.

```json
{
  "name": "get_task_graph",
  "inputSchema": {
    "properties": {
      "graph_id": { "type": "string" }
    },
    "required": ["graph_id"]
  }
}
```

Response: `{ graph_id, label, status, version, tasks: [...], edges: [{ from, to }] }`

### BrainClientProtocol Changes

Add to `benchmarks/arc3/adapter.py`:

```python
async def register_task_graph(self, label: str, session_id: str, owner: str, tasks: list[dict]) -> dict: ...
async def get_ready_tasks(self, graph_id: str) -> dict: ...
async def advance_task(self, graph_id: str, task_id: str, status: str, result: str | None = None) -> dict: ...
async def fail_task(self, graph_id: str, task_id: str, reason: str) -> dict: ...
async def get_task_graph(self, graph_id: str) -> dict: ...
```

**`LocalBrainClient`** — implement all 5 by calling `mcp_engine/tools/task_graph.py` handlers.

**`NoOpBrainClient`** — return safe empty stubs:
- `register_task_graph` → `{ graph_id: "noop", task_ids: [], ready_tasks: [], cycle_errors: [] }`
- `get_ready_tasks` → `{ graph_id: graph_id, ready: [] }`
- `advance_task` → `{ task_id: task_id, new_status: status, newly_unblocked: [] }`
- `fail_task` → `{ task_id: task_id, status: "failed", blocked_dependents: [] }`
- `get_task_graph` → `{ graph_id: graph_id, label: "", status: "active", version: 0, tasks: [], edges: [] }`

**`LedgerBrainClient`** — wrap delegate calls + record per-call ledger entries (same pattern as all other ledger-wrapped methods).

- All 5 tools callable through `BrainClientProtocol` (LocalBrainClient, NoOpBrainClient, LedgerBrainClient)
