### Problem

Currently, Campy retrieval is purely reactive: an agent or tool must explicitly invoke `current_truth`, `compile_context`, or `ask` to surface memories. This introduces two limitations:
1. **Tool-call latency:** Waiting for an explicit MCP retrieval query pauses agent execution while the graph is scanned and embeddings are evaluated.
2. **Agent amnesia blind spot:** If an agent fails to recognize that a task depends on a decision made 3 weeks ago in a different session, it will not call retrieval at all, repeating mistakes or contradicting established constraints.

In human cognitive architecture (and as claimed in Campy's patent disclosure regarding the **Cocktail Party Effect**), memory is not a passive warehouse. The brain maintains an active "warm frontier": continuous, passive sensory intake (hearing background chatter, seeing file paths or error codes) pre-activates relevant graph neighborhoods *before* conscious recall is requested.

### Biological Alignment: Thalamic Priming & Sensory Pre-Fetching

In biological cognition (as highlighted in Nate B. Jones' analysis of local vs. cloud prosumer architectures), the brain does not wait for an explicit retrieval instruction to search memory. Instead, it uses **Priming**: passive sensory intake (hearing a word, seeing an error code, observing a modified file) immediately triggers subconscious pattern-matching along neural pathways. By the time conscious attention focuses on the object, the relevant knowledge neighborhood is already active.

### What it does (scope)

This card builds the **Anticipatory Pre-Activation Engine**, transforming retrieval from a purely reactive pull into an anticipatory, pre-warmed state machine.

1. **Bounded Warm Frontier Data Structure (`campy/brain/temporal_lobe/warm_frontier.py`):**
   - Maintains an in-memory, bounded set of pre-activated node IDs with activation scores `[0.0, 1.0]`.
   - Bounded to a maximum size (`max_warm_nodes = 50`, configurable in `campy.toml`).
   - Applies continuous temporal decay: activation scores decay over turns/time (`decay_half_life_turns = 5`).
   - **Dense Supernode Safeguard (`performance-and-debugging.md`, `anti-patterns.md`):** If an entry node's degree exceeds 50 (`degree(node) > 50`), bypass open neighbor expansion. Instead, selectively expand strictly the top 5 incident edges sorted by `pathway_strength DESC` to prevent background traversal explosion into giant hubs (enforcing B283 supernode hygiene).

2. **Passive Ingestion Activation Flow:**
   - On every turn ingested via `notify_turn`, the engine extracts recognized entity tokens, git branch context, and modified file paths.
   - Performs a lightweight 1-to-2 hop graph neighbor expansion from matched nodes via `gateway.py` / `oxigraph_client.py`.
   - Boosts activation scores for connected Decisions, Constraints, and Lessons.
   - Zero perceptible latency: neighbor expansion is bounded and executes in <5ms.

3. **Thalamic Retrieval Integration:**
   - `bundle_compiler.py` and `step5_retrieval.py` check the warm frontier during candidate ranking.
   - Candidate nodes present in the warm frontier receive an activation boost multiplier `(1.0 + warm_score * 0.35)` applied to their calibrated vector/lexical score.
   - Cold-start resilience: If the warm frontier is empty or low confidence, retrieval falls back seamlessly to standard dual-scope ranking.

4. **Step 4b Associative Trigger Binding:**
   - When an incoming turn contains error traces, test failures, or key operations (e.g. git rebase, docker deploy), Step 4b checks stored Lessons/Procedures.
   - If similarity exceeds 0.65, it automatically pre-activates the corresponding Lesson in the warm frontier so it is immediately injected into the next prompt bundle.
