# B334 - LONGCONTEXT Benchmark Self-Admits It's a Mock; benchmark_sources.md Claims the Real 8,000-Scenario Dataset

State: complete — merged via PR #57 (2026-08-20)
Priority: P1

Plan: none yet.

### Problem

`benchmarks/benchmark_sources.md` describes "LoCoBench" as a real external dataset:
`arxiv:2509.09614`, `github.com/SalesforceAIResearch/LoCoBench`, "8,000 evaluation scenarios across 10
languages."

But `benchmarks/longcontext/harness.py` openly admits it isn't that. `setup()` (around line 35-42)
contains the comment:

```python
# In a real scenario, this would load from benchmarks/data/locobench/
# For now, we ensure we have tasks to run.
```

...and `_load_or_generate_tasks()` (docstring: "Mock or load LoCoBench tasks") generates 5 synthetic
"needle in haystack" tasks per configured context size (`benchmarks/longcontext/harness.py`, confirmed
again for this card: `for i in range(5)` loop, `random.randint(10000, 99999)` needle values) — a
handful of synthetic tasks, not the cited 8,000-scenario real dataset. This is the same class of
problem as B333 (AMA-Bench/MemoryArena), but here the code itself already documents the gap honestly in
a comment — the problem is that `benchmark_sources.md` and any downstream report don't carry that same
honesty forward.

### What it does (scope)

1. Update `benchmarks/benchmark_sources.md`'s LoCoBench entry to state plainly that the current harness
   runs a small synthetic needle-in-haystack proxy (state the actual current task count — 5 per
   configured context size), not the real 8,000-scenario dataset, while still crediting LoCoBench as
   the design inspiration if that's accurate.
2. Rename the benchmark identifier away from "LoCoBench"/"LONGCONTEXT" implying real-dataset parity
   (check `benchmarks/runner.py` registration call sites and any result files under
   `benchmarks/results/longcontext.json` for the exact string to change) to something like
   `synthetic-longcontext-needle` — consistent with whatever naming convention B333 lands on for its
   equivalent rename, since both are the same category of issue.
3. Optionally (only if low-effort): if `SalesforceAIResearch/LoCoBench` is genuinely easy to pull in
   (e.g. a small pip-installable package or a manageable static download), wire up real dataset loading
   behind the existing `# In a real scenario, this would load from benchmarks/data/locobench/` comment
   as a stretch goal. Do not treat this as required — the required scope is items 1 and 2 (honest
   labeling), not necessarily building real dataset integration.

### Dependencies

None. Independent of B332/B333/B335 — separate files, can run in parallel. Should use the same naming
convention decided in B333 for consistency (e.g. both proxy benchmarks prefixed `synthetic-`), but
doesn't need to block on B333 completing first — coordinate naming via a quick grep of whichever lands
first.
