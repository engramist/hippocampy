# B521: the drift report measures outcomes, not paperwork

**Status:** Done

`scripts/drift_report.py` counted commits that mention a gate and open PRs with a filled
`## Score effect`. On 2026-10-25 it said "ok: gate results are being reported" for a fortnight in
which the LoCoMo score sat flat at about 0.52, 19 of 41 commits were docs-only, and a lever counted
in Python what the graph should compute. It now reports outcomes; the old sections stay.

1. **Score trend.** Merged PRs in the window (`gh pr list --state merged`) have their
   `## Score effect` parsed in the three formats in use (suite/baseline/branch/gained/lost table;
   run/flags/score/"vs main (R88 0.525)" table with a combined "7 gained / 14 lost" cell; bullets with
   "A -> B, N gained / M lost"). Per PR rows are listed; per published metric (LoCoMo cat 1-4,
   LongMemEval overall, DMR) the earliest baseline is set against the latest branch score. Slices
   (a LongMemEval question type, LoCoMo adversarial) are listed but not trended. "Score flat" means
   no metric rose by more than `--score-threshold` (default 0.01).
2. **Docs share.** Docs-only commits as a share of all; flagged above 40%.
3. **Graph structure** (`--store PATH`, a copy; opened read-only through `graph_structure_report.open_store`):
   Observations, share with `subject_id`, share with `object_id` (principle 8's target), and the share
   of `owns`/`relates_to` Observations with an entity object. Five COUNT queries.
4. **Graph computes (watch).** Regex call sites added and removed under `campy/brain/thalamus/` in the
   window. A watch item, not a failure.
5. **Verdict.** drift = score flat and (docs share high or no gate result); watch = score flat only;
   ok otherwise. Without `gh` the score is unknown and the old paperwork rule applies.

Run over 2026-10-11..25 it gives "drift: score flat, docs share high" (LoCoMo 0.526 -> 0.525, docs
43.5%, thalamus regex +2/-0), which is what the fortnight was.

Serves Principles 1 (the score is the measure), 2 (regex-versus-graph watch) and 8 (object-linked
share). Reporting tooling; no retrieval change.
