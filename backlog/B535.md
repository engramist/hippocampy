# B535: a vocabulary steward proposes kind links and kinds from closed choices; a rule promotes

**Status:** Open — gate pending (stack gate on fresh conversations; target: count questions per scripts/gate_slice.py)

Lever 1e of the object-linking work, on top of B522-B525 and B534. WordNet (B534) runs inside the NLP process and
links kinds that are lexical hypernyms. It misses common-sense links ("dog" is a "pet": WordNet files the pet sense
elsewhere), about a fifth of what it links is wrong for a conversation ("book series" under "group"), and entities
that a speaker owns are left without a kind (Scout, owned by Andrew). On two stores, 46 of 95 and 27 of 49 kinds had no
parent. A steward agent sits above the NLP process and keeps filling and checking that vocabulary.

1. **Three closed-choice tasks** (`temporal_lobe/steward.py`), each a fixed package built from the graph:
   (a) the parent of a kind with no `BROADER`: the kind, three entities filed under it with their source quotes, the
   other live kinds as a numbered list; (b) the kind of an entity that is the object of a live `owns` Observation and has
   no `INSTANCE_OF`: the entity, the turns that name it, the live kinds; (c) keep or reject of each WordNet `BROADER`
   link. A number outside the list, or a number whose echoed name is another kind's, is rejected and counted; "none"
   writes nothing. The model never writes a label or an id.
2. **It proposes, it never publishes.** Every write is a reifier (RDF-star node, the B534 pattern) with
   `campy:link_source "steward"` and `campy:link_status candidate|promoted|rejected|disputed`. A candidate's reifier does
   NOT assert the triple it reifies, so B524's count walk, B523's ownable test, the bundle and the structure report's
   kind vocabulary cannot see it. Promotion asserts the triple; rejecting a WordNet link retracts the triple and keeps the
   reifier as the record (`kinds.link_broader_sourced` does not put it back).
3. **A declared rule promotes** (`steward.PROMOTION_RULE`): an independent second source agrees. (i) WordNet's hypernym
   closure contains the parent (`wordnet.hypernym_support`, any ancestor, same sense policy as B534); (ii) the same
   proposal recurs from two different evidence sets (different entities or turns, and the candidate list in the opposite
   order); (iii) a second model, when `[llm.steward_second]` is configured (absent by default); or a person
   (`steward.agree`). A steward "reject" of a WordNet link retracts it only on (ii) or (iii); otherwise it is "disputed"
   and the link stays in the walk. Every vote and every agreeing source is on the reifier (`campy:evidence_set`,
   `campy:steward_reason`, `campy:agreed_by`).
4. **Reads.** `steward.proposals` (every record), `steward.status_counts` (per relation, source and status; reported by
   `scripts/graph_structure_report.py`), and the loop's own `steward.parentless_kinds`, `steward.owned_without_kind`,
   `steward.wordnet_links`, `steward.recurring`, `steward.agreed_open`. The count and ownable queries needed no change:
   they read the plain triples, which only promoted links have.
5. **Where it runs.** A daemon sweep step (24 calls per sweep) and `scripts/run_steward.py` on a store COPY
   (`--max-calls N` for a sample first). The steward's model is `[llm.steward]` over the global `[llm]`; it reads the
   graph only and is never shown a benchmark question or answer.

Flag: `[observations] vocab_steward`, env `CAMPY_VOCAB_STEWARD`, default off.

Serves Principles 2 (the vocabulary lives in the graph, read by named queries), 3 (the model advises, a rule decides,
every record names its sources), 8 (a count over a kind a question can name reaches the entities filed under narrower
kinds, and owned entities get kinds). Measurements are in the PR. Gate pending.
