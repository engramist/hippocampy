# B321 - Advisory Co-Activity: Surface What Other Agents Just Touched

State: todo
Priority: P1

Plan: (inline — self-contained, sized for a Sonnet-level implementer)

Depends on: **B312** (provenance) for attribution quality. Composes with **B316**
(per-workspace isolation) and **B318** (fail-open). None are hard blockers — the core query
works on today's schema.

### What This Card Is NOT — read this first

A customer running a swarm of build agents reported agents overwriting each other's work in a
shared working tree: agent A edits a file, agent B (holding a stale read) writes a whole-file
replacement over it, A's work is lost.

**This card does not fix that, and must not be described as fixing it.** That is a lost-update
concurrency bug in the build runtime. The damage happens at the file write, within seconds.
Campy is an advisory, fail-open memory service consulted at recall time — by the time anything
here surfaces, the overwrite has already happened. The real fixes live in the customer's
runtime: a git worktree per agent with an orchestrator merge step, or compare-and-swap writes
against a known base revision, or a single-writer file service.

**Do not add locking or leasing to Campy to close this gap.** A lock must fail closed; B318
commits Campy to failing open. Those are incompatible availability contracts, and a Campy that
blocks builds when it is unavailable is worse for the customer than no Campy at all.

What this card *does* address is the second-order cost, which is real and is memory-shaped:
after a collision (or just in normal parallel work), agents redo work nobody remembers was
done, and no one can reconstruct who changed what. That is worth fixing on its own merits,
and it composes with a proper worktree fix rather than substituting for one.

### What This Card Does

**Task 1 — The co-activity query.**

Register as a named query (B314's registry, `queries/coactivity.py`) if B314 has landed;
otherwise put it in `campy/brain/thalamus/tools/work_summary.py` next to the existing
B290 code and convert it later.

```python
async def recent_coactivity(
    db, *, file_paths: list[str] | None = None,
    entity_ids: list[str] | None = None,
    within_minutes: int = 120,
    exclude_session: str,
    limit: int = 20,
) -> list[dict]:
    """Other sessions' recent work on the same files or entities.
    Returns [{file_path, agent_source, session_id, last_modified_at,
              minutes_ago, summary, git_branch}]"""
```

Rules:

- **`exclude_session` is required, not optional.** An agent seeing its own edits reported back
  as "someone else touched this" is worse than no signal — it teaches agents to ignore the
  section entirely.
- Order by `last_modified_at` descending, newest first.
- `within_minutes` is a window, not a cutoff on relevance: work from three days ago is not
  co-activity, it is history, and history is what ordinary recall already covers.
- Match file paths exactly **and** by directory prefix — two agents in the same module
  collide even when the exact files differ. Normalize paths (resolve `./`, strip trailing
  slashes) before comparing; do not attempt to resolve symlinks, since Campy may not share a
  filesystem with the agent.

**Task 2 — Surface it in recall, honestly worded.**

Add a bundle section in `campy/brain/thalamus/bundle_compiler.py` following the existing
`_stage_*` pattern (read the file first — B305/B306/B307 established conventions there,
including the `0.70` relevance-floor convention, which does **not** apply here since this is a
time-and-path match, not a similarity match).

The wording of this section matters more than the query. It must read as observation, never
as instruction:

> **Recent activity by other agents** (advisory, may be stale)
> `src/auth/service.py` — modified ~4 min ago by `agent:copy-edit` (session `abc123`)

Do **not** emit "do not edit this file," "locked by," "wait for," or any phrasing implying a
guarantee. Campy does not know whether that agent is still working, whether it finished, or
whether it crashed. Presenting a stale observation as a claim about the present is how an
advisory system gets blamed for a coordination failure it never promised to prevent.

Include the staleness explicitly ("~4 min ago") so the reading agent can weigh it.

**Task 3 — Omit the section when it is empty.**

If no other session touched anything relevant in the window, the section must be **absent**,
not present-and-empty. B305 established this convention for exactly the right reason: a
non-empty section is read as signal, and a section that is always present becomes noise the
model learns to skip.

**Task 4 — Fail-open, no exceptions.**

Per B318: if the co-activity query errors or times out, the bundle is compiled without the
section. It must never fail a recall. Give it the tightest budget in the bundle — it is the
least important section and the most likely to be a sequential scan.

**Task 5 — Make capture cover file paths on the agent's own path.**

Confirm that `WorkArtifact` rows are actually being written during ordinary agent work, not
only when a document is explicitly registered. Read the B290 capture path in
`campy/brain/thalamus/tools/work_summary.py` and `artifacts.py` and determine what triggers a
`WorkArtifact` write.

If artifacts are only recorded on explicit calls, this card's query has nothing to read in the
customer's scenario, and the card is not done. In that case add a lightweight write from the
post-tool-use path recording `(file_path, session_id, agent_source, last_modified_at)` on file
edits — reusing `WorkArtifact` rather than adding a table. Keep it fail-open and off the
critical path (B318's write budget, 2.0s).

**State what you found in the PR either way** — whether the capture side already works is the
single biggest unknown in this card, and the answer determines whether follow-up work is needed.

### Acceptance Criteria

- [ ] Two sessions write `WorkArtifact` rows for the same `file_path`; each session's recall
      surfaces the *other's* activity and never its own
- [ ] `exclude_session` is a required keyword argument — omitting it is a `TypeError`
- [ ] Activity older than `within_minutes` is excluded
- [ ] Directory-prefix matching surfaces a sibling file in the same module
- [ ] Path normalization: `./src/a.py`, `src/a.py`, and `src//a.py` are treated as one path
- [ ] The section is **absent** from the bundle when there is no co-activity — assert the key
      is missing, not that it is empty
- [ ] Section text contains no imperative or exclusivity language — assert against a
      denylist (`do not`, `locked`, `reserved`, `wait for`, `owned by`) so the wording cannot
      regress into implying a guarantee
- [ ] Section includes a human-readable staleness figure for each entry
- [ ] Query failure or timeout produces a bundle without the section and does not raise —
      test by injecting an exception into the query
- [ ] Cross-workspace isolation: a session in workspace A never sees workspace B's activity
      (trivially true under B316's separate databases; assert it anyway so it stays true if
      the isolation model ever changes)
- [ ] `pytest tests/ -q` failure set identical to pre-change baseline

### What This Card Does NOT Do

- Does not prevent, detect, or resolve concurrent file overwrites — see the top section
- Does not add locks, leases, claims, reservations, or any mutual-exclusion primitive
- Does not block, delay, or gate any agent action
- Does not detect contradictory *decisions* between agents ("A chose Postgres, B chose
  Mongo") — that is embedding-proximity + polarity detection at write time and is a separate,
  genuinely Campy-shaped card worth filing next
- Does not notify or push — this is pull-only, surfaced on the next recall

### Outcome

An agent starting work sees that another agent touched the same files minutes ago, and can
re-read before writing or pick different work. It does not prevent collisions — nothing at
this layer can — but it cuts the redo cost that follows one, and it makes "who changed this
and when" answerable after the fact instead of a forensic exercise.
