# B312 - Provenance Fields + Explicit Supersession on Fact-Bearing Nodes

State: done
Priority: P0

Plan: (inline — self-contained, sized for a Sonnet-level implementer)

Depends on: nothing. **This is the first card in the cloud/interop series (B312–B317) and
every other card in the series assumes it has landed.**

### Why

Campy is being evaluated as the graph engine behind an external platform's capability
graph. That platform's governance standard mandates two things Campy does not currently
guarantee:

1. *"Include provenance on every harvested or observed fact: owning source, source
   version, observation time, and evidence reference."*
2. *"Deletions and supersessions are explicit, so a projection can remove stale
   relationships deterministically."*

Beyond the external driver, both are independently correct for Campy. Today a recalled
fact cannot answer "where did you learn this, from which version of that source, when,
and what's the evidence?" — which is the question a user asks the moment memory returns
something wrong. And decay/archival is currently implicit (`archived BOOLEAN`), so a
consumer cannot distinguish "this was superseded by a newer fact" from "this aged out"
from "this was wrong."

### Current State (verified in code)

`campy/brain/hippocampus/schema.py` (1378 lines) holds a `NODE_TABLES` dict of ~53 node
table DDL strings. Fact-bearing tables today carry: `text_raw`, `embedding`,
`embedding_model`, `embedding_dim`, `confidence`, `confidence_low`, `pathway_strength`,
`archived`, `anomaly_type`, `flagged_for_review`, `created_at`.

There is **no** source attribution, no source version, no evidence pointer, and
`created_at` conflates "when the fact was written" with "when the fact was observed"
(they differ for anything backfilled or harvested).

**An additive migration mechanism already exists and must be reused.** At
`schema.py:1117` there is a `_MIGRATIONS` list of `(table, column, type)` tuples, applied
around line 1242 via `ALTER TABLE {table} ADD {col} {col_type}`, guarded by a
`_column_exists()` helper so it is idempotent and safe on existing databases. Do not
invent a new migration path — append to this list.

Note for rel tables: `_REL_MIGRATIONS` immediately follows and uses drop+recreate, because
Kùzu 0.11.3 (pinned) has no `ALTER REL TABLE`. It is only safe when no existing edges use
the affected types. Read that block before touching any rel table.

### What This Card Does

**Task 1 — Add four provenance columns to fact-bearing node tables.**

Add to `NODE_TABLES` DDL (for new databases) *and* to `_MIGRATIONS` (for existing ones):

| Column | Type | Meaning |
|---|---|---|
| `source` | `STRING` | Owning source identifier — e.g. `agent:claude-code`, `harvest:git`, `user:direct`, `import:temporal`. Free-form but namespaced `<kind>:<id>`. |
| `source_version` | `STRING` | Version of the source at observation time — git SHA, descriptor version, adapter version, model ID. Nullable when genuinely unversioned. |
| `observed_at` | `TIMESTAMP` | When the fact became true / was observed. Distinct from `created_at` (when Campy wrote the row). For live capture the two match; for backfill they do not. |
| `evidence_ref` | `STRING` | Pointer to the evidence — message ID, file path + line, run ID, URL. Nullable, but strongly preferred. |

Apply to these tables (**Tier 1 — required**), which carry claimed or observed facts:

```
Concept, Decision, Constraint, Requirement, ActionItem, GlobalConstraint,
GlobalPreference, Lesson, Procedure, KnowledgeGap, Plan, PlanStep, Hypothesis,
ActionFact, ActionEffect, VictoryCondition, Rule, Transition, DocumentExtract,
WorkSummary, WorkArtifact
```

Then read the full `NODE_TABLES` dict and apply the same judgement to the `Arc*` pattern
tables (`ArcMechanic`, `ArcActionPattern`, `ArcEffectPattern`, `ArcPrecondition`,
`ArcFailureMode`, `ArcRecoveryPolicy`, `ArcWorldModelStep`) — these are learned/inferred
patterns and should carry provenance too (**Tier 2 — include unless you find a concrete
reason not to; state the reason in the PR if you skip any**).

Do **not** add provenance to structural/ontology/runtime-record tables: `GistClass`,
`GistExample`, `SchemaOrgType`, `Label`, `LLMProvider`, `Workspace`, `Session`,
`Message`, `Document`, `MainQuest`, `SideQuest`, `MergeEvent`, `DisambiguationEvent`,
`TaskGraph`, `TaskNode`, `GridSnapshot`, `Dataset`, `PuzzleCostSummary`, `ArcRun`,
`ArcTaskResult`, `ArcEvent`. These are either Campy's own bookkeeping or ontology
scaffolding — they are not claims about the world, and adding provenance to them is noise.

**Task 2 — Add explicit supersession.**

Two halves, both written in the same operation:

*(a) Node columns* (add to DDL + `_MIGRATIONS`, same Tier 1 + Tier 2 table set):

| Column | Type | Meaning |
|---|---|---|
| `superseded_by` | `STRING` | Primary key of the node that replaced this one. NULL = current. |
| `superseded_at` | `TIMESTAMP` | When supersession happened. |
| `supersession_reason` | `STRING` | One of a small controlled vocabulary — see below. |

Controlled vocabulary for `supersession_reason` — define as a module-level frozenset in
`schema.py` and validate on write:
`replaced` (a newer fact says it better), `contradicted` (proven false),
`source_removed` (the upstream source no longer asserts it), `merged` (folded into
another node — pairs with the existing `MergeEvent` flow), `expired` (time-bounded fact
whose window closed).

*(b) A `SUPERSEDES` rel table* so lineage is traversable, not just a dangling ID.

Kùzu 0.11.3 supports multiple `FROM ... TO ...` pairs on one rel table — the existing
`_REL_MIGRATIONS` block already relies on multi-pair rel tables (see the `ESTABLISHED_IN`
comment), so follow that pattern. Cover the Tier 1 + Tier 2 tables, same-type pairs at
minimum (`Lesson -> Lesson`, `Decision -> Decision`, …). Cross-type supersession is out
of scope for this card.

**B323 reconciliation note (added retroactively, does not change the Task 2 requirement
above — this card had already landed with `SUPERSEDES` live by the time B323's audit ran).**
B323's Task 4 flagged that `SUPERSEDES` duplicates the pre-existing `DEPRECATED_BY` rel
table (`Concept`/`Decision`/`Constraint`/`Lesson` self-pairs) with the *opposite* arrow
convention — `SUPERSEDES` is `(newer)-[:SUPERSEDES]->(older)`, `DEPRECATED_BY` is
`(older)-[:DEPRECATED_BY]->(newer)`. B323's preferred fix is for this card to extend
`DEPRECATED_BY` (add the missing pairs + edge properties) instead of introducing
`SUPERSEDES` at all, keeping this card's node columns
(`superseded_by`/`superseded_at`/`supersession_reason`) as the fast filter either way.
Because this card had already landed (schema live, `mark_superseded()` writing
`SUPERSEDES`, `tests/test_provenance.py` exercising it) by the time B323 ran its audit,
merging the two mechanisms in place was judged out of scope for B323 to do silently — that
would be an in-place rel-table migration B323 did not audit for safety. Per B323's own
instructions for this situation, no third mechanism was added, and the merge is tracked
as a follow-up: **backlog/B326.md**. Until B326 lands, `SUPERSEDES` and `DEPRECATED_BY`
both exist and neither is written by the other's call path.

**Task 3 — One helper, one write path.**

Add to `campy/brain/hippocampus/schema.py` or a new
`campy/brain/hippocampus/provenance.py` (implementer's call — pick whichever keeps
`schema.py` from growing further; it is already 1378 lines, so a new module is probably
right):

```python
async def mark_superseded(
    db: KuzuClient, *, table: str, node_id: str,
    superseded_by: str, reason: str, at: datetime | None = None,
) -> None:
    """Set the three node columns AND create the SUPERSEDES edge together."""
```

Both halves must happen in one call so they cannot drift. Raise `ValueError` on a reason
outside the vocabulary. If a caller ever sets `superseded_by` directly without the edge,
that is a bug — note it in the docstring.

Also add a small write-side helper so capture paths can attach provenance without
repeating themselves:

```python
def provenance_fields(
    *, source: str, source_version: str | None = None,
    observed_at: datetime | None = None, evidence_ref: str | None = None,
) -> dict:
    """Return the four provenance params, defaulting observed_at to now(UTC)."""
```

**Task 4 — Populate provenance at the primary capture sites (best-effort, bounded).**

Do **not** attempt to retrofit all ~500 write sites. Scope to the main capture path:
`campy/brain/thalamus/tools/capture.py` and `campy/brain/thalamus/tools/lessons.py`
(`upsert_lesson`). Set `source` from the session's client/role if available (see how
`Session` records client identity — check `campy/brain_daemon.py:_dispatch` around line
217 and the `Session` node fields), `observed_at` to now, `evidence_ref` to the message
or session ID being processed. `source_version` may be NULL here — it becomes meaningful
in harvest/import paths that don't exist yet.

Everything else keeps writing NULL provenance for now. That is acceptable and expected;
B317's eval pack will show which paths still need it.

### What This Card Does NOT Do

- Does not add the `authority` property (projected vs earned) — that is **B313**
- Does not backfill provenance onto existing rows — NULL is the correct value for facts
  written before this card
- Does not retrofit provenance into all write sites — only the two named capture paths
- Does not change decay/sweep behavior to *use* supersession — `campy/brain/brainstem/
  sweep.py` keeps working as-is. Wiring sweep to emit `expired` supersessions instead of
  silent archival is a good follow-up card, not this one.
- Does not add cross-type supersession edges

### Outcome

Every fact Campy stores can answer "who said this, from what version, when, and on what
evidence," and every removal is an explicit, queryable event rather than a row quietly
flipping `archived`. This is the precondition for Campy being trusted as a store by any
governed platform, and it is the schema foundation the rest of B313–B317 builds on.
