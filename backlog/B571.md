# B571: test_secret_scrubber's notify_turn test fails when test_explore_graph or test_b69_valence runs first

**Status:** Fixed 2026-11-16 in PR 450. `test_b69_valence.py` and `test_explore_graph.py` now snapshot `sys.modules`
in `setup_module`. Their teardown puts every entry they replaced back exactly, and drops every module first imported
while their stubs were in place, since those modules bound the stubs. Found in passing while running the full suite
for object-text matching, where CI turned red.

**Principles:** P6 (measure correctly before believing): a test whose result depends on run order does not check
what it names.

**Cause.** Each teardown popped `campy.brain.hippocampus.graph.embeddings` (and `campy.brain.thalamus.tools`) whether
or not the file had stubbed it, and left modules imported under the stubs (`schema.py` among them) holding the stub.
The next import of the embeddings module created a second module object. The scrubber test patched that new object,
while the capture code still held the old one.

**What.** `tests/test_secret_scrubber.py::test_notify_turn_embeds_scrubbed_content_not_raw` passes alone, but fails
with "embedding provider was never called" when `tests/test_explore_graph.py` or `tests/test_b69_valence.py` runs
before it. Both files replace modules in `sys.modules`, so the scrubber test's patch lands on a module object that the
code under test no longer imports.

**Fix (to design).** Have the two files restore `sys.modules` (monkeypatch.setitem, or a fixture that puts the
original modules back), or have the scrubber test patch the module the code imports at call time.

**Graph edge.** None: test isolation only.
