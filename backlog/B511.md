# B511: attribute facts reach OWL properties — structured attribute field + rule fallbacks (under CAMPY_OWL_PROPERTIES)

**Status:** open (PR pending gate) · Follows B509. Same flag, default off; flag off is unchanged.

## Problem

In the R95 fresh-ingest LoCoMo store (ENTITIES + GRAPH_LINKING + SKOS_VOCAB + OWL_PROPERTIES),
`scripts/graph_structure_report.py` showed 205 `has_attribute` Observations, 14 properties, 7.8% linked
(HAS_PROPERTY), 4.9% with a typed value, 0 supersessions. Property resolution needs a "name: value" object
(`observation_keys.parse_attribute`); the extractor writes that for 4% of attribute claims.

## Diagnosis (R95, 205 objects)

| shape | n | named by B509 | why |
|---|---|---|---|
| bare value ("park", "perfect", "gf") | 159 | 0 | no colon, no number: `parse_attribute` falls to `_quantity_key`, which needs exactly one number (observation_keys.py `parse_attribute` last branch) -> None -> `apply` returns (attribute_properties.py `apply`, `if key is None`) |
| other longer phrase | 18 | 0 | same path |
| quantity phrase | 11 | 10 | named by `_quantity_key`, but 3 of the 10 are not attributes ("one of the most rewarding things", "combine two of my passions"): nothing checked the number was a quantity |
| "name: value" | 9 | 6 | 3 lost: `name:` and `attribute:` keys are in `_STOPWORDS`, so the name has no tokens |
| verb phrase ("love", "going well") | 8 | 0 | no name exists |

Most `has_attribute` objects in LoCoMo are not attributes at all: the extractor uses the predicate for
adjectives, feelings and nouns. No rule can name those without inventing a name.

## Change (under `[observations] owl_properties`)

- **Structured field.** The extractor prompt gains `"attribute": {"name", "value"}` (only with the flag).
  `attribute_names.validate_structured` keeps it only when the name is a short noun phrase (1-3 words, no
  verbs or placeholders) and the value appears in the turn as written. Rejections are counted
  (`attribute_name_invalid`, `attribute_value_not_in_turn`, ...). The model advises; rules decide.
- **Rule fallbacks** (`hippocampus/attribute_names.py`, pure): quantity phrase (B499's `_quantity_key`, now
  refusing "N of ..." partitives and long phrases, name rebuilt as the content words: "currently on page
  200" -> page = 200), copula ("my X is Y", "Max's age is 3": possessor must be the subject), count (bare
  number named by the next word in the turn: "my four dogs"), age ("3-year-old"), and the literal key
  `name:`. Every value must appear in the turn. No rule, no property.
- `ap.apply(rules=...)` / `ap.backfill(rules=...)`: `rules=False` reproduces B509 exactly (used for the
  offline before/after).

## Offline measure (rule-only, no model; stores stripped of B509 state, backfilled)

See the PR. Rules alone do not raise coverage on LoCoMo (the objects are not attributes); they remove false
properties and add the age/name shapes. The structured field is the lever; it needs a fresh-ingest gate.
