### Problem

`import spacy` pulls `torch` into `sys.modules` (verified). Measured RSS on this machine:

| Imports | RSS |
|---|---|
| bare Python | 14.8 MB |
| `+ kuzu` | 24.3 MB |
| `+ spacy` (pulls torch) | **239.9 MB** |
| `+ fastembed` | 75.1 MB |
| `+ kuzu + fastembed` | **76.1 MB** |

spaCy/torch costs **~225 MB** — essentially the entire memory problem. Removing it
puts the daemon under the <80 MB target on its own.

`torch` is also ~2 GB of wheel for a dependency used only for token classification,
and it dominates install time and container image size (B385 ships to Fargate).

### Current usage — read this before planning

Files are `step1_ner.py` and `step1b_relations.py`. (B384's card text said
`step1_zoning.py` / `step1b_fast_relations.py`; those names do not exist.)

`campy/brain/temporal_lobe/loop/step1_ner.py` uses:
- `spacy.load("en_core_web_md")`, cached in a module-level `_nlp`
- `doc.ents` — named entity recognition
- `doc.noun_chunks` and `chunk.root.dep_` — **dependency parse labels**

`campy/brain/temporal_lobe/loop/step1b_relations.py`:
- `extract_relations(doc, entities)` takes a spaCy `Doc` object directly

### Gate 0 — Feasibility spike (do this FIRST, report before building)

ONNX token classification gives NER. It does **not** give dependency labels or
noun chunks. Before writing production code, timebox a spike and report:

1. Which ONNX NER model is viable, with its **license** (the card requires
   Apache-2.0 or MIT — no CC-BY-NC, no research-only), size on disk, and RSS when
   loaded under `onnxruntime` (already a dependency via fastembed).
2. How the model is distributed. It must work **offline** at runtime — B385 ships a
   zero-egress container. Pre-baked into the image or downloaded at install time,
   never at first inference.
3. **A concrete replacement for `noun_chunks` + `chunk.root.dep_`.** Options to
   evaluate: an ONNX dependency parser; a POS-tagger + shallow-chunk heuristic; or
   dropping chunk-based candidates entirely and relying on NER spans.
4. Measured entity-extraction agreement against the current spaCy output on a
   sample of real turns.

**If no option clears the license + offline + accuracy bar, STOP and report.** Do
not silently degrade extraction quality to make the card pass. Reporting "not
feasible as specified, here are the three options and their tradeoffs" is a
successful outcome for this gate.

### Scope

1. Replace spaCy NER in `step1_ner.py` with the ONNX pipeline chosen at Gate 0,
   preserving the existing return contract of `extract_entities()`.
2. Replace the `Doc`-typed interface between `step1_ner.py` and
   `step1b_relations.py` with an explicit, engine-neutral dataclass (tokens, spans,
   labels). `extract_relations()` must no longer accept a spaCy `Doc`.
3. Remove `torch`, `torchvision`, `thinc`, `spacy` from `pyproject.toml` and
   `requirements.txt`. Remove the spaCy model download from `campy/cli/install.py`
   and from CI.
4. `tests/test_torch_free_import.py`: importing `campy.brain_daemon` leaves zero
   `torch`, `thinc`, `spacy` entries in `sys.modules`.
