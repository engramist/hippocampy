# B491: Gate results must record what the model received

**Status:** open · **Found:** 2026-10-19 (e2e lead) · **Repo:** campy-benchmarks (`diag_answer_replay.py`, `eval_gate.py`)

## Problem

A gate JSON is the only record of a comparison, and it can't show what the
model was actually sent:

- The replay's `Recorder.achat` keeps only the **last** prompt per question.
  Any second LLM call in `run_ask` (B489's verifier, the H2 guard's retry)
  overwrites the answer prompt.
- `run_ask`'s `meta` dict is not saved, so per-question flags such as
  `meta["verify"]` are lost.
- The JSON stores each side's `campy/__init__.py` path but not the commit
  SHA, a dirty-tree flag, or the `CAMPY_*` environment overrides in force.

The same class of mistake has cost us before: the `full_history` marker on
all three row builders (R56 identical results), the 256-token judge cap, the
lying import check.

## Fix

1. Recorder appends every call: `calls: [{role, prompt, reply}]` per question.
2. Save `meta` per question.
3. Per side, record `git rev-parse HEAD`, `git status --porcelain` non-empty,
   and every `CAMPY_*` env var.
4. `gate_report.py` prints the SHAs and env flags at the top of each table.

## Done when

An R-job's JSON alone tells you which commit and flags each side ran and the
exact text of every model call for every question.
