# B442 - adapters/claude_code/hooks/*.sh Scripts Are Copied But Never Registered — Dead Code

State: ready
Priority: P2
Branch: fix/b442-dead-adapter-hook-scripts
PR Target: main

### Note on origin

Found while implementing B440's `SessionEnd` hook, investigating
whether `adapters/claude_code/hooks/*.sh` (a separate, older set of
hook scripts from `plugin/hooks/*.py`) also needed a `session_end.sh`
counterpart.

### Problem

`adapters/claude_code/setup.py::install_hooks()` copies every `*.sh`
file from `adapters/claude_code/hooks/` (`session_start.sh`,
`pre_tool_use.sh`, `post_tool_use.sh`) into the target project's
`.claude/hooks/` directory at `campy setup`/`register()` time.

`adapters/claude_code/setup.py::_write_hook_config()` — the only
function in this file that writes an actual hook-event registration
into `~/.claude/settings.json` — only ever writes a `UserPromptSubmit`
entry, pointing at a completely different script
(`hook_user_turn.py`). **No code anywhere registers `SessionStart`,
`PreToolUse`, or `PostToolUse` for the copied `.sh` scripts.**

Claude Code has no filename-based auto-discovery convention for
`.claude/hooks/*.sh` — a hook only fires if explicitly registered by
event name in `settings.json` (or, for a plugin, in the manifest the
plugin's `plugin.json` points at — confirmed: `plugin/.claude-plugin/
plugin.json` declares `"hooks": "./hooks/hooks.json"`, which is the
actual live registration path, backing `plugin/hooks/*.py`, not these
`.sh` scripts). So **`session_start.sh`/`pre_tool_use.sh`/
`post_tool_use.sh` are copied into every registered project's
`.claude/hooks/` directory and then never actually invoked by anything.**

### Impact

- Dead code that's actively misleading: `tests/adapters/
  test_claude_code_hooks.py` asserts these scripts exist, are
  executable, and behave correctly when run directly by the test
  suite (`subprocess.run(["bash", "adapters/claude_code/hooks/
  session_start.sh"], ...)`) — which passes, since the SCRIPT itself
  works fine when invoked manually. The tests don't (and can't, without
  a real Claude Code session) verify Claude Code ever actually calls
  them, so this gap has been invisible to the test suite.
- Anyone reading `adapters/claude_code/setup.py`'s registration flow
  or the installed `.claude/hooks/` directory would reasonably assume
  these scripts are live, active hook integrations. They are not.
- The real, live SessionStart/PreToolUse/PostToolUse behavior for
  Claude Code users comes entirely from the plugin path
  (`plugin/hooks/hooks.json` → `plugin/hooks/*_wrapper.py`), which is
  a functionally equivalent but separately-maintained implementation.

### Scope

One of two directions, not prescribed here:
1. **Delete the dead code**: remove `adapters/claude_code/hooks/*.sh`,
   the `install_hooks()`/`.glob("*.sh")` copy step in `setup.py`, and
   the now-inaccurate `test_claude_code_hooks.py` assertions about
   their existence/executability — if the plugin path
   (`plugin/hooks/`) is the intended, sole live mechanism going
   forward for Claude Code users who register via `campy setup`.
2. **Actually wire them up**: add the missing `SessionStart`/
   `PreToolUse`/`PostToolUse` entries to `_write_hook_config()` (or a
   new equivalent), so the `adapters/claude_code/` registration path
   genuinely activates what it copies — if this path is meant to be an
   independent, non-plugin-marketplace way to get the same
   integration (e.g. for users who install directly from source
   rather than via the plugin manifest).

Whichever direction: this decision affects whether `session_end.sh`
(this card's own trigger — the reason this was found) needs to be
added here too, or whether B440's `plugin/hooks/session_end_wrapper.py`
is already the complete, sole implementation.

### Acceptance Criteria

- [ ] Decision made and documented: dead code removed, or genuinely
      wired up to fire.
- [ ] If wired up: verified against a real Claude Code session that
      `adapters/claude_code/`-registered hooks actually invoke (not
      just that the scripts run correctly in isolation, which is
      already covered and passing).
- [ ] `tests/adapters/test_claude_code_hooks.py` updated to match
      whichever direction is chosen.
- [ ] Work executed in branch `fix/b442-dead-adapter-hook-scripts` and
      PR created targeting `main`.

### Outcome

`adapters/claude_code/`'s hook scripts either genuinely work or are
removed — no more silently-inert code masquerading as a working
integration.
