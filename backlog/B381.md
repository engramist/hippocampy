### Problem

Currently, Campy is tested primarily by running it "locally" in the background of developer machines and subjectively observing whether assistants (Claude Code, Codex, Cursor) remember past context. This approach lacks:
1. **Objective Local KPIs:** There is no automated instrument tracking whether running Campy in the background is actually saving tokens, maintaining low memory, or speeding up agent execution.
2. **Disconnected Benchmark Efforts:** Extensive memory-testing work has been done in the sibling `ARC_AGI` repository (e.g. `test_a059_memory_hot_path_latency`, `test_a084_mechanic_memory_transfer_diagnostics`, `test_a221_disappearance_graph_write`), but this is not unified into Campy's core benchmarking harness.
3. **Narrow Ask-Eval Coverage:** The existing `benchmarks/ask_eval/` harness (B304) has only 16 questions and tests only a single model (`llama3.1:8b`), leaving paraphrasing accuracy low (25%) and ignoring modern agent memory standards.
4. **Lack of Baseline Measurement:** Without a definitive baseline snapshot taken *before* implementing our P0 cards (B384, B374, B382, B383), we cannot empirically prove that our architectural refactors improved weight, speed, and accuracy.

### What it does (scope)

This card builds the **Unified Decision-Grade Agent Memory Benchmark Suite**, establishing automated local KPIs, integrating the sibling `ARC_AGI` world-model evaluation, and adopting industry agent-memory standards:

#### 1. The 4-Tier Local KPI Framework
Build `benchmarks/kpi_monitor.py` to continuously evaluate the local background daemon:
- **Tier 1: Resource & Footprint KPIs:**
  - Idle physical footprint (`vmmap -summary` on macOS, `/proc/[pid]/status` on Linux).
  - Allocation delta per 100 ingested turns (monitoring for memory leaks).
- **Tier 2: Token Economics, Speed & Graph Traversal KPIs (`performance-and-debugging.md`):**
  - Emitted token compression percentage on over-budget bundles (target 50%–70% reduction) and bypass tracking for sub-budget bundles (100% fidelity, 0s LLM overhead).
  - Retrieval compilation latency (target <10ms via pre-warmed candidate frontier).
  - Graph neighborhood expansion latency per hop (isolated $\le 2$ hop latency $<5$ms).
  - Edge scan and block hit counts during neighborhood expansion.
  - Query plan regression verification (flag unindexed scans or unbounded Cartesian joins in `kpi_monitor.py`).
  - TTFT (Time-To-First-Token) latency reduction for downstream LLM calls.
- **Tier 3: Cognitive Retention & Deprecation KPIs:**
  - Cross-session recall precision across multi-turn distances (1 to 20 sessions).
  - Stale constraint rejection (Negative Control $\ge 95\%$).
- **Tier 4: Model Handoff Fidelity KPIs:**
  - Zero constraint violations when switching between Frontier and Economy model tiers (B383).

#### 2. Sibling `ARC_AGI` World-Model Benchmark Integration
Formally wire the memory evaluation from `/Users/djshelton/Desktop/GitProjects/ARC_AGI` into Campy's CI:
- **Mechanic & Rule Transfer:** Benchmark cross-game transfer accuracy (`get_transferred_rules`).
- **Disappeared Entity Persistence:** Measure graph state recall for entities occluded or removed over time.
- **Hypothesis vs. Evidence Convergence:** Measure reduction in exploratory moves when an agent is backed by Campy's memory graph versus memoryless runs.

#### 3. Industry Agent-Memory Benchmark Suite (Quarantined in Sibling Repo)
External benchmarks are isolated in the sibling repository `/Users/djshelton/Desktop/GitProjects/campy-benchmarks` to adhere to `docs/ecosystem-rules.md` (zero heavy external dependencies in Campy core). The sibling harness has been initialized with `run_all.py` and suite directories. Remaining work focuses on adapter wiring:
- **LoCoMo (Long-Context Memory Benchmark):** Multi-session factual recall and dynamic constraint updates over 50+ turns.
- **MemoryGym (Spatial/Temporal Consistency):** Testing memory persistence across long intervals without context rot.
- **MemBench / Multi-Session Continuity:** Evaluating personal preference retention and contradictory belief arbitration.

#### 4. Automated Baseline Comparison Tool
The sibling suite and local harness provide a single comparison workflow:
```bash
python run_all.py --baseline    # Records current snapshot into baseline_snapshot.json
python run_all.py --compare     # Diff against baseline after card implementation
```
Outputs automated Markdown comparison tables for PR descriptions.
