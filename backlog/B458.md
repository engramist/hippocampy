# B458 - current_truth: Exact Identifier Match Loses to Near-Identical Notes (RRF Fusion)

State: fixed (2026-09-30 — see completion notes)
Priority: P1

### Problem Statement

Found by campy-benchmarks' MemoryGym suite (2026-09-30), run against both
the B385 container and a local `--isolated` daemon with the same code and
LLM. Each episode stores one note, "Observation at Step 0 for
memgym_mysterypath_epN: MysteryPath navigation sequence is: ...", then
queries "MysteryPath navigation sequence for memgym_mysterypath_epN".
From some episode on, `current_truth` returned another episode's note
(mostly `ep2`'s) as the top hit: success 55% in the container run, 20% in
the local run. The recalled paths were complete, just the wrong episode's.

Root cause, in `current_truth`'s reciprocal rank fusion (RRF) of the
vector and FTS lists (confirmed with `debug_ranking` on a reproduced store):

1. **Zero-evidence lexical hits got full rank credit.** B454 made the FTS
   query an OR of content words ranked by bm25, so it also returns notes
   that match only words every note shares. Those score ~0 (FTS5 clamps
   such a term's IDF to 1e-6), but RRF is rank-only, so they took lexical
   ranks 2..10 with full credit. The one note matching the episode id
   scored 2.57, the rest 0.0.
2. **Ties fell to insertion order.** The embedding model can't tell the
   near-identical notes apart, so the target note is often outside the
   per-table vector top 10. It is then a lexical-only hit at rank 0, which
   fuses to exactly the same score as the vector-only hit at rank 0; the
   sort was stable and vector sources are inserted first, so the vector hit
   won.

Any user storing several similar notes (per-run logs, per-ticket notes)
could have one stale note override an exact identifier match.

### What It Does (Scope)

- `_shared._drop_weak_lexical`: drop FTS hits scoring under 1% of the best
  hit before fusion. Nothing is dropped when the best hit itself has no
  evidence (tiny stores, where bm25 IDF degenerates).
- `_shared._fusion_sort_key`: sort fused results by final score, then by
  lexical score, so an exact tie goes to the lexical match.
- Both are applied in `retrieval.current_truth` only.

Not changed: `bundle_compiler._stage_semantic_context`'s lexical fallback
(B435). It doesn't use RRF, but it also admits FTS hits with no score floor
at a fixed distance of 0.299, so zero-evidence hits can take slots there
too. Left for a separate card if the benchmarks show it.

### Acceptance Criteria

- [x] A query naming a unique identifier returns that note first when the

- [x] The same holds when it is outside the vector top 10 (lexical-only).
- [x] Each of the two changes is needed: each test fails with only the

### Completion notes (2026-09-30)

Reproduced in the sandbox with an isolated daemon, a stub LLM and a hashed
bag-of-words embedding (huggingface.co is blocked there): MemoryGym 90%,
both failures "wrong episode" (one `ep2` again). On that store, top-hit
accuracy over all 20 episodes went from 18/20 to 20/20 with the fix, and
18/20 with the lexical filter alone (the remaining miss was the tie). The
full suite with the fix: MemoryGym 100%.

The real-model confirmation is the unticked criterion: rerun MemoryGym with
all-MiniLM-L6-v2 and llama3.1:8b.
