# B458 - current_truth: Exact Identifier Match Loses to Near-Identical Notes (RRF Fusion)

State: fixed (2026-09-30; reopened the same day when the real-model rerun still failed, fixed again -- see "Round 2"; confirmed on the real model, all criteria met)
Priority: P1

### Problem Statement

Found by campy-benchmarks' MemoryGym suite (2026-09-30), run against both
the B385 container and a local `--isolated` daemon with the same code and
LLM. Each episode stores one note, "Observation at Step 0 for
memgym_mysterypath_epN: MysteryPath navigation sequence is: ...", then
queries "MysteryPath navigation sequence for memgym_mysterypath_epN".
From some episode on, `current_truth` returned another episode's note
(mostly `ep2`'s) as the top hit: success 55% in the container run, 20% in
the local run. The recalled paths were complete, just the wrong episode's.

Root cause, in `current_truth`'s reciprocal rank fusion (RRF) of the
vector and FTS lists (confirmed with `debug_ranking` on a reproduced store):

1. **Zero-evidence lexical hits got full rank credit.** B454 made the FTS
   query an OR of content words ranked by bm25, so it also returns notes
   that match only words every note shares. Those score ~0 (FTS5 clamps
   such a term's IDF to 1e-6), but RRF is rank-only, so they took lexical
   ranks 2..10 with full credit. The one note matching the episode id
   scored 2.57, the rest 0.0.
2. **Ties fell to insertion order.** The embedding model can't tell the
   near-identical notes apart, so the target note is often outside the
   per-table vector top 10. It is then a lexical-only hit at rank 0, which
   fuses to exactly the same score as the vector-only hit at rank 0; the
   sort was stable and vector sources are inserted first, so the vector hit
   won.

Any user storing several similar notes (per-run logs, per-ticket notes)
could have one stale note override an exact identifier match.

### What It Does (Scope)

- `_shared._drop_weak_lexical`: drop FTS hits scoring under 1% of the best
  hit before fusion. Nothing is dropped when the best hit itself has no
  evidence (tiny stores, where bm25 IDF degenerates).
- `_shared._fusion_sort_key`: sort fused results by final score, then by
  lexical score, so an exact tie goes to the lexical match.
- Both are applied in `retrieval.current_truth` only.

Not changed: `bundle_compiler._stage_semantic_context`'s lexical fallback
(B435). It doesn't use RRF, but it also admits FTS hits with no score floor
at a fixed distance of 0.299, so zero-evidence hits can take slots there
too. Left for a separate card if the benchmarks show it.

### Round 2 (2026-09-30): identifiers rank first

The real-model rerun of `--suite all` after round 1 (#266) scored MemoryGym
25% (20% before), with the same "`ep2` everywhere" pattern -- but MemoryGym
run alone in a fresh store scored 100%. The difference: `--suite all` runs
LoCoMo first in the same store. Reproduced in the sandbox (LoCoMo then
MemoryGym, one store: 90%) and probed with `debug_ranking`:

- With other conversations in the store, the words the episode notes share
  ("MysteryPath", "navigation", "sequence") are rare store-wide, so the other
  episodes score bm25 3.48 against the target's 5.62 (62%). They are real
  partial matches, so round 1's weak-lexical floor rightly keeps them.
- They then collect RRF credit from both lists; the target is lexical-only
  (outside the vector top 10), so it ranks 4th. RRF is rank-only: it has no
  way to say "this is the one result that contains the id you asked for".
  Round 1 only covered the special case where the shared words score 0.

Fix: `_shared._fusion_sort_key(query)` ranks results by how many of the
query's identifiers they contain before the fused score. An identifier is a
whitespace chunk with both a letter and a digit (`memgym_mysterypath_ep7`,
`B458`, `v2`), matched like the FTS query phrases it: its alphanumeric parts
in order, non-alphanumeric separators, word-bounded (`ep1` does not match
`ep17`). Queries without identifiers keep round 1's ordering exactly.
Round 1's weak-lexical floor and lexical tie-break stay: they still help
queries with no identifier.

Tests: `test_exact_identifier_wins_in_a_store_shared_with_other_notes` (60
unrelated notes; fails with round 1 only) and
`test_identifier_patterns_match_whole_identifiers_only`. Probed stores: the
mixed store 18/20 -> 20/20, the MemoryGym-only store stays 20/20. Full
suite: same failure set as main in the sandbox.

### Real-model confirmation (2026-09-30)

`--isolated --suite all` with all-MiniLM-L6-v2 and llama3.1:8b on main after
#267: MemoryGym **100%** (25% after round 1, 20% before B458). MemBench and
ARC unchanged. LoCoMo showed 0.82 against 0.89, from two probes (`p_6_active`,
`p_8_active`) failing `stale_value_not_marked_superseded`. Not a B458 effect:
LoCoMo answers through `ask`, which does not use `current_truth`'s fusion,
and both questions contain no identifier. The answers were correct and retired
the old values with "prohibits the use of ...", which scorer v2 did not count
as a supersession cue. Fixed in campy-benchmarks scorer v3 (#2); rescored,
the run is 0.89 like every earlier run. One run is one sample: campy-benchmarks
`--repeat N` (#3) now measures run-to-run spread.
