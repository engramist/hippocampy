# B405 - Concept Deduplication Aborts Mid-Merge; Alt-Label Gazetteer Never Populates

State: ready
Priority: P0
Branch: feat/b405-fix-alt-label-link

### Problem

`quests.link_concept_has_alt_label` writes a property to a relationship table that
has none:

```cypher
CREATE (c)-[:HAS_ALT_LABEL {created_at: timestamp($now)}]->(l)
```

`HAS_ALT_LABEL`'s DDL declares only `FROM`/`TO` pairs — no `created_at`, no
properties at all. Verified directly against `kuzu==0.11.3`:

```
Binder exception: Cannot find property created_at for .
```

**This query raises every time it is called.** It is not guarded.

### Blast radius

The call site (`campy/brain/thalamus/tools/quests.py:863`) is the duplicate-Concept
merge routine. Its sequence:

1. Create a `Label` node from the duplicate's text — **succeeds**
2. Embed the label — guarded by `try/except`
3. **Wire canonical → altLabel — RAISES, unguarded**
4. Redirect `REQUIRES`/`ENABLES`/`REPLACES`/`CONTRADICTS`/`PART_OF`/`CHOSEN_OVER`/
   `IMPLEMENTS`/`EXTENDS`/`ALTERNATIVE_TO`/`CO_OCCURS_WITH` edges from duplicate to
   canonical — **never reached**

Consequences:

- **Concept deduplication never completes.** Duplicates are never merged; their
  edges are never redirected to the canonical node.
- **An orphan `Label` node leaks on every attempt** — step 1 already committed.
- **The `HAS_ALT_LABEL` gazetteer is empty**, because the only code that populates
  it throws before writing.

### Why this matters beyond the immediate bug

`docs/superpowers/specs/2026-09-05-entity-candidate-generation-design.md` identifies
the SKOS `Label` layer as the graph's most valuable untapped asset for entity
linking — a growing gazetteer of every entity ever committed, with aliases. That
analysis assumed the layer was being populated. It is not.

**This corrupts B401's measurement.** B401 measures "what fraction of spaCy-proposed
spans already exist as a `Label` in the graph?" and its decision rule says a **low**
result means "gazetteer not yet dense enough — keep spaCy." If alt-labels have never
been written, B401 will measure near-zero and reach that conclusion **for the wrong
reason** — mistaking a bug for a design finding.

**B405 must land before B401 runs**, and B401 should note whether its window includes
data written after this fix.

### Scope

1. Remove `{created_at: ...}` from the `HAS_ALT_LABEL` write, **or** add `created_at`
   to the rel table's DDL as a schema migration. Decide which is right — the edge is
   classified `plain` in `EDGE_REIFICATION`, so adding a property reclassifies it to
   `star` and B394's translation must change to match. **Prefer removing the
   property** unless creation time is genuinely needed; do not reclassify casually.
2. Make the merge routine transactional or idempotent so a mid-sequence failure
   cannot leave an orphan `Label` behind.
3. Assess and report existing orphan `Label` nodes. **Do not delete without sign-off.**
4. Add a test that runs the full dedup path end to end and asserts the
   `HAS_ALT_LABEL` edge exists and edges were redirected — not merely that no
   exception was raised.
