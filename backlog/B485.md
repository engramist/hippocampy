# B485 - Graph Expansion of the Observation Section for Multi-hop (M4.1)

State: implemented (off by default; gate pending: LoCoMo-10 multi-hop via replay with `CAMPY_OBSERVATIONS_EXPAND_HOPS=1`)
Priority: P2

Plan: `learnings/e2e-improvement-plan.md` M4.1 and Part G; `backlog/B472.md`; `learnings/2026-10-m3-observations.md`

### Problem Statement

LoCoMo multi-hop / inference questions ("What might Caroline's political
leaning be?", "Would Melanie go to a pride parade?") need facts about one
entity from several sessions. The Observation section returns the 8 best
matches to the question; the other facts about the same person sit under the
similarity floor or outrank each other, and the model sees them scattered.

### Fix (behind `[observations] expand_hops = 0|1`, default 0 = unchanged)

- After the first-pass Observations, read the Concepts they are
  OBSERVATION_ABOUT (subject and object): the hop-1 entities.
- Fetch further live Observations about those Concepts, excluding the ones
  already picked, ranked by embedding similarity to the question, up to
  `[observations] expand_limit` (6). Total <= `observation_limit` + `expand_limit`.
- Group the section by entity, one item per group, dates and quotes kept:
  `About Caroline: [Caroline, 2023-05-08] did: ... ("...") | [Caroline, 2023-06-27] ...`.
  An Observation goes under the hop-1 entity most first-pass Observations are
  about; one about no entity stays a single line. Within a group: conversation order.
- Applies only where Observations apply (conversation section is not the
  whole history). The ask prompt gains one sentence describing "About X:".
- Env `CAMPY_OBSERVATIONS_EXPAND_HOPS`. Two new gateway NamedQueries
  (`thalamus.bundle_observation_entities`, `thalamus.bundle_observations_expand`);
  no existing query changed. Nothing is stored (no shadow store): the entities
  are read from the graph on each compile.
- Compression never prunes Observation items and a group is one item, so
  nothing is dropped; the section grows by <= 6 observations (~600 tokens).

### Not done

- More than one hop (values above 1 behave as 1).
- Gate: replay on LoCoMo-10 multi-hop; bundle tokens are not budget-capped.
- On two-speaker chats (LoCoMo) the speaker is usually the only hop-1 entity,
  so the group is "everything about Tim" ranked by similarity; the gain depends
  on that ranking.
