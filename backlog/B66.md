### B66 · Plan & PlanStep Schema (Graph-Native Agent Plans)

**Problem:** When agents formulate multi-step strategies, the Brain captures each step as an isolated ActionItem or Message. The causal ordering — step 2 depends on step 1's output — is lost. Without plan structure as a first-class graph entity, the system cannot learn from sequences of actions, only from individual facts.

**What it does:** Adds `Plan` and `PlanStep` node tables to the Kùzu schema, with relationships that capture intentional ordering, quest targeting, and entity linkage. Plans become retrievable, comparable, and scorable graph structures.

**New Node Tables:**

`Plan`:
- `plan_id STRING PRIMARY KEY`
- `goal TEXT` — what the plan aims to achieve
- `strategy TEXT` — optional high-level approach description
- `embedding FLOAT[384]`
- `embedding_model STRING`
- `embedding_dim INT64`
- `step_count INT64`
- `valence DOUBLE` — overall outcome score (-1.0 to +1.0), NULL until evaluated
- `valence_source STRING` — "user_feedback" | "exit_code" | "test_result" | "system" | NULL
- `status STRING` — "active" | "completed" | "abandoned"
- `confidence DOUBLE`
- `confidence_low BOOLEAN`
- `pathway_strength DOUBLE`
- `archived BOOLEAN`
- `created_at TIMESTAMP`
- `completed_at TIMESTAMP`

`PlanStep`:
- `step_id STRING PRIMARY KEY`
- `step_number INT64`
- `description TEXT`
- `embedding FLOAT[384]`
- `embedding_model STRING`
- `embedding_dim INT64`
- `expected_outcome TEXT`
- `actual_outcome TEXT` — filled on completion
- `valence DOUBLE` — per-step outcome (-1.0 to +1.0), NULL until evaluated
- `status STRING` — "pending" | "in_progress" | "succeeded" | "failed" | "skipped"
- `created_at TIMESTAMP`
- `completed_at TIMESTAMP`

**New Relationship Tables:**
- `PLANNED_IN` — `Plan → Session` (provenance)
- `TARGETS` — `Plan → (MainQuest | SideQuest)` (quest linkage)
- `STEP_OF` — `PlanStep → Plan` (membership)
- `NEXT_STEP` — `PlanStep → PlanStep` (intentional causal ordering)
- `ACTS_ON` — `PlanStep → Concept` (which graph entities this step touches)
- Plan-level `PRODUCED_LESSON` — `Plan → Lesson` (outcome learning)

**Why `NEXT_STEP` is not redundant with timestamps:** PlanSteps have declared causal dependency (step 3 depends on step 2's output). This is agent reasoning, not clock time. The set is bounded (3-10 steps per plan) — no supernode risk.

**HNSW Vector Indexes:** Create indexes on both `Plan` and `PlanStep` tables for embedding-based retrieval.

**Acceptance Criteria:**
- `mcp_engine/schema.py` defines Plan + PlanStep node tables with all listed properties
- All 6 new relationship tables created with correct FROM/TO typing
- HNSW indexes created for Plan and PlanStep embeddings
- Schema init (`sidequests setup`) creates tables without error on fresh DB
- Existing schema migration does not break — additive only
- `kuzu_client.py` updated if any new query patterns needed
- Unit tests verify table creation, relationship creation, and HNSW index availability

**Outcome:** Plans are first-class graph citizens — retrievable by embedding, traversable by structure, scorable by outcome.
