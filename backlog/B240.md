# B240 - One-Click Install Release Gate and User-Facing Docs

State: ready
Priority: P0

Plan: backlog/plans/B-240-one-click-release-gate-and-user-facing-docs.md

### Problem

Even after the package path, bootstrap script, and validation harness exist, the project needs a clear go/no-go release gate and user-facing documentation. Without a single release checklist, it is easy to publish a command that works on the developer machine but fails for real users.

### What This Card Does

Creates the final release gate for one-click install: docs, troubleshooting, supported platforms, privacy guarantees, install/uninstall behavior, validation evidence, and public command readiness.

### Dependencies

- B236 - public package path
- B237 - hosted bootstrap script
- B238 - clean-machine validation
- B239 optional - Homebrew path

### Files to Create/Modify

| File | Action |
|---|---|
| `docs/one-click-install-release-gate.md` | CREATE - final go/no-go checklist |
| `README.md` | MODIFY - make one-click install the primary path only when gate passes |
| `Instalation_Instructions.md` | MODIFY - rewrite as user-facing quickstart/troubleshooting |
| `docs/troubleshooting-install.md` | CREATE - common failures and repair commands |
| `docs/public-release-audit.md` | MODIFY - record final audit status |
| `backlog/masterBacklogTracker.md` | MODIFY - track B236-B240 status and dependencies |

### Acceptance Criteria

- [ ] Release gate lists every validation command and expected result.
- [ ] Release gate documents supported platforms and explicitly marks unsupported ones.
- [ ] Docs explain where user memory lives (`~/.campy`) and that installer/uninstaller must preserve it by default.
- [ ] Docs include inspect-first and one-line install commands.
- [ ] Docs include repair commands: `campy doctor --repair`, `campy status`, `campy activity --follow`.
- [ ] Docs explain how to verify Codex, Claude Code, Claude Desktop, and VS Code integration.
- [ ] Docs include uninstall behavior and data deletion behavior as separate steps.
- [ ] README does not promote the one-click command as canonical until B236-B238 pass.
- [ ] Public-release audit and patent-pending language remain accurate.
- [ ] Backlog tracker reflects which one-click cards are complete and which are still pending.

### Validation Commands

```bash
rg -n "one-click|bootstrap.sh|doctor --repair|activity --follow|~/.campy|uninstall|Codex|Claude|VS Code" README.md Instalation_Instructions.md docs
bash scripts/audit_public_release.sh --release
.venv/bin/campy doctor
.venv/bin/pytest -q tests/test_public_release_manifest.py tests/test_packaging_installed_mode.py tests/test_bootstrap_script.py tests/test_bootstrap_clean_home.py
```

### Outcome

The project has a final release gate that tells us when the one-click installer is safe to advertise as the primary install path.
