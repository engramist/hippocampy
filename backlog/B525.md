# B525: Kind labels are clean singular nouns; meta-nouns are never kinds

**Status:** Open — gate pending (R103 stack + kind hygiene vs R100 on conv-42,conv-43,conv-47)

Lever 1c of the object-linking work, on top of B522-B524. B524's measurement found two vocabulary gaps that stop
"How many dogs does Andrew have?" from resolving at all: the store has no `dog` kind, only `my dogs` and `puppies`,
and the kind `name` (a meta-noun) swallows named things (Scout is `INSTANCE_OF` only `name`, Toby is `INSTANCE_OF`
person, breed, `my dogs` and pet). A question can only name a kind that exists under a plain noun.

1. **Normalisation at write time** (`kinds.normalise_kind_label`, used by `entities.resolve_kind`): leading
   determiners (a, an, the, my, our, your, his, her, their, its, this, that, these, those) are dropped; the last
   word goes to the singular with the spaCy model the NER step already loads, and only when the tagger calls it a
   plural noun ("dogs" -> "dog", "puppies" -> "puppy", "mice" -> "mouse", "model kits" -> "model kit"); plural-only
   nouns (binoculars, glasses, ...) stay. Without the model a suffix rule applies. The wording the model used is
   kept as a SKOS altLabel (`HAS_ALT_LABEL`), so lookup by the old wording still works.
2. **Meta-nouns are never kinds** (`kinds.META_NOUNS`: name, thing, type, kind, sort, stuff, one, item, example,
   part, way, lot, bit): the proposal is dropped and counted (`kinds_dropped_meta`). Matched on the whole label, so
   "flooring type" is still a kind.
3. **Consolidation of an existing store** (`scripts/consolidate_kinds.py`, `kinds.plan_hygiene` /
   `apply_hygiene`): each kind gets its clean label; kinds that collapse to one label merge into one survivor (a
   kind already carrying the clean label, else most instances, else lowest id) with `INSTANCE_OF` and `BROADER`
   re-pointed, altLabels moved, the old label kept as an altLabel and the merged kind archived (never deleted); a
   meta-noun kind loses its `INSTANCE_OF` edges (plain edges have no archive form, so those edges are the only
   thing removed) and is archived; an altLabel that is another live kind's prefLabel (a prefLabel outranks an
   altLabel, as in `plan_kind`) or exactly its own kind's prefLabel is detached. Set-based SPARQL updates through
   registered NamedQueries (`kinds.merge_*`, `kinds.set_kind_label`, `kinds.drop_instance_of`,
   `kinds.detach_alt_label`); idempotent.
4. **No semantic links** (puppy `BROADER` dog) are added. The script reports, as data, how many young-of pairs exist.

Flag: `[observations] kind_hygiene`, env `CAMPY_KIND_HYGIENE`, default off (the write-path rule only; the
migration is an explicit script). It does not live under `skos_vocab` because that flag is default on and this
changes what gets written.

Serves Principles 8 (a fact hangs off a subject by a relation to an object entity of a kind a question can name)
and 2 (the answer is the graph query; Python only cleans labels by rule). Measurements are in the PR. Gate pending.
