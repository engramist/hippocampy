# B305 - Bundle Relevance Floor: Stop Feeding Off-Topic Content to ask/Synthesis

State: done
Priority: P0

Plan: (inline — this card is self-contained and sized for a Sonnet-level implementer)

### Problem (found by B304's eval harness, 2026-07-15)

The B304 ask-eval matrix (`benchmarks/ask_eval/`, PR #16) ran 4 negative-control questions
about content that does NOT exist in the fixture graph (a Kubernetes deployment, a DB
administrator, a React frontend rewrite, a launch date) against 4 models × 3 harness
variants — **12 runs, 0% pass rate on every single one.** Every model hallucinated an
answer to at least one made-up question, regardless of size or harness trick.

This is not a model-quality problem. It's a retrieval-design bug: bundle sections return
their top-N ranked candidates with **no relevance floor**, so the bundle handed to the
LLM is *never empty* — even for a query about something the graph has zero information
on. Any model, however good, will treat non-empty "relevant context" as license to
answer. The B304 model/harness comparison numbers should not be trusted for a launch
decision until this is fixed, since unbounded filler content could be distorting those
scores too, not just the negative controls.

### Root Cause (verified in code)

`campy/brain/thalamus/bundle_compiler.py`, `_stage_plans()`:

```python
plans = await recall_plans_for_query(
    goal_query=query, db=db, config=config,
    limit=tier_config.get("max_semantic", 10),
    min_valence=-1.0,
)
```

No minimum similarity is applied — it takes whatever `recall_plans_for_query` ranks
highest, however weak the match. With 3 plans in a small graph, a query about Kubernetes
still gets plans back as "the best available," and they go straight into the prompt as
if relevant.

Other bundle stages need the same audit. `_stage_semantic_context` and neighboring
functions in the same file — check each one for a `min_similarity`/threshold; one path
in the file already enforces `0.70` (grep the file for "threshold: 0.70" as the reference
pattern to replicate) so the fix is making every stage consistent with that existing
convention, not inventing a new one.

### What This Card Does

1. **Audit every `_stage_*` function in `bundle_compiler.py`.** For each one that runs a
   similarity/vector search or a ranked-recall call (plans, semantic, lessons, whatever
   exists at implementation time — read the file fully first), confirm it either already
   enforces a minimum similarity or add one. Use the existing `0.70` convention as the
   default floor; if a stage's scores aren't on a comparable scale (e.g. plan ranking is
   `similarity × |valence| × pathway_strength`, not raw cosine), gate on the underlying
   `similarity` component specifically, not the composite score.
2. **`_stage_plans` specifically**: add a `min_similarity: float = 0.70` parameter (or
   read from `tier_config`), and only include a plan in the section if its `similarity`
   field clears that floor. If zero plans clear it, return `None` (same as the existing
   "no plans" early-return) rather than an empty-content section.
3. **Empty bundle is a valid, honest state — verify `run_ask` handles it correctly.**
   When every stage returns `None`/filtered-empty, `compile_bundle` should produce a
   bundle whose sections are genuinely empty, and `run_ask`'s prompt (already hardened in
   B303) should tell the model that plainly: "no relevant context was found — say so, do
   not guess." Check whether this instruction already exists for the empty case; if the
   B303 prompt hardening only covers the non-empty case, add the empty-case instruction.
4. **Do NOT filter by keyword/identifier presence** — that would break B303's lexical
   fast-path (exact `\bB\d+\b` matches should survive even at lower cosine similarity,
   since an exact identifier match is strong evidence regardless of embedding distance).
   The floor applies to *pure similarity-ranked* results; lexically-matched results are
   exempt from it by design (mirror how B303 already treats lexical hits — check
   `_lexical_plan_rows`/`_rank_plan_neighbors` in `campy/brain/thalamus/tools/quests.py`
   for the existing pattern of "lexical hits bypass the ranking-only path").

### What This Card Does NOT Do

- Does not re-run the full B304 model comparison matrix (that's a natural follow-up once
  this lands, but is not required for this card to be complete)
- Does not change the `0.70` convention's value — just makes it apply everywhere
- Does not touch H1/H2 harness variant code in `ask.py` beyond the empty-bundle prompt
  check in Task 3

### Outcome

`ask` and `compile_context` stop manufacturing answers from irrelevant filler. "I don't
know" becomes something the system can actually say when it's true — a prerequisite for
trusting any future model/harness comparison run on this graph.
