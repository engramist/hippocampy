### B79 · Wrap emb.embed() in asyncio.to_thread() in Orchestrator

**Problem:** Review #1 fix S1 wrapped LLM calls in `asyncio.to_thread()`, but `emb.embed()` calls (sentence-transformers) are still synchronous in the orchestrator. Each entity embedding blocks the event loop for ~5-20ms. With 10 entities per message, that's 50-200ms of blocking.

**What it does:** Wraps all `emb.embed()` calls in the async orchestrator with `asyncio.to_thread()`.

**Depends on:** None

**Files to modify:**
- `mcp_engine/loop/orchestrator.py` — wrap `emb.embed()` calls in `asyncio.to_thread()`

**Adapter allow-list propagation check:** No tool changes — N/A.

**Acceptance Criteria:**
- All `emb.embed()` calls in `orchestrator.py` are wrapped in `asyncio.to_thread()`
- `rg "to_thread.*embed" mcp_engine/loop/orchestrator.py` shows wrapped calls
- `pytest tests/ -k orchestrator -q` passes
- No direct synchronous `emb.embed()` calls remain in async code paths

**Outcome:** Embedding computation no longer blocks the event loop.
