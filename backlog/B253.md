# B253 - Agent Output Formatters

State: complete -- re-verified 2026-08-03 with a test-coverage caveat: 4 of 6 formatters (and the unknown-format fallback) had zero test coverage; manually smoke-tested all of them directly and confirmed they work correctly. See Audit Findings below.
Priority: P2

Plan: backlog/plans/B-253-agent-output-formatters.md

### Problem

All MCP tools currently return raw JSON dictionaries. Every agent receives the same format regardless of whether it's Claude Code (wants structured markdown), ChatGPT Desktop (wants conversational prose), or an ARC solver (wants mechanic priors in specific JSON schema). Agents waste tokens reformatting raw data into their preferred shape.

### What This Card Does

Adds adapter-specific output formatters that shape ContextBundles (from 252) into the form each agent type consumes most efficiently. One bundle, multiple delivery shapes.

### Dependencies

- B252 complete (Bundle Compiler)

### Design Decisions

| Decision | Choice | Rationale |
|---|---|---|
| Formatter architecture | Protocol/ABC with per-adapter implementations | Extensible; new adapters just add a formatter |
| Selection mechanism | `client_name` parameter on tool call | Already passed by adapters in `notify_turn` |
| Default format | `generic` (raw JSON, backwards compatible) | No change to existing behavior unless opted in |
| Format parameter name | `output_format` on `compile_context` | Explicit agent control |

### Acceptance Criteria

- [ ] `BundleFormatter` protocol defines the contract.
- [ ] Each adapter has a corresponding formatter implementation.
- [ ] Claude Code formatter produces structured markdown with headers and decision lists.
- [ ] Codex formatter produces compact, code-relevant context.
- [ ] Generic formatter returns raw JSON (backwards compatible).
- [ ] `compile_context` accepts `output_format` parameter.
- [ ] Unknown `output_format` falls back to generic.
- [ ] All formatters respect the token budget from the bundle.

### Audit Findings (2026-08-03 re-verification)

- `BundleFormatter` protocol (`campy/brain/thalamus/formatters/base.py`), formatter registry (`formatters/__init__.py`), and all 6 formatter implementations (`generic.py`, `claude_code.py`, `claude_desktop.py`, `codex.py`, `chatgpt_desktop.py`, `arc.py`) exist and match the plan's file list.
- `.venv/bin/python -m pytest -q tests/test_formatters.py` → 8 passed. Reading the test file shows coverage is thin: **only `GenericFormatter` and `ClaudeCodeFormatter` are actually exercised.** `ArcFormatter`, `ChatGPTDesktopFormatter`, `ClaudeDesktopFormatter`, and `CodexFormatter` are imported in the test file but never instantiated or called — no test invokes `.format()` on them, and `get_formatter()`'s unknown-format-falls-back-to-generic behavior is never tested either.
- Per the audit brief's "if a criterion's only coverage is mocked/stubbed, verify it yourself" guidance, manually smoke-tested the four uncovered formatters plus the fallback path directly against a real `ContextBundle` (not mocked):
  ```
  ArcFormatter            -> valid JSON with "memory_state" key, 388 chars
  ChatGPTDesktopFormatter -> natural-language prose ("Here's what I found about ...")
  ClaudeDesktopFormatter  -> conversational prose
  CodexFormatter          -> compact "// CONTEXT: ..." comment-style output
  get_formatter("some_unknown_agent_xyz") -> falls back to GenericFormatter ("generic")
  format_bundle(bundle, agent_type="some_unknown_agent_xyz") -> valid JSON string, len 458
  ```
  All four produce correctly-shaped, sensible output for their target adapter, and the unknown-format fallback works as specified. This is a genuine test-coverage gap, not a functional break — the acceptance criteria are actually met, they're just not regression-protected for 4 of 6 formatters.
- `compile_context` accepts `output_format`: confirmed in `campy/brain/thalamus/tools/context_tools.py::compile_context` (`agent_type = params.get("output_format") or params.get("agent_type") or "generic"`).
- "All formatters respect the token budget from the bundle": formatters render whatever `bundle.sections` already contains — budget enforcement itself happens upstream in `bundle_compiler.py` (truncation flag, per-tier limits), not re-applied inside each formatter. This matches the design ("Assembly strategy... truncate from the tail" in B252) rather than being a gap unique to this card.
- Full suite: `.venv/bin/python -m pytest -q` → 1600 passed, 59 skipped, 2 xfailed (no regressions).

Recommend a follow-up card (not created here, out of this audit's scope) to add direct unit tests for the 4 uncovered formatters and the fallback path, since manual smoke-testing isn't a substitute for regression coverage going forward.

### Outcome

Agents receive memory in the exact shape their prompt expects. Claude Code gets markdown; ChatGPT gets prose; ARC gets structured JSON. Zero reformatting tokens wasted.
