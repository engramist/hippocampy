# B316 - Workspace Router: One Database Per Workspace

State: todo
Priority: P1

Plan: (inline — self-contained, sized for a Sonnet-level implementer)

Depends on: **B315** (Principal — the router keys off `principal.workspace_id`).
Benefits from B314 but does not require it.

### Why

`campy/brain_daemon.py:65` opens exactly one database for the process life:

```python
self.db = KuzuClient(str(DB_PATH))      # DB_PATH = get_database_path(), line 42
```

For a multi-tenant deployment the isolation model has to be chosen. Three options were
considered:

| Model | Isolation | Risk |
|---|---|---|
| Shared graph + `tenant_id` predicate | query-level | one missing `WHERE` leaks another tenant's memory |
| DB per workspace | **filesystem-level** | routing bug (loud, not silent) |
| Container per tenant | process-level | cost, no cross-workspace anything |

**DB per workspace is the choice**, for two reasons specific to this codebase. First,
with ~500 Cypher sites (see B314) a predicate-based boundary is not auditable — you cannot
prove every query carries the filter. Physical separation needs no proof. Second, Kùzu is
embedded and single-writer per database: many small databases turn that limitation into
horizontal parallelism instead of a global bottleneck.

Sharding boundary rule: **shard where traversal does not need to cross.** Agents working
in one workspace never traverse into another. Cross-workspace knowledge is a separate,
deliberately-promoted store — not an accidental traversal.

### What This Card Does

**Task 1 — `WorkspaceRouter`.**

New module `campy/brain/hippocampus/graph/router.py`:

```python
class WorkspaceRouter:
    def __init__(self, root: Path, *, max_open: int = 32,
                 schema_init: Callable[[KuzuClient], Awaitable[None]]): ...

    async def get(self, workspace_id: str) -> KuzuClient:
        """Return a client for this workspace, opening (and initializing
        schema on) the database if it does not exist yet."""

    async def close(self, workspace_id: str) -> None: ...
    async def close_all(self) -> None: ...

    @property
    def open_count(self) -> int: ...
```

Behavior:
- **LRU cache** of open clients, bounded by `max_open`. Evicting closes the client cleanly.
  A `KuzuClient` holds an open `kuzu.Database` handle (`kuzu_client.py:__init__`) — leaking
  these will exhaust file descriptors under load, which is the failure mode this bound
  exists to prevent.
- First access to an unknown workspace creates the directory and runs `init_schema()`.
  Concurrent first-access for the same workspace must not race — guard per-workspace with
  an `asyncio.Lock` (a dict of locks keyed by workspace_id), not a global one.
- Eviction must not close a client that has an in-flight operation. Simplest correct
  approach: refcount in-flight borrows and skip eviction of a busy client, falling back to
  the next LRU candidate. If every candidate is busy, exceed `max_open` and log at WARNING
  rather than blocking or closing something in use.

**Task 2 — Path derivation, and the traversal vulnerability.**

`workspace_id` comes from a principal, but principals will eventually be minted from
external identity systems, so **treat it as untrusted input for filesystem purposes.**

A workspace id of `../../etc` or `a/b/../..` must not escape the root. Do not attempt to
sanitize by stripping characters — that is a blocklist and blocklists lose. Instead:

```python
def _workspace_dir(root: Path, workspace_id: str) -> Path:
    if not _WORKSPACE_ID_RE.fullmatch(workspace_id):   # ^[A-Za-z0-9][A-Za-z0-9_-]{0,63}$
        raise ValueError(...)
    digest = hashlib.sha256(workspace_id.encode()).hexdigest()[:16]
    return root / f"{workspace_id}-{digest}"
```

Allowlist regex **and** a digest suffix: the regex makes traversal impossible, the digest
makes collisions from case-insensitive filesystems impossible. Then assert the resolved
path is inside root (`resolved.is_relative_to(root.resolve())`) as a final backstop — belt
and braces, because this is the one place in the card where a bug is a security bug rather
than an availability bug.

**Task 3 — Fix the write lock, which is currently global.**

`kuzu_client.py:_get_write_lock()` (line ~36) returns **one lock per event loop, shared
across all `KuzuClient` instances**. Read the comment block above it before changing
anything — the per-loop weakref keying exists to fix a real bug (stale locks bound to
closed loops) and must be preserved.

With one database that shared lock is correct. With N workspace databases it serializes
every write across every tenant, which destroys the main benefit of sharding.

Change the key from `id(loop)` to `(id(loop), db_path)`, keeping the weakref-to-loop
staleness check exactly as it is. `KuzuClient` will need to retain its `db_path` (it
currently takes it as a constructor arg but does not appear to store it — check and store
it).

This is a genuine concurrency change to a file with careful existing reasoning. Do not
simplify the surrounding logic while you are in there.

**Task 4 — Wire into the daemon, backward-compatibly.**

In `campy/brain_daemon.py`:
- Construct a `WorkspaceRouter` rooted at the parent of the existing `DB_PATH`.
- In `_dispatch`, resolve `db = await router.get(principal.workspace_id)` and pass that to
  the handler instead of `self.db`.
- **The `local` workspace must resolve to the existing `DB_PATH` unchanged**, so an
  existing local install keeps its memory with no migration. Special-case it explicitly in
  `_workspace_dir` (with a comment), do not rely on the digest happening to match.
- Close all clients on daemon shutdown — find the existing shutdown path in `start()`
  (line 77) / `main()` (line 417) and hook in.

Keep `self.db` as an alias for the local workspace client if other code paths (the loop
worker at line 253, background sweep at 324, trigger compile at 356, file-bridge regen at
371) depend on it. **Audit those four background tasks** — they currently assume a single
DB. For this card they may keep operating on the local/default workspace only; note the
limitation in the PR. Making sweep workspace-aware is a follow-up card, and it is a real
one — a per-workspace consolidation scheduler is nontrivial.

### Acceptance Criteria

- [ ] Two different workspace ids yield clients backed by different directories, and a
      fact written to one is **not** readable from the other (the isolation test — write
      via one client, read via the other, assert absent)
- [ ] First access to a new workspace creates the directory and initializes schema
- [ ] Concurrent first-access to the same new workspace (`asyncio.gather` of 10 `get()`
      calls) initializes schema exactly once — assert via a counter on the injected
      `schema_init`
- [ ] LRU eviction closes the evicted client and `open_count` stays `<= max_open`
- [ ] A busy client is not evicted while an operation is in flight
- [ ] **Traversal tests**: `../../etc`, `a/b`, `..`, `` (empty), a 200-char id, and an id
      with a null byte all raise `ValueError` and create nothing on disk
- [ ] Resolved path is always inside root — property test over a set of adversarial ids
- [ ] `local` workspace resolves to the pre-existing `DB_PATH` — an existing local install
      sees its memory unchanged (seed a DB at the old path, route as `local`, read it back)
- [ ] Write lock is per `(loop, db_path)`: concurrent writes to two different workspaces
      overlap in time; concurrent writes to the same workspace serialize. Assert with
      timing or an instrumented counter, not by inspecting the lock dict.
- [ ] The existing per-loop staleness behavior still holds — run the existing
      `kuzu_client` lock tests unmodified (grep `tests/` for them first)
- [ ] Daemon shutdown closes all open clients
- [ ] `pytest tests/ -q` failure set identical to pre-change baseline

### What This Card Does NOT Do

- Does not make sweep/consolidation, the loop worker, trigger compile, or file-bridge
  regen workspace-aware — they stay on the default workspace; follow-up card
- Does not implement S3 cold storage / dormant-workspace eviction to object storage
- Does not implement cross-workspace promotion (the shared knowledge tier)
- Does not add per-workspace quotas, backup, or PITR
- Does not change how `workspace_id` is *derived* — that is B315's job and stays there

### Outcome

Tenant isolation becomes physical rather than predicate-based, so it is provable rather
than auditable-in-principle. Kùzu's single-writer constraint stops being a ceiling and
becomes per-workspace parallelism. Existing local installs are untouched.
