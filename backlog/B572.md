# B572: query_hits.labels_in scans every Concept label in the store on each question

**Status:** Open. Raised 2026-11-16 by the review session on PR 450 (object-text matching). Must be fixed before
`object_text_match` could be on by default.

**Principles:** P2 (graph first): the query should be anchored, not a store-wide scan.

**What.** `query_hits.labels_in(terms)` lower-cases every Concept label and altLabel in the store (`LCASE(STR(?label))`
in a sub-select) and joins the question's terms against them. That is fine on a one-conversation benchmark store, but
a personal store holds tens of thousands of Concepts, and the scan runs once per question.

**Fix (to design).** Anchor or index the comparison:
- match the case variants `question_terms` already emits through the `text_raw` index, and measure whether it
  reproduces the lower-case rule on the recap stores (OT-1's 279 and 275 must hold); or
- store a lower-cased label literal on each Concept at write time, and compare that.

**Graph edge.** Reads `text_raw` and `HAS_ALT_LABEL`; the second option writes a new literal on Concept, which a named
query must read.
