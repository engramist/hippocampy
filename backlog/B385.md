### Problem Statement

Campy has historically operated as a local single-user daemon (`~/.campy/brain.db` and Unix domain sockets). While B315 (Principal derivation), B316 (WorkspaceRouter filesystem sharding), and B325/B328 (Streamable-HTTP MCP + IAM/SigV4 authentication) scaffolded the security and routing primitives, Campy cannot currently be deployed to the cloud as a turn-key managed memory service.

Our first enterprise customer and evaluator, **VibeGuide**, requires Campy to run continuously in the cloud—with AWS as the first deployment target. VibeGuide agents and build-workers need:
1. **Cloud-Native Deployment**: A lightweight, containerized runtime on AWS ECS/Fargate operating within strict egress and resource budgets (currently ~245MB bare baseline under Kùzu, automatically dropping to <80MB RAM once B384 lands).
2. **Persistent Multi-Tenant Isolation**: Physical storage separation where VibeGuide projects/agents are sharded into distinct graph and vector stores without risk of cross-tenant leakage.
3. **Dual Ingress Alignment**: Identical workspace-isolated access whether calling via streamable-HTTP MCP (`POST /mcp`) or direct REST endpoints (`/api/v1/recall`, `/api/v1/bundle`, `/api/v1/decide`, `/api/v1/notify`).
4. **Hardened Minimal Surface**: Full route authentication (`auth = "iam"` via SigV4), bind-guard enforcement on `0.0.0.0`, and suppression of the web dashboard (`dashboard_enabled = false`) while retaining health probes (`GET /health`) for AWS Application Load Balancers.

```
                       (/data/campy)

```

1. **Path & Environment Flexibility (12-Factor Cloud)**:
   - Make `campy/paths.py` respect `CAMPY_HOME` / `CAMPY_DATA_DIR` so containerized environments can point all state to persistent mounts (e.g. `/data/campy`).
   - Enable 12-factor environment variable overrides in `campy/brain/brainstem/config.py` for cloud configurations (`CAMPY_SERVER_AUTH`, `CAMPY_SERVER_BIND_HOST`, `CAMPY_SERVER_DASHBOARD_ENABLED`, `CAMPY_IAM_WORKSPACE_MAP_JSON`, `CAMPY_IAM_TENANT_MAP_JSON`).

2. **REST & Ingress Hardening**:
   - Ensure `web/server.py` retains `/api/v1/*` routes when `dashboard_enabled = false` so that non-MCP clients (like VibeGuide build-workers) are not rejected.
   - Wire `WorkspaceRouter` into `campy/brain/brainstem/rest_api.py` so REST endpoints dynamically resolve the caller's partitioned database based on `request.state.principal.workspace_id`.
   - Provide an enriched `GET /health` endpoint returning memory RSS, version, and storage health.

3. **AWS Container Assets**:
   - Deliver a production-grade multi-stage `deploy/Dockerfile` (`python:3.12-slim`, non-root user `campy`, pre-cached FastEmbed ONNX weights for offline execution, `HF_HUB_OFFLINE=1`).
   - Provide `deploy/ecs-task-definition.json` optimized for AWS Fargate with EFS volume mount configuration.
   - Provide `deploy/docker-compose.yml` for local cloud-parity testing.

4. **VibeGuide Integration Guide**:
   - Author `docs/vibeguide-integration-guide.md` specifying SigV4 header requirements, workspace header usage (`x-campy-workspace-id`), REST/MCP payload contracts, and offline security model.

5. **Graph Storage & Concurrency Guardrail (`engines-and-portability.md`, `migration-security-testing.md`)**:
   - Embedded graph/vector engines (`pyoxigraph` RocksDB + `sqlite-vec`) mandate POSIX file-locking semantics. On Amazon EFS mounts, `WorkspaceRouter` enforces strict directory sharding (`/data/campy/workspaces/<workspace_id>/`) with isolated lock lifetimes.
   - Enforces single-writer concurrency topology per workspace partition, eliminating distributed multi-writer lock contention and graph corruption over network file systems.
