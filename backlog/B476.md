# B476 - Turn Ordinal (M1.2)

State: turn_index implemented; collapse removed after R37 (never fired: max same-speaker same-session cosine 0.69 on a golden DMR store); T2 pending (2026-10-10)
Priority: P2

Plan: `learnings/e2e-improvement-plan.md` M1.2, Part D stages 1/3/4, G.2.

### Problem Statement

On DMR the six conversation turns in a bundle are mostly one speaker's turns
from one session, all stamped `[Speaker 1, 2022-12-14 07:00]`. The answer
model cannot order them, and near-identical turns take slots and distract the
small model (replay R26/R27).

### Decision and Implementation

Two commits so the read path can be split out if the gate needs it.

**A - write path (needs a full T2 run to gate).**

1. `Message.turn_index` (INT64, nullable): the number of Messages the session
   already held when the turn was captured (0-based). `SCHEMA_MIGRATIONS`
   entry `("Message", "turn_index", "INT64")`; `NODE_TABLES` is untouched on
   purpose, following B472's `speaker`/`occurred_at` (migrations-only columns).
   Message is not a PROVENANCE table and has no new edge, so
   `PROVENANCE_TABLES`, `EDGE_REIFICATION`/`classify_edge` and
   `vector_indexing._SPECS` (the index is over `text_raw`, not the new
   property) are unchanged. `docs/rdf-schema-mapping.md` lists no per-property
   Message rows, so it needs no row. The B411 fixture's two Message rows gain
   `turn_index`.
2. New queries (existing ones keep their params, per G.2):
   `capture.count_messages_in_session`, `capture.set_message_turn_index`.
   Neither is in the counted query sets of `tests/test_b396_sparql.py`
   (capture queries are not part of ORCHESTRATOR/total), so no count changes.
3. `notify_turn` counts, links and numbers under a per-(event loop, session)
   `asyncio.Lock`. Guarantee: within one process, indices are unique and
   consecutive in link order, even for concurrent calls. Not covered: a second
   process writing the same store; deleting a session's Messages (a later
   count reuses a number). A failed count leaves the index unset and never
   fails capture. A turn with no session has no index. Old stores keep
   working: absent triple means None.

**B - read path (the ordinal shows only on stores that carry `turn_index`).**

1. `_bundle_conversation` returns `turn_index` per row; the stamp renders
   `[Speaker 1, 2022-12-14 07:00, turn 5]` when present, unchanged otherwise
   (`bundle_compiler._turn_stamp`).

**Near-duplicate collapse: removed.** Originally part B (a `_pick_conversation`
cosine collapse at 0.9, `thalamus.bundle_conversation_collapsing`,
`[retrieval] collapse_near_duplicates` / `near_duplicate_cosine`). Gate R37
(eval_gate replay on golden stores, branch vs main) produced byte-identical
bundles on all 110 questions (DMR 50, LoCoMo-10 60): it never fired. On a
golden DMR store the cosine between same-speaker same-session turns has max
0.691, p90 0.512, median 0.339 over 146 pairs, none near 0.9. The
"near-duplicates" seen in replay R26 were topical neighbours (different facts
on the same topic), not paraphrases; a threshold low enough to fire would
collapse distinct facts. So it was removed rather than tuned; the conversation
stage calls `thalamus.bundle_conversation` as on main.

The turn ordinal stays: DMR sessions share one timestamp per session, so
stamps cannot order turns within a session. It only takes effect on stores
ingested with the write half, so it is measured by a fresh-ingest (T2) run.
