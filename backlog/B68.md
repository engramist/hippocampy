### B68 · Passive Plan Detection (Step 4 Plan Sense)

**Problem:** When agents formulate plans in natural language (numbered steps, ordered lists) without calling `register_plan`, the Brain treats each step as an isolated ActionItem. The causal sequence is lost. The passive system needs a fallback detector for plan structure.

**What it does:** Adds a **Plan sense** to the Step 4 Cocktail Party Effect that detects ordered multi-step sequences in the conversational stream and auto-creates Plan + PlanStep nodes from them. This is the passive complement to B67's active `register_plan` tool.

**Depends on:** B66, B67

**Detection Approach (Three Layers):**

### Layer B — Structural Pattern Detection (Step 4)

New signal set in `step4_pattern.py`:

```python
_PLAN_SIGNALS = [
    # Numbered/ordered lists (most reliable)
    r"(?:^|\n)\s*(?:step\s+)?\d+[\.\):]",
    r"(?:^|\n)\s*[-•]\s+(?:first|then|next|finally)\b",
    
    # Plan framing language
    r"\bmy (?:approach|plan|strategy)\b",
    r"\bhere(?:'s| is) (?:the|my) plan\b",
    r"\bi(?:'ll| will) (?:start by|begin with|first)\b",
    r"\bthe steps (?:are|would be)\b",
]
```

When Plan sense fires AND 3+ ordered items detected in the message:
1. Extract ordered items from the text (regex for numbered/bulleted sequences)
2. Create Plan node (goal = first sentence or plan framing phrase)
3. Create PlanStep nodes for each extracted item
4. Chain via `[NEXT_STEP]` edges
5. Tag: `confidence_low=true`, `source="passive"` (inferred, not declared)

### Layer C — Retrospective Plan Inference (Background Sweep)

During the background sweep's `confidence_low` re-scoring pass:
- Identify sequential Messages within a Session that all classified as `gist:PlannedEvent`
- If 3+ consecutive PlannedEvent messages have high mutual embedding similarity AND sequential timestamps → retroactively infer they were a plan
- Create Plan + PlanStep nodes with `confidence_low=true`, `source="retrospective"`
- Weakest signal — only used when neither active declaration nor structural detection caught it

### gist:PlannedEvent Interaction

`gist:PlannedEvent` fires on individual planning language ("We plan to add Codex in M8") and correctly routes to ActionItem. The Plan sense is a **higher-order detector** — it looks for *sequences of PlannedEvents*, not individual ones. When the Plan sense fires, the individual ActionItems are still created but additionally linked as PlanSteps of the detected Plan.

**Acceptance Criteria:**
- `_PLAN_SIGNALS` added to `mcp_engine/loop/step4_pattern.py`
- Plan sense detects 3+ ordered items and creates Plan + PlanStep chain
- Passively-detected plans tagged `confidence_low=true`, `source="passive"`
- Background sweep Layer C detects retrospective plans from sequential PlannedEvent messages
- gist:PlannedEvent ActionItems are linked as PlanSteps when a Plan is detected
- Does NOT fire on simple 2-item lists (threshold: 3+ items)
- Does NOT create duplicate Plans if agent already called `register_plan` for the same content (dedup via embedding similarity > 0.90)
- Unit tests: plan detection from numbered lists, bullet lists, mixed format
- Unit tests: non-plan ordered lists (e.g., "Top 3 restaurants") do NOT trigger plan creation
- Integration test: passive plan detection → recall_plans returns it

**Outcome:** The Brain captures plan structure from conversational text as a fallback when agents don't actively declare plans. Combined with B67, this ensures plan learning works in both active and passive modes.
