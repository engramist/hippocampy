# B341 - Support Pre-Baked/Offline Embedding Models for Egress-Locked Deployments

State: complete — merged via PR #60 (2026-08-20)
Priority: P2

Plan: none yet.

### Problem

`campy/brain/hippocampus/graph/embeddings.py`'s `_get_st_model()` (around line 78-83) lazily loads a
`sentence-transformers.SentenceTransformer(model_name)` on first use, which — unless the model is
already cached locally — fetches model weights from `huggingface.co` over the network. This is
prewarmed at daemon startup (`campy/brain_daemon.py`, per the `prewarm()` call path referenced
elsewhere in this codebase).

A prospective integrator evaluating Campy for use inside a confined build/agent sandbox found that
`huggingface.co` is not on their environment's egress allowlist (a deny-by-default network policy), so
this startup fetch fails closed — the daemon can't complete its prewarm step at all in that kind of
environment unless the model is pre-baked into the image/filesystem ahead of time. This isn't a bug in
Campy — deny-by-default egress in a confined sandbox is a reasonable and increasingly common posture —
but Campy currently has no documented or built-in path to support it.

### What it does (scope)

1. Confirm the current caching behavior: `sentence-transformers`/`huggingface_hub` caches downloaded
   models under `~/.cache/huggingface/` (or `$HF_HOME`) by default. Verify this is in fact where
   `_get_st_model()`'s fetch lands, and that a pre-populated cache directory is sufficient to make the
   fetch a no-op (check whether `SentenceTransformer(model_name)` respects `HF_HUB_OFFLINE=1` /
   `TRANSFORMERS_OFFLINE=1` env vars to skip the network check entirely even when a local cache exists —
   this is the key mechanism to wire up).
2. Add explicit support for offline/pre-baked operation: if `HF_HUB_OFFLINE` (or a Campy-specific config
   flag, e.g. `[embeddings] offline = true` in `campy.toml`) is set, `_get_st_model()` should load
   strictly from the local cache and fail with a clear, actionable error (not a generic network
   timeout) if the model isn't already present — e.g. "embedding model not found in local cache and
   offline mode is enabled; pre-bake the model into the image or unset offline mode."
3. Document a concrete "pre-bake the model" recipe (e.g. a one-line `python -c
   "from sentence_transformers import SentenceTransformer;
   SentenceTransformer('all-MiniLM-L6-v2')"` run during image build, before the egress lock takes
   effect) in `docs/deployment-agentcore.md` or a new `docs/offline-deployment.md`, alongside the env
   var / config flag from item 2.
4. Add a test that verifies the offline-mode error path produces the clear actionable message when the
   cache is empty (mock/stub the cache-miss condition rather than requiring an actual empty
   `~/.cache/huggingface/` in CI).

### Dependencies

None.

### Files to create/modify

- `campy/brain/hippocampus/graph/embeddings.py` (`_get_st_model()` and the module's offline-mode
  handling).
- `campy/brain_daemon.py` (prewarm call site, if the offline flag needs to be threaded through).
- `campy.toml` schema/defaults (new `[embeddings] offline` flag, if that's the chosen mechanism instead
  of relying solely on the `HF_HUB_OFFLINE` env var — support the env var at minimum since it requires
  no code changes to sentence-transformers' own behavior; a Campy-specific config flag is a nice-to-have
  on top).
- `docs/deployment-agentcore.md` or new `docs/offline-deployment.md` — the pre-bake recipe.
- Test file covering `embeddings.py` (locate existing tests via `rg -l "embeddings" tests/`).

### Acceptance Criteria

- [ ] Setting `HF_HUB_OFFLINE=1` (at minimum; a Campy-specific config flag is optional bonus scope)
      with a pre-populated model cache allows the daemon to start and serve embeddings with zero
      network calls — verified by a test or documented manual repro (e.g. run with network access
      blocked via a firewall rule / `HF_HUB_OFFLINE=1` and confirm no outbound `huggingface.co` request
      occurs).
- [ ] Setting offline mode with an **empty** cache fails with a clear, actionable error message (not a
      generic connection-timeout stack trace) — verified by a test.
- [ ] A documented pre-bake recipe exists and was manually verified to populate the cache correctly.
- [ ] No regression to the default (online, cache-populating) behavior when offline mode is not set.
