# B516: campy-graph skill — compute answers by graph query, anchored on the subject

**Status:** Done

**Principle:** 2 (graph first) and 3 (the model advises; rules decide). Not a retrieval lever.

Lever B505 answered "How many pets will Andrew have?" by regex-parsing the question for a kind word,
pulling every entity `INSTANCE_OF` pet and counting rows in Python: no subject, no relationship, so it
counted every pet in the conversation. Inspection of a real benchmark store found why a subject-anchored
query was not available: Observations carry a resolved `subject_id` (84%), but `predicate` is one of nine
generic verbs and the object is mostly free text (`object_id` on 68 of 844).

Shipped:
- `skills/campy-graph/SKILL.md`: the rules (the graph computes, every fact hangs off its subject, the model
  proposes and rules decide, no wording regex deciding answers, no write-only terms, one construction), the
  schema as built with file:line, how to query (gateway, read-only copy), worked SPARQL patterns with their
  results on a store copy, repo anti-patterns, and a design-review checklist.
- `skills/campy-graph/run_patterns.py`: runs the patterns against a copy of any store, read-only.
- One-line pointers in AGENTS.md, CLAUDE.md, GEMINI.md and `.github/copilot-instructions.md`.
- `.agents/skills/graph-solutions/`: the general graph-solutions skill, previously untracked, added next to
  `graph-expert` (vendor manifest dropped).

Finding for the capture side (not fixed here): entity-to-entity ownership has no object entity in most
Observations, and `OBSERVATION_ABOUT` does not record the subject/object role, so counts per subject over a
kind cannot be answered by a trustworthy query yet. That is a capture card, not an answering card.
