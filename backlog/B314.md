# B314 - GraphGateway: Named-Query Chokepoint + Raw-Cypher Ratchet

State: done
Priority: P0

Plan: (inline — self-contained, sized for a Sonnet-level implementer)

Depends on: nothing hard. Can land in parallel with B312/B313.

### Problem (verified by measurement)

`campy/brain/hippocampus/graph/kuzu_client.py` opens with:

> *"THIS IS THE ONLY FILE THAT IMPORTS KUZU. Migration to Neo4j or another provider =
> rewrite this file only."*

The first sentence is true — `import kuzu` appears at `kuzu_client.py:14` and nowhere else
in `campy/`. **The second sentence is false.** Cypher text is written inline across the
codebase and passed through `KuzuClient.execute()` as strings. Measured counts of lines
containing `MATCH `/`CREATE `/`MERGE `:

```
campy/brain/hippocampus/schema.py               112
campy/brain/brainstem/sweep.py                   68
campy/brain/thalamus/tools/quests.py             42
campy/brain/thalamus/tools/lessons.py            41
campy/brain/thalamus/tools/arc_queries.py        40
campy/brain/thalamus/tools/arc_mechanics.py      27
campy/brain/thalamus/tools/arc_artifacts.py      27
campy/brain/temporal_lobe/loop/step7_pathway.py  27
campy/brain/hippocampus/quest.py                 27
campy/brain/thalamus/tools/task_graph.py         24
campy/brain/temporal_lobe/loop/orchestrator.py   24
... ~500+ total across 46 files
```

Swapping the storage engine means rewriting all of them. Kùzu is pinned at `0.11.3` and
was **archived in Oct 2025** — this is not a hypothetical risk. Separately, an external
platform evaluating Campy has a standing rule: *"Avoid unbounded traversals and
database-specific query semantics in layer interfaces."* Inline Cypher at every call site
violates it directly.

There is a third payoff, and for the cloud work it is the biggest one: a chokepoint is the
only place a tenant-visibility predicate can be injected reliably. Enforcing it at 500 call
sites is not auditable; enforcing it at one is. **B316 (workspace router) depends on this
seam existing.**

### Realistic Scoping

A single card cannot safely migrate 500 query sites. This card builds the seam, proves it
on one vertical slice, and installs a **ratchet** so the number can only go down. Bulk
migration happens in follow-up cards, one module at a time.

### What This Card Does

**Task 1 — `GraphGateway` and the named-query registry.**

New module `campy/brain/hippocampus/graph/gateway.py`:

```python
@dataclass(frozen=True)
class NamedQuery:
    name: str              # "lessons.recall_by_similarity"
    cypher: str            # parameterized template — $params only, no f-strings
    params: tuple[str,...] # required parameter names
    mutating: bool         # routes to execute_write vs execute_read
    description: str       # what question this answers, in one line

class GraphGateway:
    def __init__(self, client: KuzuClient, registry: QueryRegistry): ...

    async def run(self, name: str, /, **params) -> Any:
        """Look up `name`, validate params against the declared set,
        route to execute_read/execute_write by `mutating`."""

    async def execute_raw(self, cypher: str, params: dict | None = None,
                          *, mutating: bool, reason: str) -> Any:
        """ESCAPE HATCH — every use is a migration debt. `reason` is required
        and is logged. Counted by the ratchet in Task 4."""
```

Registry rules, all enforced at registration time (raise on violation, so a bad query
fails at import rather than in production):

- Cypher must be a **static string**. Reject any template containing `{` outside a Kùzu
  literal map, and reject f-string construction by convention — the registry receives a
  finished string, so any interpolation happened at the call site and is a review defect.
- All variable input goes through `$param`. Kùzu's `execute(query, params)` already
  supports this (`kuzu_client.py:execute`).
- Every query declares `mutating`. `GraphGateway.run` routes mutating queries through
  `KuzuClient.execute_write()` so the existing asyncio write-lock discipline
  (`_get_write_lock()`, `kuzu_client.py:36`) is preserved. **Read `kuzu_client.py` fully
  before writing this — the per-event-loop write-lock keying is subtle and must not be
  bypassed.**
- Duplicate names raise.

Registry organization: one module per domain under
`campy/brain/hippocampus/graph/queries/` (`lessons.py`, `quests.py`, `retrieval.py`, …),
each exporting a list of `NamedQuery`, assembled into one registry at import. Naming
convention: `<domain>.<verb>_<subject>`.

**Task 2 — Migrate one vertical slice as proof.**

Pick `campy/brain/thalamus/tools/lessons.py` (41 Cypher lines — large enough to be real,
small enough to finish, and already well covered by tests). Move every Cypher string in
that file into `queries/lessons.py` as named queries; the tool functions call
`gateway.run("lessons.…", …)`.

Keep the existing tool signature `async def x(params: dict, db: KuzuClient, config: dict)`
unchanged. Accept a `KuzuClient` and construct/obtain a gateway internally, **or** accept
either a `KuzuClient` or a `GraphGateway` — implementer's choice, but do not break the
signature, because ~14 tool modules and the daemon dispatch depend on it. Changing that
signature is B315's job, not this card's.

Behavior must be identical. `tests/` should pass unchanged — if a test needed editing to
accommodate this refactor, that is a signal the refactor changed behavior; investigate
rather than editing the test.

**Task 3 — Do NOT migrate `schema.py`.**

`schema.py` holds 112 Cypher lines but they are DDL (`CREATE NODE TABLE`, `ALTER TABLE`),
which is inherently engine-specific and correctly lives next to the engine adapter. Add
`schema.py` to the ratchet's allowlist with a comment explaining why. Same for
`kuzu_client.py` itself.

**Task 4 — The ratchet (this is what makes the card durable).**

A script, `scripts/check_cypher_ratchet.py`, that:

1. Counts Cypher-bearing lines outside the allowlist (`kuzu_client.py`, `schema.py`,
   `graph/queries/**`, `tests/**`)
2. Counts `execute_raw(` call sites
3. Compares both against a checked-in baseline file, `scripts/cypher_baseline.json`
4. **Fails if either count increases.** Prints the delta and the offending files.
5. Prints a reduction summary when counts drop, and rewrites the baseline only when run
   with `--update` (so lowering the bar is a deliberate, reviewable commit)

Wire it into whatever the repo uses for checks — inspect `Makefile` and `pytest.ini` and
follow the existing convention rather than adding a new one. If there is a lint/CI target,
add it there; if not, add a `make check-cypher` target and note in the PR that CI wiring
is a follow-up.

The ratchet is the mechanism that converts a 500-site problem from "someday" into
"monotonically decreasing."

### Acceptance Criteria

- [ ] Registering a `NamedQuery` whose cypher contains `{` raises at import time
- [ ] `gateway.run()` with a missing declared param raises before touching the DB
- [ ] `gateway.run()` with an unregistered name raises `KeyError` with the name in the
      message
- [ ] Mutating queries route through `execute_write` — assert the write lock is used
      (mock/spy on `KuzuClient.execute_write`), not just that the query ran
- [ ] Read queries route through `execute_read`
- [ ] `execute_raw()` without a `reason` raises `TypeError`
- [ ] All Cypher in `campy/brain/thalamus/tools/lessons.py` is gone — assert by grepping
      the file in the test, so the migration cannot silently regress
- [ ] Existing lesson tests pass **unmodified** (`pytest tests/ -k lesson -q`)
- [ ] Ratchet script exits 0 on the current tree
- [ ] Ratchet script exits non-zero when a Cypher line is added to a non-allowlisted file
      (test by writing a temp file into a scratch dir the script scans, or by unit-testing
      the counting function directly against a fixture — do not commit a deliberately
      failing file)
- [ ] `pytest tests/ -q` failure set identical to pre-change baseline

### What This Card Does NOT Do

- Does not migrate the other 32 files — follow-up cards, ratchet enforces direction
- Does not migrate `schema.py` DDL (allowlisted by design)
- Does not add a second storage backend — the seam exists, no adapter is built
- Does not change tool function signatures (that is B315)
- Does not inject any visibility/tenant predicate yet (that is B316, which consumes this)

### Outcome

The claim in `kuzu_client.py`'s docstring becomes true incrementally instead of being
aspirational. Every query becomes a named, bounded, parameterized question with one
enforcement point — which is simultaneously the engine-portability seam, the security
seam B316 needs, and the artifact an external platform's governance review actually asks
for.
