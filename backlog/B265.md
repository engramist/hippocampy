### Problem

Campy has a `plugin/` directory with a Claude Code plugin manifest (`.claude-plugin/plugin.json`) but no native plugin structure for Codex or Gemini CLI. Skills, hooks, and MCP config are scatter-copied to each platform by manual file surgery in `plugin_installer.py`. This is fragile — we spent hours debugging stale paths, orphaned config entries, and broken hooks after the codebase refactor.

All three platforms now have native plugin systems that handle discovery, versioning, updates, and conflict resolution. We should use them.

### What This Card Does

Restructures `plugin/` into a single directory that is simultaneously a valid Claude Code plugin, Codex plugin, and Gemini CLI extension by including all three manifests:

```
plugin/
├── .claude-plugin/plugin.json       # Claude Code manifest
├── .codex-plugin/plugin.json        # Codex manifest
├── gemini-extension.json            # Gemini CLI manifest
├── skills/                          # SHARED across all platforms
│   ├── campy-grill/SKILL.md
│   ├── campy-diagnose/SKILL.md
│   ├── campy-tdd/SKILL.md
│   ├── campy-handoff/SKILL.md
│   ├── campy-improve-architecture/SKILL.md
│   ├── recall/SKILL.md
│   ├── brief/SKILL.md
│   ├── learn/SKILL.md
│   ├── session-start/SKILL.md
│   ├── memory-awareness/SKILL.md
│   ├── quest-management/SKILL.md
│   └── status/SKILL.md
├── hooks/
│   ├── hooks.json                   # Claude Code + Codex hook config
│   ├── campy_hook.py                # Shared hook logic module

│   ├── pre_tool_use.sh              # Claude Code bash wrapper

├── .mcp.json                        # MCP server config (shared)
├── GEMINI.md                        # Gemini context file
└── README.md
```
