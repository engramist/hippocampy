# B228 - Expose ARC World-Model Tools Through MCP Adapters

State: complete (2026-05-03)
Priority: P0

Plan: backlog/plans/B-228-expose-arc-world-model-tools-through-mcp-adapters.md

### Problem

Even after tool handlers exist, ARC will still see `Unknown tool` unless the MCP tool schemas, stdio adapter, daemon route, and client-facing adapter allow-lists all expose the same tool names.

This exact gap appeared in live smoke: `recall_mechanic_priors` was missing from the running sidequests-brain MCP surface.

### What This Card Does

Adds adapter/daemon/schema/readiness coverage for the new ARC world-model tools:

- `publish_mechanic_summary`
- `recall_mechanic_priors`

It also ensures future adapter routing does not regress when new tools are added.

### Acceptance Criteria

- [ ] `tools/list` includes `publish_mechanic_summary`.
- [ ] `tools/list` includes `recall_mechanic_priors`.
- [ ] MCP stdio call to `publish_mechanic_summary` returns accepted/upserted status.
- [ ] MCP stdio call to `recall_mechanic_priors` returns `{"results": [...]}` or empty results, not unknown tool.
- [ ] Claude Desktop/Codex/Gemini-facing adapter paths do not silently drop the tools.
- [ ] Tool schemas reject malformed payloads clearly.
- [ ] Docs/tool-catalog contains request and response examples.
- [ ] Smoke test can assert the tools exist when `--arc-world-model-tools` or equivalent flag is used.

### Validation Commands

### Outcome

ARC no longer needs to degrade to `capability_missing` for the core world-model memory tools when sidequests-brain is up to date.
