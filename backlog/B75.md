### B75 · Make Plan Graph Writes Transactional

**Problem:** `_create_plan_graph` in `mcp_engine/tools/__init__.py` makes 5+ sequential `db.execute_write()` calls: Plan node → Session link → Quest link → PlanSteps → NEXT_STEP edges. If any middle write fails, the plan is partially created with orphan steps or missing quest links.

**What it does:** Batches plan graph creation into a single multi-statement Cypher query or adds compensating deletes on failure.

**Depends on:** None

**Files to modify:**
- `mcp_engine/tools/__init__.py` — refactor `_create_plan_graph` to batch writes

**Adapter allow-list propagation check:** No tool changes — N/A.

**Acceptance Criteria:**
- `_create_plan_graph` either succeeds completely or leaves no partial state
- Plan node, all PlanStep nodes, STEP_OF edges, NEXT_STEP edges, PLANNED_IN edge, and TARGETS edge are written atomically (single query or with rollback)
- `pytest tests/ -k "plan or register_plan" -q` passes
- No orphan PlanStep nodes exist after a simulated mid-write failure

**Outcome:** Plan registration is atomic — no partial plan graphs in the database.
