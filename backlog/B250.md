# B250 - Tabular Ingestion Pipeline

State: needs work -- re-verified 2026-08-03: found and fixed one real crash bug (TIMESTAMP cast), but LLM summary, key-fact extraction, and change-detection/archiving acceptance criteria are unimplemented. See Audit Findings below.
Priority: P1

Plan: backlog/plans/B-250-tabular-ingestion-pipeline.md

### Problem

When a user uploads a spreadsheet or CSV, Campy should not store it wholesale without understanding it, nor should it discard the tabular structure by chunking it into text. It needs to do both: preserve the full queryable data AND extract knowledge into the graph.

### What This Card Does

Extends the document ingestion pipeline to handle tabular files (CSV, XLSX, TSV) with intelligent two-layer storage: full data in SQLite and extracted knowledge (summary, schema classification, key facts) in the Kuzu graph.

### Dependencies

- B249 complete (Dataset node + tabular store)

### Design Decisions

| Decision | Choice | Rationale |
|---|---|---|
| Parsing library | pandas (already a dependency via data science stack) | Handles CSV, XLSX, TSV; familiar API |
| Classification | Reuse gist/schema.org pipeline on column headers + sample rows | Consistent with existing Campy classification |
| Key fact extraction | LLM summarizes dataset + extracts notable values | Totals, constraints, outliers become graph Concepts |
| Change detection | SHA256 hash of file (same as `ingest_document`) | Idempotent re-upload |

### Acceptance Criteria

- [ ] Uploading a CSV creates a Dataset node with correct schema_json, row_count, column_count.
- [ ] Full tabular data is queryable via `query_table()`.
- [ ] LLM summary is stored on Dataset node description.
- [ ] Key facts (totals, notable values) are extracted as Concept nodes linked via `DESCRIBED_BY_DATASET`.
- [ ] Extracted Concepts participate in normal `current_truth` retrieval.
- [ ] Re-uploading same file (unchanged hash) returns `already_current: true`.
- [ ] Re-uploading changed file archives old Dataset node and creates new one.
- [ ] XLSX files with multiple sheets are handled (one Dataset per sheet or configurable).
- [ ] Full test suite passes.

### Audit Findings (2026-08-03 re-verification)

The existing test suite for this card (`tests/test_tabular_ingest.py`) is **100% mock-based** — every test uses `mock_db = AsyncMock()` with `db.execute = MagicMock(return_value=None)`. None of it exercises a real KuzuDB. Per the audit brief, that is not sufficient evidence a criterion is met, so I ran a real end-to-end smoke test: a real `KuzuClient` against a throwaway on-disk DB, a real `Dataset` node table, and `ingest_tabular()` called on an actual 3-row CSV.

**Bug found and fixed (trivial, isolated, no test regressions):** the initial real run failed with `Binder exception: Expression $created_at has data type STRING but expected TIMESTAMP. Implicit cast is not supported.` — `_ingest_single_dataset()` in `campy/brain/sensory_cortex/tabular_ingest.py` builds the `CREATE (d:Dataset {...})` Cypher by interpolating every field as `key: $key`, including the two TIMESTAMP-typed columns (`created_at`, `last_accessed_at`), which are passed as ISO-format strings. Kuzu 0.11.3 does not implicitly cast STRING → TIMESTAMP (this is the exact same class of issue `ingest.py` already works around for Document nodes by wrapping with `timestamp($created_at)` — see `campy/brain/sensory_cortex/ingest.py` line ~395). Because every existing test mocks `db.execute`, this Binder exception was never triggered and every real (non-mocked) tabular ingestion into Kuzu was silently failing at the Dataset-node-creation step — the `except Exception` swallows it into `{"error": ...}`, which the caller in `ingest_tabular()` just skips over without surfacing.

  Fix applied: wrapped `created_at`/`last_accessed_at` in `timestamp(...)` when building the Cypher property list (same file, `_ingest_single_dataset`). Verified the fix resolves the crash and re-ran the full suite with no regressions:
  ```
  .venv/bin/python -m pytest -q tests/test_tabular_ingest.py tests/test_tabular_store.py   # 30 passed
  .venv/bin/python -m pytest -q                                                             # 1600 passed, 59 skipped, 2 xfailed
  ```

**Real gaps found via the same real-DB smoke test, still unresolved (not fixed — these need real implementation work, not a one-liner):**

- **"LLM summary is stored on Dataset node description" — not implemented.** `_ingest_single_dataset()` sets `description` to a hardcoded f-string template (`f"Dataset from {file_path.name} sheet '{sheet_name}' with {row_count} rows and {col_count} columns"`), not an LLM call. The code comment admits this directly: `# Generate a description (simplified - LLM generation would require async LLM call)`.
- **"Key facts (totals, notable values) are extracted as Concept nodes linked via DESCRIBED_BY_DATASET" — not implemented at all.** `facts_extracted` is hardcoded to `0` with the comment `# Could extract facts from data summary`. Confirmed via the smoke test: after ingesting a real CSV, `MATCH (c:Concept) RETURN count(c)` → `0`, `MATCH ()-[r:DESCRIBED_BY_DATASET]->() RETURN count(r)` → `0`. The `DESCRIBED_BY_DATASET` edge type exists in the schema and is *read* by `bundle_compiler.py` (B252), but nothing anywhere in the codebase ever *creates* it.
- **"Extracted Concepts participate in normal current_truth retrieval" — cannot be true**, since no Concepts are ever created by this pipeline (follows directly from the previous point).
- **"Re-uploading same file (unchanged hash) returns already_current: true" — not implemented.** `ingest_tabular()` hardcodes `results["already_current"] = False` unconditionally. Confirmed via smoke test: ingesting the identical CSV twice returns `already_current: False` both times, with two distinct new `dataset_id`s and two separate Dataset nodes left in the graph (`MATCH (d:Dataset) RETURN count(d)` → `2` after two ingests of the same unchanged file). The existing test `test_change_detection_same_hash` doesn't actually assert `already_current is True` — its own docstring/comment admits "hash check is not yet fully implemented."
- **"Re-uploading changed file archives old Dataset node and creates new one" — not implemented.** Follows from the above: there is no lookup-by-`content_hash` or archiving logic at all; every call to `ingest_tabular()` unconditionally `CREATE`s a brand-new Dataset node with a fresh UUID.

**Criteria confirmed working via the real-DB smoke test:**
- Uploading a CSV creates a Dataset node with correct `schema_json`, `row_count`, `column_count` (verified with real values: 3 rows, 3 columns, schema listing all 3 columns with dtypes).
- Full tabular data is queryable via `query_table()` (round-tripped the same 3 rows back out through the real SQLite file).
- XLSX multi-sheet handling (`per_sheet` vs `first_only` strategy) is implemented and covered by real pandas/openpyxl-backed tests (`tests/test_tabular_ingest.py::TestXLSXIngestion`, 3/3 passed with pandas actually installed — previously silently skipped, same pyproject.toml gap noted on B249).

Net: roughly half of this card's acceptance criteria are genuinely met; the other half (LLM summarization, fact extraction, change detection, archiving) were never implemented despite being explicit, checked-off-sounding criteria. Reopening as needs-work rather than fixing in place, per audit instructions, since these require real design/implementation work (LLM call wiring, fact-extraction heuristics, hash-based dedup/archive flow), not a trivial patch.

### Outcome

Users can upload spreadsheets and CSVs to Campy. The data is preserved for querying AND understood by the graph for retrieval.
