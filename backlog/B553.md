# B553: WordNet is required by the principled profile but optional everywhere else

**Status:** Done (2026-11-06). Found while fixing B546's CI (2026-11-05).

**Principles:** P6 (a gate must say what ran), P7.

**What was seen.** WordNet is the optional extra `wordnet` (nltk + corpus, B523). CI installs neither, so every test of B523's WordNet path, B534's links and B546's typing is skipped there; B546 types nothing at all without it, silently. A home where the profile `principled` is on but WordNet is missing would run a different pipeline than the gate measured.

**To do.** CI installs `.[test,wordnet]` and downloads the corpus (`python -m nltk.downloader wordnet`), so those tests run; `campy status` and benchmark provenance record whether WordNet is available; under profile `principled` without WordNet, the daemon logs one warning at start naming the members that degrade. Decide whether the profile should require it (start refuses) or degrade (warn); record the decision.

**Decision (user, 2026-11-05).** Degrade and warn; the daemon never refuses to start for a missing WordNet.

**Done.** CI installs `.[test,wordnet]` and the corpus. `config.PROFILE_NEEDS_WORDNET` names the members that read WordNet (B523 ownership_rule, B534 wordnet_kinds, B535 vocab_steward, B546 typed_objects); `profile_report` carries `wordnet: {available, degraded}`, so `campy status` and benchmark provenance (which call it) record it; the daemon logs one warning at start naming the switched-on members that degrade. When B544 merges, add `loop.entity_admission` to the list if its kind check reads WordNet.
