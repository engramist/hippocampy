# B224 - Wiki Projection Drift Guard and Obsidian Hygiene

State: complete
Priority: P2

Plan: backlog/plans/B-224-wiki-projection-drift-guard.md

### Problem

Read-only wiki projection only works if drift is visibly prevented. If users edit generated Markdown, stale or conflicting facts could appear more trustworthy than the graph. Obsidian also creates side files and encourages linking habits that can blur generated content with human notes.

SideQuests needs guardrails so the wiki stays tactile without becoming a shadow store.

### What This Card Does

Adds projection drift detection, generated-file hygiene, and Obsidian-friendly conventions.

This card does not implement editable wiki ingestion. It protects the invariant that generated Markdown is a projection of KuzuDB, not an alternate source of truth.

This card also makes the vault pleasant to use in Obsidian by generating safe vault conventions: read-only banners, ignored Obsidian workspace noise, optional recommended settings, and a clear manual notes area.

### Acceptance Criteria

- [x] Generated pages include `projection_hash` derived from rendered graph-backed content.
- [x] Exporter detects manual edits to existing generated pages before overwrite.
- [x] On drift, exporter either quarantines the edited file or writes a `.conflict.md` copy before regenerating.
- [x] Drift events are reported in sweep summary.
- [x] Generated wiki output is ignored by git by default, or the docs explain why it is intentionally tracked.
- [x] Architecture doc defines a separate `wiki/manual-notes/` area for human-authored notes.
- [x] Manual notes are not treated as authoritative until ingested through normal graph ingestion.
- [x] Generated pages include a short read-only notice linking users to `manual-notes/` for human writing.
- [x] Obsidian workspace/cache files are ignored.
- [x] Optional generated Obsidian settings do not require any community plugins.
- [x] Obsidian graph noise is controlled by bounded links and no global all-node index links.
