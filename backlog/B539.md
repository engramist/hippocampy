# B539: the harness's non-answer filter fails answers the judge never sees

**Status:** Open

Principle 6: doubt the scorer before the pipeline. The failure breakdown (300 LoCoMo questions, R98 + R100) found that 74 of the 180 failures were auto-failed by the benchmark harness's `non_answer` regex before the judge saw them:
- **Correct by design:** 69 lead with a real abstention.
- **False positive:** 1 is a correct answer ("May 10, 2023") with a trailing hedge ("The exact date is not specified"). The regex is unanchored: `does not mention`, `not specified` and `no information` match anywhere in the answer.
- **Self-contradicting abstentions:** 8 open with "I don't have that information" and then state the correct fact in the same answer, e.g. "… However … on June 13, 2023". The B538 replay found 3 more of these once dates were resolved inline.

**Work:**
1. **Anchor the regex.** It should match only an answer that opens with an abstention and asserts nothing after it. A hedge note after a substantive answer goes to the judge. This is a measurement fix. Re-score every stored baseline the same way before comparing anything, and name the counting definition next to every figure.
2. **Policy for "abstain + fact" answers.** Either send them to the judge or keep auto-failing them. This is the owner's call. Report both numbers whichever is chosen.
3. **Answer side, separate lever.** The answer prompt's "If no line answers, say you don't have that information" invites a leading abstention even when a line answers. A structural fix would make abstention a separate field the model sets, not a sentence prefix. Gate it as its own lever (P5: structure, not wording).
