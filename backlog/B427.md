# B427 - ~41 Test Files Validate the Retired Kùzu/Cypher Engine, Not the Shipped Oxigraph/SPARQL Engine

State: ready (deprioritized — see Correction below)
Priority: P3
Branch: docs/b427-kuzu-test-suite-migration

### Correction this card starts from

An earlier pass on the 2026-09-11 re-vet mischaracterized `kuzu==0.11.3` as "still a hard
runtime dependency." **That was wrong.** Verified precisely (2026-09-12):

- `kuzu` lives in `[project.optional-dependencies].test` in `pyproject.toml` — a separate,
  opt-in-only extra, never in `[project.dependencies]`.
- `requirements.txt` has no kuzu.
- The documented dev setup (`pip install -e ".[dev]"`) does not pull it in (`dev` and `test`
  are disjoint extras).
- The real end-user install path (`pipx install hippocampy` via `scripts/bootstrap.sh`) never
  requests `[test]`.
- `pip show hippocampy`'s own `Requires:` metadata (checked in a real dev venv) lists 17
  packages; kuzu is not one of them.

So kuzu is **not shipped, not installed by a normal user, and not a runtime dependency** —
it was already correctly isolated as a test-only extra. No packaging fix is needed. The
prior turn's "top priority, fix this" framing does not apply; this card exists for the
separate, real issue found while investigating it.

### The real, separate finding

`tests/kuzu_test_client.py` is a genuine `kuzu.Database`/`kuzu.Connection` client (the
pre-cutover `kuzu_client.py`, relocated under `tests/`). **~41 test files** import it as
their DB backend and exercise it via `.cypher`, while the shipped engine
(`OxigraphClient`) executes `.sparql` (`gateway.py`'s `_is_oxigraph` branch). Only 4 files
are explicitly Kùzu-specific (`test_*_real_kuzu.py`); the other ~37 are ordinary domain
tests (`test_provenance`, `test_authority`, `test_task_dependency`,
`test_bundle_compiler_stages`, `test_fact_ingest`, `test_workspace_router`, …) that just
inherited Kùzu because that is what the shared test fixture happened to be.

Consequence: a meaningful share of the suite validates an engine that is **not what
ships**, and cannot catch drift on the SPARQL path — plausibly part of why the
B412/B418/B420/B421/B422 family of bugs (SPARQL-path defects) shipped despite a large,
green test suite. `test_kuzu_import_isolation.py` already enforces zero Kùzu imports in
`campy/` itself; this card is about the *test* side of that boundary, which currently has
none.

### Scope (measured, 2026-09-12)

- 41 files import `tests.kuzu_test_client` (excl. `conftest.py`, which provides the shared
  fixture).
- Of those, **6 make zero raw `.execute()` calls** (drive the DB only through
  gateway/handler functions) — candidates for a near-mechanical client swap.
- The remaining **35 make ~300 raw `db.execute(cypher, …)` / `conn.execute(...)` calls**
  between them (heaviest: `test_bundle_compiler_stages.py` 35, `test_graph_export.py` 33,
  `test_task_dependency.py` 20, `test_authority.py` 20, `test_provenance.py` 15,
  `test_b404_sweep_pk.py` 15) — each needs the Cypher rewritten to the equivalent SPARQL
  (or, where simpler, test setup switched to `OxigraphClient.write_node()`/`write_edge()`
  and assertions to `_execute_and_collect()` / a SPARQL `SELECT`, the pattern already used
  by `tests/test_b420_entity_link_handlers.py` and siblings).
- `tests/test_checkpoint_lock_serialization.py` specifically exercises `kuzu_test_client`'s
  own `_get_write_lock()` — a Kùzu-specific concurrency primitive with no 1:1 Oxigraph
  analog (the gateway's own `asyncio.Lock` is the real equivalent); needs a rewrite against
  that, not a client swap.
- 4 files (`test_*_real_kuzu.py`) test Kùzu-specific behavior (FTS/vector-index mechanics)
  that has no meaning post-cutover — likely deletion or an Oxigraph-analog rewrite
  (`sqlite-vec`'s FTS5/vec0), decided per file.

### Suggested approach, if picked up

1. Migrate the 6 zero-raw-Cypher files first (near-mechanical; validates the swap pattern).
2. Triage the 4 `real_kuzu` files individually (delete vs. rewrite as Oxigraph-analog).
3. Work through the 35 raw-Cypher files in descending call-count order, in small batches
   with their own PRs — each migration should assert the SAME domain behavior, not just
   "the query runs" (cf. the B412 card's own standard: "asserting NON-EMPTY, CORRECT
   results", not merely no-exception).
4. Once all 41 are migrated, delete `tests/kuzu_test_client.py`, the `test` extra from
   `pyproject.toml`, and retire `kuzu` from the repo entirely (no more test-only extra).

### Priority note

Downgraded to P3. It is real test-quality debt worth fixing, but — now that the "kuzu is a
shipped dependency" premise is corrected — there is no urgency driver; it competes with
B418b, B401, and other open items on ordinary priority.

    migrated onto `OxigraphClient` as part of that fix (8/8 pass).
