# B466 - Relation Extraction Reads "Replace X with Y" Backwards

State: fixed (2026-10-04; unit-tested, real-store confirmation pending)
Priority: P1
Depends on: B460

### Problem Statement

Found while building B465 (`campy graph repair-supersession-edges`, which
verifies old CHOSEN_OVER edges by re-reading their source messages with Step
1b). In the LoCoMo fixture the edge "Memcached CHOSEN_OVER Redis" is left
unverifiable: its source message is "Architecture change: Replace Memcached
with Redis cluster on port 6379.", and Step 1b reads nothing from it.

`step1b_relations.extract_relations` (as of B460) read a replace-type verb
only as subject -> verb -> object:

- "We replaced Memcached with Redis." -> `We REPLACES Memcached`: the person
  doing the replacing became the new value.
- "Replace Memcached with Redis cluster on port 6379." (imperative, no
  subject) -> nothing.
- "The team swapped Jenkins for GitHub Actions." -> nothing (`swap` was not a
  relation verb at all).

When Step 1b produces nothing, Step 3b's LLM picks the relation, which is how
the inverted CHOSEN_OVER edges B460 found were written.

### What It Does (Scope)

`step1b_relations`: a replace-type verb with an object X and a "with"/"for"
object Y gives **Y REPLACES X**, whatever the subject is (`_swap`):

| verb | new value introduced by |
|---|---|
| replace | with |
| swap | with, for |
| substitute | with; **for introduces the old value** ("substitute X for Y": X takes Y's place) |
| exchange, trade | for |

- Passives of the same frame: "Memcached was replaced with Redis",
  "Jenkins was swapped for GitHub Actions". A passive with a "by" agent keeps
  B460's reading ("Vue 2 has been replaced by React 19 with Next.js": React
  19, not Next.js).
- spaCy hangs "with Y" on the object instead of the verb in the fixture
  sentence; for replace/substitute that attachment is accepted (the meaning
  is the same), for swap it is not ("swapped seats with the other team").
- A negated frame ("we did not replace X with Y") gives nothing -- neither
  Y REPLACES X nor the old `We REPLACES X`.
- A replace verb with no "with" object is unchanged ("OpenTelemetry replaced
  Zipkin": OpenTelemetry REPLACES Zipkin).

Not changed:

- **The cross-clause form "X is deprecated; migrate to Y".** B460 deliberately
  reads no supersession from a "to" without a "from"; this card keeps that.
- Negation is still ignored for the other verb patterns ("OpenTelemetry did
  not replace Zipkin" still gives OpenTelemetry REPLACES Zipkin). Pre-existing;
  only the new frame checks it.
- B464 (open) also edits `step1b_relations.py` (`_span_text` -> `_span`,
  `_relation` adds `names`). This card only calls `_relation`, so the two merge
  without semantic conflict.
