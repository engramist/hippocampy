# B415 - Make kpi_monitor.py Actually Measure

State: complete
Priority: P0
Branch: feat/b415-b416-measurement-integrity

### Problem

`benchmarks/kpi_monitor.py` does not measure. It emits hardcoded literals:

```python
"daemon_idle_rss_mb": 245.6,
"live_steady_state_rss_mb": 1200.0,
"write_burst_peak_spike_mb": 1100.0,
retrieval_latency_ms = 28.5 if not smoke else 8.5   # a constant, not a measurement
```

Those numbers came from B381's card table. **Two of them are known wrong:**

- `245.6` was **import-time-only** RSS. Warm — with models actually invoked, which is
  what a running daemon holds — the figure is ~590 MB.
- `1200.0` came from a development venv carrying a stale `torch`, which inflated it by
  ~150–225 MB. `torch` is not a declared dependency (B400).

So `baseline_snapshot.json` is a set of literals, at least two of which are false, and
`--compare` diffs two sets of constants. Running it produces something shaped like a
result and carrying no information.

This was found while attempting the post-cutover baseline comparison the whole B381
harness exists to enable.

### Why this matters beyond one script

The Oxigraph migration was justified three times on numbers. Two of those
justifications collapsed under measurement (`<80 MB` was import-time-only; OWL
inference was 10,589x–86,576x write amplification). The instrument meant to catch that
class of error was itself reporting constants.

### Scope

1. **Replace every hardcoded metric with real instrumentation.** Tier 1 RSS must be
   sampled from a live process; retrieval and LLM latency must be timed, not asserted.
   If a metric genuinely cannot be measured in-process, emit `null` and say why —
   **never a placeholder that reads like a measurement.**

2. **Fail loudly on a contaminated environment.** Assert `torch` is absent from
   `sys.modules` during any measurement run, and abort with an explanatory error if
   present. A contaminated environment must not be able to silently produce a baseline.
   (See B416 — this is the enforcement half of the same problem.)

3. **Record methodology alongside every number**: warm vs cold, whether the model was
   invoked, sample count. Per `docs/superpowers/specs/2026-09-05-entity-candidate-generation-design.md`
   §5, a bare RSS figure with no methodology is the defect, not the number.

4. **Invalidate the existing baseline.** `baseline_snapshot.json` cannot be compared
   against — regenerate it from real measurement and mark the old one superseded rather
   than silently overwriting. The same applies to the sibling repo's
   `baseline_kuzu_live.json` if it shares the defect; check and report.

### Explicitly NOT in scope

- Do not "fix" a metric by adjusting the constant to a better guess. Measure it or
  return `null`.

### Acceptance Criteria

- [x] Zero hardcoded metric values remain; `grep` for the old literals returns nothing
      (verified against the code body, excluding the module docstring's historical
      narrative, which legitimately names the old numbers as prose).
- [x] A measurement run in a `torch`-contaminated environment **aborts with a clear
      error** — demonstrated by running it both ways (`.venv/bin/python`, contaminated,
      aborts; a throwaway clean venv under `/tmp`, torch-free, runs to completion).
- [x] Every emitted metric carries methodology (warm/cold, invoked, sample count).
- [x] Regenerated baseline is reproducible: two consecutive runs agree within a stated
      tolerance (RSS metrics within ~1%; sub-100ms timing metrics — real measurement
      noise, not present with a hardcoded constant — within ~20%).
- [x] Old baseline marked superseded, not overwritten
      (`baseline_snapshot.superseded-2026-09-04.json`).
- [x] Report whether the sibling repo's baseline shares the defect: **no** — see below.

### Sibling repo report (campy-benchmarks/baseline_kuzu_live.json)

Does not share the defect. `run_all.py` calls real suite runners (locomo, memory_gym,
membench, arc_bridge) over MCP against a live daemon; every per-suite number in the
JSON traces to an actual scenario run. The one static-looking block,
`canonical_baseline_targets`, is explicitly a target dict (string values like
`"<80MB (via B384)"`), not numbers dressed up as measurements — the failure mode this
card is about.

### Implementation notes

- Tier 1 RSS: real, sampled via `psutil` — self-process (in-process), import-only and
  warm-invoked (spaCy + fastembed loaded and invoked, subprocess-isolated, mirrors the
  corrected design-doc methodology; re-measured warm figure: ~583–589 MB, matching the
  card's "~590 MB" claim), plus a write-burst RSS spike from 5000 real graph writes and
  a real allocation-delta sample. Subprocess stages are skipped (null + reason) in
  `--smoke` mode for speed.
- Tier 2: `retrieval_compilation_latency_ms` now reads `compile_bundle()`'s own
  `compilation_ms` from a real end-to-end call (real `GraphGateway`, real in-memory
  `OxigraphClient`, real fastembed query embedding) — replaces the literal
  `28.5 if not smoke else 8.5`. `graph_hop_latency_2hops_ms` now times a real SPARQL
  query instead of a `time.sleep()` stand-in. `llm_generation_latency_s` makes a real
  timed call to the local Ollama endpoint (llama3.1:8b) when reachable, else `null`.
- Tier 3 (ask-eval scores) and most of Tier 4 (handoff constraint violations, markdown
  overhead) have no in-process measurement path — running `benchmarks/ask_eval/`'s real
  harness inline would take minutes and needs a populated daemon. These are `null` with
  an explicit reason rather than the removed hardcoded literals.
  `handoff_overhead_ms` *is* measured for real (`get_handoff_context()` timed against
  an in-memory store).
- `assert_environment_clean()` (B416 integration) gates the entire run, not just
  `--out`: any known-harmful contaminant aborts before any measurement happens.

### Outcome

The instrument measures. A baseline comparison means something, and a contaminated
environment cannot produce one silently.
