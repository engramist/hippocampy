# B415 - Make kpi_monitor.py Actually Measure

State: ready
Priority: P0

### Problem

`benchmarks/kpi_monitor.py` does not measure. It emits hardcoded literals:

```python
"daemon_idle_rss_mb": 245.6,
"live_steady_state_rss_mb": 1200.0,
"write_burst_peak_spike_mb": 1100.0,
retrieval_latency_ms = 28.5 if not smoke else 8.5   # a constant, not a measurement
```

Those numbers came from B381's card table. **Two of them are known wrong:**

- `245.6` was **import-time-only** RSS. Warm — with models actually invoked, which is
  what a running daemon holds — the figure is ~590 MB.
- `1200.0` came from a development venv carrying a stale `torch`, which inflated it by
  ~150–225 MB. `torch` is not a declared dependency (B400).

So `baseline_snapshot.json` is a set of literals, at least two of which are false, and
`--compare` diffs two sets of constants. Running it produces something shaped like a
result and carrying no information.

This was found while attempting the post-cutover baseline comparison the whole B381
harness exists to enable.

### Why this matters beyond one script

The Oxigraph migration was justified three times on numbers. Two of those
justifications collapsed under measurement (`<80 MB` was import-time-only; OWL
inference was 10,589x–86,576x write amplification). The instrument meant to catch that
class of error was itself reporting constants.

### Scope

1. **Replace every hardcoded metric with real instrumentation.** Tier 1 RSS must be
   sampled from a live process; retrieval and LLM latency must be timed, not asserted.
   If a metric genuinely cannot be measured in-process, emit `null` and say why —
   **never a placeholder that reads like a measurement.**

2. **Fail loudly on a contaminated environment.** Assert `torch` is absent from
   `sys.modules` during any measurement run, and abort with an explanatory error if
   present. A contaminated environment must not be able to silently produce a baseline.
   (See B416 — this is the enforcement half of the same problem.)

3. **Record methodology alongside every number**: warm vs cold, whether the model was
   invoked, sample count. Per `docs/superpowers/specs/2026-09-05-entity-candidate-generation-design.md`
   §5, a bare RSS figure with no methodology is the defect, not the number.

4. **Invalidate the existing baseline.** `baseline_snapshot.json` cannot be compared
   against — regenerate it from real measurement and mark the old one superseded rather
   than silently overwriting. The same applies to the sibling repo's
   `baseline_kuzu_live.json` if it shares the defect; check and report.

### Explicitly NOT in scope

- Do not "fix" a metric by adjusting the constant to a better guess. Measure it or
  return `null`.

### Acceptance Criteria

- [ ] Zero hardcoded metric values remain; `grep` for the old literals returns nothing.
- [ ] A measurement run in a `torch`-contaminated environment **aborts with a clear
      error** — demonstrated by running it both ways.
- [ ] Every emitted metric carries methodology (warm/cold, invoked, sample count).
- [ ] Regenerated baseline is reproducible: two consecutive runs agree within a stated
      tolerance.
- [ ] Old baseline marked superseded, not overwritten.
- [ ] Report whether the sibling repo's baseline shares the defect.

### Outcome

The instrument measures. A baseline comparison means something, and a contaminated
environment cannot produce one silently.
