# B221 - Graph-Native Wiki Projection Architecture

State: complete
Priority: P0

Plan: backlog/plans/B-221-graph-native-wiki-architecture.md

### Problem

Humans need tactile, browsable knowledge surfaces. A graph-native memory system is powerful, but without a wiki-like surface it can feel invisible, hard to inspect, and less emotionally trustworthy than tools like Obsidian, Karpathy-style wikis, or "Memory Palace" interfaces.

Flat-file wikis solve browsability but introduce data drift, token bloat, stale summaries, and a second source of truth. SideQuests should offer the human affordance without surrendering the graph-native architecture.

### What This Card Does

Defines the architecture for a read-only Markdown wiki projection generated from KuzuDB during the Dreaming/sweep phase. The graph remains the single source of truth. Markdown is a browsable cache, not an editable database.

Obsidian is the default human UI target because it gives users backlinks, graph view, search, and a tactile local vault without SideQuests needing to build a full wiki frontend first. The projection must still be plain Markdown so it remains usable in any editor or file browser if Obsidian is not installed.

The design must include persona isolation so different roles or mental frames can browse distinct projections without polluting the underlying graph or each other's view.

Graph-solutions decision: this remains a labeled property graph design, not RDF. The core workload is traversal-first browsing, provenance, neighborhood exploration, backlinks, and path-to-source explanation over KuzuDB nodes and relationship properties. RDF/ontology export may be a future interoperability layer, but it is not the product path for the first wiki.

### Acceptance Criteria

- [x] Architecture explicitly states KuzuDB is the single source of truth.
- [x] Architecture states Obsidian is the default wiki UI target, while generated Markdown remains portable.
- [x] Markdown files are read-only projections and must not be ingested back as authoritative facts.
- [x] Dreaming/sweep phase is identified as the writer of wiki projections.
- [x] Persona isolation model is defined: output paths, filtering, naming, and access boundaries.
- [x] Hot user journeys are defined: open wiki, browse home page, follow backlinks, inspect source IDs, switch persona, and open graph view.
- [x] Starter graph projection model is defined: `WikiPage`, `WikiSection`, `PersonaProjection`, `GENERATED_FROM`, `MENTIONS`, and `RELATED_PAGE` or their no-new-node equivalents.
- [x] Drift controls are specified: projection metadata, source node IDs, generated timestamps, and no manual edit contract.
- [x] Token-bloat controls are specified: summaries, backlinks, source IDs, and bounded page sizes.
- [x] Dense-node/supernode risk is addressed by bounding backlinks, related pages, and neighborhood depth per page.
- [x] Design explains why this neutralizes flat-file wiki drift while preserving tactile browsability.
