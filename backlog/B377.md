### Problem

HippoCampy currently relies on `kuzu==0.11.3` as its embedded graph and vector engine. However, Kùzu presents several critical architectural and operational blockers:
1. **Upstream Project EOL / Archived:** In October 2025, the `kuzudb/kuzu` repository was officially archived. Extension registries are decommissioned, storage format is frozen, and no official security or compatibility updates are produced. Community forks (RyuGraph, Bighorn) lack institutional backing.
2. **Transient Memory Spikes (B311) & Index Lock-in (B285):** Kùzu's checkpoint-at-commit behavior causes 100MB -> 1.1GB memory spikes under write bursts, and Kùzu does not support in-place vector index updates or unindexed row movement for archived nodes without table reconstruction.
3. **M&A and Commercialization Due Diligence:** While Kùzu is MIT, other alternative candidates like Neo4j Community (GPLv3) introduce unacceptable copyleft "poison pill" risks for commercial acquisition or IPO due diligence.
4. **Architectural Invariants:** Alternatives like Apache Jena Fuseki or Neo4j require running external JVM server daemons consuming 1–4 GB RAM, directly violating Campy's core invariant: **an embedded, single-process, local daemon with minimal RAM**.

### The Solution: Embedded Oxigraph (RDF-star) + sqlite-vec

**Oxigraph (`pyoxigraph`)** is a featherweight, native Rust graph engine embedded directly in Python:
- **Zero Server Overhead:** Embedded in-process (`import pyoxigraph`), backed by RocksDB, consuming only **20–50 MB RAM idle** (10–25 MB binary).
- **Clean License for M&A:** Dual-licensed under **Apache 2.0 / MIT**, providing 100% clean IP due diligence with express patent grants.
- **Native Edge Metadata (RDF-star):** Full W3C RDF-star (`<< :s :p :o >>`) support for Campy's rich edge properties (`[LOADED]`, `[CO_OCCURS_WITH]`, `[ENABLES]`, `[DEPRECATED_BY]`).
- **Semantic Web / Ontological Alignment:** Native support for gist (W3C OWL) upper ontology and schema.org sub-graphs without needing a separate inference engine (Campy's Gated Consolidation Loop handles neurosymbolic reasoning).

Because Oxigraph is a pure graph/RDF-star store, fixed-dimension vector retrieval (`FLOAT[384]`) is decoupled into **`sqlite-vec`**—an embedded, zero-daemon, C/Python SQLite extension (Apache 2.0 / MIT) that handles HNSW / cosine vector indexes with sub-millisecond latency.

### What it does (scope)

1. **Graph Abstraction Facade Migration (`campy/brain/hippocampus/graph/`):**
   - Refactor `kuzu_client.py` into `graph_client.py` backed by `pyoxigraph.Store` over local RocksDB storage.
   - Implement RDF-star serialization and SPARQL-star queries for node and edge operations.
   - Map Campy's edge metadata directly to RDF-star statements:
     ```turtle
     << :Session_s1 :LOADED :Decision_d42 >> :injected_at "2026-09-04T12:00:00Z"^^xsd:dateTime ;
                                             :token_estimate 145 .
     << :Concept_c1 :CO_OCCURS_WITH :Concept_c2 >> :count 12 ;
                                                   :strength 0.85 .
     ```
2. **Embedded Vector Store Integration (`sqlite-vec`):**
   - Create `campy/brain/hippocampus/graph/vector_store.py` using `sqlite-vec` over a local SQLite database (`~/.campy/vectors.db`).
   - Re-index `FLOAT[384]` embeddings generated by `fastembed` (B355).
   - Support vector cosine similarity queries and threshold filtering for Step 2 centroid matching and Step 5 dual-scope retrieval.
3. **Data Migration via Streaming Export/Import:**
   - Update `campy export-graph` and `campy import-graph` (B281) to migrate data from legacy Kùzu `.jsonl` dumps into Oxigraph + sqlite-vec.
4. **Memory Verification:**
   - Validate that the combined Oxigraph + sqlite-vec engine idles at **<60 MB total RAM**, completely eliminating B311's 1.1 GB checkpointing spikes.
