### Problem

Campy operates as a background daemon without ambient user visibility. To know if Campy is alive or what it is doing, an operator must run `campy activity --follow` in a terminal or open the FastAPI dashboard in a browser. This leads to:
1. **Silent disconnection:** Users don't notice if the daemon stopped or crashed until their AI starts repeating questions.
2. **Lack of tactile feedback:** Users miss the visceral sense of "my AI is actively learning and remembering."
3. **High cognitive friction:** Restarting the daemon, clearing context, or inspecting the active Quest requires memorizing CLI commands.

### What it does (scope)

Build a native, ultra-lightweight desktop menu-bar companion (macOS menu bar & cross-platform system tray) that interfaces with the local Brain Daemon over Unix domain sockets / HTTP:

1. **Ambient Visual Feedback:**
   - Clean status icon in system tray / menu bar: Idle (neutral), Active (pulse/glow on memory write or recall), Warning/Down (disconnected).
2. **Quick Context Dropdown:**
   - Displays Active MainQuest and current Git branch.
   - Live memory counter (Concepts, Decisions, Constraints count).
   - Recent memory activity feed (last 5 captured turns or retrieved decisions).
3. **One-Click Operator Controls:**
   - Quick button to launch Memory Control Panel (`http://127.0.0.1:7799`).
   - One-click "Restart Daemon" / "Force Sweep".
   - Direct switch to pause/resume memory capture.
4. **Zero-Bloat Footprint:**
   - Standalone native wrapper (e.g. lightweight PyObjC / rumps for macOS, or minimal WebView) consuming <30 MB RAM.
