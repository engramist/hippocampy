# B279 - Vector Similarity Calibration Audit and Fix

Plan: backlog/plans/B-279-vector-similarity-calibration.md

### Problem

Embeddings are L2-normalized (`embeddings.py` uses `normalize_embeddings=True`), but `KuzuClient.vector_search()` converts the HNSW distance to a score via `1/(1+distance)` and every consumer treats that score as if it were **cosine similarity**. The two are different nonlinear scales:

- If the index metric is L2 (as the code comment in `kuzu_client.py:95` claims): a score of 0.92 corresponds to cosine ≈ 0.996, so the additive-merge threshold in Step 5 (`GRAY_ZONE_UPPER = 0.92`) effectively only fires on near-exact duplicates. The gray-zone contradiction arbitration (0.75–0.92) almost never triggers. **Net effect: duplicate Concept nodes silently accumulate**, defeating the dedup design.
- If Kuzu 0.11.3's default index metric is cosine (no `metric` arg is passed at index creation): score 0.75 corresponds to cosine ≈ 0.667 — looser than the documented thresholds.

Either way, every threshold in the system calibrated against "similarity" (Step 5 dedup at 0.75/0.92, quest routing S1 at 0.85/0.60, analogical search min_similarity 0.7, warm frontier MIN_ACTIVATION 0.3, basal ganglia matching) does not mean what its documentation says.

### What This Card Does

1. Determines the actual distance metric Kuzu 0.11.3 uses for `CREATE_VECTOR_INDEX` when no metric is specified (empirically, with a test).
2. Changes `KuzuClient.vector_search()` to return **true cosine similarity** regardless of index metric.
3. Adds a calibration regression test: insert vectors of known cosine similarity, assert the returned score matches within epsilon.
4. Audits and recalibrates every threshold that consumes `vector_search` scores.
5. Documents the score semantics in the `vector_search` docstring.
