# B477 - Cross-Encoder Rerank of Conversation Candidates Before the Cut (M2.1)

State: implemented (2026-10-10; ships off, merge gate pending)
Priority: P2

Plan: `learnings/e2e-improvement-plan.md` M2.1

### Problem Statement

On LoCoMo-10 the turn that holds the answer has median fused (vector + FTS
reciprocal-rank) rank ~28, while the conversation stage keeps 6. Raising
`conversation_limit` raised evidence recall but not accuracy and doubled
latency. The ordering is the problem, not the count: a bi-encoder embeds the
question and the turn separately; a cross-encoder reads them together and
orders a short list much better.

### Decision and Implementation

1. **`[retrieval] reranker = "none" | "<model name>"`**, default `"none"`.
   **`[retrieval] reranker_candidates = 50`**. With a model set,
   `GraphGateway._bundle_conversation` scores (question, turn) for the best 50
   candidates by fused score and the top-`limit` cut takes the best by
   cross-encoder score. Candidates beyond 50 keep their fused order behind them.
2. **Placement.** After the B459 lexical gate, the user-only / question /
   de-dup filter and the B463 successor bridge; before the cut. The gate and
   the bridge still decide what may be evidence; the reranker only decides
   which of it survives the cut and, under `conversation_order = "rank"`
   (B474), its order (rank = cross-encoder order). The final
   `conversation_order = "time"` sort still runs after the cut. A B463 successor
   statement shares no words with the question, so it takes the cross-encoder
   score of the on-topic turn that led to it when that is higher than its own
   (the analogue of inheriting the leading turn's fused score); those leading
   turns (possibly assistant turns) are scored for this and never returned.
   When there are no more candidates than `limit` and order is "time", scoring
   is skipped (it could not change the output).
3. **Model.** fastembed `TextCrossEncoder` (ONNX Runtime) -- the package that
   already serves the embedding model (B355). The plan said
   sentence-transformers; that is PyTorch and `tests/test_no_torch_dependency.py`
   forbids it. Checkpoint: `Xenova/ms-marco-MiniLM-L-6-v2`, MS MARCO MiniLM-L6
   cross-encoder, 91 MB `model.onnx` (14 MB tokenizer etc. excluded),
   downloaded on first use into fastembed's cache (`local_files_only` follows
   the embeddings offline setting). New module
   `campy/brain/hippocampus/graph/reranker.py`: lazy load once per process,
   cached, lock-guarded, CPU provider. If the package or model is unavailable,
   or scoring raises, it logs one warning per model and the stage keeps the
   fused order (the failure is remembered for the process).
4. **Off the event loop.** `_dispatch_oxigraph` runs the reranked query's
   handler with `asyncio.to_thread` (the vector store has its own lock and
   `check_same_thread=False`; the RDF store is thread-safe).
5. **Speaker and blending (R34 revision).** First version scored
   `"<speaker>: <text>"` and let the cross-encoder order replace the fused
   order. R34 gate (eval_gate replay on golden stores, reranker on vs main):
   LoCoMo-10 dev 0.317 -> 0.383 (gained 7, lost 3), DMR dev 0.520 -> 0.400
   (gained 2, lost 8). The lost DMR questions (valid_18, 28, 31) read "Speaker 2
   asks Speaker 1 ... what Speaker 1 said earlier"; with the label in the scored
   text the cross-encoder matched the label in the question's framing and
   promoted the OTHER speaker's turns ("Speaker 2: Cute! Where do you hike? My
   pet ... is a cow") over the right one ("Speaker 1: He is a black lab named
   trooper"), and replacing discarded the fused ranking's speaker-aware
   embedding signal (B472 1b). Fix: (a) score the bare turn text; (b)
   `[retrieval] reranker_mode = "blend" | "replace"`, default `"blend"`: the
   reranked window is ordered by reciprocal rank fusion (k=60) of fused rank and
   cross-encoder rank, `1/(60+fused_rank) + 1/(60+ce_rank)`; `"replace"` is the
   original cross-encoder-only order. Successor-bridge inheritance is unchanged
   (the successor's cross-encoder score is raised to its leading turn's before
   ranking). `CAMPY_RETRIEVAL_RERANKER_MODE` overrides the key for gate runs.
   `reranker.CALLS` counts scoring passes and the first logs
   "reranker active: <model> mode=<mode>" at INFO. Re-gate pending.
6. **Threading.** `bundle_compiler._stage_conversation` reads the settings
   like `conversation_limit`. Per plan G.2 the existing query is untouched: a
   new `thalamus.bundle_conversation_reranked` (params + `reranker`,
   `reranker_candidates`) is used only when a reranker is set, so `"none"`
   runs the B474 query exactly as before. `CAMPY_RETRIEVAL_RERANKER` in the
   environment overrides the config key (so a gate replay on a store copy can
   enable it without editing that copy's `config.toml`).

### Measured

50 (question, turn) pairs of ~30 words on CPU (Apple M2 Max, ONNX CPU
provider): ~240 ms best of 3 (0.24-0.31 s over 5 runs). Model load ~3.5 s
once per process. Longer real turns cost more.

Offline replay (campy-benchmarks `diag_locomo10_fusion.py` `rerank` variant,
copy of the R24a LoCoMo-10 dev store, 36 questions with evidence found, no
B463 bridge; campy-benchmarks#36): evidence-turn recall at limit 6 / 12 / 20
base 0.327 / 0.327 / 0.367 (15 / 15 / 16 questions), rerank 0.469 / 0.531 /
0.531 (21 / 23 / 23). Dev split, diagnostic only -- not the gate.

### Tests

`tests/test_b477_reranker.py`: a fake scorer that reverses the fused order
changes which turns survive the cut; rank order = reranker order, time sorts
after the cut; only the top N fused candidates are scored; no scoring when it
cannot change the output; bare-text scoring (no speaker prefix); blend keeps a fused-top turn the cross-encoder ranks modestly, replace unchanged, blend default; load failure and scoring
failure fall back to the fused order and log once; `reranker="none"` returns
rows identical to the unchanged query and the stage keeps the old query name
and params; a B463 successor keeps its leading turn's score; env override; the
real model prefers the named speaker's turn and a 50-pair CPU latency number
(both skip when the checkpoint is not cached; `CAMPY_TEST_REAL_RERANKER=1`
allows the download).

### Noted in passing (not fixed here)

The de-dup key is the turn text alone, so two speakers saying the identical
sentence collapse to the newest one regardless of speaker.
