# B249 - Dataset Node + Tabular Data Store

State: complete -- re-verified 2026-08-03 with one caveat (delete_table does not archive the Dataset node; pandas not in pyproject.toml deps). See Audit Findings below.
Priority: P1

Plan: backlog/plans/B-249-dataset-node-tabular-store.md

### Problem

Spreadsheets, CSVs, and tabular data don't fit naturally as graph nodes or vector embeddings. Forcing them into DocumentExtract chunks loses their columnar structure. Forcing them into individual Concept nodes pollutes the graph with data that has no relational meaning at the entity level.

Campy needs a way to store structured tabular data while keeping the graph as the metadata index and relationship layer.

### What This Card Does

Adds a `Dataset` node type to the Kuzu schema and a local SQLite-per-dataset storage layer. The graph holds metadata, schema description, and provenance pointers. The SQLite file holds the queryable rows and columns.

### Dependencies

- None (foundation card)

### Design Decisions

| Decision | Choice | Rationale |
|---|---|---|
| Tabular storage engine | SQLite (one file per dataset) | Zero-server, portable, SQL-queryable, already in Python stdlib |
| Storage location | `~/.campy/tables/{dataset_id}.sqlite` | Follows existing runtime dir convention |
| Graph relationship | Pointer-based (`storage_uri` on Dataset node) | Graph stays lean; heavy data lives outside Kuzu |
| Schema metadata | `schema_json` property on Dataset node | Enables retrieval without opening the SQLite file |

### Audit Findings (2026-08-03 re-verification)

Actually checked each acceptance criterion against current repo state (code paths are now under `campy/brain/sensory_cortex/tabular_store.py`, `campy/brain/hippocampus/schema.py`, `campy/paths.py` after the anatomy refactor — the card's original file paths are stale but the equivalent code exists and was reviewed).

- Dataset node type + all 18 properties: present in `campy/brain/hippocampus/schema.py` (`NODE_TABLES["Dataset"]`, lines ~786-807). Verified by reading the schema and by creating a real Dataset node via a live KuzuDB in a smoke test.
- `create_table_from_dataframe()`, `query_table()`, `get_table_summary()`, `delete_table()`: implemented in `campy/brain/sensory_cortex/tabular_store.py`, matching the plan exactly.
- **Ran the real test suite, not just read it**: `tests/test_tabular_store.py` uses `pytest.importorskip("pandas")`, and **pandas is not declared as a dependency anywhere in `pyproject.toml`**. In a clean checkout of this worktree, pandas was absent and all pandas-dependent tests silently skip rather than fail — meaning "full test suite passes" was previously true only because the tabular feature's own tests never actually ran. Installed `pandas`+`openpyxl` into `.venv` and re-ran: `.venv/bin/python -m pytest -q tests/test_tabular_store.py tests/test_schema.py` → **47 passed, 0 skipped**. Real SQLite read/write, read-only enforcement (`PRAGMA query_only`), and schema/row-count/sample-row summaries all verified against real data, not mocks.
- HNSW vector index on `Dataset.embedding`: confirmed in `schema.py`'s `embedding_tables` list (includes `"Dataset",  # B249`) and exercised through `db.create_vector_index("Dataset", "embedding", "dataset_emb_idx")` at schema-init time. No dedicated test asserts this (neither `test_tabular_store.py` nor `test_schema.py` mention `Dataset` for the index), so this is verified by direct code inspection, not an automated regression test.
- **Caveat — `delete_table()` does not "archive the Dataset node"** as the acceptance criterion states. It only unlinks the SQLite file (`campy/brain/sensory_cortex/tabular_store.py:73-79`). There is no code anywhere in the repo that sets `Dataset.archived = true` or otherwise updates the graph node when a table is deleted (`grep -rn "archive.*[Dd]ataset" campy/` returns nothing). `delete_table()` is also never called from any production code path or exposed via any MCP tool — it currently exists only as a library function exercised by its own unit tests. Not a blocker for the foundation this card promises, but the acceptance criterion as written is not met.
- **Caveat — missing dependency declaration**: `pandas` (required by `create_table_from_dataframe`) and `openpyxl` (required by B250's XLSX path) are not in `pyproject.toml`'s `dependencies` or `optional-dependencies`. A fresh `pip install -e .` does not pull them in, so the tabular store is non-functional out of the box today. Left as-is rather than fixed inline since changing `pyproject.toml` dependencies is a project-wide decision outside this card's stated file list.

Commands run as evidence:
```
.venv/bin/pip install pandas openpyxl
.venv/bin/python -m pytest -q tests/test_tabular_store.py tests/test_schema.py   # 47 passed
```
