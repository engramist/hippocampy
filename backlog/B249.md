# B249 - Dataset Node + Tabular Data Store

State: ready
Priority: P1

Plan: backlog/plans/B-248-dataset-node-tabular-store.md

### Problem

Spreadsheets, CSVs, and tabular data don't fit naturally as graph nodes or vector embeddings. Forcing them into DocumentExtract chunks loses their columnar structure. Forcing them into individual Concept nodes pollutes the graph with data that has no relational meaning at the entity level.

Campy needs a way to store structured tabular data while keeping the graph as the metadata index and relationship layer.

### What This Card Does

Adds a `Dataset` node type to the Kuzu schema and a local SQLite-per-dataset storage layer. The graph holds metadata, schema description, and provenance pointers. The SQLite file holds the queryable rows and columns.

### Dependencies

- None (foundation card)

### Design Decisions

| Decision | Choice | Rationale |
|---|---|---|
| Tabular storage engine | SQLite (one file per dataset) | Zero-server, portable, SQL-queryable, already in Python stdlib |
| Storage location | `~/.campy/tables/{dataset_id}.sqlite` | Follows existing runtime dir convention |
| Graph relationship | Pointer-based (`storage_uri` on Dataset node) | Graph stays lean; heavy data lives outside Kuzu |
| Schema metadata | `schema_json` property on Dataset node | Enables retrieval without opening the SQLite file |

### Acceptance Criteria

- [ ] Dataset node type exists in Kuzu schema with all specified properties.
- [ ] `create_table_from_dataframe()` writes a pandas DataFrame to SQLite.
- [ ] `query_table()` executes read-only SQL and returns results.
- [ ] `get_table_summary()` returns schema, row count, and sample rows without loading full table.
- [ ] `delete_table()` removes SQLite file and archives Dataset node.
- [ ] `tables_dir()` returns correct path under `~/.campy/tables/`.
- [ ] Dataset node has HNSW vector index on embedding field.
- [ ] All new code has test coverage.
- [ ] Full test suite passes.
