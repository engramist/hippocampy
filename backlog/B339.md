# B339 - Label Replayed Memories as Data, Not Instructions, in ask/compile_context Output

State: complete — merged via PR #63 (2026-08-20)
Priority: P2

Plan: none yet.

### Problem

An external security audit found that stored memories are replayed into downstream agent context as
plain, unlabeled strings, with no data-vs-instruction marking. The only existing defense is the
embedding-similarity anomaly detector (`campy/brain/temporal_lobe/loop/anomaly_detection.py` — see
its module docstring, "Detects anomalies in the Loop's Step 4 that indicate potential prompt
injection, goal hijacking, or constraint violations"), which flags content that *contradicts a
pre-existing high-confidence GlobalConstraint or GlobalPreference* via cosine similarity
(`HIGH_CONFIDENCE_THRESHOLD = 0.8`, `similarity > 0.75` check). This is a real and useful defense
against a narrow case — but a genuinely novel injected instruction, one that doesn't contradict
anything already stored, has nothing to be similar to and passes through unflagged. And even flagged
content is still served to the caller today (`check_anomalies` returns `has_anomaly`/`anomalies` as
metadata — confirm whether any caller currently uses that to actually withhold or clearly quarantine
the content, versus just logging/surfacing it alongside the still-served text).

This is a structural gap, not a bug: any system that replays stored free text into an LLM's context is
exposed to this class of injection risk. This card is about reducing blast radius via labeling, not
claiming to eliminate the risk category entirely — that's not achievable with a labeling change alone.

### What it does (scope)

1. Find every place where recalled/retrieved memory content is assembled into a prompt or context bundle
   handed to an LLM — the primary surfaces are `ask` (`campy/brain/.../ask.py` or wherever B289's
   thalamic-compression `ask` implementation lives — grep `rg -rn "def ask"` under `campy/brain/`) and
   `compile_context`/`compile_card_context` (B252's bundle compiler). Also check `current_truth` and
   `recall_relevant_lessons`/`recall_procedures` if they format text for direct LLM consumption rather
   than returning structured data to a caller that formats it separately.
2. At each surface, wrap replayed memory text with an explicit data/instruction boundary marker in the
   assembled prompt — e.g. XML-style tags (`<retrieved_memory source="..." trust="stored_data">...
   </retrieved_memory>`) or an equivalent clear delimiter — plus a short system/instruction-level note
   telling the LLM that content inside those tags is retrieved data to reason about, not instructions to
   follow, mirroring the "instruction source boundary" pattern already used elsewhere for treating tool
   output as data rather than commands.
3. When `check_anomalies` flags content (`has_anomaly: true`), do not silently include it in the
   assembled context unlabeled — either exclude it from synthesis and surface the anomaly as metadata
   only, or include it but with an explicit "flagged as a possible constraint contradiction" annotation
   in the same delimiter wrapper, so a downstream agent (or the calling harness) can make an informed
   choice rather than silently trusting it. Pick whichever behavior is less disruptive to existing
   `ask`/`compile_context` callers and document the choice.
4. Add tests proving: (a) memory content in an assembled `ask`/`compile_context` prompt is wrapped in
   the new data-boundary marker, (b) anomaly-flagged content is handled per the policy chosen in item 3
   (excluded or clearly annotated — a test should assert whichever behavior was picked).

### Dependencies

None. Touches `ask`/`compile_context` code paths that B289/B252 built — read those cards
(`backlog/B289.md` if present, or grep for "thalamic compression"/"GraphBundleCompressor") for context
on the existing prompt-assembly structure before changing it, to avoid breaking the compression
pipeline's existing invariants.

### Files to create/modify

- The `ask` implementation module (locate via grep).
- The `compile_context`/`compile_card_context` bundle-compiler module (B252).
- `campy/brain/temporal_lobe/loop/anomaly_detection.py` (only if item 3's chosen policy requires
  `check_anomalies`'s return shape to change — likely it doesn't, and the caller-side change is
  sufficient).
- New/updated tests near each modified prompt-assembly module.

### Acceptance Criteria

- [ ] Every place that assembles retrieved memory text into an LLM-bound prompt wraps that text in an
      explicit data/instruction boundary marker, verified by a test inspecting the assembled prompt
      string.
- [ ] A documented, tested policy exists for anomaly-flagged content (excluded from synthesis, or
      included with explicit flagged-content annotation) — not silently included unlabeled as today.
- [ ] Existing `ask`/`compile_context` tests still pass (no regression to synthesis quality/behavior
      beyond the labeling change itself).
- [ ] The change is documented in `docs/ARCHITECTURE.md` (or wherever the anomaly-detection /
      Cocktail-Party-Effect security model is currently documented) as part of the project's stated
      prompt-injection defenses, with an honest note that this reduces but does not eliminate the risk.
