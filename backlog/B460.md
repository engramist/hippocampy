# B460 - Calibrated Decisions in the Write Path (Local-First)

State: in-progress (Part A done 2026-10-01: items 2, 4 partial, 6. Part B 2026-10-01: item 1 machinery done, opt-in; the labeled set can't support a usable model. Items 3, 5 wait on more labels)
Priority: P2

### Problem Statement

Every decision point in the write path produces a confidence number that is
used as if it were a probability, and none of them is one:

| Step | Decision | Where the number comes from |
|---|---|---|
| 2 (System 2) `step2_gist._classify_with_llm` | 1 of 7 gist classes | the LLM writes its own `"confidence"` in JSON |
| 2 (escalation) `classify_concept` | escalate to System 2? | cosine band 0.18–0.50, not a probability |
| 3b `step3b_relations` | 1 of 9 relation types or null | LLM forced choice, confidence self-reported |
| 4 `classify_artifact` | save as decision/constraint/requirement/action_item/none | `0.67 + 0.15 * regex_hits`, hand-set gist priors |
| 6 `step6_arbitration.arbitrate` | additive / contradiction / uncertain | LLM forced choice, parsed by regex |

Thresholds (`NOISE_FLOOR`, `HARD_LOCK`, `ASSISTANT_CAP`, the salience
multiplier, the B300 single-token cap) are stacked on these numbers.

This is the idea behind TypeSafe's Jev model (typed answers with calibrated
probabilities), but it can be done locally without sending turns to a hosted
API.

### What It Does (Scope)

1. **Step 4 classifier:** replace the regex-count confidence with a small
   local classifier over features the Loop already computes (sentence
   embedding, gist class, keyword-signal counts as features rather than as
   the score). Calibrate it (Platt or isotonic) on labeled data from B462's
   gold set plus any additional labeled turns. Keep the regex signals as
   features, not as the confidence.
2. **Constrained choices for LLM steps (2, 3b, 6):** request output
   constrained to the allowed choices (Ollama `format` JSON schema), and
   derive confidence from the model's token probabilities over the choices
   where the provider exposes logprobs. Fall back to today's behavior where it
   doesn't. Drop self-reported confidence.
3. **Category spec as input:** feed `campy/data/artifact_categories.yaml`
   (B462) definitions and exclusions into the Step 4 classifier's training
   labels and into the LLM prompts. Seed the spec into the graph at
   `init_schema` (following the `ROUTING_TABLE` pattern) now that there is a
   runtime reader. Add definitions for gist classes the same way.
4. **50/50 escalation and vagueness log:** when the calibrated top-choice
   probability is near the top-two margin (configurable, default margin <
   0.15), escalate to System 2 (LLM) instead of guessing. Log each such case
   with the two competing categories to the activity feed, so recurring pairs
   show where the spec's definitions overlap.
5. **Re-derive thresholds** from the calibration curve so `HARD_LOCK = 0.90`
   means a measured ~90% precision on the labeled set.
6. **Fix artifact text:** reified artifacts currently store the entity span
   (`orchestrator._reify_concept` uses `entity["text"]`, e.g. "PostgreSQL")
   rather than the statement. Store the statement (sentence) so a correctly
   typed artifact is useful at recall.

### Follow-up (separate card when this lands)

Learn *whether to keep* from outcomes, not only *what type*: nodes that are
later recalled or strengthened (`pathway_strength`) vs. never touched or
deprecated are free labels for the save gate itself.

### Acceptance Criteria

- [ ] On the B462 labeled set (held-out split), the Step 4 reliability table
      has max per-bin |confidence − accuracy| ≤ 0.10 for bins with ≥ 10 items.
- [ ] Reified-type accuracy and false-save rate are no worse than the B462
      baseline; report both.
- [ ] Steps 2, 3b, 6 no longer read a self-reported confidence field.
- [ ] Near-50/50 cases are logged with the competing pair.
- [ ] Artifacts store the statement text; a test covers it.
- [ ] No new network dependency; runs fully offline with Ollama or no LLM.

### Outcome

Thresholds in the write path mean what they say, and the system tells us
which category definitions are vague.

### Part A (done 2026-10-01): the parts that don't need data

**Item 6, artifact text.** Reified artifacts now store and embed the entity's
sentence (`step4_pattern.entity_sentence`, the scoping Step 4 already uses)
instead of the entity span. A Decision reads "We decided to use PostgreSQL
for the job queue." rather than "PostgreSQL". Concepts still store the
entity.

**Item 2, constrained choices (Steps 2 and 6).** New
`campy/brain/llm/decide.py`:
- Options are lettered and the model answers with one letter.
- Where the provider returns token log-probabilities
  (`LLMClient.chat_choice`, `logprobs=True, top_logprobs=10, max_tokens=3`),
  each option's probability is read from the first answer token,
  renormalised over the valid letters.
- If the endpoint rejects the logprobs parameters, it is asked again without
  them.
- Clients without `chat_choice` (Bedrock, test doubles) fall back to parsing
  the text, by letter or by a single matching label, and get `probs = None`.
- Self-reported confidence is gone. Step 2 System 2 `confidence` is the
  class probability, or `None` when unknown. No code read that value
  (`gist_confidence` is stored on typed entities but never consumed).

**Item 4, partially: near ties.** A top-two margin under 0.15 (the card's
default):
- Step 6: a near tie becomes `uncertain`, so both nodes stay
  `confidence_low`. That is the existing safe outcome.
- Step 2: a near-tie answer is not saved as a `GistExample`, so ambiguous
  labels don't move the centroids.
- Both are logged as `[Gate:NearTie] step=... pair=a|b p=... margin=...` in
  the Loop log. It goes to the Loop log, not the activity feed, because the
  Loop has no activity-feed hook today.
- Near ties are only detectable with log-probabilities; on text-only
  providers nothing changes.

**Step 3b is not converted.** Its answer has several parts (head, tail and
relation type), so it doesn't fit one lettered choice without either two calls
or enumerating entity pairs. It still self-reports confidence. Left for a
follow-up.

**Tests:** `tests/test_b460_decisions.py` (12):
- probability extraction and renormalisation, near ties, text fallback and
  ambiguity, no-raise;
- `chat_choice` against a fake OpenAI response, plus the
  rejected-parameter retry;
- the Step 6 near tie becoming `uncertain`, Step 2 probabilities and the
  near-tie flag;
- the artifact statement written to a real Oxigraph store.

`tests/test_loop.py::test_step2_llm_fallback_called_in_gray_zone` now expects
`confidence is None` (it pinned the removed self-reported 0.78).

**Not verified here:** whether a live Ollama returns log-probabilities through
its OpenAI-compatible endpoint for the configured model. The sandbox has no
Ollama. If it doesn't, Steps 2 and 6 use the text path, which is no worse
than before.

### Part B (2026-10-01): item 1 — the calibrated classifier (machinery done; data is the blocker)

**What was built** (opt-in, off by default):
- `campy/brain/temporal_lobe/save_gate_model.py`: a multinomial logistic
  regression over the five categories (decision, constraint, requirement,
  action_item, none) with a fitted temperature.
  - Features: Step 4's keyword hit counts (as features, not the score),
    hashed word unigrams/bigrams of the entity's sentence, and optionally the
    gist class and the 384-d sentence embedding.
  - Prediction is pure Python, so the daemon gains no dependency.
  - The model is a JSON file artifact, not agent state. It is loaded from
    `[save_gate] model_path` (new in `campy.toml`, empty by default) and
    cached per path and mtime. An unreadable file is logged and ignored.
- Step 4 hook: `classify_artifact(..., gate_model=, embedding=)`.
  - With a model, the artifact type and confidence are the most likely
    artifact category's calibrated probability. The result also carries
    `probs`.
  - Everything after scoring is unchanged: no gist → noise, the B300
    single-token cap, `NOISE_FLOOR`, `ASSISTANT_CAP`, `HARD_LOCK`, and the
    salience/evidence rescues.
  - If the model fails on an input (e.g. it needs an embedding that isn't
    there), Step 4 falls back to keyword scoring for that entity.
  - Near ties between the top two categories are logged as
    `[Gate:NearTie] step=step4` (item 4).
  - The orchestrator embeds the entity sentence only when the configured
    model needs it, once per sentence per message.
- `benchmarks/save_gate/train_gate.py` (numpy):
  - **Training and evaluation:** trains on `gold.yaml` with nested 5-fold
    CV. Each outer fold's model and temperature are fitted without that
    fold, so every reported prediction is held out, calibration included.
  - **Scoring:** uses the full-mode baseline's `score_full`, plus top-label
    reliability, ECE and NLL, and checks this card's reliability criterion.
  - **Saving:** `--out` saves a model trained on all items.
  - **Pipelines:** `--pipeline full` builds per-entity rows with gist and
    sentence embedding (Steps 1–3, needs the models).
- `run_baseline.py --mode full --gate-model PATH` scores a trained model
  with exactly the full-mode baseline's pipeline and metrics.
- Tests: `tests/test_b460_gate_model.py` (14):
  - features, prediction, temperature, round trip and loader;
  - the Step 4 hook, including that the rules after scoring still apply;
  - fallback and near-tie logging;
  - `run_loop` end to end with a configured model, including the embedding
    path;
  - training on half the set, and temperature recovery on synthetic data.

**Results on the B462 set** (pipeline `none`: text features only. The sandbox
can't download the embedding model, so gist and embedding features weren't
tried):

| Features (l2) | 5-way acc. | ECE | Temp. | Reified | False-store | Missed-save | Reliability criterion |
|---|---|---|---|---|---|---|---|
| ngrams+signals (0.01) | 45.4% | 0.068 | ~0.68 | 0 | 17.5% | 69.6% | FAIL, 2 bins, max gap 0.24 |
| ngrams+signals (0.001) | 45.4% | 0.062 | ~1.14 | 0 | 10.0% | 71.4% | FAIL, 2 bins, max gap 0.18 |
| signals only (0.01) | 42.8% | 0.131 | ~0.80 | 0 | 12.5% | 80.4% | FAIL, 2 bins, max gap 0.33 |

Exploratory, not adopted: adding spaCy's averaged `en_core_web_md` word
vectors (available offline) gave 43–49%. That is within the noise for
n=152 (one standard error is about ±4 points).

**What this means:**
- **Calibration works:** held-out ECE is about 0.06.
- **The classifier is too weak to be useful.** About 28 examples per
  category can't teach "decision without the word decided" from text
  alone. Its calibrated confidence never reaches `HARD_LOCK`, so with this
  model the Loop would reify nothing. Using it now would trade overconfident
  saves for no saves.
- **Today's keyword gate is overconfident on the same set.** When a keyword
  fires (77/152), it claims 0.82, or 0.92 with gist agreement, which crosses
  `HARD_LOCK`. The type is right 59.7% of the time, about 23 points of
  overconfidence. Whenever the gist agrees, those decisions are confirmed
  as artifacts. How often the gist agrees needs the full-mode baseline.
- **The bottleneck is labels, not modelling.** Two things would change the
  picture:
  1. **Real, owner-reviewed labels**, a few hundred per category. Two
     sources: the review queue (disambiguation outcomes), and the "Learn
     whether to keep" follow-up below (nodes later recalled or strengthened
     vs. never touched).
  2. **The embedding feature** (`--pipeline full --features
     ngrams,signals,gist,embedding` on a machine with the models). It's
     the most likely single gain. It is untested on real embeddings here,
     though the code path is covered with a stub embedder.

**Not done:** no trained model is shipped or configured. Items 3 (spec
seeding) and 5 (re-deriving thresholds) need a model good enough to use.
The decision to enable the classifier waits on the run above with
embeddings, and on owner-reviewed labels.
