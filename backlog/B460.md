# B460 - Calibrated Decisions in the Write Path (Local-First)

State: ready (blocked on B458)
Priority: P2

### Problem Statement

Every decision point in the write path produces a confidence number that is
used as if it were a probability, and none of them is one:

| Step | Decision | Where the number comes from |
|---|---|---|
| 2 (System 2) `step2_gist._classify_with_llm` | 1 of 7 gist classes | the LLM writes its own `"confidence"` in JSON |
| 2 (escalation) `classify_concept` | escalate to System 2? | cosine band 0.18–0.50, not a probability |
| 3b `step3b_relations` | 1 of 9 relation types or null | LLM forced choice, confidence self-reported |
| 4 `classify_artifact` | save as decision/constraint/requirement/action_item/none | `0.67 + 0.15 * regex_hits`, hand-set gist priors |
| 6 `step6_arbitration.arbitrate` | additive / contradiction / uncertain | LLM forced choice, parsed by regex |

Thresholds (`NOISE_FLOOR`, `HARD_LOCK`, `ASSISTANT_CAP`, the salience
multiplier, the B300 single-token cap) are stacked on these numbers.

This is the idea behind TypeSafe's Jev model (typed answers with calibrated
probabilities), but it can be done locally without sending turns to a hosted
API.

### What It Does (Scope)

1. **Step 4 classifier:** replace the regex-count confidence with a small
   local classifier over features the Loop already computes (sentence
   embedding, gist class, keyword-signal counts as features rather than as
   the score). Calibrate it (Platt or isotonic) on labeled data from B458's
   gold set plus any additional labeled turns. Keep the regex signals as
   features, not as the confidence.
2. **Constrained choices for LLM steps (2, 3b, 6):** request output
   constrained to the allowed choices (Ollama `format` JSON schema), and
   derive confidence from the model's token probabilities over the choices
   where the provider exposes logprobs. Fall back to today's behavior where it
   doesn't. Drop self-reported confidence.
3. **Category spec as input:** feed `campy/data/artifact_categories.yaml`
   (B458) definitions and exclusions into the Step 4 classifier's training
   labels and into the LLM prompts. Seed the spec into the graph at
   `init_schema` (following the `ROUTING_TABLE` pattern) now that there is a
   runtime reader. Add definitions for gist classes the same way.
4. **50/50 escalation and vagueness log:** when the calibrated top-choice
   probability is near the top-two margin (configurable, default margin <
   0.15), escalate to System 2 (LLM) instead of guessing. Log each such case
   with the two competing categories to the activity feed, so recurring pairs
   show where the spec's definitions overlap.
5. **Re-derive thresholds** from the calibration curve so `HARD_LOCK = 0.90`
   means a measured ~90% precision on the labeled set.
6. **Fix artifact text:** reified artifacts currently store the entity span
   (`orchestrator._reify_concept` uses `entity["text"]`, e.g. "PostgreSQL")
   rather than the statement. Store the statement (sentence) so a correctly
   typed artifact is useful at recall.

### Follow-up (separate card when this lands)

Learn *whether to keep* from outcomes, not only *what type*: nodes that are
later recalled or strengthened (`pathway_strength`) vs. never touched or
deprecated are free labels for the save gate itself.

Tool/adapter allow-lists: no tool changes. No shadow stores: the classifier
is a model artifact, not agent state; the category spec lives in the graph.

### Acceptance Criteria

- [ ] On the B458 labeled set (held-out split), the Step 4 reliability table
      has max per-bin |confidence − accuracy| ≤ 0.10 for bins with ≥ 10 items.
- [ ] Reified-type accuracy and false-save rate are no worse than the B458
      baseline; report both.
- [ ] Steps 2, 3b, 6 no longer read a self-reported confidence field.
- [ ] Near-50/50 cases are logged with the competing pair.
- [ ] Artifacts store the statement text; a test covers it.
- [ ] No new network dependency; runs fully offline with Ollama or no LLM.

### Outcome

Thresholds in the write path mean what they say, and the system tells us
which category definitions are vague.
