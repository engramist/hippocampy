### B69 · Valence & Outcome Propagation (Pain/Pleasure Learning)

**Problem:** The Brain learns through frequency (Hebbian/LTP) and time (Ebbinghaus decay) but has no mechanism for learning through outcomes. A plan that catastrophically failed and a plan that succeeded perfectly have the same graph weight if accessed equally often. Humans learn fastest from intense pain or reward — the Brain should too.

**What it does:** Implements the valence propagation system that makes outcome signals flow through the graph, affecting retrieval ranking, Lesson extraction, and the Amygdala Reflex. Depends on B66 (schema) and B67 (tools that write valence).

**Depends on:** B66, B67

**IP Claims (record in Inventors Notebook):**
- **Valence-Weighted Graph Retrieval** — retrieval ranking incorporates historical outcome signals from Plan nodes, not just frequency and recency
- **Amygdala Reflex at Plan Registration** — preemptive warning system that fires before execution, not after failure. Triggered by embedding similarity between a new plan's goal and existing negative-valence plans
- **Graph-Native Behavioral Reinforcement** — outcome learning without a separate RL training loop; valence propagates through existing graph edges to affect entity-level retrieval
- **Dual Valence Granularity** — per-step and per-plan valence scores with computed aggregation, preserving audit trail of which specific steps succeeded or failed

**Valence Propagation Rules:**

1. **Plan → Lesson**: When `report_outcome` finalizes a plan with |valence| > 0.7, auto-create a Lesson node via existing Step 7.5. Lesson inherits the plan's valence. Linked via `[PRODUCED_LESSON]`.

2. **PlanStep → Concept**: When a PlanStep completes with negative valence, all Concepts linked via `[ACTS_ON]` edges get a **valence annotation**. This is NOT a mutation of the Concept — it's an edge property on a new `[OUTCOME_SIGNAL]` relationship:
   - `OUTCOME_SIGNAL` — `PlanStep → Concept` with properties: `valence DOUBLE, plan_id STRING, observed_at TIMESTAMP`
   - Multiple outcome signals can exist (concept was involved in both successes and failures — the history is preserved)

3. **Concept → current_truth**: During Step 5 retrieval, if a retrieved Concept has `[OUTCOME_SIGNAL]` edges, compute the recency-weighted average valence. Inject into the result: `{ ..., outcome_valence: -0.6, outcome_warning: "This entity was involved in 2 failed plans (most recent: 3 days ago)" }`.

4. **Plan → register_plan (Amygdala Reflex)**: At registration time, vector-search existing Plans. For matches with similarity > 0.75:
   - If match.valence < -0.5 → add to warnings[] with the plan's goal, valence, and the specific failed steps
   - If match.valence > 0.5 → add to suggestions[] with the plan's goal, valence, and the successful step sequence
   - Both sorted by |valence × similarity| descending

**Step 4 Updates — Two New Senses:**

Add to `step4_pattern.py`:

```python
# OUTCOME SENSE: Success detection (Dopamine)
_SUCCESS_SIGNALS = [
    r"\bperfect\b", r"\bgreat job\b", r"\bexactly (?:right|what)\b",
    r"\bship it\b", r"\bapproved\b", r"\blooks good\b", r"\bwell done\b",
    r"\bnailed it\b", r"\ball tests pass\b", r"\bmerged?\b",
]

# OUTCOME SENSE: Failure detection (Pain)  
_FAILURE_SIGNALS = [
    r"\bthat(?:'s| is) wrong\b", r"\brevert\b", r"\bundo\b",
    r"\bthat broke\b", r"\bfailed\b", r"\brollback\b",
    r"\bnot what i (?:asked|wanted|meant)\b", r"\bstart over\b",
    r"\btry again\b", r"\bwrong approach\b",
]
```

When outcome senses fire:
- Check if there's an active Plan in the current session (status="active")
- If yes: auto-call `report_outcome` with inferred valence (+0.8 for success signals, -0.8 for failure signals)
- If no active Plan: create a Lesson node directly with the valence (standalone outcome learning, no plan context needed)

**Retrieval Ranking Update:**

Current: `pathway_strength × confidence`
New: `pathway_strength × confidence × (1 + outcome_boost)`

Where `outcome_boost`:
- 0.0 if no OUTCOME_SIGNAL edges (default — no change for non-plan entities)
- Positive for concepts with positive valence history (surfaces golden paths)
- Negative for concepts with negative valence history (demotes pain paths)
- Capped at ±0.3 to prevent valence from dominating over relevance
