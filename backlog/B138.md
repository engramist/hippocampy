# B138: Expose SolveEngine Internal Brain Calls in Agent Trace

**Status**: Ready  
**Assigned**: TBD  
**Depends on**: None  
**Complexity**: Medium (2–4 hours)  
**Priority**: P2 (MEDIUM — debugging blind spot; brain I/O from solve engine is invisible in agent_trace, making 200–300ms solve gaps undiagnosable)  
**Plan**: backlog/plans/B-138-solve-engine-trace.md

## Problem Statement

`SolveEngine.solve()` makes multiple brain calls internally (`recall_plans`, `recall_lessons`, `register_plan`) but has no access to the orchestrator's `_execution_trace` list. These calls only appear in the `arc_server` stream with no matching context in `agent_trace`.

Evidence from `master_timeline.json`:
```
agent_trace stream:
  event: solve_phase_start   elapsed_ms=0
  event: solve_phase_end     elapsed_ms=1ms    ← 1ms in agent_trace

arc_server stream (same time window):
  arc_recall_plans    duration=180ms
  arc_recall_lessons  duration=95ms
  arc_register_plan   duration=55ms
  Total: ~330ms of unaccounted activity
```

The 1ms elapsed in `agent_trace` vs 330ms of actual activity in `arc_server` creates a phantom gap in the timeline. Debugging solve behavior requires manual cross-referencing of two streams.

## What This Card Builds

1. Passes an `emit_trace_event` callback into `SolveEngine.__init__()` (or sets it as an optional attribute after construction).
2. `SolveEngine` calls the callback before/after each brain call: `recall_plans`, `recall_lessons`, `register_plan`, and any other async brain interactions.
3. The orchestrator provides its `_emit_trace_event` method as this callback.
4. The `master_timeline.json` now shows solve-internal brain calls as `agent_trace` events interleaved with `arc_server` events at the correct timestamps.

## Files to Create/Modify

- `agents/arc3/solver.py` — accept optional `emit_trace_event` callback in `__init__`; call it before/after each brain I/O inside `solve()`
- `agents/arc3/orchestrator.py` — pass `self._emit_trace_event` to `SolveEngine` at construction or call time

## Ecosystem / Layer Compliance

- Layer: ARC agent solve engine (`agents/arc3/solver.py`) + orchestrator integration
- No cross-layer import violations. The callback is a plain `Callable`, not an import of orchestrator internals.
- Complies with `docs/arc-harness-rules.md` and `docs/ecosystem-rules.md`.

## Acceptance Criteria

- [ ] `master_timeline.json` shows `solve_recall_plans`, `solve_recall_lessons`, `solve_register_plan` events in the `agent_trace` source
- [ ] Solve phase elapsed_ms in agent_trace matches approximate actual duration (within 50ms of arc_server measurement)
- [ ] `SolveEngine.__init__` accepts `emit_trace_event: Callable | None = None`
- [ ] Callback is optional — `SolveEngine` works correctly when callback is None (no trace events emitted)
- [ ] `pytest -q tests/` passes with no regressions

## Outcome Statement

After this card, the agent_trace stream is complete. Solving activity is fully visible without cross-referencing the arc_server stream. Solve debugging time drops significantly as each brain call, its latency, and its results are visible in the unified timeline.
