# B231 - Installer Hardening and One-Line Bootstrap

State: complete
Priority: P0

Plan: backlog/plans/B-231-installer-hardening-one-line-bootstrap.md

### Problem

Installing SideQuests on a new machine still requires too many manual steps: clone the repo, create a virtual environment, install editable mode, run setup, debug launchd, verify adapter configs, and manually check logs.

A public user needs a single reliable install command with clear diagnostics and a repair path. A private/work-computer user needs the same workflow before public launch.

### What This Card Does

Builds an idempotent installer and bootstrap path that can set up SideQuests on a fresh macOS machine with minimal user intervention.

This card adds a private bootstrap script now and prepares the installer architecture for the later public one-liner.

### Acceptance Criteria

- [ ] `scripts/install.sh` can bootstrap from a fresh source checkout on macOS.
- [ ] Installer is idempotent: running it twice does not duplicate Codex TOML sections, Claude MCP entries, VS Code MCP entries, launchd plists, or config blocks.
- [ ] Installer checks Python version and rejects unsupported Python 3.14+ with an actionable message.
- [ ] Installer creates/repairs `~/.sidequests` with correct permissions.
- [ ] Installer creates/repairs launchd daemon config and can restart the daemon.
- [ ] Installer registers Codex, Claude Code, Claude Desktop, and VS Code where present without breaking existing unrelated config.
- [ ] Installer runs smoke checks after setup and prints next-step repair commands.
- [ ] `sidequests doctor` reports daemon, socket, Kuzu, config, activity log, capture, adapter registration, Python version, package mode, and launchd health.
- [ ] `sidequests doctor --repair` performs safe repairs only and never deletes user memory data.
- [ ] `sidequests activity --follow` is documented as the live operator indicator after install.
